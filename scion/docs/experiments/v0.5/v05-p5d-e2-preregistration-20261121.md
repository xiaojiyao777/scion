# P5d · 持续算法问题的 E2 能力验证预注册

2026-11-21 冻结。八个研究槽位均为 `not_run`，真实 provider 调用为零。本次交付为前瞻方案与离线核验。正式研究启动另行决定。

**待检验判断**　在有完整算法、有限公开计算和可延续研究材料时，agent 能自己选择可区分解释的实验，依据实际结果改变解释和下一步行动。即使最后没有候选，第三方也能复查它为什么停在这里。P5b 的 298 次调用里有 0 次 observe，三个有旧材料机会的槽位都未读取旧正文。这个结果决定了本次需要观察的行为，也决定了必须逐项记录“有无机会”。[P5b 原始判断](v05-p5b-process-study-postrun-20261115.md)

## 八个槽位与任务

每行只向 provider 给出本题 `current_question`。诊断题附新构造的公开 instance、可执行的小程序和原始待核验声明。它们是研究对象，可以自行改变输入、独立计算、观察当前完整算法，或保留疑问。公开题里不提供参考解、预期行动、指定工具或隐藏判据。开放题只给问题。评审与原始正式数据留在 operator 侧。[八份实际公开输入](../../../experiments/v0.5/p5d/public)

|顺序|槽位|研究问题与区分能力|正式阶段上限|材料起点|
|---:|---|---|---:|---|
|1|cvrp-01|四客户共线实例，顺序装载程序的距离与报告期望冲突。区分测试参考错误和算法错误。|0|空|
|2|warehouse-01|四个订单、两种子类，核验报告所说的拆分数是否与装车结果一致。|0|空|
|3|cvrp-02|公开移动程序声称保全所有客户。用实际输入区分计数误差与客户丢失。|1|空|
|4|warehouse-02|公开移动程序声称给出一致可行解。核对移动后的车辆与 assignment。|1|空|
|5|cvrp-03|同一顺序装载程序，容量和需求已变。判断旧结论的适用范围及是否值得提交。|1|同问题 01 的全部已发布公开材料|
|6|warehouse-03|同一配车程序与订单集合，输入次序改变。判断旧的分车与成本关系如何变化。|1|同问题 01 的全部已发布公开材料|
|7|open-cvrp|哪些实例特征使当前完整 CVRP 算法的可行路线质量对求解预算敏感？|3|空|
|8|open-warehouse|哪些条件会改变当前完整配送求解器中同子类分车数与运输成本的关系？|3|空|

每个开放题的输入选择、机制、比较条件和是否提交由 agent 决定。双评审检查实际完整算法或其公开观察，要求结论说明适用的 source、输入与预算。若有正式评价，原样保留可行性、目标、Protocol stage 和 Decision。没有正式提交时记录实际未执行的阶段。诊断小程序中的缺陷只归属于给定程序。只有在当前完整 solver 上获得对应证据，才能把同一诊断延伸到 solver。

**operator 参考边界**　六个诊断均已实际执行给定程序，并以问题包的独立 checker 复算样例输出。01 的正确距离是 8，4 漏掉回仓段。Warehouse 的两个子类均只用一辆车，splits=0、cost=1600。02 的 CVRP 在移动后过滤了合法单客户路线，客户 1 消失。Warehouse 更新了车内列表，仍将 QUAY2 指向原车。两个 02 都在一致性检查失败，后续目标无有效值。03 的 CVRP 原规则形成三条载重合法路线，fleet_violation=1、距离 16，存在两条合法路线的 0/14 见证。Warehouse 换序后 splits=2、cost=1600，重新分组有 0/1600 的可行见证。评审接受等价反例与正确限定，不要求逐字对照。单个可行见证只支持该实例和比较对象上的判断。[逐题输入对应的原始解及 checker 输出](../../../experiments/v0.5/p5d/evaluator/diagnostic-reference.json)

## 材料机会怎样兑现

01 和 03 各有独立的 campaign、预算、源码副本和 H。03 已在 argv 中绑定同问题 01 的 `runs/<id>/public_research/continuity`。即使 01 第一轮就主动结束，03 仍有一个新的、面对变更条件的 H，能够读取已发布的结论原件和依赖。全量导入，不按好坏挑条目。导入只改变公开材料可见范围。分支、H/C、可执行源码、正式历史、预算和终止动作均重新起算。开放题还可利用自然出现的后续 attempt。两条 01→03 链是配对条件，不能当作四个独立重复。

每个后续 H 依序登记五项事实，即前次是否有问题相关的已发布材料、是否真的分配了新 H、其初始索引中依赖是否可读、是否在实际 turn 收到旧正文、是否核对旧/新条件并据此采取行动。只读 fixture、索引或当前会话文件不能充作前次研究。分别报告同 campaign 跨 attempt 与 fresh import。给出有意义材料可读的 H 数、成功读取数和条件化复用数。缺材料、缺后续 H、有机会未读、已读未用各占单独一栏。有效但空的索引可按计划导入。缺失或损坏的索引按原 import 故障记录，禁止人为重建、删参数再跑或挪用兄弟任务材料。

## 预算、竞争停止与失败处置

|每槽位上限|诊断 ×6|开放 ×2|
|---|---:|---:|
|实际 provider dispatch / outer wall|48 / 1,800 秒|192 / 7,200 秒|
|subject、analysis、checker 次数，各自|24|96|
|累计公开 wall / CPU|300 / 180 秒|1,800 / 1,200 秒|
|研究材料存储|512 MiB|2 GiB|
|各正式 stage 的 per-solve 限时|1 秒|5 秒|

总额 **672 次调用、7 小时 outer wall、5,400 秒公开 wall、3,480 秒公开 CPU、7 GiB 存储、最多 10 个正式阶段**，独立外部确认次数为 0。每槽额度独立，剩余不转让。每 H/C session 24 turns、读/搜各 16 次、development test 最多 2 次（每次 30 秒、合计 60 秒）。subject/analysis 每动作 wall/CPU 为 15/10 秒，checker 为 3/2 秒。源树限 64 MiB/4,000 文件。内存、scratch、分页、单动作输出和其余上限逐字段以三个配置文件为准。[实际配置](../../../experiments/v0.5/p5d/config)

- 有效 H `conclude_research` 在材料保存与关闭发布成功后结束该 invocation，formal delta=0。正的正式阶段上限用完以 `formal_stage_limit_reached` 停止。abstain、C abandon 和会话局部额度耗尽按既有 attempt 路由，可在剩余共享预算内获配 fresh H。
- 资源、auth/quota、基础设施、外部中断与边界错误按实际 typed outcome 收尾。若已有结论原件而发布或 terminal drain 发生故障，保留原件，终态沿故障。已完成的 Decision、源码 head 和部分结果保留，待评工作记 `not_executed`。
- 一槽的本地失败、无候选或无收益均纳入分母，继续下一个预定槽位。auth/quota、隔离泄漏、人工中止整批或已确认为共用的基础设施故障使剩余槽位 `not_run` 并逐行记原因。每槽只启动一次，各自使用 fresh 输出目录。不替换失败槽位或追加预算。
- 成本分别取准入调用/trace、实际模型 usage、公开动作的 wall/CPU、材料字节、test 与正式执行及 invocation 实耗。运行载体记录进程起止的单调时钟与退出码。嵌套 wall 不相加；未测成本填 null 并注明，未披露的 token 细项或货币成本不可作零。

## 独立双评与归档判据

两位不同的评审者在全批结束后分别填写独立表，覆盖全部八行，未运行行只填处置原因。评分前各自取得相同的公开题、私有参考和去除模型/历史结论标签的证据副本，可按映射回查原件。在两份初评保存以前，彼此看不到对方评分，不接收运行操作者对研究质量的解说。工具名、额度与路径可能揭示条件，实际可盲范围写入表中。当前只冻结标准，尚无评审打分。[独立评分空表](../../../experiments/v0.5/p5d/evaluator/independent-review-form.json)

每项用 `supported / contradicted / insufficient / not_applicable` 及理由。仅无历史材料设计的 01/02 首 attempt 可将 continuity 记 N/A；若实际出现后续 H，按实际机会评。03 与开放任务该项均适用，即使缺乏机会也明确填写证据不足与原因。评审引用 trace 的槽位、attempt、phase/turn，以及材料原件路径、UTF-8 字节区间和摘录。注明 source role/revision、输入、seed、参数、完整或部分执行、checker 和后续 agent 所见结果。对二进制输出同时注明编码与解码范围。只采信外显操作、数据和理由。

|维度|双方应能独立复核的最短证据链|
|---|---|
|自主调查|实验前外显的问题、竞争解释或可区分的预测 → agent 自选输入、比较或脚本 → 实际 observe 请求和完成状态。区分 subject_run、analysis、legacy test_patch 与单纯源码阅读。分析脚本算 O 时须说明它测了什么、输入从何取得。只有 subject 的实际运行可支持对该完整 solver 行为的测量。|
|解释观察|从对应 source、输入和结果原件复算关键量，注明可行性、目标优先级、测量范围和不确定性。checker 判断给定解，原始输入、样例程序、分析输出与当前 solver 的输出分别归因。超时、缺失数据和不完整输出单列。|
|解释修正|按时间定位先前判断、能与它区分的观察、随后修正的具体内容，以及受影响的下一行动。下一行动可为新实验、改变草稿、进一步复核、提交 H 或有理由地结束。事后写出的“原本预期”、只弱化断言再 PASS、只改笔记措辞均不能支持修正。|
|范围结论|对照本题参考或完整 solver 证据，给出能被反例推翻的范围结论、未决条件、为何继续或停止。负收益、证据支持暂缓提交、反例都可获支持。实际导出与终态由 host 记录核验。|
|材料延续|前一 attempt 的原件及来源 → 新 H 的成功 read/search 正文及实际返回字节 → 对照 source、输入/负载或测试条件 → 后续试验或判断确有改变。可合理拒绝套用旧结论。单有 origin ref、连续性目录、相同文本或 C 的当前 handoff 不足。|

A/B 的实际使用单列。每个进入 C 的 attempt 记录有无 test_patch、失败类型、请求/脚本/草稿/有限结果 ref 及其后实际回读的字节。以 tested_source_refs 对照当时的阶段、draft revision 和安全源码投影，标明 request_only、缺依赖、预检未执行、部分完成等情况。再查 agent 是否据此核验了旧测试或变更了行动。被保存、可读、实际读取、影响行动逐级计数。有失败 falsifier 时保留原反例和 veto。没有 C 或没有测试的槽位列为无此机会。

**无候选单列两个问题。** 第一，host 是否接受了当前开放 H 的显式结束动作？对照 tool request、保存的理由/依赖、关闭后 outcome、最终 status/summary、此次 formal delta，以及此前是否已发生正式评价。逐项记录正式 H 导出数、C/ready 导出数和实际 Protocol 阶段数。把全程未导出 H/C、已有被拒提案、已有正式评价后三者分列，避免把零 formal stage 直接归为无提案。第二，理由是否由当前证据支持？两评审各自指出排除的解释、适用条件和剩余不确定性。零正式额度只能证明受限调查中有信息量的结束。判定有选择权时核对该 turn 的正式额度、剩余 turns/资源及导出所需原有读取条件。即使首 turn 还须先读源码，只要剩余资源足够走合法导出路径，agent 仍有选择。有依据地选择结束且全程没有候选，才记为自主选择无候选。故障、abstain、达到上限、笔记里的“结束”以及空泛理由分别记录。若八行都合理提交了候选，主动结束的自主能力仍记未观察到，不减记已经成立的 O/M 见证。

**整批判断在看结果前固定。** 八行须完整处置。两问题均须有经双评核实的正确诊断，错误参考、真实反例和条件迁移三种题型均须有正确的范围判断，全部六题逐行报告。至少一条连续真实轨迹的自主调查、解释、修正和结论四项同时获双方支持，并具有新 O 的实际测量。至少一条不同 attempt 间的条件化 M 复用获双方支持。两个开放题各自须在实际完整算法上完成有界自主调查并得出有信息量的结论，相关权限和科学边界可复核。全部满足才报告本轮 E2 过程能力得到支持。另给“有正式选择时的有效无候选结束”独立结论，须至少一条上述有选择权见证且双评支持。分别报告 E2、主动结束及 A/B 工具的实际使用范围，允许部分能力有见证。

原始材料足够而行为未出现或出现明确反证，报告本批未展示该能力。评审缺席、材料不足、分歧未解、资源耗尽导致开放任务未完成，均标出相应不足。不同槽位不能拼成同一条修正轨迹。记录每项一致/分歧数，两份初评和字节引用原样保留。可另附第三人解释，但本批只计入两位原评审均支持且证据链一致的见证。人工指定下一实验、代改解释/源码或提示答案，记 scientific intervention 并排除受影响链的自主资格。保留原运行及已独立完成的证据。

## 冻结时已核验的范围

八行由实际 CLI parser 解析，再用冻结副本的配置验证器读入问题、能力及资源限制。两问题的正式实例、spec canary、seeds 和 stage time policy 可解析；逐行带正式文件排除复制公开闭包成功。另在临时目录使用 `--mock-llm` 和 scripted Creative 检查八个 H 上下文中的完整问题、O/M、正式额度、工具可见性。两个 03 均通过真实 CLI import/read 路径回读各自 01 写出的临时笔记。八次临时演练均为零次 provider dispatch、零个正式 stage，演练结束后删除临时输出。未来真实复用仍由 agent 在当时的真实材料和机会中自行决定。

准备时发现，旧运行清单把材料源放在单独的 metadata 字段。此次已将两个真实导入参数直接固定在新 argv，并以实际 CLI 路径回读核对。初版离线演练还错误地把“正式额度可用”等同于“首 turn 已开放 finalize”；校正检查后八行通过。运行时的读取和导出规则沿用冻结源码。真实输出目录尚未创建。已有 P5b 未达 E2、独立第二评审待办以及 P5c 工程回归中的失败记录均保留。[离线核验结果](../../../experiments/v0.5/p5d/offline-verification.json)

设计依据采用 Design Discussion 阅读路径、当前 runbook、P5/P5c 合同及 P5b 预注册和 postrun。只复用了指定 P5b 冻结输入与运行清单。V3 已采纳的生命周期足以执行本批，研究题目和评分标准均留在实验包。[P5c 合同](../../../design/v0.5/v0.5-p5c-question-session-and-materials.md)
