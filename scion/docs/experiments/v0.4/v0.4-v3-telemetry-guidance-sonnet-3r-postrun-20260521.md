## Why `population_restart` Continued

`population_restart` 有 3/1/12 pair signal，但最终仍 `continue_explore`，原因是当前 v3 decision/lifecycle 分两层：

1. `DecisionEngine` 先看 screening gate win rate。case-level gate win rate 是 1/8 = 0.125，低于 promotion threshold，因此产生 `SCREENING_FAIL_WIN_RATE`。
2. `BranchLifecyclePolicy` 再判断低信号分支是否保留。该实验有至少一个 case win，且 case-level losses 为 0，所以不是明确退化；policy 返回 keep exploring，并附加 `SCREENING_WEAK_SIGNAL_CONTINUE`。

pair-level 的一个 loss 被 case aggregation 稀释了：`P-n101-k4` 一 win 一 loss，case-level 不是 loss。按当前规则，pair-level 3 win / 1 loss / 12 tie 不足以 promote，也不足以 abandon，因此 `continue_explore` 符合分支生命周期。

最终 `n_active_branches=0` 但 `last_result=continue_explore` 也符合当前实现：

- campaign loop 达到 `effective_rounds_completed=3` 后设置 `final_reason=max_rounds_exhausted`

- `status.last_result` 保留最后一个 completed StepResult，即 formal decision 的 `continue_explore`
- 当前 branch list 反映 terminalized state，所以 `n_active_branches=0`

这是可解释的 reporting nuance，不是 lifecycle correctness bug。但 status 最好额外显示 `terminalized_active_branches` 或 final branch states，避免把 `continue_explore` 误读成还有 active branch。
