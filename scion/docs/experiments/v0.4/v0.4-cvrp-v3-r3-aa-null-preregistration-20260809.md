## Fixed calibration design

Run three independent stage diagnostics:

| Stage | Cases | Ledger seeds used | Pair records | Solver executions |
|---|---:|---|---:|---:|
| quality (`screening`, expanded) | all fixed 12 | `11,29` | 24 | 48 |
| validation | all fixed 12 | `47,53` | 24 | 48 |
| frozen | all fixed 12 | `61,67` | 24 | 48 |

Each pair runs original B0 twice with the same case, same ledger seed, same
selected surface and same resolved time limit. `replicates=1` and
`seed_offset=0`; therefore this diagnoses repeatability under the actual
time-budgeted runner rather than between-seed variation. Runs use the fixed
dimension-only budgets: 30 seconds through dimension 100, then 45/60/90/120
seconds through 200/350/700/1001. Canary is not part of this null diagnostic.

For each stage, pair deltas are independently label-swapped 2,000 times. Each
permutation takes the median within case, then evaluates the exact R3 rule:

- case net score `(W-L)/12 >= 0.25`;
- case loss rate `L/12 <= 0.20`;
- median distance improvement at least the problem practical delta;
- bootstrap median CI low `>= 0`;
- feasibility/fleet behavior remains recorded by the existing runner, but no
  failed solver execution may be silently converted to a numeric delta.

The artifact reports empirical null pass rate and a one-sided 95% Wilson upper
bound. `decisive_cases` is descriptive only. The legacy `protocol_power` block
is retained for artifact compatibility but is not the R3 rule or a power claim.

an alternative rule or population requires a new commit and preregistration.

first command starts.

Passing this diagnostic only rejects an obvious false-pass problem under the
observed B0 repeatability noise. It does not prove 80% power at delta 2, does
not guarantee promotion, and does not establish full CVRPLIB generalization.
