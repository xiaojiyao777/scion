## Arms and normalization

### Exact arm

Use the current checked-in exact `generate_patch` definition, whose
`input_schema` matches all four historically recorded trace schemas. It may
return the primary typed exact/full-file operation and its bounded
`additional_changes` set. The complete frozen object is `tools/exact.json` in
the input bundle.

### Diff arm

Use the same `generate_patch` tool name with a diff-specific description and
one strict schema. The complete frozen object is `tools/diff.json` in the input
bundle:

```json
{
  "diffs": [
    {"file_path": "visible/editable/path.py", "unified_diff": "..."}
  ],
  "evidence_refs": ["..."],
  "test_hint": "optional tainted text"
}
```

The diagnostic parser accepts ordinary unified hunks only for the declared
visible editable file. Context and removed lines must match the frozen source
exactly; hunk positions, counts and final bytes must be deterministic. Reject
overlap, duplicate paths, missing or extra context, `/dev/null`, rename,
binary, mode, fuzzy/offset repair and undeclared trailing text.

Normalize both arms into the same ordinary `PatchProposal`, apply each to a
fresh copy of the frozen source and run unchanged
`validate_patch(..., approved_hypothesis=H)`. There is no shell/model tool loop,
same-call repair, retry, solver, Protocol or Verification-quality grader. The
three experiment-owned runtime modules remain within the prelaunch correction
above; production campaign growth is zero.

## Measurements

For every fixture and arm record:

- provider terminal status, finish reason, tool name and JSON/schema validity;
- normalized file/action/edit set, when normalization succeeds;
- deterministic apply result and unchanged Patch Contract result, when
  normalization succeeds;
- exact changed symbols and use/update sites;
- H-obligation coverage: `0=missing`, `1=partial or unused scaffold`,
  `2=complete causal wiring`;
- source-anchor coverage: `0=wrong owner/symbol`, `1=correct file but incomplete
  sites/data flow`, `2=all required owner, update and consumer anchors closed`.

A parse/apply rejection has no normalized patch. Assign both rubric scores
deterministically to zero with source `fixed_no_normalized_patch`; do not create
a blind-review packet. Every normalized patch, including a Contract rejection,
does receive a packet. Two blind reviewers receive H, frozen source, normalized
resulting patch and the two rubrics, but not arm, raw expression format,
historical C response or solver/Protocol outcomes. Resolve rubric disagreement
by reporting both scores; do not create a model grader or majority gate. The
adoption conditions below must hold independently under both reviewers' scores.

## Interpretation and adoption

schema causality `UNIDENTIFIABLE`; keep the production expression unchanged.
A provider-terminal single `generate_patch` call whose expression then fails

resumed.
