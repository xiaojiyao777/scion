## Findings

- `agentic_session_timeout` was treated as a campaign-terminal control failure.
  This is too strong: a single APS session budget exhaustion should fail the
  current attempt/branch, not stop a fixed-round diagnostic campaign.
- CVRP mechanism-premise matching still had false positives:
  - route-limit/fleet gates read risk mitigation text as a positive premise;
  - Shaw related-removal gates read contrast text such as "unlike Shaw" as a
    missing related-removal claim.
- DeepSeek `v4pro-max` is not currently suitable for full code generation in
  Scion's non-streaming tool-call patch protocol. Tool selection and hypothesis
  work, but code generation is too slow under `reasoning_effort=max`.

## Repairs

- Downgraded APS session timeouts to non-counting attempt failures. They still
  close the current attempt and preserve branch-local failure evidence, but no
  longer set `StepResult.stopped=True`.
- Narrowed CVRP premise text extraction to research-claim fields. Risk,
  no-op, complexity, and runtime-budget prose are no longer scanned as premise
  claims.
- Added Shaw contrast guards so non-Shaw proposals that mention existing Shaw
  behavior for comparison are not rejected as missing/duplicate Shaw removal.
- Kept hard LLM call timeout and masked-timeout classification from the prior
  DeepSeek repair.
