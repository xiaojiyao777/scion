## Root Causes

1. Active facts are now present and source-aligned, but not yet action-shaping enough. The agent sees CVRP/VNS facts, yet failed mechanisms and "already present but augmentable" distinctions are not compactly represented as adapter/provider-owned negative guidance.
2. The runtime feedback strongly points to VNS dominance, so the agent keeps searching near VNS/local-search or ALNS mechanisms. That is rational, but without sharper failed-mechanism memory it re-enters neighbor/candidate-list territory after a code-generation failure.
3. Premise contradiction gates are using the same facts as the agent, but the rejection logic can overmatch. Attempts 4 and 5 look like cases where the provider/gate should identify exact contradicted spans or downgrade to novelty/quality feedback instead of hard `premise_contradicted`.
4. Raw tool observations remain too large and often truncated/omitted. The independent facts packet fixes the key grounding problem, but code repair still lacks compact path-level evidence explaining why a declared mechanism did not execute.
5. Smoke and formal telemetry are not fully aligned. Smoke can pass mechanisms that formal screening later finds zero/missing, as seen in `double_bridge_perturb`; conversely, smoke may not give enough path evidence to repair `vns_candidate_list_filter`.
6. Observability splits one proposal attempt across multiple sessions and mixes statuses (`code_failed` vs telemetry repairable). This makes it harder to audit counted rounds, uncounted proposal attempts, and branch lifecycle without joining DB, session, and metrics artifacts.

## Recommended Fixes

### P0

- Scion core: require every LLM `tool_selection` prompt, including code-phase and targeted-symbol reads, to carry the same active-facts anchor/digest/provenance metadata. This is generic provenance plumbing, not CVRP semantics.
- Scion core: promote all uncounted proposal failures into the next hypothesis context as compact negative memory: attempt id, branch id, mechanism id, stage, exact failure, and whether a variant is allowed. Include `code_generation_failed`, `agent_quality_blocked`, `hypothesis_contract`, and `TELEMETRY_VALIDATION_REPAIRABLE`, not only successful screening rows.
- Scion core: improve algorithm-smoke feedback with path-level evidence: whether the operator was selected, whether the declared mechanism branch executed, positive/zero/missing telemetry counts per smoke case, and the exact declared field that failed. Keep this compact so raw observations can remain truncated.
- CVRP adapter/provider: refine premise contradiction rules to require exact contradicted premise spans and adapter-owned `variant_allowed` guidance. For example, distinguish "regret repair is missing" from "add a new destroy operator that uses existing regret repair"; distinguish "route-limit violation is default" from "improve feasible seed construction."
- CVRP adapter/provider: emit adapter-owned failed-mechanism/novelty facts for code-failed or telemetry-failed mechanisms such as `vns_candidate_list_filter` and `double_bridge_perturb`. Do not hardcode these in Scion core or proposal logic.

### P1

- Scion core: align smoke with formal telemetry guard. A smoke pass should require positive activation on the declared mechanism path, and should warn when only unconditional or zero-effect telemetry is observed.
- Scion core: add an attempt ledger artifact that normalizes proposal attempts across hypothesis/code sessions and links LLM trace filenames, prompt manifest digests, gate digests, metrics paths, and final classification.
- CVRP adapter/provider: enrich active solver facts with concise "existing capability and owner" summaries for VNS operator registry, candidate-list-like pruning, regret repair, and route-limit guards, while keeping semantics entirely adapter-owned.
- Experiment observability: add a metrics summary artifact per screening with pair wins/losses/ties, runtime stats, telemetry pass/fail, declared mechanisms, and branch lifecycle decision, so auditors do not need ad hoc DB/JSON joins.

### P2

- Docs/tests: add tests asserting hypothesis/code prompt manifests include non-truncated `agentic_active_algorithm_facts` and that gate rejections cite the same `fact_packet_digest` used by the agent.
- Docs/tests: add tests for the tool-selection anchor invariant, including code-phase targeted reads.
- Docs/tests: add provider tests for premise contradiction span attribution and downgrade behavior when a proposal augments an existing mechanism rather than claiming it is absent.
- Docs/tests: document the adapter/provider contract for active facts, failed-mechanism facts, novelty facts, and provenance. The core should remain problem-agnostic; CVRP facts and novelty semantics should stay in the CVRP adapter/provider.
