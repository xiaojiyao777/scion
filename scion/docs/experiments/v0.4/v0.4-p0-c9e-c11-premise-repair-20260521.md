# v0.4 P0 Repair: Branch-Local C9e, Premise Scope, C11 Guidance

Date: 2026-05-21

## Inputs

This repair follows the post-run analysis of the 4-round premise-scope/C11
validation experiment. The relevant framework issues were:

- C9e solver-design integration preview/contract checked imports against the
  champion snapshot, so a branch-local helper added in an earlier patch could
  be reported as missing when a later patch imported it.
- CVRP mechanism novelty rules still over-matched some explicit variants:
  random/noise removal, stochastic/diversity repair, and negated Shaw/removal
  savings contrasts.
- Repeated proposal/code quality failures could be surfaced as
  `infra_loop/check_environment`, which misdirected debugging away from agent
  traces and gate feedback.
- C11 expected-telemetry guidance did not make ALNS/VNS phase modifications
  explicit enough: the agent could declare one mechanism id while using generic
  `.alns` or `.vns` telemetry buckets.

## Changes

- `ContractGate.validate_patch(...)` now accepts `base_snapshot_path` and uses
  that base for C9d surface identity and C9e solver-design integration checks.
  `ExploreStepPipeline` passes the current branch workspace, and contract
  preview tools use `context.branch_workspace` before falling back to the
  champion snapshot.
- CVRP novelty predicates now treat random/noise/diversity variants and
  negated contrasts as allowed variants unless the hypothesis explicitly claims
  the already-present mechanism is missing or newly added.
- `StagnationDetector` now distinguishes `proposal_quality_loop` from
  `infra_loop`; repeated proposal/code/schema/activation-diagnostic failures
  recommend `inspect_agent_trace`, not `check_environment`.
- Hypothesis schema, hypothesis prompt, and the CVRP solver-design adapter
  guidance now state that existing ALNS/VNS phase changes must declare the
  changed lever as a specific mechanism id and use that same id in
  `expected_telemetry`.

## Boundary Notes

- Scion core remains problem-agnostic. It carries generic patch contract,
  stagnation, and telemetry schema behavior.
- CVRP-specific active solver facts and premise checks remain in the CVRP
  adapter/provider layer.
- Telemetry activation diagnostics remain framework lifecycle signals; they
  should guide branch repair and agent feedback rather than being collapsed into
  ordinary win-rate failure.
