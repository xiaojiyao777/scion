## Fixed staged measurement design

The primary statistical unit is a case. Within a case, R2 takes the median of
paired champion-minus-candidate `total_distance` effects across the exact seed
set, so positive values mean that the minimizing candidate is better. With
equivalence band `0`, a positive effect is a case win, a negative effect a loss
and zero a tie. Pair W/L/T remains descriptive.
`fleet_violation` is the only problem-declared protected objective and is a
separate regression veto; it does not change the distance estimator.

Initial screening is a mechanism screen only. It can never pass directly:

- 8 cases × seeds `11,29,43,59`;
- if the ordinary fixed screening threshold is reached, the only result is
  `EXPAND_SCREENING` on the same exact candidate;
- a pre-threshold sparse no-loss practical signal may also receive that exact
  expansion; otherwise an initial result with case win rate `>= 0.5` and CI
  high `>= 0` receives the same one expansion;
- an initial win rate below `0.5` or negative CI high fails without expansion;
- the quality screen is 12 cases × ordered seeds
  `11,29,43,59,73,79,97,103` and contains every initial pair;
- only the quality screen may pass to validation;
- screening requires case win rate `>= 0.60` and median distance improvement
  `>= 2.0`.

The exact initial cases are:

- `A/A-n64-k9`, `B/B-n63-k10`, `E/E-n101-k14`, `P/P-n65-k10`;
- `CMT2`, `CMT4`, `M/M-n200-k17`, `X/X-n110-k13`.

The exact quality-screen additions are `A/A-n80-k10`, `E/E-n101-k8`, `CMT3`
and `tai150c`. These are determined by the checked-in Protocol selection, not
by candidate results. They are structural coverage inputs, not H obligations.

Validation uses all 12 declared validation cases with seeds `47,53,71,83`.
It requires case win rate `>= 0.66`, median improvement `>= 1.0` and bootstrap
CI low `>= 0`. Frozen uses all 12 declared frozen cases with seeds `61,67,89`,
the same aggregate improvement requirements and the fixed canary seed `101`.
Validation details and frozen details retain the V3 exposure limits.

Runtime is problem-owned by stage and case scale. Defaults are 30 seconds for
screening/validation and 60 seconds for frozen; the exact 45/60/90/120-second
scale rules in the fixed Protocol apply. Runtime or fleet failure cannot be
relabelled as distance improvement.

The old A/A `MDE@80%=9.9` and later eight-seed pair-level `MDE=9.6` used
incompatible estimators or populations. They are historical low-power
diagnostics only. R2 does not claim calibrated power, does not claim that eight
seeds are sufficient for delta `2`, and will not add seeds after seeing data.

## Provider context inventory

Every H receives each supplied field exactly once. There is no token-triggered
top-k, opaque compression or host algorithm-quality rules catalogue; one
problem-owned objective/API fact packet remains. The fixed H view contains:

| H section | Scientific purpose |
|---|---|
| problem summary/object and objective policy | define CVRP feasibility, fleet priority and distance objective |
| solver mechanics and research surfaces | explain the active ALNS/VNS implementation, ownership and editable boundary |
| available actions, existing files and create patterns | show what can actually be modified or added |
| complete current source projection | show every visible file once, using the branch-owned current version for changed paths and the champion version otherwise |
| champion structural metadata | identify the current version and active operator-pool shape without hidden case outcomes |
| compact screening history | expose recent same-branch evidence in detail and older/sibling evidence structurally, with the latest observation exactly once |
| typed research-rejection roots | distinguish proposal friction from an algorithm result |
| problem measurement diagnostics | explain case scale, objective semantics and observational mechanism evidence |
| research question and neutral CVRP prior | provide accepted historical positives/negatives without choosing the next mechanism |

H is asked for one evidence-grounded mechanism or refinement, but same-branch
depth, a pivot and a new mechanism are all valid. The host does not require
novelty or a "materially different" idea.

Every C receives the approved H, problem and solver mechanics, the complete
current contents of every visible editable source file, the approved target,
surface/interface specification, import whitelist, editable/frozen patterns,
active problem constraints and phase-specific implementation guidance. C does
not receive source hashes, ownership receipts or lifecycle self-proof text.

The provider interface remains the direct V3 two-call interface rather than an
interactive shell agent:

- H returns one `generate_hypothesis` structured object;
- C returns one `generate_patch` typed edit set;
- C may modify existing modules or create a new allowed module, use ordered
  exact replacements or a justified complete-file edit, and change multiple
  same-mechanism files in one candidate;
- complete visible source substitutes for ad-hoc file-reading calls;
- process, network, environment, dynamic-import and arbitrary filesystem APIs
  are unavailable inside candidate code.

This is the fixed R2 tool surface, not an assertion that it is ideal. Postrun
must report whether H could locate the mechanism, whether C implemented the
approved idea faithfully, and whether schema/edit friction rejected useful
work. If interactive research tools or a different source projection are later
justified, that is one changed factor in a fresh preregistered matched rung—not
an in-place R2 change.

## Minimum evidence and attention analysis

Scion records only the lineage necessary to reconstruct which branch source,
H/C, Verification result, fixed case/seed stage, aggregate statistics and
Decision occurred. Raw pair metrics remain available for scientific analysis.
Provider traces and call-journal diagnostics are best effort and do not decide
candidate validity.

Postrun analysis will report, without creating a gate:

- provider input/output token counts and the offline byte contribution of H/C
  context sections;
- each H's stated bottleneck, mechanism, expected effect and relationship to
  prior branch evidence;
- C fidelity to H, files/edit intents used, and whether the mechanism was
  actually activated during evaluation;
- schema, binding, edit application, Contract and Verification rejection
  causes as separate framework-friction counts;
- operator selected/invoked/completed/accepted/best counts when available,
  strictly as observational mechanism evidence;
- initial versus quality-screen case effects, runtime/fleet outcomes,
  validation/frozen state and exact promotion status.

Neither prompt length, tool use, activation nor a qualitative hypothesis score
can admit, reject, rank or promote the current candidate. Only Contract protects
the declared edit boundary, Verification protects problem semantics, and the
fixed Protocol plus Decision controls advancement.

## Search organization and continuation

The scheduler keeps queued formal work ahead of new proposals. At most three
active branches are available; same-tier EXPLORE work is least-recently-served.
A completed non-promoting screening retains its verified candidate as the
branch's provisional source under V3 section 11.2. A subsequent fresh H may
refine it or pivot using its measured evidence.

Expanded screening, validation and frozen always drain on the same exact
candidate with no H/C call and no new workspace. Candidate-local malformed
proposal, structural Contract failure or Verification failure records one typed
outcome and schedules forward from clean current source. Missing provider
terminal response, local binding failure after a completed provider result,
workspace/infrastructure/resource failure or interruption is terminal. No H/C
call is retried and this campaign is never resumed.

Run until 12 formal stages complete or one genuine terminal outcome occurs. The
12-stage bound is a formal-evidence horizon, not a provider-call budget:
candidate-local research rejection schedules forward without consuming it,
and R2 intentionally adds no new wall-clock/provider-call gate. Monitor
`scheduled_calls`, effective formal rounds and typed research rejections. If a
sequence of proposal/Contract/Verification rejections prevents formal evidence
from advancing, an explicit external interruption may seal the root; classify
that as a neutral research-rejection stall, never a formal solver-performance
negative. Postrun must attribute provider/schema/edit/Contract/Verification
causes separately to candidate design/implementation or framework/tool
friction. If stage 12 leaves an exact candidate queued for another formal
stage, seal the root as horizon-censored; do not extend it.

## Outcome classifications

Classifications use this precedence: observed promotion; exact-candidate
horizon censoring; completed no-promotion; invalid infrastructure; explicit
research-rejection-stall interruption; other explicit interruption.

- `CVRP_PROMOTION_OBSERVED_REPLAY_PENDING`: at least one exact candidate passes
  screening, validation and frozen and receives `PROMOTE`; retained improvement
  remains pending independent B0 replay.
- `VALID_12STAGE_FUNNEL_HORIZON_CENSORED`: 12 stages complete with an exact
  candidate queued for another fixed formal stage. This is funnel evidence,
  not promotion.
- `VALID_12STAGE_NO_PROMOTION_LARGE_EFFECT_NOT_DEMONSTRATED`: 12 interpretable
  stages complete with no promotion and no queued candidate. This rejects the
  exact candidates at this uncalibrated rung only.
- `RUN_INVALID_INFRA`: provider, configuration, framework, runner or resource
  failure truncates the horizon.
- `INTERRUPTED_RESEARCH_REJECTION_STALL`: an explicit external interruption
  seals a root whose formal stage count stopped advancing because of repeated
  proposal/Contract/Verification rejection. It is neither a formal solver-
  performance negative nor a completed campaign; postrun owns causal
  attribution.
- `INTERRUPTED`: an explicit external interruption ends the run.

Postrun must state research behavior, measurement reach, framework friction
and promotion evidence separately. No single failure reason may substitute for
that analysis.
