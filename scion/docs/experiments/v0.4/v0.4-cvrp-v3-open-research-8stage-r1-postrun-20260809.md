## Research-path defects exposed by R1

These are prospective framework/experiment corrections. They do not
reinterpret R1.

1. **Case aggregation suppresses sparse effects.** A case is currently called
   a win only when seed wins strictly exceed both losses and ties. Thus
   `2W/0L/2T` becomes a case tie, even when its paired median is positive. A
   fresh protocol should define case direction from a pre-registered paired
   case estimator and keep pair W/L/T descriptive. Screening advancement must
   remain distinct from validation/frozen promotion. A prospective
   median-sign reanalysis changes the expanded depth-one result to 7W/2L/3T,
   win rate `0.583`; it still misses R1's `0.60`, so this is not a retroactive
   pass.
2. **The four-seed rung is underpowered.** Calibration reports MDE@80%=9.9,
   while the observed depth-one median is +3.75 and the practical threshold is
   +2. A fresh power-aware design is required; no seed may be appended to this
   root.
3. **One valid C was lost to a brittle edit selector.** The branch-C refinement
   returned a complete structured edit, but its `old_string` contained one
   blank line between top-level functions while source contained two. Exact
   application found zero byte-identical matches and rejected it before
   Contract or Verification. A deterministic unique blank-line-run repair is
   justified; general whitespace or fuzzy matching is not.
4. **Cross-campaign memory is incomplete.** H saw the earlier SWAP* record but
   not the more recent deep-ejection negative. The short neutral prior should
   record both this R1 depth-one observation and the negative depth-two/deeper
   evidence without prescribing an operator.
5. **Terminal accounting is inconsistent.** The eight attempts comprise five
   evaluated candidates, two candidate-local research rejections and one
   infrastructure block. The terminal summary counts both rejections, while
   the status validity projection counts only one. The durable root remains
   unchanged; prospective accounting must preserve the typed rejection audit.

Provider context was large because it included complete editable solver source
and structured branch evidence, not because of Trust/Hash rules. Outputs stayed
focused on algorithms. The next context change should therefore remove
repetition and improve current-source/edit usability, while retaining complete
source and concise mechanism/case evidence; it should not add more rules.
