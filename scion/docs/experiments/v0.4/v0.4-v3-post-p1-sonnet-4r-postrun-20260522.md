## 8. 修复建议

### P0

无新增 P0。当前产物没有显示 generic Scion core 运行控制、module split、formal telemetry 统计或 branch finalization 的阻断性错误。

### P1

1. CVRP adapter/provider：补齐 active algorithm facts 和 novelty facts。
   至少加入 `_random_removal` / scheduler `"random"` destroy operator 的 fact id、symbols、summary 和 allowed-variant guidance，避免把既有 random removal 包装成新机制。这个修复必须留在 CVRP adapter/provider，不应把 random/removal 语义写进 generic Scion core。

2. CVRP adapter/provider：对 "existing helper but renamed telemetry" 做 novelty 归因。
   当候选只把已有 helper 换 mechanism id 或加 telemetry 时，应标成 instrumentation/activation variant，而不是 new algorithmic mechanism。

3. Hypothesis guidance：减少 C11 activation field retry。
   保持 generic core 只处理 declared runtime field roles；具体 examples/negative facts 由 CVRP provider 渲染。目标是让首稿就使用 `context_records.*_iterations` / `phase_runtime_ms.<mechanism>` 作为 activation，而不是 aggregate/effect fields。

4. Decision/lifecycle reporting：若 weak screening 因 runtime regression 仍 `continue_explore`，summary 应给出 typed lifecycle reason。
   这属于 generic decision explainability，不应引用 CVRP 语义。

### P2

1. `agentic_session_index.json` 可补持久化 `branch_id`、phase/attempt_kind 和 paired hypothesis/code session id，减少 postrun 关联成本。

2. Tool planner 去重：对已成功的 `feedback.query_screening`、`feedback.query_runtime` 和同一 `context.read_algorithm_file` 做更强的 within-session de-dup，降低 `agentic_tool_observations` truncation。

3. 增加一个短 synthetic/controlled telemetry case 覆盖 `median_delta < 0` 的 P1-C 正样本，避免只能从 pair-level loss 间接判断。

4. Summary 可增加 `proposal_quality_blocks` 明细列表，把 C11 schema block 和 premise contradiction block 直接列在顶层，减少从 `steps`、DB 和 session output 反查的成本。
