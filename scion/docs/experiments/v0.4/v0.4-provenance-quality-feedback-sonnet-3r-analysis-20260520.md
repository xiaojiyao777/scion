## Low-Quality Agent Behavior Still Present

- Repeated broad reads: most hypothesis sessions still read local search, destroy/repair, acceptance, scheduler, construction, and config regardless of target. The observations were not fatal, but they keep prompts large and can dilute branch-specific feedback.
- Provider-induced repetition risk remains: premise feedback says a mechanism is contradicted, but without exact spans or allowed-variant guidance the agent can only infer a broad "avoid this area" rule.
- Experiment history still contains confusing labels for premise blocks. The compact negative memory is correct, but other history lines classify the same event as failed hypothesis contract.
- Screening feedback is deterministic but not very action-oriented. It identifies neutral signal, but does not strongly suggest how to refine a branch with pairwise weak wins, especially `nn_candidate_list_filter`.
- Activation diagnostic feedback was clear in the code loop, but the run did not validate reuse of that diagnostic in a subsequent hypothesis attempt.

## Root Causes

1. Provenance plumbing is now mostly correct. This run no longer shows a gate/agent source split.
2. Remaining false premise blocks are CVRP adapter/provider matching errors: the provider still conflates "uses or adapts an existing mechanism" with "claims the mechanism is absent".
3. Generic failure classification still has a lifecycle mapping bug: agent-quality premise blocks can be stored as `hypothesis_contract`/`CONTRACT`.
4. Branch lifecycle is directionally correct for weak screened candidates, but final max-round cleanup removes active branches in a way that obscures which branch should be continued in a subsequent run.
5. Prompt volume is still high because the planner continues broad algorithm-file reads before narrowing to branch-owned targets.

## Recommended Fixes

### P0 - Scion Core, Generic

- Fix StepRecord/DB classification for provider quality rejections. `premise_contradicted` and other agent-quality proposal blocks must persist as agent-quality categories, not `hypothesis_contract` or branch failure code `CONTRACT`.
- Ensure experiment history uses the same compact failure category as negative memory. If a session is blocked by `proposal_premise_contradicted`, no downstream planner-facing line should call it `FAILED_HYPOTHESIS_CONTRACT`.
- Add/verify unit coverage that `proposal_activation_diagnostic` is rendered into later same-branch hypothesis negative memory with attempt/session/branch/mechanism/stage/failure summary/digest/provenance.

### P0 - CVRP Adapter/Provider

- Require exact `contradicted_span` or `matched_span` for every `premise_contradicted` response. If no exact span can be cited, downgrade to duplicate/novelty feedback or allowed variant guidance.
- Fix the `adaptive_neighborhood_selection` false positive: adaptive ordering/selection of an existing VNS neighborhood should not be mapped to `intra_two_opt_reversal` unless the proposal explicitly claims the 2-opt/reversal operator is missing.
- For Shaw/related removal, distinguish "baseline lacks related removal" from "adds a variant trigger/scoring/use of existing Shaw removal". The latter should return `variant_allowed=true` or duplicate/novelty feedback with allowed guidance, not premise contradiction.
- Re-run or add provider tests for route-limit/fleet and regret-repair examples, since this experiment did not exercise those cases.

### P1 - Scion Core, Generic

- Reduce repeated broad reads by carrying a short per-branch "already inspected algorithm files and relevant facts" cache into tool-selection prompts.
- Make screening feedback more branch-actionable while staying generic: surface deterministic weak-signal features such as pairwise wins/losses, median delta, runtime deltas, and activation/effect coverage as compact branch feedback.
- Preserve `continue_explore` branches across validation-run boundaries or emit a ranked carry-forward artifact. For this run, `59d35829` should be the top carry-forward candidate.

### P1 - CVRP Adapter/Provider

- Add provider guidance for allowed variants of existing destroy/repair/local-search mechanisms. The guidance should remain in the adapter/provider and should not be moved into Scion core.
- Add an adapter-side compact summary that says which active mechanisms already exist and which axes are still open for variants, for example trigger policy, scoring policy, schedule, candidate filtering, and telemetry activation.

### P2 - Observability and Docs

- Add a concise provenance audit section to campaign summaries: counts of prompts with facts anchors, per-session digest/source, and gate-agent digest equality.
- Add a branch carry-forward summary to campaign summaries: branch id, mechanism, screened metrics, diagnostic blocks, and recommended next lifecycle action.
- Document that activation diagnostics are uncounted proposal-quality feedback, not normal screened failures.

## Run Recommendation

Do not run a 4/6-round validation immediately as a proof of full closure. Fix the P0 classification mismatch and CVRP provider span/variant behavior first.

After those two fixes, a 4/6-round run is useful. It should explicitly allow branch continuation and should prefer reusing the `59d35829` nearest-neighbor candidate-filter branch before spending all budget on fresh sibling branches.
