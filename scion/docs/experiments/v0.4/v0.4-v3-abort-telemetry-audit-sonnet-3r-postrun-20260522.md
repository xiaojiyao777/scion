这轮验证基本证明 APS abort/index/telemetry diagnostics 的主修复方向有效：

- `partial_hypothesis_only` 在 `agentic_session_index.json` 中不再被误打成 `contract_boundary_failure`。所有 partial session 都有 `failure_detail`/`failure_reason`，有 hypothesis 的条目也有 `target_file`、`mechanism_ids`、`hypothesis_summary`。

仍需立即处理的 P0/P1：

- P0：API 余额不足仍被当成 transient provider error 进入多次重试和后续 APS session。最后能停，但停得太晚。
- P0：最终纯 hypothesis 失败 session `5afdfbf4...` 的 output/index 是 `llm_transient_api_error`，但 DB/audit payload 和 campaign summary 的 `proposal_session_ref.primary_failure` 仍残留 `contract_boundary_failure/schema_or_target_preview_failed`。这不是 partial regression，但仍会污染 postrun 归因。
- P1：formal metrics 的 telemetry guard 细节有内部不一致：overall `passed=false`，field-level failure 明确；但 mechanism-level `passed=true`、`effect_status=positive`。规则可能是 "all declared effect fields must be positive"，但诊断文案像 "any positive effect is enough"。
- P1：agentic sessions 的 `observation_chars` 仍普遍在 100k+，下一轮会继续拉高成本和余额风险。
