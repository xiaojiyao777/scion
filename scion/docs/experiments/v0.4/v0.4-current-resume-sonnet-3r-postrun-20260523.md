## LLM Context/Tooling Findings

### What Worked

- Every generation prompt included active solver facts and/or source provenance from `context.read_active_solver_design`.
- Required preface reliably provided `context.list_surfaces`, `context.read_problem`, `context.list_algorithm_files`, `context.read_active_solver_design`, and `context.read_solver_call_graph`.
- Later rounds saw prior screening/runtime feedback. Round 2 saw one prior row; Round 3 saw two prior rows and a larger runtime feedback block.
- Code prompts had full approved target file content and integration context. This is why generated code modified the algorithm body and wired Round 2 scheduler changes instead of leaving the mechanism inert.
- The schema preview retry loop caught incorrect telemetry role assignments before code generation. This is materially better than letting malformed telemetry claims reach screening.

### Repeated File Reads And Missing Ledger

The two-phase resume is not yet a real phase inheritance model. Each formal round had:

1. Hypothesis-only session reads required context, feedback, active facts, call graph, and 5-6 files.
2. ContractGate approves the hypothesis.
3. Code session starts another agentic session and repeats required context, active facts, call graph, memory/feedback, and broad file reads.

The code prompt has `agentic_resume_context`, but it is a text summary, not a reusable observation ledger. It does not let the code phase say "hypothesis already read local_search.py at digest X and active facts at digest Y; only read target or stale files now." This is directly contrary to the Hooke/Claude Code reference recommendation:

```text
full audit transcript
-> host-built API-visible context projection
-> model emits typed tool_use blocks
-> host validates, executes, budgets, and records tool observations
-> next turn inherits compact state and selected observations
```

Scion has prompt manifests and observation ids, but they are not first-class phase transition state. They are still mostly prompt text.

### Fixed File-Count Budget

Every hypothesis session hit:

`solver_design_algorithm_file_read_budget_reserved`

This means the tool planner repeatedly consumes a fixed number of full-file reads from a similar prefix (`local_search`, `destroy_repair`, `acceptance`, `config`, `construction`) and then loses access to the rest of the active object. The failure is not only budget size; it is budget shape. A solver-design proposal should reserve reads by owner role and unresolved need:

- target owner file,
- integration caller/callee file,
- state/model file if route mutation is involved,
- telemetry/context API file or surface manifest if new telemetry is declared,
- optional symbol reads instead of full-file reads.

The current behavior reads many files "just in case" and still sometimes misses the file needed for wiring until retry.

### Oversized Observations

Prompt manifests show large `agentic_tool_observations`:

- Round 1 hypothesis: 83,285 chars, truncated; retry 112,971 chars, omitted.
- Round 2 hypothesis: 84,488 chars, truncated; retry 114,357 chars, omitted.
- Round 3 hypothesis: 85,413 chars, truncated; retry 124,944 chars, omitted.
- Code prompts: 16,728-24,126 chars, truncated.

The model has enough context to work, but much of the budget is spent on repeated raw observations. The useful context is smaller: active fact packet digest, source file digests, file/symbol summaries, feedback rows, and target file content. Large observations should be persisted as artifacts with compact previews and stable observation ids.

### Gate Versus Agent Visibility

The gate sees cleaner evidence than the agent:

- Gate sees full screening metrics, case-level outcomes, per-field telemetry guard details, and decision features.
- Agent sees feedback summaries in later rounds, but not a normalized ledger connecting prior hypothesis, exact code diff, telemetry activation/effect fields, and failure reason in a compact reusable format.
- Round 3 shows the gap: the gate correctly identified `phase_best_delta.segment_exchange` as the failing declared field. The code agent had enough API guidance to know `record_move(..., delta=...)` matters, but no pre-generation guard warned that `delta=None` would leave `phase_best_delta` at zero while improvement counts were positive.

The branch decision was correct, but the diagnostic text should distinguish "some effect field positive" from "all declared effect fields satisfied."

## Required Fixes Before Next Run

### P0

1. Implement phase-inherited `AgenticObservationLedger`.

   The code phase should inherit observation ids, source digests, fact packet digest, file digests, target owner file, preview artifacts, and schema feedback from the hypothesis phase. It should only re-read files if digest, champion version, branch code, context policy, or problem spec changed.

2. Replace fixed full-file count budgeting with role-aware solver-design read budgeting.

   The provider should expose owner roles and priority paths. The host should reserve reads for target owner, integration caller/callee, state/model APIs when route mutation is involved, and telemetry/context APIs when new telemetry is declared. Prefer symbol reads after required target content.

3. Make code-phase resume use the ledger, not large raw observation text.
