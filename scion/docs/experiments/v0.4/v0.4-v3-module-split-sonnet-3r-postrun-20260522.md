## 8. 质量判断

Scion v3 控制满足项：

- effective screening 都有 contract/verification result，并记录 metrics artifact。
- candidate runtime path 都进入 `policies/baseline_algorithm.py`，不是 facade 或 import fallback。
- proposal-quality loop 没有把 blocked attempts 误计为 `n_experiments`。
- algorithm smoke feedback 在 Step 2 和 Step 6 能驱动 code retry 并最终 pass。
- proposal blocks 和 screening decisions 都有 structured reason codes。

不足：

- CVRP novelty false positive 明显。两个 block 都来自文本窗口过宽或 acknowledgement 识别不足，
  误伤了合理的 variant/filter/contrast proposal。
- `campaign_summary.steps[].failure_detail` 对 Step 5 截断过强，只能从 session transcript
  还原完整 smoke evolution；summary 可读性不足。
- `stagnation_signals` 只指出所有 recent steps 都是 `solver_design`，但 CVRP 目前只有一个
  declared surface；该 warning 对本实验 actionable value 低。

## 9. P0 / P1 / P2 建议

### P0

修复 CVRP novelty/provider false positives，不改 generic Scion core：

- 在 `scion/problems/cvrp/mechanism_novelty/local_search.py` 中，允许
  `active/current + _or_opt_1/_2/_3 + without/no/lacks candidate/filter/pruning/nearest-neighbor`
  表达为 existing Or-opt variant，而不是 missing Or-opt premise。
- 在 `destroy_repair/random_removal.py` 中，允许
  `random/removal (uniform)`、`distinct from random`、`unlike random`、`random is uniform`
  这类 contrast/acknowledgement 表述，不触发 missing random-removal contradiction。
- 给上述两类 false positive 增加 CVRP provider unit tests，fixture 使用本次 session 中的
  `knn_candidate_filter` 和 `cluster_removal_destroy` hypothesis 文本。

### P1

提高 agent-quality/smoke feedback 的闭环可执行性：

- 对 algorithm smoke failure 的 final summary 保留完整 failure code、field path 和最后一次
  repair guidance，避免只在 transcript 中可见。
- 对 declared mechanism telemetry，code prompt 可更明确地区分：
  `record_iteration`/`record_phase` 是 activation/runtime，`record_move(... delta=..., best_improved=...)`
  是 effect。Step 5 的 agent 连续三版没闭合 telemetry，说明当前 guidance 对 construction
  target 仍不够强。
- 对 effect telemetry missing 的 screening failure，summary 可区分 “field missing because
  mechanism no-op” 与 “field present zero”。Step 2 同时有 13 missing 和 3 zero，诊断应更直观。

### P2

改进实验诊断和推荐，但保持问题语义在 adapter/provider：

- 对 CVRP provider active facts 增加 “allowed variant” examples，让 agent 更自然地提出
  filter/scoring/budget variants，而不是被迫避开已存在 mechanism 名称。
- 对单 surface 问题降低 `family_coverage`/`stagnation_signals` 的噪声；CVRP 当前只有
  `solver_design`，`switch_action` 建议不一定可执行。
- 对短预算 screening 的 runtime report 增加 per-mechanism elapsed / no-op trigger count 摘要，
  方便区分算法质量失败与 10s budget 截断效应。
