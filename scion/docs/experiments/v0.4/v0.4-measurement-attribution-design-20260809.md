# v0.4 Measurement Attribution Design

Date: 2026-08-09
Status: prospective diagnosis design; excluded from Decision

## Purpose and boundary

A campaign without a promotion does not by itself identify whether the limiting
factor was the proposed algorithm, mechanism exercise, search budget, case and
seed sampling, estimator semantics, or provider context and edit friction.
This design separates those explanations without changing an active campaign
or adding another candidate gate.

The V3 `Contract -> Verification -> Protocol -> Safe Features -> Decision`
path remains the only promotion authority. All outputs below state
`decision_features_excluded=true` and cannot rejudge R3 or any accepted
Warehouse promotion. No deployment, identity, lease, signing, receipt, hash
chain, model grader, retry loop or algorithm-quality gate is introduced.

## Reuse before invention

Execution reuses the existing problem-owned paths:

- chronological candidates from `formal_candidates/index.jsonl`;
- exact source materialization through `fixed_candidate_replay`;
- paired case/seed execution through `ExperimentProtocol.run_experiment` and
  `LocalSubprocessRunner`;
- the existing raw pair JSON and case-level aggregation;
- exact Warehouse snapshots through `champion-heldout-comparison`.

At most one experiment-owned analysis command, capped at 220 lines, may be
added. It orchestrates the existing fixed-candidate replay for atomic blocks,
reads completed raw pair files and emits bounded aggregates; production
campaign modules remain unchanged. It never enters Decision. Cell manifests
and diagnostic outputs live in the experiment root, not in framework policy.

Before the first expensive factor or budget replay, the existing Protocol
runner receives the bounded analysis-complete record described below. A replay
that cannot establish fresh subjects, scheduled/actual order, both absolute
objective vectors, feasibility and subject timing does not launch. This avoids
knowingly spending the frozen cohort while leaving order, warm state, headroom
and CPU overlap unidentifiable. The correction adds no runner, ledger, gate or
Decision input.

## CVRP candidate cohort

After R3 is terminal, select the first `min(8, N)` Verification-passed exact
candidates in chronological order. Deduplicate repeated stages of the same
source and retain each candidate's recorded immediate base. Never select a
cohort from favorable W/L/T or replace every base with B0.

With fewer than four eligible candidates, report execution feasibility and
candidate-specific directions only. General factor attribution is
`UNIDENTIFIABLE`.

## Case and seed factor replay

Run the unchanged source/base and dimension budgets in these cumulative cells,
but execute only the four non-overlapping atomic blocks below:

- first 8 cases x first 4 seeds;
- first 8 cases x all 8 seeds;
- all 12 cases x first 4 seeds;
- all 12 cases x all 8 seeds.

Analysis must first decompose them into non-overlapping blocks:

| Block | Cases | Seeds |
|---|---|---|
| Q00 | first 8 | first 4 |
| Q01 | first 8 | added 4 |
| Q10 | added 4 | first 4 |
| Q11 | added 4 | added 4 |

For every exact candidate and cumulative cell, report pair W/L/T, each case's
seed-median effect, case W/L/T, net score, loss rate, the case-effect median and
the existing deterministic bootstrap interval. Rule components are descriptive
and are not a new Protocol verdict.

Report seed sensitivity on the same first 8 cases and case sensitivity on the
same seed prefixes. Q11 is only the joint added-cases/added-seeds atomic block;
this diagnosis has no pre-registered interaction contrast, so interaction is
`UNIDENTIFIABLE`. The unit of cohort aggregation is the candidate, not every
pair. Family and size summaries are descriptive; cumulative or multi-mechanism
candidates cannot support single-mechanism causal credit.

The terminal-R3 diagnosis reuses `fixed_candidate_replay` through an
experiment-owned `protocol_factory` that explicitly constructs
`ExperimentProtocol(..., champion_result_cache_enabled=False)`. Let A be the
immediate base and B the candidate; schedule AB when
`(candidate_ordinal + block_ordinal + case_ordinal + seed_ordinal) mod 2 == 0`
and BA otherwise. Both subjects run fresh. Persist both scheduled and actual
order, source/base/block/cell IDs, each side's full objective mapping and
feasibility, wall start, monotonic start/end, elapsed and time limit, stop or
timeout reason and bounded failure/exit facts. This is a small extension of the
existing Protocol record, not a second runner.

Execute every block once in `Q00 -> Q01 -> (Q10 union Q11)` order. Expansion
aggregates immutable prior blocks and never reruns any completed block.

## Matched sensitivity boundary

The completed same-seed A/A/null diagnostic constrains only a limited
false-pass question. It does not establish the power or MDE of the future
12-case x 8-seed case-median design at practical delta `2`.

Before freezing another promotion campaign, estimate sensitivity using that
exact roster, estimator, equivalence semantics, seed structure and dimension
budgets. Record the supported empirical MDE and the claim it permits. If the
design cannot establish useful sensitivity near delta `2`, either add
independent cases outcome-blind before launch or retain the design and state
that a negative result cannot exclude improvements smaller than the matched
MDE. Additional seeds are repeated observations within a case, not additional
independent cases. This calibration chooses a claim and future design; it does
not create a candidate futility gate or reinterpret R3.

## Budget response

Use the same frozen cohort and the 8 x 4 core at `0.5x`, `1x` and `2x` the
dimension-only budget. Reuse the 1x cell above; execute only the missing 0.5x
and 2x cells. Keep cases, seeds, source, base and surface unchanged, run
serially, disable result reuse, and prohibit concurrent tests or solver work.
Freeze half-up integer budgets before execution: `15/23/30/45/60` seconds at
0.5x, `30/45/60/90/120` at 1x and `60/90/120/180/240` at 2x. Counterbalance
the three budget-arm orders by a deterministic rotation over candidate, case
and seed ordinals. If the legacy fixed replay cannot materialize that rotation,
execute its frozen order once and label whole-arm machine drift
`UNIDENTIFIABLE` rather than claiming counterbalance.

Interpret evidence in this order:

1. mechanism loaded and attempted;
2. state changes were accepted;
3. best updates occurred;
4. longer time increased search opportunity;
5. final objective responded to that opportunity.

Budget exhaustion alone does not establish opportunity constraint. Missing
attempt/accept/best-update telemetry makes activation attribution
`UNIDENTIFIABLE`, while final paired objective response may still be reported.

## Warehouse measurement reanalysis

Reanalyse exact R8 `v2-v1`, R8 `v3-v2` and production-1.2 `v2-v1` snapshots.
Historical raw evidence has only three seeds, so a read-only reanalysis cannot
claim the TASK's two-versus-four-seed comparison.

If that comparison remains useful, run one clean provider-free replay over the
complete original case universes with four seeds frozen before execution. Run
every case once per exact comparison, then derive the selector and estimator
arms offline:

- historical action-dependent selector;
- equal-count evenly spaced selector;
- equal-count size/headroom/structure-stratified selector;
- first two versus all four seeds;
- seed-vote versus paired-median estimator.

Select a future regression population only by coverage and stability across
seed/estimator arms, never by which arm enlarges an accepted effect. Existing
Warehouse promotions remain accepted and synthetic and production effect sizes
remain separate.

## Context and edit-surface diagnosis

An H research-core A/B is allowed only after at least two independent completed
H calls show the same schema/context friction: invalid schema or abnormal
completion, required source/objective/mechanics/legal surface missing or
truncated, or an explicit misunderstanding caused by repeated wrappers. Token
count or weak ideas alone do not trigger it.

A C expression A/B is allowed after either one deterministic typed-edit apply
or multi-file-anchor failure, or two independent schema-valid, structurally
closed C traces omit the causal use/update sites required by complete,
source-grounded multi-site H proposals. R2 and R3 each contain one
scaffolding-only time-aware-credit trace, so the second diagnostic trigger is
met without claiming schema causality. Freeze the approved H and source, then
compare one-shot current expression with one-shot source-bound unified diff.
Normalize both to the same `PatchProposal` before unchanged Contract and
deterministic apply; use no fuzzy repair, retry, shell or model tool loop. Score
parse/apply success and blinded H-obligation/source-anchor coverage only, never
solver W/L/T.

Run this as a post-R3 diagnostic without changing the production proposal or
campaign path. Freeze four solver/Protocol-outcome-blind fixtures: the R2 and
R3 time-aware-credit omissions plus two chronological successful multi-file C
contexts selected only by existing parse/apply facts. Each fixture receives
exactly one control and one treatment call, counterbalanced by fixture ordinal,
using `gpt-5.6-terra`. Both arms reuse the same frozen H and serialized provider
context, check that its `approved_hypothesis` value equals H, and then run the
unchanged `validate_patch(..., approved_hypothesis=H)` after normalization.

The durable result contains the frozen H/source/tool values, raw terminal
response, canonical patch, parse/apply and Contract results. Blind reviewers
see neither arm nor raw expression format. Before calls, freeze both ordinal
rubrics: H-obligation coverage is 0 missing, 1 partial/unused scaffolding, 2
complete causal use/update wiring; source-anchor coverage is 0 wrong owner or
symbol, 1 correct file with incomplete sites/data flow, 2 all required owner,
update and consumer anchors closed. Diagnostic production-code growth is zero.
Only an adopted treatment may promote a strict diff normalizer into the core,
with complete schema/parser wiring capped at 220 lines.

## Identifiability stops

Report `UNIDENTIFIABLE` rather than filling gaps when the campaign is not
terminal, the cohort was outcome-selected, exact source/base cannot be
materialized, a factor cell is incomplete or contaminated, fewer than four
candidates exist, telemetry required for an activation claim is absent, CPU
competition overlaps any factor, budget or Warehouse atomic block, or the
requested population exceeds the fixed cases and seeds actually measured. An
overlapped block is contaminated as a whole; do not select individual pairs by
observed outcome or reconstructed overlap guesses.

## Next promotion campaign, if needed

Keep model, provider context/tool surface, dimension bands, validation, frozen
and final blocks fixed. Use a newly pre-registered quality connecting
population with three cases in each of four cells: non-X `<=100`, non-X
`101-200`, X `101-200` and X `>200`.

The first eight contain two cases per cell and the added four contain one per
cell. This supplies four fixed coverage strata and a family direction in the
shared mid-size support; only the X cell has a same-benchmark-family
mid-to-large direction. The complete family-by-size interaction remains
`UNIDENTIFIABLE`.

The fixed cells support a non-X-low versus non-X-mid mixture description, an X
mid-to-large direction and non-X-versus-X at mid size. The proposed non-X low
cell uses A/B/E while the mid cell uses Tai/Tai/M, so that contrast does not
identify a causal within-family size effect. These are different stratum
descriptions and cannot be combined into a general family-by-size effect.
Existing validation, frozen and final populations remain relatively
X/large-heavy, so a future claim is "balanced screening followed by legacy
robustness holdouts", not a population-balanced end-to-end campaign.

A static feasibility audit found that the first straw roster was not admissible
under the proposed clean-reference and dimension-budget evidence contract:
`F-n135-k7` has a known reference-cost mismatch, and `Tai100b/c` have manifest
dimension 101 while filename parsing would assign the <=100 budget. A viable
candidate roster, still not frozen until the provider-free diagnosis is
complete, is:

```text
A-n62-k8, Tai100b, X-n106-k14, X-n317-k53,
B-n66-k9, Tai100c, X-n110-k13, X-n376-k94,
E-n76-k7, M-n121-k7, X-n148-k46, X-n876-k59
```

It requires the following outcome-blind exact `case_globs` to recover the
ledger 45-second budget before the new campaign is preregistered and frozen,
just as the existing CMT aliases do: `cvrplib/tai/tai100b.vrp`, `tai100b.vrp`,
`cvrplib/tai/tai100c.vrp` and `tai100c.vrp`. After freeze neither aliases nor
dimension bands may change. Before launch, assert clean reference data, exact
manifest dimensions and resolved budgets, three cases per cell, complete
source/solution availability and no overlap with the current screening,
validation, frozen or final-replay paths. This roster also changes the old
seed-0 B0 `gap_pct >= 2%` stratum: only four of twelve meet it, although all
twelve absolute B0-minus-BKS headrooms are positive. Freeze that claim and
distribution explicitly rather than describing the roster as matched to R3.
Absolute headroom still spans roughly `9..2802`, so retain both sides' absolute
objectives for audit and use within-case paired or normalized effects for
cross-case summaries; do not infer a causal headroom effect from this roster.

Change only one quality measurement axis at a time:

```text
8 cases x 4 seeds
  -> add seeds only: 8 x 8
  -> add cases only: 12 x 8
  -> validation -> frozen -> independent final B0 replay
```

Each expansion reuses the exact candidate without another H/C call. No dynamic
family subset, favorable seed, threshold change, dimension-band change or
post-freeze alias change is permitted.

The existing single expansion authorization commits to both added-seed and
added-case blocks: `8x8` is a diagnostic checkpoint with no Decision and no
result-based early stop; the expanded gate runs once at complete `12x8`.
Use the existing expansion round rather than building another state machine.
The future generic fresh-order/raw-evidence patch has a 100-line production-
growth ceiling, and immutable atomic-expansion wiring has a further 150-line
ceiling. If the combined change exceeds 250 added production lines, stop and
redesign rather than adding a parallel runner, ledger or orchestration layer.
