## Frozen selector arms

Historical selectors reproduce the accepted action-dependent counts:

- R8 `v2-v1`, create, n=10: synthetic `m01,m03,m05,m06,l02,l04,s02,s03,ml02,ml04`;

- prod `v2-v1`, modify, n=6: production `micro01,micro04,s03,ms02,m03,ml02`.

Equal-count even selectors use the existing manifest-index spacing rule with
n=8:

- synthetic: `m01,m03,m06,l02,l04,s02,ml02,ml04`;
- production: `micro01,micro03,s01,s03,ms02,m01,m04,ml02`.

The raw pair schema does not retain either side's absolute objective vector, so
actual `subcategory_splits` headroom is `UNIDENTIFIABLE`; a signed delta must
not be substituted. Instead, one candidate-independent stratified cohort per
universe is frozen before execution from case input alone.

For each case, define static consolidation headroom `H` from the frozen
Warehouse model semantics. Convert order quantities to pallets using the
declared pallet and box packing types. Within every
`(subcategory, vehicle category, pickup region)` compatibility cell, compute a
conservative lower bound as the maximum
of capacity, distinct-pickup and declared-amount-limit lower bounds. Atomic
units are unlocked orders plus distinct non-null locked vehicle ids. `H` is the
sum of positive atomic-units-minus-lower-bound differences. It is an input
structure proxy, not a solver objective or candidate-effect prediction.

Take the unique minimum- and maximum-H case from each size cell. If an extreme
ties, maximize exact Gower distance over capacity pressure, locked ratio,
hazard ratio and subcategory count; compare rational values without rounding,
then use manifest order. The size cells are small/medium/medium-large/large for
synthetic and micro/small/medium-small/(medium plus medium-large) for
production. The resulting exact cohorts, in manifest order, are:

- synthetic: `m05,m06,l02,l04,s01,s03,ml01,ml04`;
- production: `micro01,micro02,s01,s03,ms01,ms02,m01,ml02`.

All required fields exist. Synthetic medium has a tied low-H extreme (`m04`,
`m05`), resolved by the frozen Gower rule to `m05`; the other extremes are
unique. A tracked feature/H table and selector result must accompany the input
bundle with `candidate_values_used=false`; analysis only filters raw deltas by
these exact ids.

the two synthetic groups with a 17-case frozen split, and one containing the
production group with a 16-case frozen split. Both use the four-seed ledger and
30-second budget above. This command already copies exact champion directories,

Its built-in `gate_outcome`, `supports_candidate` and
`all_groups_supported` fields are incidental legacy mechanics and must be
retained verbatim but marked `builtin_support_flags_authoritative=false` in the
derived report. They never determine diagnosis completeness or alter accepted
promotions. Completeness instead requires exact case/seed coverage, all groups
and canaries completed, no execution/candidate/champion failure, and no cached
runtime pair.

not contain a formal-candidate index and the targets are already exact champion
directories. At most one small read-only analysis command may be added to
derive the selector x seed-prefix x estimator table from the two completed raw
files. It cannot execute a solver, write framework policy or enter Decision.
Because each pair is champion-first and candidate-second rather than
counterbalanced, runtime is not an endpoint and the final report must retain a
possible warm-cache/order-effect limitation even under CPU-exclusive execution.
