# Active Algorithm Facts Control Repair, 2026-05-20

## Context

The previous branch-lifecycle portfolio validation showed that branch lifecycle
and portfolio behavior had improved, but it exposed a P0 framework-control
problem: semantic gates were operating from concise active-solver facts while
the proposal agent saw a much larger, partly truncated tool-observation blob.
That violates the v3 rule that Scion may control boundaries deterministically
but must not give gates a clearer private view of the research object than the
agent receives.

## Repair

- **P0-A: adapter-owned active facts.** Generic
  `proposal.active_solver_snapshot` is now a provider facade. CVRP active
  solver facts live under `problems/cvrp/active_solver_facts.py` and are
  exposed by `CvrpAdapter.active_solver_design_provider()`.
- **P0-B: prompt-visible facts.** APS extracts the adapter fact packet into
  `agentic_active_algorithm_facts`, renders it before raw tool observations,
  and records digest/provenance in prompt manifests. Raw tool observations
  remain audit/debug support and may still be compacted.
- **P0-C: shared-fact semantic gates.** Mechanism novelty and premise
  contradiction checks may reject only using the same active fact packet shown
  to the agent. Rejections include fact ids, fact-packet digest, and
  provenance.
- **P0-D: activation diagnostics.** Proposal-smoke telemetry activation misses
  now produce `proposal_activation_diagnostic` detail with a best-effort
  subtype such as not connected, trigger not reached, instrumentation missing,
  expected telemetry mismatch, or smoke budget/case insufficiency. This is
  repair/lifecycle feedback, not ordinary solver-quality screening evidence.

## Boundary Notes

Scion core remains problem-agnostic. It calls adapter/provider hooks, carries
generic schema, records evidence, and enforces deterministic boundaries. CVRP
solver facts, algorithm structure summaries, and CVRP semantic novelty logic
remain in the CVRP problem package.

The only allowed relationship is:

```text
problem adapter/provider -> active_algorithm_facts packet
same packet -> agent prompt/context
same packet -> semantic novelty/premise gate
gate rejection -> fact ids + digest + provenance
```
