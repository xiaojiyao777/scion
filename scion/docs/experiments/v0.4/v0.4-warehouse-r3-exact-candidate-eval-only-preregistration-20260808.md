## Execution semantics

The manifest contains one source candidate and three requested stage rows.
`--conditional-stages` requires a completed `pass` before advancing to the next
stage. For this `modify` candidate, `--expand-screening` deterministically
evaluates the Protocol-configured 14-case expanded production screening
population (`expand_to_modify: 14`). If the initial validation row returns
`expand`, the executor automatically runs one expanded validation row with the
same candidate source; only a completed `pass` from that row advances to
frozen. No later stage runs after a non-pass or execution error.

The exact candidate artifact is materialized independently under the output
root for evaluation. The source campaign is read-only for this operation.

## Outcome classification

Classification uses only the completed rows in
`fixed_candidate_replay_comparison.v1.json`:

- `TRUNCATED_QUEUE_CONFIRMED`: expanded screening passes, validation passes
  (after the one automatic expanded validation row if requested), and frozen
  passes.
- `SCIENTIFIC_NEGATIVE`: evaluation completes normally but an executed
  Protocol stage does not pass. The first non-pass stage is the causal stopping
  point; subsequent skipped rows are consequences, not additional negative
  observations.
- `RUN_INVALID_INFRA`: materialization, configuration, runner or Protocol
  execution produces an error rather than a completed gate outcome. This is
  not scientific evidence and receives neither S1 scientific label. A repair
  may be rerun only when the scientific inputs and stage policy above remain
  unchanged, with the failed attempt retained in the post-run record.

A frozen pass means only that the previously queued exact candidate survived
this pre-registered evaluation chain. It does not mutate the original campaign
or constitute a campaign promotion.
