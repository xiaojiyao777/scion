## Root Causes

1. repeated mechanism identity 把 acceptance strategy 误当作机制 id。
   `simulated_annealing+adaptive_operator_weights` 是很多 candidate 共用的 acceptance context，不是 route removal、regret repair、or-opt 等机制本体。这个错误直接解释了为什么 unrelated proposals 被反复标为 repeated adaptive weights。

2. CVRP active facts 覆盖仍不完整。
   facts packet 已覆盖 Shaw、construction diversity、adaptive weights、部分 local search，但没有明确暴露 `_or_opt_1`、`_route_removal`、`_regret2_insertion`/`_regret3_insertion`。agent 因此持续提出已存在机制。

3. retry/rejection state 有错位。
   若 semantic retry 改变了 hypothesis，final `output.hypothesis` 仍可能和早先 structured rejection 搭在一起，例如 branch 48 上 construction premise contradiction 与最终 Or-opt hypothesis 的错位。这会污染后续 agent feedback。

4. tool-selection 没有 facts digest。
   generation prompt 有 facts，但 tool planner 没有同源 facts packet。如果 planner 决定 owner file、是否补读、何时结束，它可能没有足够稳定的 fact anchor。

5. raw observations 仍过大，且截断影响文件级核对。
   active facts 未截断，但 raw owner-file excerpts/API summaries 的大体积截断让 agent 更容易依赖概括性、不完整的上下文。

6. activation contract 反馈过晚。
   `.vns`、`.alns`、whole telemetry maps 这类 activation references 应在 hypothesis preview 层被早期拦截，而不是进入 proposal attempt 后才以 DB contract failure 形式消耗 attempt。

7. failure router 将候选质量问题误升级为 infra。
   branch 48 的 `blocked_infra` 是全局 `contract` streak 的结果，而这些 contract failure 本质上是 hypothesis/candidate schema 失败。它不是 runner、DB、tooling 或 screening infra 失败。

## Recommended Fixes

这些建议严格遵守 v3 边界：Scion core/proposal 不应硬编码 CVRP 语义；研究对象 facts/novelty 应继续由 adapter/provider 提供。core 层只处理通用的 identity、状态一致性和 failure routing。

1. 在 CVRP adapter/provider 扩充 active facts。
   增加显式 facts/provenance，覆盖 `_or_opt_1`、`_route_removal`、`_regret2_insertion`、`_regret3_insertion`、destroy/repair/VNS operator registration。让 provider 能把这些重复 proposal 判为同源 `premise_contradicted` 或 provider-level novelty rejection。

2. 修正 generic repeated mechanism identity。
   不要把 `novelty_signature.acceptance_strategy` 当作 mechanism id。优先使用 `mechanism_changes[].id` 和显式 `novelty_signature.mechanism_id`；如果需要比较完整 novelty signature，应保留字段角色，而不是把 acceptance context 归一化成机制名。

3. 为 history-based repeated rejection 增加可解释 provenance。
   repeated rejection 可以没有 `fact_packet_digest`，但应包含 previous hypothesis id、previous branch/step、candidate normalized ids、matched normalized ids，并明确这是 campaign history match，不是 adapter fact contradiction。

4. 修复 semantic retry output consistency。
   final `output.hypothesis`、`structured_rejection`、failure event 必须指向同一个 candidate attempt。如果 retry 后 hypothesis 改变，不能把前一次 premise rejection 贴到新 hypothesis 上。

5. 将机制重复和 C11 schema failure 从 infra streak 中剥离。
   `mechanism_novelty_rejected`、invalid `expected_telemetry.activation` 应归入 search guidance / agent quality / contract-boundary failure，而不是推动 `blocked_infra`。failure streak 至少应 branch-scoped；升级 infra 需要真实 infra evidence。

6. 提前拦截 activation diagnostic 错误。
   hypothesis contract preview 应直接拒绝 `.vns`、`.alns`、whole maps、`phase_improvement_counts` 这类非机制专属 activation references，并给出具体修复模板：使用 `solver_algorithm_phase_runtime_ms.<mechanism_id>` 或通过 `context.record_phase`/`context.record_move` 产生新机制 evidence。

7. 缩小或结构化 raw observations。
   把 active facts 作为 primary factual context，raw observations 作为 audit/support。优先给 owner-file symbol summaries、operator registries、exact function list，避免 80k+ 截断文本掩盖关键 owner-file 事实。

8. 给 tool-selection 加轻量 facts anchor。
   如果 tool-selection 继续只负责选工具，可以保持当前设计；如果它会决定 owner file 或上下文是否足够，应注入小型 fact-id/digest summary，使 planner 与 generation/gate 使用同一个事实来源。

9. 分离 “Scion generic control fix” 与 “CVRP research facts fix”。
   generic control 可修 repeated identity、retry consistency、failure routing；CVRP 机制存在性和 novelty 只能通过 CVRP adapter/provider facts/rules 表达，不能回写为 core/proposal 的 CVRP 特判。
