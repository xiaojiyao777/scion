## Promoted algorithm change

H3 replaced random `MoveOrder` source/destination selection with a deterministic
sampled relocation search. It looks for unlocked satellite orders whose
subcategory already exists on a feasible destination vehicle, screens the
affected Warehouse constraints, and ranks relocations lexicographically by
subcategory-split reduction and then local vehicle-cost reduction. The operator
keeps its existing registry share; the promotion changes
`operators/move_order.py` without adding another competing operator or changing
the registry weights.

The strongest evidence is the two later, fresh-comparison stages:

- validation: all `18/18` pairs won across six cases and three seeds;
- frozen: all `12/12` pairs won across four cases and three seeds;
- both stages: median primary-metric improvement `+11`;
- candidate/champion execution failures: `0/0`.

This is positive evidence for the exact promoted candidate on the declared
synthetic validation and frozen populations. It is not yet an external or
production-population generalisation result.

## Runtime interpretation

Runtime remains a supporting signal only. The promoted candidate's validation
and frozen comparisons used fresh champion runs and showed median runtime
ratios below one, but Protocol does not use runtime as the standalone research
objective. The H3 screening stage used cached champion results, so its runtime
aggregate was excluded. None of these runtime observations should replace the
primary lexicographic objective result.

## Framework terminal defect

Promotion completed at stage 6 and champion v2 was present before termination.
The next scheduled action selected the stale H1 branch. Reconciliation returned
`no patch to reconcile`; the campaign then stopped because no explicit
research-rejection disposition was available for that branch. The wrapper
returned normally, but the campaign remained incomplete at `6/36`.

This separates two conclusions:

1. the completed H3 scientific and promotion path succeeded;
2. post-promotion stale-branch reconciliation still prevents long-horizon
   continuity and must be repaired before a 36-stage campaign can be expected
   to continue naturally.

The stop must not be relabelled as a solver failure, candidate rejection or
provider outage. It is a framework lifecycle defect after valid scientific
work had already completed.

## What R3 can establish

R3 supports these claims:

- the direct V3 Warehouse agent can produce three substantive, source-bound H/C
  pairs in one campaign;
- Protocol can distinguish uncertain, negative and positive candidates rather
  than promoting every generated patch;
- one agent-generated algorithm change completed screening, validation and
  frozen evaluation and became champion v2;
- the promoted H3 candidate has strong positive evidence on the exact declared
  synthetic validation and frozen sets.

R3 does not support these stronger claims:

- that the requested 36-stage campaign completed;
- that Scion can already continue through multiple post-v2 promotions in one
  uninterrupted run;
- that H3 improves unseen production instances or a different data population;
- that the observed runtime differences are a primary solver improvement;
- that an independent fixed-candidate reproduction has already been completed.
