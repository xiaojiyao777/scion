## Proposal Quality Loop 根因

当前 campaign loop 把 proposal-only failure 和 screened experiment 分开计数：

- proposal attempts: 所有 APS proposal 尝试，共 7 次。
- effective experiments: 进入 formal screening 的实验，共 2 次。
- proposal-quality blocks: 失败在 proposal/gating 阶段的次数，共 5 次。

5 次 block 分别是：

1. Round 1：`sa_reheat_plateau_escape` 的 expected telemetry activation 写成 `solver_algorithm_phase_improvement_counts.*` 和 `solver_algorithm_phase_best_delta.*`，这是 effect 字段，不是 activation 字段。
2. Round 2：`knn_candidate_filter` 声称 Or-opt-1 missing；framework facts 显示 `_or_opt_1` 已注册。
3. Round 3：最终 LLM trace 里有 `sa_reheat` 非空文本，但 APS output 存成 `hypothesis_text=""`，schema preview 因空字符串失败。
4. Round 6：`cross_route_reversed_or_opt` 声称 cross-route Or-opt segment relocation missing；facts 显示 `_or_opt_1/_2/_3` 和 `_or_opt` 已覆盖跨 route relocation。
5. Round 7：`knn_inter_ls` 的 effect 引用 `solver_algorithm_phase_delta_sum.knn_inter_ls`，该字段未声明。

因此停止逻辑是合理触发的：第 5 个 proposal-quality block 后，campaign 自然停止为 `proposal_quality_loop`。但对 3-round formal smoke 来说，这个上限偏紧：只要出现 3 个前置 proposal failure，再完成 2 个 experiment，后续再失败 2 次就会在第三个有效 experiment 前停止。

分支选择不是主要根因。`segment_removal_destroy` 被保留后，v3 portfolio 在 active branch cap 以内继续扩展新分支，最后有 3 个 active branches。这符合当前分支多样性设计。

## C11 Telemetry Feedback 判断

C11 strictness 在 formal screening 前是必要的：如果 mechanism 声明了 activation/budget/effect，framework 必须保证 smoke 和 formal 都能证明这些字段可观测。`sa_reheat` 的 abandon 也说明 strict guard 有价值：机制确实激活了，但没有产生声明 effect。

问题不在于 C11 原则过严，而在于反馈对 agent 不够稳定、跨 session 不够可记忆：

- Round 1、4、5、6、7 都出现 activation/effect/aggregate 字段类别混淆。
- `sa_reheat` 和 `segment_removal_destroy` 最终能修正，说明单次反馈有用。
- local-search 类 hypothesis 后续仍反复误用，说明允许字段 pattern 没有在 prompt/tool surface 中足够显眼。
- final rejection 常只暴露“字段无效/未声明”，没有同时列出当前 mechanism 最接近的合法 activation、budget、effect examples。
- `SCREENING_TELEMETRY_FAILED` 作为 top-level reason 太粗，掩盖了 `TELEMETRY_EFFECT_NOT_OBSERVED`。

建议把 C11 feedback 调整为“严格执行、清晰提示”：规则不放松，但在 schema preview 和 screening summary 中直接给出合法字段模板和机制 id。
