# Scion v0.4 K6 Single Proposal Runtime and APS Deletion Plan

*Date: 2026-07-12*
*Status: K6 implementation and preflight/postrun repair accepted; replacement formal controls pending*

## Decision

After K5, promote the V3 two-round `direct_v3` path to the sole production
proposal runtime for both warehouse and CVRP. Do not keep repairing the
historical `agentic_ablation`/APS graph in place. Close the remaining direct
acceptance gaps, route both problem families through the same kernel, then
physically delete the legacy agentic runtime and its control graph.

This follows the architecture authority:

- V3 explicitly defines `Proposal Engine (Hypothesis -> Code)` as two direct
  structured provider calls;
- V3 explicitly excludes building a generic agent framework;
- Contract, Verification, Protocol, Safe Feature Extractor, and deterministic
  Decision remain outside the creative runtime.

Pi and Claude Code remain implementation references, not runtime templates.
Scion adopts immutable turns, typed transitions, ordered durable events,
centralized provider/tool execution, and explicit cancellation. It does not
adopt an interactive discovery tool loop, automatic compaction, hidden retry,
or session budget machinery.

## Target Runtime

```text
ProblemRuntime / deterministic safe source retrieval
  -> ProposalContextSnapshot + SourceLedger
  -> one durable hypothesis provider attempt
  -> one authoritative Hypothesis Contract decision
  -> ProposalContextSnapshot bound to approved hypothesis
  -> one durable code provider attempt
  -> one authoritative Patch Contract decision
  -> Workspace -> Verification -> Protocol -> Decision
```

Every later provider call is a new durable attempt. It is not an inner retry of
the same attempt. Missing governance dialect, novelty prose, branch-lesson
objects, telemetry declarations, or runtime-budget claims cannot trigger a
second provider call or block code.

## Why a Production Tool Loop Is Unnecessary

Pi's multi-turn `LLM -> tool -> LLM` loop is useful when the task boundary and
relevant files are initially unknown. Scion's problem package already owns the
research boundary, editable/frozen paths, source provenance, solver entrypoint,
and safe API surface. `ProposalContextSnapshot` and `SourceLedger` can expose
the complete safe active boundary deterministically before the provider call.

The direct patch schema already supports `additional_changes`, so algorithm
research is not restricted to a single file. The outer Contract, workspace,
and Verification paths already consume the same multi-file `PatchProposal`.
Target-intent calls, model tool selection, observation ledgers, inner preview,
and local repair loops therefore add control-plane work but no scientific
authority.

## K6.1 Direct Correctness Acceptance

The first three correctness gaps are now closed in the integrated worktree:

1. **Real CVRP direct outer smoke**
   - use the real CVRP adapter, Contract, workspace, Verification, Protocol,
     and Decision;
   - assert exactly one hypothesis and one code provider call;
   - assert zero target-intent and tool-selection calls.
2. **Direct multi-file end-to-end proof**
   - parse a typed primary edit plus `additional_changes`;
   - pass through Contract, workspace materialization, and Verification;
   - prove complete source/digest ownership for every modified existing file.
3. **Durable interruption semantics**
   - record an explicit `interrupted`/`non_resumable` terminal transition for
     `KeyboardInterrupt` or operator cancellation;
   - do not copy APS resume machinery or silently reuse a pending provider
     attempt;
   - any later continuation receives a new attempt id and binds only to a
     durably stored approved hypothesis.
The final route-switch item is now accepted:

4. **CVRP and warehouse launcher route**
   - stop forcing the agentic alias;
   - emit the same explicit production runtime as warehouse;
   - remove APS step/call/observation/session controls from the prepared
     command and manifest.

## Deletion Scope

The explicit agentic production deletion target is 57 files and roughly
26,000 lines, but that is only the first layer:

- top-level `agentic_session*.py` modules;
- remaining top-level `agentic*.py` orchestration modules;
- agentic observation/tool-selection/session ledgers;
- `legacy_agentic_projector.py` and `legacy_agentic_sections.py`;
- `core/proposal_pipeline/agentic_*` modules;
- the `agentic_ablation` runtime-mode branch, CLI alias, launcher fields, and
  postrun production fallback paths.

The import-graph audit found that `proposal/tools/**` is production-reachable
only through APS bridges: active-solver preview/map, target intent, model tool
selection, observation tooling, mechanism novelty preview, and solver-design
smoke. After moving the small generic JSON/digest/path primitives used by the
direct runtime to their direct owners, delete the whole package together with
those APS bridges. Do not preserve a registry or compatibility wrapper merely
to keep historical tests importable.

The deletion graph also includes:

- `core/proposal_pipeline/{boundaries,classification,constants,problem_quality,runtime_mode}.py`;
- CreativeLayer target-intent, tool-selection, and `fix_code` provider paths;
- target-intent authority/binding, active-solver map/snapshot, mechanism-novelty,
  and solver-design preview/smoke packages;
- runtime selector and aliases in CampaignManager, CLI, launchers, manifests,
  readiness, and postrun;
- `pending_retry`, `retry_llm`, consecutive retry state, and scheduler priority;
- APS prompt projection, session index, observation compaction, and postrun
  compatibility fallback.

Historical artifact reading must use an explicit versioned offline reader or
be deliberately retired; it must not keep a production compatibility runtime
alive. Formal candidate v1 is therefore an explicit offline replay input;
production writes v2 with per-file source attribution.

The corresponding agentic test graph is replaced by a smaller direct
acceptance matrix. Historical fixtures may remain only as inert migration or
audit evidence, never as a reason to preserve production behavior.

- add interruption terminal semantics;
- add real CVRP direct outer smoke;
- add multi-file direct end-to-end Contract/workspace/Verification proof;

Accepted evidence:

- workspace multi-file materialization is transactional and rollback tested;
- real CVRP and warehouse direct outer smokes each make one H and one C call;
- H/C cancellation terminalizes the same attempt as interrupted/non-resumable.

### K6.2 Switch both production launchers

- warehouse and CVRP resolve to the same production runtime;
- remove agentic command/config fields;
- require completion preflight and reject forced research targeting for formal
  launch roots;
- separate no-provider-call guarded-wrapper readiness from optional external
  live-probe diagnostics; formal operators use the guarded workflow and
  `run.sh` owns the one durable pre-campaign completion receipt;
- parse the concrete prepared command with the current real CLI;
- accept the configured manifest model, including `gpt-5.6-sol`, without a
  hard-coded model-name gate;
- run the controlled warehouse/CVRP outer acceptance matrix without launching
  a formal experiment.

### K6.3 Route and physically delete

- remove the runtime enum branch and alias;
- delete APS session/planner/preview/repair/budget modules and legacy projector;
- delete production agentic ledgers and fallback joins;
- update artifact schema/readers explicitly;
- publish a file/line deletion ledger and zero-residual grep.

Also remove the research-suppressing controls that survived outside APS:

- provider and campaign proposal-attempt/quality/drain limits;
- character/item/file/tool/session caps and compact/omit-to-fit projections;
- the 85% near-whole-file exact-replace rejection and the ban on source-bound
  existing-file full-file modification;
- retry/fix/partial-resume state and automatic scheduler re-execution.

Scientific protocol isolation, subprocess timeouts, feasibility, Contract,
Verification, Protocol, and deterministic Decision remain. They are external
experiment correctness boundaries, not provider-context budgets.

### K6.4 Post-delete integrated acceptance

- focused owners, full proposal/core regressions, replay, compile, and diff
  checks;
- real warehouse and CVRP completion preflight from one clean commit;
- rewrite `TASK.md` and `current-state.md` to the final single-runtime state.

### K6.5 Formal research controls

Only after K6.4 passes on the final integrated worktree:

1. run the warehouse production control;
2. review framework behavior and artifacts;
3. run one clean, non-target-bound CVRP production campaign;
4. judge research effectiveness from actual algorithm proposals, code,
   Verification, Protocol evidence, and solver outcomes.

No formal experiment runs from the transition worktree or before physical
legacy deletion.

## Acceptance

- one production proposal runtime and no `agentic_ablation` branch;
- exactly one durable hypothesis call and one durable code call per normal
  candidate attempt;
- complete safe source is visible without character, token, file, item,
  observation, or session budgets;
- no truncation, top-N, compact-to-fit, omit-to-fit, or summary substitution;
- no target-intent, tool-selection, semantic/schema/grounding/preview/code, or
  provider hidden retry loop;
- minimal research hypothesis reaches code without governance dialect fields;
- path, source, approved-hypothesis identity, Contract, Verification,
  Protocol, and Decision remain fail-closed at their single owners;
- multi-file CVRP patch reaches workspace and Verification with exact source
  provenance;
- interruption and infra failure remain distinct from research rejection;
- production Python line count shows a material net deletion, not a helper-file
  reshuffle or compatibility wrapper layer.

Zero-residual production greps must find no runtime matches for:

```text
agentic_ablation | --agentic-proposal | AgenticProposal | agentic_session
hypothesis_target_intent | tool_selection | fix_code | ProposalToolRegistry
pending_retry | consecutive_llm_retries | retry_llm
LLMRetryExhaustedError | LLMTransientProviderError
proposal_attempt_limit | proposal_quality_loop_limit
fresh_runtime_replay_drain_limit | stage_transition_drain_limit
near_whole_file | RESULT_TOO_LARGE
```
