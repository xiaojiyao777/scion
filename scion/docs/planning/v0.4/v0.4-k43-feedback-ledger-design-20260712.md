# Scion v0.4 K4.3 Feedback Ledger Design

*Status: superseded as an implementation target by K6; retained as the A0/A1
design and failed-attempt audit record*
*Date: 2026-07-12*

## Final Decision

Do not implement `ProposalFeedbackLedger` as a new permanent framework object.
The two reverted A1 attempts showed that it existed primarily to reproduce the
legacy agentic compact bytes. K6 removes that renderer and APS graph entirely.
After the route switch, make the remaining direct producers full-only, delete
their `lossless` branches and duplicate strings, and retain the existing
authoritative snapshot/owner map. Any further consolidation must demonstrate a
net deletion and cannot add a second schema or compatibility projector.

The remainder of this document records the earlier candidate design and its
acceptance analysis; it is not an instruction to build the ledger.

## Historical A1 Candidate

K4.3-A replaces the current feedback/history mode branches with one canonical
`proposal_feedback_ledger.v1`. The ledger contains only complete, safe,
renderer-required primitive facts. It must not contain full `StepRecord`,
`ProtocolResult`, `Branch`, or other domain-model mirrors, and must not be
implemented with `asdict`, dataclass-field iteration, generic object
serialization, `SimpleNamespace`, or domain-model reconstruction.

The authoritative hypothesis context persists only:

```python
"proposal_feedback_ledger": ProposalFeedbackLedger
```

The following historical strings and compact payload leave the authoritative
context:

```text
experiment_history
blacklist_summary
sibling_summary
branch_dossier
branch_dossier_payload
champion_baselines
agent_quality_feedback
```

Direct and legacy renderers materialize the six provider strings at the prompt
boundary. `branch_dossier_payload` is not reinserted into structured context.
There is no sidecar, second truth, budget, truncation, or propagated mode flag.

## Sequencing Decision

The A0 legacy-boundary characterization is complete. Two attempted A1
implementations were fully reverted after the structural checkpoint: preserving
the historical compact agentic bytes required a large second renderer and an
exact feedback ledger whose implementation grew substantially more than the
mode branches it replaced.

K5.5 removes the hidden agentic source/output projections and establishes
full-context parity first. K6 then deletes the legacy runtime and projector.
K4.3-A completes as direct producer/branch deletion, not ledger construction.
The A0 characterization remains an audit record for what was removed, not a
requirement to preserve those limits.

## Canonical Schema

### Top level

```python

    "schema_version": Literal["proposal_feedback_ledger.v1"],
    "branch": BranchFeedbackFacts,
    "steps": list[ScreeningStepFacts | PreProtocolStepFacts],
    "blacklist": list[BlacklistFacts],
    "siblings": list[SiblingFacts],
```

Every mapping has an exact key set. Nullable fields remain present with
`None`; optional mapping keys are not used.

## Safety Validator

The builder first applies the existing promotion-path exclusion and safe-step
filter. Runtime validation then enforces:

- exact key sets at every mapping and exact discriminator-specific union keys;
- `ordinal == list index`, ordered steps, and no duplicate ordinal;
- positive round numbers and finite numeric values;
- canonical relative POSIX paths with no absolute path, drive, backslash,
  empty segment, `.` or `..`;
- only screening results in `ScreeningStepFacts`;
- only allowlisted no-protocol stages in `PreProtocolStepFacts`;
- no hybrid variant containing keys from the other variant;
- no validation/frozen steps;
- no raw pair rows, raw metrics/calibration, BKS, holdout, DecisionFeatures,
  raw prompt, provider message, LLM response/trace, or opaque object;
- safe feature names; names associated with forbidden sources fail closed;
- primitive JSON values only and no non-finite float.

Safety is structural. Failure text is not rejected merely because it contains
words such as “validation”; forbidden data is excluded by admission path and
schema, not by destructive substring redaction.

Required negative tests include nested unknown keys, duplicate/incorrect
ordinal, out-of-order steps, hybrid variants, disallowed stages, unsafe feature
names, invalid paths, non-finite values, and injected validation/frozen/raw
fields.

## Renderer Interfaces

The sole production builder may receive domain objects only at the extraction
boundary and returns a validated primitive ledger:

```python
def build_proposal_feedback_ledger(
    *,
    branch: Branch,
    safe_steps: Sequence[StepRecord],
    blacklist: Sequence[HypothesisRecord],
    siblings: Sequence[Branch],
    taxonomy: Sequence[Any] | None,
) -> dict[str, Any]:
    ...
```

Direct rendering is always complete:

```python
def render_direct_feedback_views(
    ledger: Mapping[str, Any],
) -> dict[str, str]:
    """No bool, limit, max-items argument, character cap, or mode branch."""
```

It returns exactly the six historical provider field names, excluding
`branch_dossier_payload`.

Legacy compaction belongs only to the legacy projector:

```python
class LegacyAgenticProjector:
    def project_feedback_views(
        self,
        ledger: Mapping[str, Any],
    ) -> dict[str, str]:
        ...
```

Only policy-free formatting of a single case, pattern, or dossier value may be
shared. Top-N selection, slicing, summarization, and character limits cannot
live in canonical producers or shared direct helpers.

## Legacy Projection Migration

The following existing behavior moves, without duplication, into
`LegacyAgenticProjector`:

- agent-quality attempts: latest 4;
- agent-quality detail: first non-empty line, 900 characters;
- rejection extra fields: 240 characters;
- experiment history: latest 8 rounds;
- detailed pattern/cases: latest 3 rounds;
- verification detail: 200 characters;
- pre-protocol detail: first line, 700 characters;
- opportunity diagnostics: 3;
- auxiliary reasons: 4;
- informative case selection: 4;
- visible case features: 4;
- consecutive-diagnosis details: 150 each and 300 aggregate;
- What Worked: first 5 and hypothesis text 100 characters;
- champion baseline fallback cases: 8;
- dossier timeline: latest 6;
- dossier mechanisms: 12;
- dossier touched files: 16;
- dossier runtime/telemetry diagnostics: latest 8;
- blacklist: 10;
- siblings: 5 and branch id first 8 characters.

The latest-six screening window in feedback grounding is a real temporal
derived view, not a provider-size limit, and remains in both modes. Within that
window, direct renders all safe category lines and legacy renders 4 per
category.

## Deletion Map

In `context/feedback.py`, remove all `lossless` parameters and branches from
agent-quality, experiment-history, failure-detail, case, feature, consecutive-
failure, What Worked, and champion-baseline functions. Move compact-only
`_select_cases_for_prompt` and `_first_line` behavior to the legacy projector.

In `context/feedback_grounding.py`, make the renderer consume screening
primitives, preserve the latest-six temporal view, and move category `[:4]`
policy to legacy projection.

In `context/branch_dossier.py`, consume primitives directly and delete domain
probing, `max_timeline_items`, internal `lossless`, and all dossier caps.

In `context_manager/history.py`, render complete blacklist/sibling primitives
and move the 10/5/id-8 compact behavior to legacy projection.

No compact compatibility helper remains in producer modules.

## Atomic Wiring

1. Complete K4.3-A0 legacy-boundary characterization first. Expected values
   must be handwritten from the accepted old branches, not generated from the
   new implementation. Lock the 4/8/10/12/16 and related boundaries.
2. Implement the exact ledger builder/validator and both primitive renderers as
   one production migration; do not land an unused serializer or dual path.
3. `ContextManager.build_hypothesis_context()` filters safe steps once, builds
   one ledger unconditionally, and inserts only `proposal_feedback_ledger`.
4. `HYPOTHESIS_CONTEXT_OWNER_MAP` assigns the ledger to
   `evidence.screening` and removes the seven historical owner keys.
5. Direct projection pops the ledger, adds `render_direct_feedback_views()`
   output, then invokes hypothesis rendering. It never reinserts the dossier
   payload.
6. `LegacyAgenticProjector.project_hypothesis()` pops the ledger, adds
   `project_feedback_views()` output, then runs the existing profile/filter.
   Target-intent uses the same path.
7. Delete all old mode branches, compatibility formatters, `lossless: bool`,
   and `lossless=` edges in this feedback/history family.
8. Run the eight real agentic provider byte/context-digest goldens, the A0
   high-cardinality boundary characterization, direct sentinel/source-owner
   assertions, safety negatives, and the 227-test K4 baseline.

Direct tail sentinels must remain complete and appear exactly once. Agentic
provider bytes and context digests remain exact.

## K5.5 P0 Run Lock

The current full target-grounding suite has 15 failing tests. These failures
must not be classified as obsolete fixtures. At least the real agentic
hypothesis path reproduces a production failure where a successful,
untruncated `context.read_algorithm_file` result is present in tool payloads,
but its full source is absent from the provider-visible projection/manifest.

That hidden source-visibility projection defect is a K5.5 P0 blocker. K4.3-A
does not repair or weaken it. The run lock remains active until K5.5 resolves
the production path and the complete target-grounding suite passes. No new
formal warehouse control or CVRP production experiment may be launched merely
because K4.3 feedback-ledger acceptance passes.
