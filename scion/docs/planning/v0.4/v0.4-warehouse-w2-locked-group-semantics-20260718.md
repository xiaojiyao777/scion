# Scion v0.4 Warehouse W2 Locked-Group Semantics

Status: design candidate; fixed-hash review pending

Date: 2026-07-18

## 1. Decision

For Warehouse v0.4, `locked_vehicle_id` is an origin-group identifier. It is
not a permanent destination vehicle identifier.

For every `locked_vehicle_id is not None`, including the empty string under the
current input model, the complete closed rule is:

```text
all orders with the same locked_vehicle_id
= one indivisible movable group

the group may move to another vehicle or merge with other complete groups or
free orders

the group may not split, partially move, disappear, duplicate, or disagree
between Solution.assignment and Vehicle.order_ids

every resulting vehicle must still satisfy all other Warehouse constraints
```

A singleton locked group is one movable atomic group. The initial greedy
vehicle ID may equal `locked_vehicle_id`, but that is an initialization layout,
not a continuing feasibility invariant.

If a later business version needs an order pinned to one named target vehicle,
it must add a distinct field such as `fixed_vehicle_id` or an explicit
`lock_policy`, upgrade the problem and manifest versions, and provide an actual
vehicle identity authority. V0.4 must not overload `locked_vehicle_id` with two
meanings.

This is a problem-owned semantic correction. It adds no generic gate, agent
approval, retry, search budget, patch limit, truncation, or per-candidate
checklist.

## 2. Why this contract is authoritative

The human prose drifted, but the data model, executable Oracle, MILP, baseline
merge behavior, tests, and accepted historical evidence already agree on group
integrity:

- `surrogate/surrogate-problem-spec-v1.md` defines Phase 2 as an indivisible
  first-stage logical vehicle that may be merged; its operator and phase tables
  also allow a locked group to move as one unit.
- The same document's old H7 table and pseudocode instead pin every order to a
  same-named vehicle. Those clauses conflict with the stronger model and are
  superseded by this contract.
- production data generation assigns one shared synthetic group ID to all
  orders in a booking. The instance schema has no independent vehicle or
  original-target table from which permanent placement could be reconstructed.
- `surrogate/oracle.py` rejects a group only when its orders are split across
  vehicles. Its tests explicitly accept a whole group or singleton moving to a
  differently named vehicle.
- `surrogate/milp_model.py` models each group as one movable unit and permits it
  to share a destination with other groups or free orders.
- the baseline whole-vehicle merge can move a complete locked group.
- Warehouse formal Verification reaches this same Oracle.
- historical R3 champion evidence already contains valid whole-group moves;
  changing the Oracle to fixed-original would retroactively reinterpret
  accepted evidence instead of correcting prompt noise.

The active W1 population contains 31 formal cases with 8,387 orders, including
662 locked orders in 227 groups. There are 153 multi-order groups and 74
singleton groups. Every observed group is internally compatible in category,
city, and route, and every active greedy initial solution passes the executable
Oracle.

Commit `95fdaba6` is historical corroboration: it changed old fixed-original H7
behavior to group integrity and recorded that a locked booking must move as a
whole but may merge into another vehicle.

The exact W1 population authority is already sealed in
`scion/contracts/warehouse_w1_population_receipt.v1.json` at SHA-256
`5b7ddcf6c1cda6fa9fb742d1463c9fd4a3bbbcf3dbb361d8ef7172f0684f116c`.
It binds accepted commit `0599fc29bc2c38e954c4cf06fc8be110c433dd3a`, reconciliation SHA
`520ea97a42537f7536bf54837fa0a14f58438cb09ebe71f3dacb7a40e69b9f97`,
protocol `3.2-prod`, manifest `prod-1.1`, and all four population digests.
W2 may not redefine the 31-case authority from its own output.

## 3. Corrected owner boundary

The semantic owner remains the Warehouse problem layer:

- `surrogate/surrogate-problem-spec-v1.md` owns human-readable domain meaning;
- `surrogate/models.py` owns the field description;
- `surrogate/greedy_init.py` owns the initial layout, explicitly without
  claiming permanent placement;
- `surrogate/oracle.py` owns executable H7 group integrity;
- `surrogate/milp_model.py` owns the independent exact-model interpretation;
- `surrogate/operators/base.py` owns the operator-facing invariant;
- `scion/docs/reference/milp-model.md` owns the active formal-model reference;
- both Warehouse `problem-v1.yaml` mirrors and the adapter guidance own what the
  research agent is told;
- `surrogate/MILP_SOLVER_NOTES.md` must describe the current movable-group model
  rather than obsolete reserved fixed slots.

Generic Verification, DecisionFeatures, Protocol, scheduler, lineage, and
promotion code must not learn Warehouse lock semantics. The adapter may explain
the problem contract, but final feasibility continues to come from the
problem-owned Oracle.

Existing conservative operators may continue to skip locked groups. The
contract permits whole-group movement; it does not require every operator to
implement it. Do not rewrite algorithm implementations merely to make every arm
equally expressive.

W2's text-only proof is owner-specific; it does not pretend every text literal
is absent from executable AST:

- `models.py`, `operators/base.py`, and `oracle.py` may change only
  comments and docstrings. Their docstring-stripped AST, computed by removing
  the leading string expression from every module, class, sync function, and
  async function and hashing UTF-8 `ast.dump(..., annotate_fields=True,
  include_attributes=False)`, must equal the pre-W2 digest in the preservation
  manifest.
- `_phase2_init` in `greedy_init.py` has one admitted semantic correction:
  replace the exact truthy fallback for `locked_vehicle_id` with the exact
  `is not None` conditional in the manifest. Comments and docstrings may also
  change. The verifier reverse-replaces that one code fragment, strips
  docstrings, and requires the pre-W2 AST digest; no other executable node may
  change. This closes the empty-string group case without widening W2 into an
  algorithm rewrite.
- `adapter.py` may change only the two exact locked-order guidance fragments in
  `WarehouseDeliveryAdapter.render_operator_interface`. The verifier requires
  the exact old fragments to be absent and exact new fragments to occur once,
  reverse-replaces the new fragments with the old fragments, and requires the
  reconstructed raw file SHA-256 to equal the pre-W2 raw hash. No other adapter
  byte may change.
- each Warehouse problem YAML may change only
  `research_surfaces[0].prompt.implementation_guidance` and
  `research_surfaces[1].prompt.implementation_guidance`. The verifier parses
  each file, replaces those two scalars with a domain sentinel, canonicalizes
  the remaining tree as sorted compact UTF-8 JSON, and requires the masked
  digest in the preservation manifest. All other parsed values are immutable.
  Verification uses the manifest-pinned claw CPython/PyYAML versions and a
  SafeLoader variant that rejects duplicate mapping keys before masking; a
  toolchain mismatch or duplicate key fails closed. Each allowed path must
  exist in the manifest, resolve to a YAML string scalar, and match the exact
  manifest path set; a mapping, list, null, extra path, or hard-coded substitute
  path fails before masking.
- Markdown owners are prose-only and have their pre-W2 raw hashes recorded;
  their changes are reviewed against this contract rather than presented as an
  executable-equivalence proof.

The two YAML mirrors must carry the same locked-group rule after the allowed
edits. Any algorithm, runtime behavior, or other parsed-manifest change is
outside W2 and fails acceptance.

## 4. Agent-facing correction

Remove statements equivalent to:

- a locked order must stay in `order.locked_vehicle_id`;
- never move any order whose `locked_vehicle_id` is non-null;
- `locked_vehicle_id` names a permanent target vehicle.

Replace them with one compact rule:

```text
Orders whose locked_vehicle_id is not None form one indivisible movable group.
Move all or none; after a move, preserve assignment consistency and every other
Warehouse feasibility constraint.
```

The prompt must not force the agent to add locked-group logic to every idea. It
only removes false prohibitions so the agent may study whole-group moves when
the hypothesis and source evidence justify them.

## 5. Directed no-LLM probe matrix

W2 adds a problem-owned one-shot probe artifact and focused tests. The probes
must not run inside proposal generation, DecisionFeatures, scheduling, or every
candidate evaluation.

| Probe | Expected result |
|---|---|
| complete group remains on its initial vehicle | feasible |
| complete multi-order group moves to a new vehicle ID | feasible |
| complete group merges with free orders | feasible |
| two complete locked groups merge | feasible |
| singleton locked group moves | feasible |
| two-order empty-string group survives Phase-2 initialization and moves whole | feasible |
| one group is split across two vehicles | H7 infeasible |
| only part of a group moves | H7 infeasible |
| order is lost, duplicated, or assignment disagrees | C0/C0a infeasible |
| complete move exceeds capacity | H1 infeasible |
| complete move mixes region | H2 infeasible |
| complete move exceeds pickup limit | H3 infeasible |
| complete Phase-1 move mixes category | H4 infeasible |
| hazard quantity exceeds the ordinary limit on a non-special vehicle | H5/H8 family, observed as H5 by current fail-fast ordering |
| exact `country,ship_method` amount limit is exceeded | H6 infeasible |

Every core positive and negative fixture must agree through:

1. the canonical Oracle;
2. adapter deserialize plus formal feasibility;
3. the fixed-candidate MILP feasibility procedure whenever the fixture is
   expressible by the current MILP.

MILP coverage is mandatory for multi-order whole movement, merge with free
orders, two locked groups merged, singleton movement, split and partial move,
the empty-string group, H5/H8, and H6. Any fixture the current MILP cannot
express must record a fixed contract-owned reason in its row; the implementation
may not silently choose `not_applicable`.

The MILP procedure is not an ordinary optimization run. It maps the candidate's
vehicle IDs in lexicographic byte order to contiguous slots `0..used-1`, sets
`K = max(compute_K(instance), used)`, and retains the existing prefix symmetry
rule. It then fixes every `x[i,j]`, every `y[j]`, and every `z[j,t]`: exactly
the candidate assignment is one, exactly the mapped prefix slots are used, and
exactly the candidate vehicle type is one on each used slot; every other value
is zero. For a Phase-2 fixture the epsilon value is the fixed candidate's exact
subcategory spread, so Phase-2 semantics do not accidentally re-enable H4.
Allowing the optimizer to replace the candidate with another assignment is
invalid evidence.

PuLP's projected `LpStatus` is diagnostic only and is never status authority.
For the pinned HiGHS backend, only native `HighsModelStatus.kOptimal` plus a
solver-returned incumbent that revalidates against every fixed `x/y/z` value
maps to `fixed_candidate_feasible`. Only native
`HighsModelStatus.kInfeasible` maps to `fixed_candidate_infeasible` and, by
definition, requires no incumbent. Native `kUnboundedOrInfeasible`, time or
iteration limit, interrupt, objective bound/target, model/solve/load error,
unknown status, unavailable solver, exception, or an optimal claim without a
valid incumbent maps to
`fixed_candidate_indeterminate`; any indeterminate result fails W2 rather than
being reported as infeasible. Each identity row records `K`, the vehicle-to-slot
map, all fixed-variable digests, and solver name/version/native status. Focused
negative tests inject every non-authoritative native status and prove it cannot
become feasible or infeasible evidence.
The current Oracle's H5 and H8 predicates overlap and H5 returns first; W2
preserves that executable meaning and treats them as one probe family rather
than manufacturing an unreachable H8 result.

The H6 fixture must contain a nonempty amount-limit mapping and the exact
`country,ship_method` key. The active 31-case population has empty amount-limit
mappings, so it cannot be cited as H6 coverage.

The probe report uses schema `scion.warehouse_locked_group_probe.v1`. Each
deterministic identity row contains the fixture ID and content SHA, exact
candidate assignment and vehicle types, expected constraint family, canonical

The planned W3 arms are treatment bundles, not a pure operator-only factorial:

| Arm | Existing lock eligibility |
|---|---|
| champion | baseline merge may move an intact locked group |
| destroy-only | baseline merge may move a group; R3 destroy keeps locked orders fixed |
| merge-only | R3 merge excludes locked sources and uses the old fixed-original check |
| cumulative | both R3 operators retain the conservative fixed-original eligibility |

W3 must keep these frozen arm bytes and label the comparison as a posterior

- lock-bearing versus lock-free case strata;
- intact-group count;
- whole-groups-moved count, defined as groups whose final vehicle differs from
  the frozen greedy-initial vehicle for the same `(case, seed)`, not runtime

## 8. Acceptance

W2 is accepted only when:

- all active problem-owned prose, including `scion/docs/reference/milp-model.md`,
  uses the closed origin-group meaning;
- no active prompt or operator contract says non-null means fixed-original;
- Oracle and adapter agree on the directed matrix, and the fixed-candidate MILP
  procedure agrees on its applicable positive and negative fixtures;
- all 31 W1-bound formal inputs and their greedy initial solutions remain
  feasible;
- the H6 directed fixture proves the exact nonempty-key behavior;
- the accepted W1 receipt and all four population digests are unchanged;
- every exact-protected source and R3 evidence hash in the preservation manifest
  remains unchanged;
- focused and adjacent tests, compileall, and `git diff --check` pass;
- two independent reviews report P0=0 and P1=0;
- no generic or agent-hot-path gate, budget, retry, cap, or truncation is added.

Only an accepted W2 implementation may unlock W3.
