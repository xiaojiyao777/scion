
## 5. TREE source-layout correction

The TREE builder signature gains the already-validated
`tree_receipt_source_reference` keyword immediately after `tree_receipt`.
Direct executes first and remains the sole owner of the reference's exact key,
type, canonical scalar and identity validation.  TREE must not repeat that
shape proof; it only reads the already-validated path member and owns this one
layout equality:

```text

  == authority_root_directory_reference.path / "tree.json"
```

Failure is exact:

```text

```

The top inventory builder passes the existing argument; no new open, stat,
read, decode or descriptor is introduced.  The direct helper remains owner of
cross-receipt equality: INSTALL, SEAL and PREFLIGHT must still name the same
TREE source reference.

The accepted indirect-snapshot design explicitly says that C2e does not
re-decode the TREE prepare manifest.  This correction therefore does not parse
`prepare_manifest` again and does not invent a fixed path for the prepare
manifest itself.  Its existing exact full reference and indirect observation
remain unchanged.  Binding the actual TREE source to the canonical authority
leaf closes the coherent external-TREE attack without a second historical
producer validator.

## 6. Complete authority identity closure

### 6.1 Top-builder result

`_build_h11_indirect_authority_inventory` remains the sole global
cross-domain alias owner.  Its return becomes:

```python
tuple[
    int,
    int,
    tuple[H11RootValidatedFifo, ...],
    tuple[H11RootIndirectAuthoritySpec, ...],
    tuple[tuple[int, int], ...],
]
```

The fifth value is `authority_identity_closure`.  It is built once in this
exact order:

1. the nine direct JSON source identities in existing slot/source order;
2. the three direct-only directory identities in existing order:
   harness-root, scenario-root, receipt-root;
3. every indirect spec identity in the already-frozen `indirect_specs` order.

The nine direct source pairs are projected as
`(int(dict(reference)["device"]), int(dict(reference)["inode"]))` only after
the direct helper has validated those canonical unsigned-decimal strings.  No
scalar validator is called a second time.  The three directory and every
indirect-spec pair are already exact integers and are transported unchanged.

The indirect segment already contains the other directory classes, all FIFO
classes, prepare/seal manifests, SEAL files and INSTALL targets.  Therefore the
combined tuple represents every direct or indirect semantic authority class
exactly once.  The top builder does not re-check pairwise uniqueness while
assembling this tuple: source-to-source uniqueness remains direct-owned,
indirect-to-indirect uniqueness remains domain/top-owned, and cross-domain
uniqueness remains in the existing top alias gates.  This step only transports
their already-accepted evidence in one fixed order.  No path is reopened and
no filesystem identity is recomputed here.

The existing top alias proofs execute before return.  The existing actual
observation proof still requires every indirect observation to equal its spec
before the closure enters the retained authority view.

## 7. Transaction non-ENOENT ABI

Each of the five existing seven-leaf loops retains its direct inline
`os.stat(..., dir_fd=self._slots[12].borrow(), follow_symlinks=False)` call.
The only control-flow change is:

```python
try:
    os.stat(...)
except FileNotFoundError:
    observed = "absent"
except OSError as exc:
    raise InstallerError(EXACT_LABEL) from exc
else:
    observed = "present"
```

The five exact labels are:

```text
cannot observe H11 transaction {role} before READY closure
cannot observe H11 transaction {role} before permit publication
cannot observe H11 transaction {role} after permit publication
cannot observe H11 transaction {role} before permit commit
cannot observe H11 transaction {role} after permit writer open
```

For all seven `_H11_TRANSACTION_LAYOUT` roles at all five sites:

```text
type(caught) is InstallerError
str(caught) is the exact phase/role label
caught.__cause__ is the injected OSError object
flow.state is FAILED_PREWRITE
no permit commit frame is written
```

`FileNotFoundError` continues to mean observed absence.  If absence contradicts
the expected phase, the existing semantic phase error remains the first
failure.

This correction does not change initial JSON/directory/FIFO `os.open`, source
binding stats, future-absence stats, publication syscalls or view revalidation.
In particular, the accepted C2a contract that an initial source-open
`OSError` is re-raised as the same raw object remains exact.
