# Scion v0.4 W3 H11 C2e frozen constructor-store oracle correction

状态：候选设计；固定哈希双审通过前不得修改 scanner 的 constructor-store
classification，也不得为通过现有 scanner 改写 production constructor model

## 1. 冲突与边界

本 correction 只消除一个已经在 clean implementation 中被复现的设计矛盾，不修改
H11 业务协议、23-slot topology、phase state、fault schedule、wire schema、indirect
authority class、cleanup composition 或 legacy-removal结论。

权威输入按优先级为：

1. `v0.4-w3-h11-atomic-ownership-flow-design-20260719.md` §4.1、§4.3、
   §4.5：五类 borrowed view、`H11RootAuthorityView` 与三个 phase-data type允许
   `@dataclass(frozen=True, slots=True, init=False)` 加 explicit keyword-only
   `__init__`或AST可证明的完全等价immutable实现；constructor 是各 field 唯一 Store；
2. `v0.4-w3-h11-c2e-implementation-oracle-design-20260720.md` 固定 SHA-256
   `a30f8858873c69d8d2e34b3827325f6c34ae09e1096e43b0048848283f7ffd7b`；
3. accepted implementation baseline commit `c7c7843a8257efd1d5e1ee88582fdd4353a7ccd0`。

Python frozen dataclass 的 explicit `init=False` constructor 不能用普通
`self.field = value`；它必须以 `object.__setattr__` 完成初始化。原 C2e oracle
§3.4 把任意 `object.__setattr__` 写成失败，同时 §5.3 又没有给 exact constructor
Store 一个 classification，因此与 base 的 normative constructor ABI 不可同时满足。

冲突解决方向冻结为：保留 base constructor model；只给下面 exact constructor
field Store 一个窄 classification。任何 constructor 外、表外 class、表外 field、
重复、条件化、动态 field 或非参数 value 的 `object.__setattr__` 仍 fail closed。
本 correction为当前 C2e implementation明确选择 base允许的 dataclass branch并进一步
窄化为§2 exact九类/70 Store；“完全等价实现”不在本候选接受面，若以后选择必须先有
新的fixed design与scanner rule，不能自行替换。

## 2. `FROZEN_CONSTRUCTOR_STORE` narrow rule

C2e `H11ResolvedCall.target_kind`不扩展。exact constructor Store 记录为：

```text
target_kind = "pure-value"
canonical_target = "builtins.object.__setattr__"
rule_id = "FROZEN_CONSTRUCTOR_STORE"
```

这里的 `pure-value` 表示“不持有 filesystem/process/FD/native/data-codec 或 lifecycle
capability”，不是允许一般 mutation。`builtins.object.__setattr__`加入 §5.3 name
closure，但只能由本节 shape rule分类；普通 pure allow-set lookup 不能单独授权它。
它不进入 §6 sensitive ledger、不生成 runtime boundary，也不增加 fault owner。

### 2.2 Exact constructor and call shape

每个表中 class 必须同时满足：

```text
@dataclass(frozen=True, slots=True, init=False)
explicit __init__
first parameter exact self
all remaining parameters keyword-only
no default / *args / **kwargs / positional-only / decorator other than dataclass
return annotation exact None
```

本表class还必须通过§2.3 `EXACT_NOMINAL_CONSTRUCTION` common proof；不能只因qname
命中或dataclass decorator存在就推断constructor result。

每个 field 只允许一次 exact call：

```python
object.__setattr__(self, "<literal-field-name>", <exact-constructor-parameter>)
```

call必须有三个 positional arguments、零keyword/starred；receiver exact imported
builtin `object`且module/class/local未shadow；第一参数 exact `self`；第二参数是本表
对应 literal field；第三参数必须是同一 constructor 的 exact parameter Name。

唯一 spelling map为：

```text
_flow <- flow
_slot <- slot
_parent_slot <- parent_slot
all other fields <- same-spelled parameter
```

所有 identity/type/value gates 必须在第一条 Store 前完成；70条 Store各自在所属
constructor中形成一个无 branch/loop/try/with/lambda/comprehension/callback 的连续
suffix。suffix 内除本规则 Store外只能有下一 field Store或 implicit return；不得在
Store间调用 `_fail`、helper、property、syscall或任意可能失败的 call。

constructor annotation field set、keyword-only parameter set、literal field set与
Store set四者必须exact相等；annotation order、parameter order与Store order必须等于
§2.1。任一缺失、额外、重复或重排失败。

`self`与全部constructor parameter还必须通过§2.4 shared whole-function binding
inventory；除parameter binding本身外exact zero other binder/Store/Del。
因此 caller传入的exact value与Store使用的Name是同一binding；constructor内不得把
`flow/slot/view/predecessor/self`替换为equal或foreign object。
同一个symbol-table binding inventory也适用于`PHASE_CURSOR`的`self/phase_data`与
`ONE_ASSIGN` local；不是只扫描`Name(ctx=Store)`的语法近似。

### 2.3 `EXACT_NOMINAL_CONSTRUCTION` common proof

本节只管internal `M.<Class>` nominal provenance；external/builtin class/API仍只由原
C2e oracle的`IMPORT`/`LITERAL_CONTAINER`/pure rule管理，不因本closed set失效。
凡scanner把internal class-qualified constructor、generated constructor、factory final
constructor或slot/Flow constructor结果授予exact nominal provenance，target class都必须
在以下closed set并逐类通过同一结构证明：

```text
H11OwnedFdSlot
H11RootAuthorizationFlow
H11RootDirectoryView
H11RootFifoView
H11RootJsonSourceView
H11RootPresentOutputView
H11RootPublicationView
H11RootAuthorityView
H11RootAuthorityPhaseData
H11RootReadyPhaseData
H11RootPermitPhaseData
H11RootClosedPartition
H11RootCommitReceipt
H11RootDirectoryReference
H11RootFifoReference
H11RootIndirectAuthoritySpec
H11RootNamedStagingPlan
H11RootObservedPathIdentity
H11RootPrePermitBarrier
H11RootRolePath
H11RootTransactionState
H11RootValidatedFifo
```

每个exact ClassDef必须：

- zero explicit base、zero metaclass/其他class keyword；
- zero custom `__new__`、`__post_init__`、`__init_subclass__`、`__class_getitem__`、
  `__mro_entries__`；zero explicit `__getattribute__`, `__getattr__`, `__setattr__`,
  `__delattr__`, `__get__`, `__set__`, `__delete__`, `__set_name__`；
- Flow与slot zero decorator；§2.1九类exact一个base-frozen dataclass decorator；其余
  generated leaves exact一个direct imported stdlib `dataclass` decorator：keyword set只能
  是`{frozen=True, slots=True}`或`{frozen=True, slots=True, init=True}`，两种AST均归一为
  logical `(frozen=True, slots=True, init=True)`；zero positional/star/dynamic value、
  `init=False`、其他keyword、second decorator与explicit `__init__`；
- class annotation fields不绑定custom descriptor value；base已冻结的property/explicit
  method closure之外zero descriptor/factory；
- ClassDef body statement只能是base/oracle已冻结的ordered field `AnnAssign`、
  slot的exact `__slots__` Assign、已冻结qname/signature/decorator的explicit
  `FunctionDef`与optional docstring Expr；zero其他statement/node kind。上述禁止
  dunder即使伪装成普通explicit method也失败；
- 全22个ClassDef及本节/§3/§4用于provenance的constructor、phase method、
  factory method全部`type_params == []`；
- module symbol由该ClassDef唯一binding，按§2.4对module scope证明zero replacement、
  shadow、monkey-registration或attribute assignment；explicit class methods也zero
  post-definition replacement。

这份proof同时保证 direct optional frozen field的两次普通attribute load经过default
object dispatch并返回同一single-Store slot value，也保证factory final
`H11RootDirectoryReference(...)`等实际产生exact target实例，而非foreign/proxy/coroutine。
closed set外的class call不能从名字或annotation获得nominal provenance；新增class必须先
改fixed design。这个“closed set外”仅指internal `M.<Class>`，不覆盖原oracle
已分类的external/builtin API。

### 2.5 Global rejection

reachable closure 中除 §2.1 exact 70条外：

```text
setattr(...) == 0
object.__setattr__(...) == 0
__dict__/descriptor mutation == 0
field Store/Del outside exact constructor == 0
```

因此原 C2e §3.4 的 `object.__setattr__` rejection 应解释为“除本 correction exact
constructor Store 外”。不得把本规则推广到 `H11OwnedFdSlot`、Flow、reference、
receipt、spec、observation、validated FIFO、manager 或任何以后新增 class。

## 3. `FROZEN_FIELD` provenance correction

`FROZEN_FIELD`仍不是 type-wide allowlist。scanner只有在下列全部证据成立后才能解析
field-chain method：

1. owning class 在 §2.1 exact closure；
2. 每层 field annotation给出exact nominal class；
3. 每层 field 的唯一 Store由 §2 `FROZEN_CONSTRUCTOR_STORE`证明；
4. owning constructor 的全部 reachable callers都在 base caller table，且每个internal
   nominal field传入的是同一binding/object，其source只能是以下closed union：
   `SELF_RECEIVER`同一Flow、`LITERAL_SLOT`、通过§2.3的direct/generated
   constructor结果、`ONE_ASSIGN`绑定的§4 closed factory exact result、
   `PHASE_CURSOR`前驱或base acyclic replacement graph中已证明的predecessor
   `FROZEN_FIELD`，以及每个element均由前述constructor证明且保持identity的
   fixed tuple/container member；
5. constructor外对该field零Store/Del/mutation；
6. chain target是annotation nominal class的explicit method，而不是property返回、
   annotation-only guess、dynamic registry或type-wide method name。

仅有 class/field name mapping 不构成authority。foreign-flow、equal-but-distinct slot/
view/predecessor、unknown constructor caller或 value copy 必须失败。
两条reference edge必须显式证明：`DirectoryReference.decode`/
`FifoReference.decode` exact factory result各自只经一个`ONE_ASSIGN` local，同一
object传入对应view constructor的`reference=`，随后才能解析
`self.reference.prove(...)`；copy、redecode、equal instance或foreign factory result均不授权。

### 3.1 `PHASE_CURSOR` predecessor provenance

phase-data predecessor不能只靠annotation或一次local的名字获得authority。scanner增加
一个只适用于 base §4.5.3 closed replacement graph 的`PHASE_CURSOR` provenance：

```text
_consume_ready_commit:
  phase_data = self._phase_data
  next statement: if self._state is not AUTHORITIES_RETAINED or type(phase_data) is not H11RootAuthorityPhaseData: _fail(EXACT_LITERAL)

_publish_permit:
  phase_data = self._phase_data
  next statement: if self._state is not READY_CONSUMED or type(phase_data) is not H11RootReadyPhaseData: _fail(EXACT_LITERAL)

_commit_permit:
  phase_data = self._phase_data
  next statement: if self._state is not PERMIT_PUBLISHED or type(phase_data) is not H11RootPermitPhaseData: _fail(EXACT_LITERAL)
```

三个method都使用 base exact local spelling `phase_data`；method、expected state与
nominal type exact如上。assignment必须是各method第一条normal statement、simple Name
target、RHS exact `self._phase_data`；下一statement必须是上述 combined direct state+
type gate，条件顺序exact，失败branch只有 `_fail`。local在whole method零其他binder/
Store/Del；所有由它派生的field read/call必须由该combined gate支配，wrong state或wrong
type时零derived read/call/borrow/syscall。
method receiver `self`也必须由原 C2e `SELF_RECEIVER`加本 correction shared binding
inventory证明whole-method除parameter定义外零binder/Store/Del；gate后不得换成第二Flow。

`_consume_ready_commit`必须把同一Name object传给
`H11RootReadyPhaseData(authority_data=phase_data, ...)`；`_publish_permit`必须把同一
Name object传给`H11RootPermitPhaseData(ready_data=phase_data, ...)`。禁止flatten/copy/
aggregate/conditional replacement。`_commit_permit`没有下一phase constructor；它对
`phase_data`只读，零Store/Del/escape，只能沿 base §6.4 exact field chain构造receipt并
完成commit。

该rule只有在 scanner同时证明 base §4.5.3 全部事实时成立：Flow constructor把
`_phase_data`唯一初始化为`None`；C2a/C2b/C2c分别且只分别写入 exact
Authority/Ready/Permit data；每次replacement紧邻对应success transition；terminal、
`_transition`、`_mark_*`与其他method零replacement；三phase method的entry state/type
gate和唯一caller exact。任一表外writer、错序、非紧邻transition或第二Flow caller使
三个local全部失去provenance。

`PHASE_CURSOR`不是任意union narrowing：其他attribute、其他local spelling、普通
`type(x) is T`、annotation、assert、match/cast或state-dependent guess均不授权。

### 3.2 Optional frozen parent narrowing

`_parent_slot`是唯一允许的optional frozen field annotation：
`H11OwnedFdSlot | None`。它不获得一般union method authority。只有五类 base borrowed
view的explicit `revalidate` 中、且 constructor/caller/value已由 §2/§3证明 exact
literal pair时，scanner可使用`FROZEN_OPTIONAL_PARENT`：

```text
if self._parent_slot is None:
    exact no-parent Path.lstat branch
else:
    exact parent-bound os.stat(..., dir_fd=self._parent_slot.borrow(), ...)
```

同一个 frozen field load的`.borrow()`只在else branch取得`H11OwnedFdSlot` provenance，
且必须受该direct `is None` branch dominance；no-parent branch、join point或nested
callback中均无authority。不得为了scanner复制到local、缓存或二次读取其他parent
source；field的single-Store immutability使两次direct load保持同一object。
两个branch的path/stat shape、合法 view/slot pair、state gate与caller/count继续由 base
§4.3/§4.4.2逐行冻结，不能按role/path/runtime registry选择parent。其他optional field、
`isinstance`/truthiness/assert/match/cast或caller-supplied union一律不narrow。

no-parent branch closure不是五类通配：

| view class | exact None constructor pairs | `parent_slot is None` branch |
| --- | --- | --- |
| `H11RootDirectoryView` | self slot `15` formal-root only | exact canonical `Path.lstat` |
| `H11RootJsonSourceView` | self slots `5,16,17,18,19,20,21` only | exact canonical `Path.lstat` |
| `H11RootFifoView` | none | `_fail(EXACT_LITERAL)`，零FS call |
| `H11RootPresentOutputView` | none | `_fail(EXACT_LITERAL)`，零FS call |
| `H11RootPublicationView` | none | `_fail(EXACT_LITERAL)`，零FS call |

Directory其余 `14,13,12,11,10,9`、JSON `22,6`、FIFO `8,7`、Present `4,3`与
Publication `2` 都必须命中 base exact non-None parent pair并只走else parent-bound
`os.stat`。scanner必须把constructor literal-pair provenance与branch逐instance结合，
不能因为同class存在一个None pair就授权其他instance/no-parent lstat。

## 4. Closed factory-result provenance

为使 direct class factory 的一次 local binding 可继续使用 nominal explicit method，
`ONE_ASSIGN`增加以下 closed return table：

```text
H11RootDirectoryReference.decode -> exact H11RootDirectoryReference
H11RootFifoReference.decode -> exact H11RootFifoReference
H11RootCommitReceipt.ready_committed -> exact H11RootCommitReceipt
H11RootCommitReceipt.permit_committed -> exact H11RootCommitReceipt
```

每个 factory 必须是表中 exact class-qualified explicit method；scanner还必须验证其
AST node exact为同步`ast.FunctionDef`，不是`AsyncFunctionDef`，整个method零
`Yield`/`YieldFrom`；
唯一 `Return` 是function body最后一条top-level statement，value为对应
class-qualified generated constructor；其他nested/top-level `Return`为零，因而没有
bare return、implicit normal fallthrough、分支漏return或second return。零 `cls(...)`、
subclass/registry/callback/union/optional return。local name仍服从 whole-function
`ONE_ASSIGN`：一次 simple Name assignment且所有其他binder/Store/Del为零。

四个method的decorator/signature还必须exact为：

```text
@classmethod
H11RootDirectoryReference.decode(cls, value: H11RootFrozenJsonValue, *, label: str)
  -> H11RootDirectoryReference

@classmethod
H11RootFifoReference.decode(
  cls, value: H11RootFrozenJsonValue, *, label: str, require_root: bool,
  process_euid: int, process_egid: int,
) -> H11RootFifoReference

@classmethod
H11RootCommitReceipt.ready_committed(
  cls, fifo: H11RootFifoView, payload: bytes,
) -> H11RootCommitReceipt

@classmethod
H11RootCommitReceipt.permit_committed(
  cls, fifo: H11RootFifoView, payload: bytes,
) -> H11RootCommitReceipt
```

只有一个exact `@classmethod` decorator；首参exact `cls`且body不得调用它；参数顺序、
positional/keyword-only分界、annotation与return annotation exact；零default、
positional-only、variadic、overload或第二decorator。forward-reference spelling可有/无
引号，但解析后的logical qname必须exact。

本表不授权任意 annotation、classmethod或同名 `decode/create/from_*`。原 §3.7 support
return table保持不变并与本表取union。

## 5. Scanner acceptance tests

除原 adversarial corpus外必须新增：

- 九个exact class的70条positive Store与完整 reachable caller/value provenance；
- 每类至少一个 missing/extra/reordered/duplicate/dynamic-field/wrong-value negative；
- `self`及每种constructor parameter的Assign/AugAssign/walrus/for/with/except/
  destructure/import/Del、match sequence/as/star/mapping-rest、same-scope function/class/
  async-function name与TypeAlias rebinding negative；
- Store出现在gate前、Store间call、conditional/loop/try/comprehension negative；
- ordinary class、foreign constructor、constructor外 `object.__setattr__` negative；
- custom base/metaclass/`__new__`/descriptor/factory hook negative；
- generated dataclass省略`init`与literal `init=True`两个positive，以及`init=False`、
  dynamic init、extra keyword、shadowed/aliased dataclass与`__post_init__` negative；
- `setattr`、shadowed `object`、aliased `object.__setattr__` negative；
- equal-but-distinct flow/slot/view/predecessor value negative；
- closed factory table四个positive，以及 `cls(...)`、shadow、second return type、
  missing final return、bare return、branch fallthrough、decorator/signature drift、
  async/`Yield`/`YieldFrom`、second local binding、for/with/except/walrus/destructure
  rebinding negative；
- 三个`PHASE_CURSOR` positive，以及wrong local/type/method、非首条assignment、非紧邻
  combined state+type gate、wrong expected state/condition order、gate后置/derived-use前置、
  普通union narrowing、表外`_phase_data` writer、replacement/transition非紧邻、commit
  local escape与flatten/equal-but-distinct predecessor negative；
- 三phase method `self`的assign/match/definition/type-alias等shared binder negatives；
- PHASE/ONE_ASSIGN local的全部match capture与same-scope definition/type-alias binder
  negative；
- generic class/method/factory/type-alias的TypeVar/ParamSpec/TypeVarTuple `type_params`
  negative，并证明tests/scanner的binder constant对§2.4 exact equality；
- decode→ONE_ASSIGN→view constructor→`self.reference.prove` 两条positive，
  以及copied/equal/foreign/redecoded factory result negative；
- `FROZEN_OPTIONAL_PARENT` direct-field parent/no-parent positive，以及local cache、
  truthiness/assert/cast、join-point borrow、wrong branch、dynamic parent、foreign pair、
  Fifo/Present/Publication None-lstat与其他optional field negative；
- 证明所有 reachable AST Call仍exact一条 resolved record，constructor Store没有从
  `reachable_ast_call_count`中被隐藏。

scanner不得为了通过 production：

- 信任 type annotation而不追 constructor Store/caller/value；
- 把所有 frozen dataclass、所有 `object.__setattr__`或所有class method加入allowlist；
- 删除/忽略 constructor Call；
- 用绝对line、candidate打印graph或runtime object identity生成expected；
- 要求 production 把 pure/frozen field chain拆成重复 local噪声。

## 6. 实施与接受

1. 本文固定 SHA-256并由两份独立审计确认 P0/P1/P2=0；
2. test-only scanner先实现 §2-§5 adversarial corpus；
3. production constructor model保持 base exact ABI，不因旧scanner改写；
4. scanner回到 `unresolved == multi_target == unclassified == ()` 且
   `resolved_call_count == reachable_ast_call_count`；
5. 再继续 legacy owner removal、production fault matrix与双Python回归。

本文不授权 budget、cap、timeout、retry、skip/xfail、compatibility alias、第二owner、
第二FD seam或弱化 fault coverage。冲突时先修设计并重新固定哈希，不得让 candidate
定义自己的oracle。
