# v0.4 CVRP Baseline-Strength Contrast

*Date: 2026-06-13*
*Status: Phase A accepted; Phase B matched campaign design next*

## Purpose

This contrast tests whether Scion's weak CVRP promotion record is partly caused
by the current strong ALNS+VNS champion leaving too little measurable headroom
for generated research mechanisms.

The comparison is not a raw solver-quality contest between unequal baselines.
It asks whether Scion can conduct more effective evidence-backed research from
two different starting research surfaces:

- Control baseline: current ALNS+VNS champion.
- Contrast baseline: copied ALNS-only champion with VNS disabled.

## Boundary

The current canonical CVRP baseline must remain intact. The ALNS-only arm must
be a separate problem-owned run-root/champion snapshot with only the baseline
configuration changed:

- Current switch: `USE_VNS=True` in
  `scion/problems/cvrp/policies/baseline_modules/config.py`.
- ALNS-only variant: copied snapshot with `USE_VNS=False`.

Do not delete VNS code, do not mutate the canonical formal baseline in place,
and do not make ALNS-only a hidden replacement for ALNS+VNS. Both baselines
must be explicitly labeled in prompts, summaries, run metadata, and reports.

## Phase A - No-LLM Characterization

Run this before any agentic campaign.

Inputs must match across both baselines:

- Same repo commit.
- Same formal problem spec, protocol, split, and seed ledger.
- Same selected cases and seeds.
- Same protocol-resolved runtime limits.
- Same champion snapshot except for `USE_VNS`.

Required outputs:

- Raw objective quality distribution.
- Runtime profile and budget-hit behavior.
- A/A MDE and false-pass estimate for each baseline.
- Case-level variance and seed/RNG sensitivity.
- Headroom versus BKS where available.
- Telemetry phase evidence showing whether VNS activity is absent in the
  ALNS-only variant and present where applicable in the ALNS+VNS control.

Phase A exit:

- A report records config diff, snapshot paths, protocol/split/seed hashes,
  selected cases/seeds, runtime policy, A/A outputs, and whether each baseline
  has enough measurement power for the intended effect scale.
- If ALNS-only is much lower quality but has larger measurable headroom, the
  later interpretation must say so directly. Easier research is not the same as
  better final solver quality.

## Phase B - Matched Scion Campaigns

Only launch after Phase A is accepted.

Both arms must match on:

- Problem package, selected split/cases/seeds, protocol, and runtime budgets.
- Model and local provider settings.
- Measurement-governance setting.
- Prompt-context mode.
- Round budget and early-stop policy.
- Postrun acceptance scripts.

Suggested first campaign shape:

- 3 repeats per baseline.
- 8 effective rounds per cell.
- Formal screening protocol with protocol-resolved runtime limits.
- `measurement_governance=on`.
- Compact diagnostics prompt baseline unless a newer accepted prompt baseline
  replaces it.

## Primary Metrics

Report results relative to each baseline's own A/A MDE and headroom:

- Validation/frozen/promotion evidence above that baseline's MDE.
- Branch depth counted by distinct formal hypotheses, not artifact retry rows.
- Same-mechanism follow-up and mechanism-family transfer.
- Proposal/code failure rate and source-identity health.
- Runtime/fresh-replay noise rate.
- Cost per effective protocol row and cost per accepted research insight.

## Interpretation Rules

- If ALNS-only produces more promotions, the first conclusion is that the
  research surface is easier or has more measurable headroom, not that Scion has
  solved CVRP under the stronger ALNS+VNS baseline.
- If ALNS+VNS remains low-power while ALNS-only becomes measurable, v0.4 should
  treat baseline strength as an experimental variable in Scion value studies.
- If both baselines remain below MDE, the next repair is measurement/protocol
  design, not more lifecycle tuning.
- If ALNS-only degrades final quality too much, it can still be useful as a
  controlled research-surface ablation, but not as a production champion.
