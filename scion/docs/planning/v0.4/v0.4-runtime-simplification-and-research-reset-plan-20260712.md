## Objective

Restore Scion as a maintainable automatic research framework that spends model
and experiment effort on algorithmic hypotheses rather than prompt history,
gate dialect, compatibility projections, and telemetry-shaped repairs.

This plan preserves the v3 outer pipeline:

```text
Hypothesis -> Code -> Contract -> Verification -> Protocol
           -> Safe Feature Extractor -> deterministic Decision
```

It refactors the proposal runtime and evidence projections around that
pipeline. It does not weaken promotion criteria or move problem semantics into
generic core.

## Non-Goals

- no successor56 while this plan's P0 slices are open;
- no broad v0.5 governance matrix;
- no rewrite of Protocol or Decision during prompt/runtime extraction;
- no migration to Pi JSONL sessions or Claude Code product architecture;
- no new generic helper/common/utils dumping ground;
- no large-file split that increases total fragmentation without a deletion
  plan.

## Acceptance Outcomes

The refactor is accepted only when all of the following are true:

1. a single immutable prompt snapshot is the input to manifest, trace, and
   provider call;
2. current-stage hypothesis and code prompts receive no new budget,
   truncation, top-N selection, or omission policy;
3. host-known audit metadata does not require another LLM call;
4. proposal failure, infrastructure failure, and research iteration are
   separate durable state transitions; no hidden retry is counted as the same
   attempt;
5. hard gates protect execution/integrity/promotion, not prose style;
6. telemetry distinguishes attempt, state transition, direct effect, and
   associated downstream outcome;
7. successor evidence is loaded from durable data with scope/expiry, not
   compiled into prompt/gate source;
8. the default research path is the narrow v3 hypothesis/code kernel;
9. resume reproduces proposal, target, context digest, and transition state;
10. proposal/core public surfaces and compatibility modules have a measured
    net reduction;
11. one open, non-target-bound CVRP campaign reaches Protocol without a
    mechanical quality-gate loop;
12. solver evidence is still judged by full-solver Protocol.

## Phase R1: One Prompt Turn Snapshot

Purpose: remove double rendering without changing prompt content.

Current seam:

```text
build prompt context
  -> render once for manifest
  -> render again in CreativeLayer for provider
```

Introduce a frozen `PromptTurnSnapshot` at the existing prompt projection
owner. It contains:

```python
@dataclass(frozen=True)
class PromptTurnSnapshot:
    render_kind: str
    system_blocks: tuple[Mapping[str, Any], ...]
    user_prompt: str
    context_digest: str
```

The real AgenticProposalSession creates it after dynamic retry/observation
context is complete. Manifest, trace, and provider call consume the same
snapshot. Existing fake creative layers keep a compatibility fallback during
this phase.

Constraints:

- do not change content or gate policy;
- do not add a new package for four types;
- delete the duplicate manifest renderer;
- merge `prepared_obligations.py` into the owning projector when its call sites
  are migrated;
- finish with no net-new Python files.

Acceptance:

- system blocks and user prompt remain byte-identical;
- prompt hashes remain identical;
- render count changes from two to one per real hypothesis/target-intent call;
- all target-intent, quality-retry, grounding, and prompt-manifest tests pass.

## Phase R2: Lossless Context Ownership and Inventory

Purpose: make prompt ownership and duplication measurable without changing the
evidence seen by the model. This phase is observational and byte-preserving.

Create one versioned context inventory alongside the existing prompt with:

- every provider-visible section in order;
- source owner and durable source ref;
- exact content digest and character count;
- duplicate digest groups and nested-source relationships;
- current question, branch, champion, target, and proposal-phase provenance;
- trace/manifest refs proving which content reached the provider.

Do not remove, select, summarize, truncate, or reorder provider-visible content
in this phase. In particular, do not add character/token budgets, keep only the
latest N records, or replace content with omission receipts. The v0.4 repair
does not introduce a bounded context projection; any future reduction study is
outside this task and would require separate preregistration.

Permitted implementation work is limited to consolidating renderer ownership
behind byte-identical output and emitting the inventory/duplicate map.

Acceptance:

- all provider-visible content, order, cache markers, and hashes remain
  byte-identical;
- inventory section counts and digests match prompt manifest/trace;
- duplicate groups identify repeated evidence without removing it;
- successor55 replay yields the same prompt bytes and call sequence;
- any later context reduction is a separate, preregistered experiment rather
  than part of this structural refactor.

## Phase R3: Proposal Governance Reset

Purpose: align gates with v3 responsibilities.

Hard gates:

1. `ExecutionContractGate`
   - schema, paths, patch shape, API/interface, import/security, resource policy.
2. `ExperimentIntegrityGate`
   - executable candidate, feasibility/objective/state isolation, valid
     measurement and attribution boundary.
3. `PromotionIntegrityGate`
   - comparable evidence, split/seed/protocol identity, lineage durability,
     promotion inputs.

Everything else is either host projection or soft research diagnostic.

Tasks:

- remove free-text keyword matching for algorithmic sufficiency;
- host-fill material-difference and branch-lesson audit records where possible;
- reduce hypothesis schema toward the v3 core plus a small typed evidence plan;
- remove exact CMT2/CMT4 hypothesis wording; preserve priority cases in the
  problem protocol;
- merge duplicate proposal-quality/Contract/pipeline checks;
- make a schema failure terminate that durable provider attempt; any later call
  is an explicit new attempt, not a hidden local repair loop;
- preserve explicit rejection of wrong owner, forbidden path, unsafe APIs,
  known unchanged mechanism identity, and untrustworthy measurement.

Acceptance:

- paraphrase/property tests produce the same decision for the same structure;
- missing host-known metadata triggers no model call;
- valid hypotheses pass one approval boundary;
- reviewed unchanged mechanisms still block through typed identity and scoped
  evidence, not substring matches;
- proposal repair never counts as a research iteration.

## Phase R5: Narrow Proposal Runtime Kernel

Purpose: return the default path to the v3 two-round design.

Default runtime:

```text
deterministic host source retrieval
  -> hypothesis LLM
  -> one authoritative hypothesis Contract decision
  -> code LLM
  -> ProposalEnvelope
```

Each LLM arrow is one durable provider attempt. A schema, provider, or typed
edit failure ends that attempt with its real category; Scion does not hide a
second call inside a local repair loop. The existing agentic planner remains an
explicit ablation only while full-context parity is established, then must
either be retired or justify a separate, preregistered comparison.

Introduce or consolidate these owners without creating more fragments:

```text
proposal/runtime       kernel, state, events, failure policy
proposal/context       snapshot and projector
proposal/tools         definitions, active policy, executor
proposal/session       durable journal projection
proposal/artifacts     single sink facade
```

The current 30 top-level `agentic_session*.py` files must converge into these
owners through an explicit route-and-delete ledger. Do not add a new
compatibility facade or a second durable state graph.

Acceptance:

- one hypothesis and one code main call per candidate by default;
- no LLM tool-selection call on the default path;
- active tools are phase-minimal;
- invalid tool calls never execute, and safe observations are not truncated;
- side-effect tools run sequentially;
- observer failures cannot change scientific state;
- infra failure, proposal failure, and research iteration are separate
  transitions; any later provider call has a new durable attempt identity.

Acceptance:

- missing dependencies fail clearly rather than returning empty fallbacks;
- new experiment evidence requires no prompt/gate source edit;
- production prompt/gate modules contain no successor chronology constants;
- proposal/core Python file count and compatibility surface show a documented
  net reduction.

## Phase R7: Controlled Validation

Validation sequence:

1. replay stored prompts and historical proposals offline;
2. compare old/new gate outcomes on a curated set of valid, unsafe, duplicate,
   and paraphrased proposals;
3. run deterministic unit/integration suites;
4. run a short non-target-bound dry campaign with Protocol disabled only for
   runtime validation;
5. run one short formal CVRP campaign with the full Protocol;
6. only then decide whether broader governance ablation moves to v0.5.

The formal campaign must demonstrate:

- no exact prepared mechanism binding;
- no mechanical gate retry loop;
- a coherent problem-owned algorithmic hypothesis;
- a maintainable patch with named ownership;
- valid, typed telemetry;
- complete screening evidence including priority cases;
- correct full-solver decision, whether positive or negative.

Promotion-grade solver improvement remains the v0.4 solver goal. If the
refactored agent produces attributable mechanism effects but full-solver
results remain diluted, the next action is an explicit measurement/baseline
review, not another prompt gate.
