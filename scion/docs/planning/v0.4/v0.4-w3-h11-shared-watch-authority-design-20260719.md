## 1. 决策摘要

C3a0 必须把 H11 的四个 watched parent 收敛到一个独立的 `H11AuthorityWatchSet`：它只创建一个阻塞式 inotify instance，在该 instance 上注册四个 watch，并从唯一内核队列按原始读取顺序生成唯一、单调递增的事件 ordinal。

当前的 `AuthorityDirectoryWatch` 必须删除，不能保留兼容层。四个独立 inotify instance 即使最终被拼进同一个 Python list，也不能证明跨 parent 的真实事件全序；其所谓“全局顺序”只是调用者选择 drain 顺序后生成的观察顺序。C3a0 的职责是修正这个证明边界，而不是接入 production。

C3a0 明确不修改 `Harness.run()`，不发布 READY，不从 production FIFO 消费或验证真实 PERMIT receipt，不发布 ledger，不释放 FIFO 或 acquisition，不进入 final/final-freeze，不调用 manager/systemd，不修改 H8，也不修改 TASK/current-state。以上工作必须由后续独立切片在 C3a0 验收后完成。C3a0 仅以 typed test fixture 冻结 external committed-final binding 的输入边界。

若当前实现、旧测试或辅助 helper 与上述文档冲突，C3a0 必须删除冲突结构，不能增加兼容分支、fallback 或双轨 authority。

### 2.2 C3a0 的唯一目标

C3a0 只建立一个可独立证明的事实：四个 H11 parent 的受控事件来自同一个 inotify 队列，并且 ledger ordinal 严格等于该队列交付的原始事件顺序。

它不声称：

- production 已经使用这条 authority；
- READY、PERMIT、ledger 或 release 生命周期已经闭合；
- H11 整体已经完成；
- manager/systemd 或 H8 已经与该 authority 集成。

## 3. 当前问题证明

### 3.1 四个独立队列只提供四个局部序

当前 `AuthorityDirectoryWatch` 每个实例调用一次 `inotify_init1`。四个 parent 因而分别绑定到四个独立内核队列：

- `formal-root` → queue F
- `input-root` → queue I
- `receipt-root` → queue R
- `scenario-root` → queue S

每个队列内部能够证明自己的先后关系，例如 S 中 READY rename 发生在 PERMIT rename 之前。但内核没有在 F/I/R/S 之间提供共享序号，也没有向用户态暴露可比较的跨 instance 时间戳。

### 3.2 调用 drain 的顺序可以伪造“全局”顺序

设真实文件系统动作依次为：

1. `scenario-root/PERMIT_READY.pending` CREATE；
2. `formal-root/frozen` CREATE；
3. `scenario-root/PERMIT_READY.pending` MOVED_FROM；
4. `scenario-root/PERMIT_READY.json` MOVED_TO。

如果调用者先 drain F、后 drain S，用户态 ledger 会得到：

1. frozen CREATE；
2. READY pending CREATE；
3. READY pending MOVED_FROM；
4. READY final MOVED_TO。

如果调用者先 drain S、后 drain F，ledger 又会得到另一种顺序。两种结果都保留了各自队列的局部序，却都不能证明真实跨 parent 顺序。ordinal 是 drain 调用产生的，不是共享 observation authority 产生的。

因此，以下做法均不能修复问题：

- 固定调用 `drain(parent_role)` 的 parent 顺序；
- 在四个 drain 结果上按 Python 接收时间排序；
- 增加用户态时间戳；
- 在测试里让写入与 drain 交替，从而人为得到期望顺序；
- 事后按预期协议顺序重排事件。

这些做法只能制造确定输出，不能证明真实观察全序。

### 3.3 单一共享队列为何满足证明边界

一个 inotify instance 可以注册多个 watch。四个 parent 的事件进入同一个内核队列，`read()` 返回的原始记录序列就是该 authority 可观察到的唯一顺序。C3a0 只按该字节流逐条解析、验证并编号，不允许调用者选择 parent，也不进行重排。

这提供的是“单一 observation authority 的交付全序”，不是对文件系统内部物理时钟的额外推断。H11 所需的证据边界正是前者：所有受控 parent 必须通过同一 authority 被观察和编号。

## 4. Closed parent/leaf vocabulary

### 4.1 四个 parent role

共享 watch set 必须且只能注册：

1. `formal-root`
2. `input-root`
3. `receipt-root`
4. `scenario-root`

注册顺序固定为以上顺序。parent 路径不得重新解析；每个 watched parent 必须先通过 5.1 冻结的 canonical retained ancestor chain proof，再经该 chain 最后一项 parent directory descriptor，以 `/proc/self/fd/{fd}` 注册 watch。

### 4.2 二十个允许的 `(parent_role, leaf)`

映射键必须是完整二元组 `(parent_role, leaf)`，不能只按 leaf 分派。

| parent role | leaf | semantic role |
| --- | --- | --- |
| `formal-root` | `frozen` | `frozen-root` |
| manifest-declared output parent | manifest 中 `closer-properties` 输出路径的直接 leaf | `closer-properties` |
| manifest-declared output parent | manifest 中 `exec-stop-post-properties` 输出路径的直接 leaf | `exec-stop-post-properties` |
| manifest-declared output parent | manifest 中 `final` 输出路径的直接 leaf | `final` |
| manifest-declared output parent | manifest 中 `final-closer-properties` 输出路径的直接 leaf | `final-closer-properties` |
| manifest-declared output parent | manifest 中 `final-run-properties` 输出路径的直接 leaf | `final-run-properties` |
| manifest-declared output parent | manifest 中 `h0` 输出路径的直接 leaf | `h0` |
| manifest-declared output parent | manifest 中 `h12-absence` 输出路径的直接 leaf | `h12-absence` |
| manifest-declared output parent | manifest 中 `journal` 输出路径的直接 leaf | `journal` |
| manifest-declared output parent | manifest 中 `manager-events` 输出路径的直接 leaf | `manager-events` |
| manifest-declared output parent | manifest 中 `run-main-properties` 输出路径的直接 leaf | `run-main-properties` |
| manifest-declared output parent | manifest 中 `signals` 输出路径的直接 leaf | `signals` |
| manifest-declared output parent | manifest 中 `source-selector` 输出路径的直接 leaf | `source-selector` |
| `scenario-root` | `AUTHORIZE-RELEASE.json` | `authorization` |
| `scenario-root` | `PERMIT_READY.pending` | `permit-ready-staging` |
| `scenario-root` | `PERMIT_READY.json` | `permit-ready` |
| `scenario-root` | `PERMIT.pending` | `permit-staging` |
| `scenario-root` | `PERMIT.json` | `permit` |
| `scenario-root` | `PERMIT-LEDGER.pending` | `permit-ledger-staging` |
| `scenario-root` | `PERMIT-LEDGER.json` | `permit-ledger` |

其中十二个 output leaf 不能由 semantic role 猜测文件名。实现必须从已验证 manifest 的精确输出路径提取 immediate child leaf，并同时验证该输出路径的 parent 正好是 retained `input-root` 或 `receipt-root` 之一。路径层级不符、parent 不符、完整 output path 重复或完整 `(parent_role, leaf)` 二元组重复都必须 fail closed。相同 leaf 位于不同的合法 parent 时不能仅因名字相同被判 alias，identity 不同时必须允许；若二者实际 hardlink 到同一 `(device,inode)`，仍适用 6.5 的 semantic-object alias rule。实现和测试不得额外施加全局 leaf 唯一 gate。

最终 vocabulary 必须恰好 20 行：1 个 formal leaf、12 个 manifest output leaf、7 个 scenario transaction leaf。不得接受额外 leaf，也不得静默忽略未知 leaf。

```python
        external_permit: H11ExternalCommittedPublication | None = None,
    ) -> tuple[H11AuthorityEventSnapshot, ...]: ...

    def close(self) -> None: ...
```

`H11DirectoryReference` 是 `role/path/device/inode/mode/uid/gid` 的完整 typed reference；`H11FullFileReference` 是 final `path/sha256/device/inode/mode/uid/gid` 的完整 typed reference。`H11BorrowedParentIdentity.chain` 是非空 immutable tuple，最后一项必须与 `parent_role` 相同；它只把冻结的 `stat_child/add_watch/rename_child_noreplace/fsync_directory/adopt_new_publication/adopt_external_final/pin_provisional_child` 操作委托给最后一项 lease，`reference` property 只读返回最后一项 reference，不保存或返回 raw descriptor。每个 `H11BorrowedDirectoryLink` 保存该层真实 original owner 签发的 lease/full reference，以及它相对上一层的 exact child name；formal-root link 的 `child_name` 必须为 `None`。

`_H11OwnershipPolicy` 是整个 source→authority H11 tree 的唯一 owner-metadata
authority，只有两个合法 construction state。`ExecutionManifestSource.open_once` 在
stable original owner object 已建立、但任何 `lstat/open/stat` 或 slot adoption 之前，
从既有 trusted `require_root: bool` mode 构造并冻结唯一 policy；caller 可以选择该既有
mode，但不能传 uid、gid、pair、callable 或 override：

- `require_root is True` 时，`expected_uid == 0` 且 `expected_gid == 0`；不得以当前
  process ids、fixture owner或“任意一致 owner”替代；
- `require_root is False` 时，必须在这一个 `open_once` entry 各调用一次
  `os.geteuid()`/`os.getegid()`，验证返回 nonnegative exact `int`，并把 exact pair
  一次冻结到 policy；之后不得重读 effective ids、跟随身份变化或接受 caller override。

source 保存该 exact policy object。formal-root lexical observation/reference、四条
`SOURCE_BOOTSTRAP` observation/new reference 与 source 的五个 cells 都必须加载同一
object，并要求所有 observed/reference uid/gid 精确等于 policy pair。
`RetainedH11PermitAuthority` construction 只能从其 exact `source` 读取并强引用
`authority._ownership_policy is source._ownership_policy`；它不能重建一个字段相同的
policy，也不能接受独立 `require_root/uid/gid`。在 authority 的任何 child open 前，
input/receipt/fifo/ready/permit 五个 `AUTHORITY_EXPECTED` spec references 的 uid/gid 都
必须等于该 shared pair，且每个 construction policy 的 `ownership_policy is` 同一
object。source→authority 的 require-root state、pair value 与 policy object identity
任一不一致都必须零 authority open 地失败。

每个 `H11BorrowedDirectoryLink` 与 `H11BorrowedParentIdentity` 都强引用该 same policy
object；chain construction 必须要求各 link、reference 与 original owner policy identity
一致。此后 `_revalidate_h11_parent_chain`、add-watch pre/post、publication
pending/final/internal bind、external final、provisional pin、FIFO pin、drain last-use 与
所有 typed `fstat/stat_child` identity proof，都必须除既有 type/mode/device/inode/SHA
条件外重新要求 observed/reference uid/gid 等于 same frozen pair。仅证明“这次 before/
after uid/gid相等”或“reference 与 observation 一致”而不匹配 policy，均不合格。

`_H11RetainedFdSlot` 是所有 C3a0 borrowed descriptor 的唯一 generation gate。
original owner 创建 slot 时冻结 `_owner is owner`、creation `_thread_id`、
`_lifecycle="UNSTARTED"`、`_binding=None` 与 `_active_use=None`。`adopt` 必须在
任何 slot mutation 前同时要求 current thread 等于 owner creation thread、exact
`owner is _owner`、lifecycle 仍为 `UNSTARTED`、binding empty、no active use，以及
descriptor 为非负 exact `int`。它先在 local 中预构造 frozen
`_H11OpenFdGeneration(descriptor, unguessable_generation, "OPEN")`，再把 lifecycle
不可逆写为 `ADOPT_STARTED`，发布唯一 `_binding`，最后写为 `OPEN`；正常同步路径
中三步之间没有 call/syscall/callback。`ADOPT_STARTED` 只诚实标识 Python
local→slot adoption 的不可结构化异步窗口，正常同步执行不得停留于该状态；命中
该窗口的 abrupt failure 按 8.4 one-shot 退出，不允许在同一进程恢复或 re-adopt。
slot 一旦开始 adopt，就永远不能回到 `UNSTARTED`。

original owner 冻结自己的 creation thread；lease 保存同一 owner、同一 slot、
同一 generation object 与 issuance `thread_id` 值。`_begin_use` 必须同时要求
slot lifecycle 精确为 `OPEN`、slot identity、owner object identity、current
binding 的 generation object identity、binding 的 exact `OPEN` state、非负
descriptor、current thread 与 lease/original-owner thread identity 精确相等，
以及当前没有 active use，随后以 frozen
`_H11ActiveFdUse(owner, generation, thread_id)` STORE 登记 use，才把 descriptor
返回给同一个 lease method。`_end_use` 只接受同一 owner/generation/thread 的
exact active record，并以一条 STORE 清空。任何第二次 use，包括同线程递归 use，
都必须在 syscall 前拒绝。

lease/pin 不再提供 `borrow()->int`。raw 禁令只针对 authority boundary：borrowed
directory/publication/FIFO-pin descriptor 不能离开发起 `_begin_use` 的同一个 typed
method frame，任何 raw descriptor 都不能进入 public API、aggregate、event、
capability、binding 或 caller-owned container。不能再把这一规则误写成 private
实现中 raw `int` parameter/return 绝对为零；跨 private method/ownership boundary
只允许以下三类 exact raw seam，多一个即失败：

1. `_H11RetainedFdSlot._begin_use(...) -> int` 只把 guarded borrowed descriptor
   返回给发起调用的同一个 directory/publication lease 或 FIFO-pin typed method
   frame；该 frame 在
   `finally` 调用 matching `_end_use` 前完成 exact syscall，不能再转发或返回；
2. formal-root 的首个 lexical acquisition，或 sealed
   `adopt_owned_child/adopt_new_publication/adopt_external_final` 内 open 后立即拥有的
   method-local descriptor，只能作为 `descriptor=` 传给 exact final owner 的
   preallocated empty target slot `adopt`；caller/frame 在 adopt 正常返回后的下一
   ownership action 必须把 local 置 `-1`，失败路径只能由 local 或 slot 二者之一
   关闭。`adopt_owned_child` 中 parent descriptor 同时服从第一类 same-frame lease
   seam，新 child local 同时服从本类 local→slot seam，因此它不是第四类 raw handoff；
3. watch set 自己拥有的 inotify descriptor，只能由
   `H11AuthorityWatchSet.open -> H11BorrowedParentIdentity.add_watch ->
   _H11BorrowedDirectoryLease.add_watch` 原样传入，并只作为
   `libc.inotify_add_watch` 的 watch-instance argument；它不是 borrowed directory
   或 publication FD，也不得由 lease 保存或关闭。

slot `_close_once` 内从 binding detach 出来的 method-local descriptor、FIFO-pin
typed method 内 endpoint local，以及 watch owner 在 `open` frame 内登记到 self fields
并由唯一 `_close_owned_watches` frame 自己提取/清空/消费的 inotify descriptor，不构成
跨 ownership boundary raw seam；close/poison/rollback 与 teardown helper 之间不得
传 raw。除此之外的 raw FD parameter、return、yield、container/cache、callback 或
helper handoff 全部为零。
两个 frozen lease type 不继承、不互相转换，也没有 union factory 或 generic
dispatcher：`_H11BorrowedDirectoryLease` 的 exact surface 是
`fstat/stat_child/add_watch/adopt_owned_child/rename_child_noreplace/fsync_directory/
adopt_new_publication/adopt_external_final/pin_provisional_child`；
`_H11BorrowedPublicationLease` 的 exact surface 是
`fstat/pread/write/fchmod_0444/fsync_file`。任一类型出现对方独有 method 都是结构
失败。每个 FD-consuming typed simple method 固定为
`_begin_use -> 一个 exact syscall -> _end_use in finally`；complete-write/
complete-pread 只能由上层以多次 typed method call 向前推进，不能把 borrowed
descriptor 带出 method。除上述 watch-owned inotify argument 外，所有 lease
method 都不接收 raw integer；所有 method 都不接收 caller callable/hook 或
caller-selected flags。
`stat_child` 只能执行 `os.stat(name, dir_fd=descriptor,
follow_symlinks=False)`；`add_watch` 只能在 guard 内构造 exact
`/proc/self/fd/<descriptor>` 并调用一次 `libc.inotify_add_watch`；
`adopt_owned_child` 是 construction-only sealed method：它必须在 parent slot 的
完整 active-use guard 内，从 exact final owner 在任何 resource open 前冻结的 closed
construction policy tuple 中，按 exact qualified caller、parent role、child role/name
与 target-slot identity 选择唯一 `_H11OwnedChildConstructionPolicy`；随后验证
`UNSTARTED`/empty/no-active target state、`policy.ownership_policy is` original owner 的
shared `_H11OwnershipPolicy`，再使用 policy 内建的 flags/type/mode 与 shared expected
uid/gid pair 打开并证明 child。caller 只能传 owner、target slot、child role/name；
不得传 reference、flags、type、uid、gid、metadata policy、callable 或 proof token。

四条 source edge 的 policy `proof_kind` 固定为 `SOURCE_BOOTSTRAP`。source 在 acquisition
前没有 child device/inode 或 typed reference，每项 policy 的 `expected_reference is
None`；sealed method 必须依次完成 guarded
before-stat→openat→fstat→after-stat，要求 path/name、object type、mode/uid/gid 与三次
identity一致，并要求每次 uid/gid 等于 same ownership-policy pair，之后才在本 frame 从 observed facts 构造新的
`H11DirectoryReference`。execution manifest 还必须在同一 guard 内 read-to-EOF、验证
size/mtime/device/inode stable、构造 immutable canonical bytes 与 SHA-256，再本地构造
`H11FullFileReference`。五条 authority edge 的 policy `proof_kind` 固定为
`AUTHORITY_EXPECTED`；exact owner/spec 在任何 open 前已经冻结各 child 的完整
`H11DirectoryReference` 或 `H11FifoReference`，sealed method 只能按 role 从 owner
内部读取 policy 的 non-`None` exact expected object，并要求 before/open/fstat/after 的 path/type/metadata/
device/inode 与它完整相等，同时要求 expected object 与四个 observations 的 uid/gid
都等于 same ownership-policy pair。source bootstrap reference 不得伪装成 authority expected
reference，authority edge 也不得从 observation 自签一个 replacement reference。

new FD 的第一项 ownership action 是 method-local STORE。上述全部 proof 成功后，method
在 target-slot adoption 之前预构造 frozen `_H11AdoptedOwnedChildProof`：其
`proof_kind` 必须与 selected policy 相同，`policy` 必须是 owner-frozen exact object，
`reference` 对 source 是本 frame 新构造的 verified reference、对 authority 是 exact
owner/spec expected reference，只有 manifest proof 的 `canonical_bytes` 非 `None`。
随后立即 adopt 到 target slot并把 local 置 `-1`；adopt 正常返回后不得有任何可能
失败的 proof/reference/build step。method 不返回 raw FD，只返回该预构造 proof。
`rename_child_noreplace` 只能把同一 guarded scenario descriptor 直接作为
`renameat2` 的 source/destination dirfd 并使用 `RENAME_NOREPLACE`；
`fsync_directory` 只能调用一次 `os.fsync`。`write/fchmod_0444/fsync_file` 分别只
允许 publication complete-write、exact `0444` 与一次 file fsync。
`adopt_new_publication/adopt_external_final` 在 directory guard 内以冻结 flags 打开
exact child，open 返回后先把新 FD 登记到 method-local owner，再立即 adopt 到传入
的 exact empty publication-owner slot；它们只返回 `None`。
`pin_provisional_child` 同样在 guard 内完成 child open、local ownership、fstat/type
proof、detach-before-close，并只返回 frozen `_H11PinnedChildIdentity`。三者都不把
new child FD 返回给 caller；open-return→local STORE 及 local→slot adoption 的异步
间隙仍按 8.4 诚实界定。这三个 sealed compound method 的 active-use guard 从
parent-child open 前一直保持到 adoption 完成或 transient child close attempt 完成，
其中任何同步 failure 都只经 method 自己的唯一 exception boundary 退出。

owner close/abort 必须先确认 `_active_use is None`；`preflight_close` 只验证 exact
owner、current owner thread、lifecycle 不为 `ADOPT_STARTED` 与 no-active-use，不能
读取或返回 descriptor，也不能修改 slot。active use 或 adoption gap 存在时必须
拒绝 close/abort，不能 detach 或调用 `os.close`。`_close_once` 只能在 preflight
成功后由 original owner 调用：`CLOSED` 为无副作用 no-op；`UNSTARTED` 只单向写
`CLOSED`；`OPEN` 则先把 `_binding` 写为 `None`、把 lifecycle 写为 `CLOSED`，再从
已 detach 的 method-local binding 对 descriptor 调用最多一次 `os.close`。它捕获
并返回该 close failure，或按传入 active primary 附加 ordered note；它不返回 raw
integer。因此 close 后 lifecycle 永久为 `CLOSED`，相同或新的 descriptor 都不能
re-adopt。
lease issuance、typed use 与 original owner close/abort 只能在 frozen owner thread；
跨线程调用必须在任何 guard/slot mutation 或 syscall 前拒绝。该 thread contract
与 nonreentrant active record 一起排除同一 owner 的并发 close/use；不引入 lock、
worker thread 或跨线程 handoff。
以后即使内核把同一数字重新分配给同一 inode，旧 lease 也必须在 `_begin_use`
阶段失败。slot 不提供 descriptor property；lease 不接受 public constructor、
setter、generation override 或 caller-provided borrowed raw integer，也不能暴露
`_begin_use/_end_use`。

original owner construction 也不得把 raw FD 交给 watch set。source 的 formal-root
首个 lexical open 仍使用 method-local `descriptor=-1 -> open -> local STORE -> exact
formal slot.adopt -> descriptor=-1`；除此以外两个 multi-resource owner 的九个 child
acquisitions只能经 retained parent lease 的 sealed `adopt_owned_child`。READY/ledger
named-staging 与 targeted external owner fixture 继续经各自 sealed publication-child
method使用同一 local→exact-slot discipline。构造/post-open proof 失败时由 exact
slot 或尚未 adopt 的 local 二者之一 detach-before-close 一次。这里同样只诚实声明
Python CALL→STORE→adoption 边界，不能宣称消除 open 返回与 adoption 之间的所有
异步窗口；测试必须证明正常异常路径没有超出第二类 raw seam、没有双 close，
public API 从不接收该 local integer。

directory lease 必须由第 5.2 节两族真实 original owner 按 exact role 签发；
READY/ledger lease 只能由同一个
`_H11RetainedPublicationOwner` 签发；external PERMIT lease 只能由同一个
`_H11ExternalCommittedPublicationOwner` 签发。watch set 只强引用这些 lease
及 owner 来证明借用生命周期，永远不 detach/close 它们。两族 directory owner
继续由各自既有 exhaustive teardown 关闭；两个 publication owner
各自提供 explicit `close()` 与 `abort(active_error=...)`：四个 qualified method 都
必须先对自己的 single slot 调用 side-effect-free `preflight_close`，成功后才调用
`_close_once`。preflight failure 保持 slot/reference 零 mutation、零 detach/close；
成功 teardown 仍 detach-before-close、只尝试一次、不删除 evidence、不 retry，
abort 保留同一 active primary 并把 close failure 作为 ordered note。watch
close/poison 不得自动调用这些方法；
publisher/harness fixture 或后续 C3c owner 在 watch drain 返回或失败传播后显式
teardown。

`_revalidate_h11_parent_chain(parent=...)` 是唯一完整 parent proof。它先验证 tuple shape、角色、路径层级、每层 owner family 与目标 role，并要求 `parent.ownership_policy`、每个 link 的 policy、source policy 与 authority policy（若 chain 跨 family）都是同一 exact object；随后按 root-to-leaf 顺序证明每一层。formal-root 必须通过该 link lease 的 typed `fstat()` 匹配 full reference与 shared expected uid/gid pair，再执行既有 canonical root-link proof。对每个后续 link，必须先通过本层 lease 的 typed `fstat()` 匹配本层 full reference与 policy pair，再通过 previous lease 的 typed `stat_child(name=link.child_name)` 要求 current entry 的 directory type/device/inode/mode/uid/gid 与本层 retained reference完全一致且 uid/gid等于同一 pair。chain 可以合法地从 `ExecutionManifestSource` lease 跨到 `RetainedH11PermitAuthority` lease，但任何层都不得换 owner、policy object、转移 slot 或缓存 raw integer。只证明目标 parent、只证明最后一个 direct link、只证明 owner 自洽却不匹配 policy，或绕过 typed lease method 都不合格。

`_H11RetainedPublicationOwner`、`_H11ExternalCommittedPublicationOwner` 与
`_H11OpaquePublicationCapability` 都是 module-private。两个 publication owner
在 constructor 中都必须先创建 exact empty slot，并把 `_reference` 明确初始化为
`None`；constructor 不接受 full reference，slot adoption 也不写 reference。external
owner constructor 必须同时接收并冻结两个彼此独立的 exact objects：validated
`H11ExternalPermitCommitReceipt` 与 internally consistent
`H11ExpectedPermitPublication`；不得只接收其 fields、重建 equal copy或让二者共享一个
摘要 authority。
caller-provided `_bind_reference(reference)` 必须删除；owner 不接收 reference 或
proof token。READY/ledger owner-private one-shot
`_prove_and_bind_pending_reference(parent=..., expected_bytes=...)` 与 external
owner-private one-shot `_prove_and_bind_committed_reference(parent=...)` 是
`_reference` 从 `None` 到 `H11FullFileReference` 的仅有两个、class-qualified writer
seam。两者都必须在任何 typed syscall 或 Store 前要求 current thread 等于 owner
creation thread、exact owner/slot identity、slot lifecycle/binding 精确为 `OPEN`、
no active use、`_reference is None`，随后只通过自己签发的 generation-bound
publication lease typed `fstat/pread`、传入 exact retained parent 的完整 chain 与
typed `stat_child` proof，在 local 中构造 reference。READY/ledger seam 只接受 exact
canonical immutable `expected_bytes`，不接受 hash/reference；external seam 只加载
constructor 冻结的 exact `H11ExpectedPermitPublication` object，以其中 canonical bytes、
internally matching SHA-256/byte-count、schema 与 semantic identity 校验 typed
read-to-EOF 的 `PERMIT.json`。它不得读取 receipt 的 `payload_sha256/byte_count` 来校验
publication，也不接受 caller bytes/hash/reference/expectation。所有 proof、read-to-EOF、
SHA、identity、mode、path 与 reference allocation 成功后，method 最后一项动作才是一条 `self._reference = reference`
STORE。wrong thread、pre-adopt、closed slot、重复调用或任一 proof failure 都保持
`_reference is None` 且不能 rebind/clear；STORE 后 reference 永久保留，包括 close。

opaque capability 没有
public constructor、factory、getter 或 return path，只能由 watch set 在
pre-rename registration 内创建并保存在私有 aggregate record。caller 永远只能
传同一个 READY/ledger owner object，不能构造或提交 capability/token。
READY/ledger 的 publication phase 只存在于 watch-set aggregate record；owner
自身只引用 physical slot，`OPEN/CLOSED` lifecycle 只存于该 slot，不在 owner
重复存储，也不另存
`REGISTERED/FINAL_BOUND/CONSUMED`，避免同一逻辑状态有第二个可部分提交 writer。
capability construction 必须先要求 retained owner 的 `_reference` 已绑定，并只能
把该 exact object 复制进 capability；register/bind/drain 不接受 caller-provided
reference，也不能从 path/bytes 临时重建替换值。
`H11ExternalCommittedPublication` 则是另一条明确的跨进程边界：它强引用后续
C3c 的同一个 harness-side `_H11ExternalCommittedPublicationOwner`、该 owner
签发的 generation-bound lease、validated receipt、exact expected-publication object 与
full reference。owner 在验证 PERMIT commit receipt 后，通过 retained scenario lease
nofollow 打开 final并原地拥有 slot，由 owner 内部 one-shot committed proof-and-bind 后才
签发 immutable borrowed binding；`borrowed_binding` 必须要求 `_reference` 已绑定，并把
owner 中 same receipt、same expectation 与 same reference object 写入 binding，不能接收、
重建或替换其中任一个。C3a0 只冻结该 type/boundary 和等价本地 fixture，不消费真实
receipt。

`H11ExternalPermitCommitReceipt` 只表示 C3c 在 harness 进程消费 exact PERMIT commit
FIFO frame 后产生的已验证 immutable handoff result，不是 publication-content proof，也
不是试图从 root 进程传递 Python object。其四字段 shape 在 C3a0 冻结：`phase` 必须是
exact `"permit-committed"`，`fifo` 是 commit channel identity，`payload_sha256` 必须等于
`sha256(b"SCION_H11_PERMIT_COMMITTED_V1\n").hexdigest()`，即 exact lowercase
`"0b32db23105bfd4165781e1de72e0dcd2edfa6717f51e9e4cf08fd34d0beb59a"`；`byte_count`
必须是 exact canonical decimal string `"30"`。这两个 payload fields 只证明 FIFO frame；即使其
值碰巧与某个 JSON 一致也不得用于、复制为或比较成 `PERMIT.json` 的 digest/count。真实
FIFO read、frame 字段验证与 production receipt constructor caller 全部延至 C3c。C3a0
fixture 只能提供语义等价的 already-validated typed receipt来验证 watch-set handoff
boundary，不能借此宣称真实 receipt path 已实现。frozen `__post_init__` 必须重新验证
phase、typed FIFO reference 与 fixed-frame digest/count，任何字段不符都不得产生对象。

`H11ExpectedPermitPublication` 是独立的 frozen publication-content authority。合法对象
必须同时满足：schema exact `"SCION_H11_PERMIT_PUBLICATION_V1"`、semantic identity exact
`"scenario-root/PERMIT.json"`、`type(canonical_bytes) is bytes`、`byte_count` 是 exact
nonnegative `int` 且等于 `len(canonical_bytes)`、`sha256` 是 canonical lowercase hex 且
等于 bytes 的 SHA-256。C3c 必须在任何 final path observation、`stat/open/pread` 之前，
仅从 retained authorizer inputs 与 deterministic PERMIT construction rules 构造唯一对象；
不得从 observed final、external reference、receipt payload fields或 final `pread` 自签。
C3a0 冻结这一 boundary/type/invariant；C3c production builder 的 exact qualified name、
retained input set 与 deterministic field-serialization细节延至 C3c 设计，在这些细节冻结
前 C3a0 production constructor caller 必须为零。targeted C3a0 fixture 则必须在任何
pending/final write、rename、stat/open/pread 前，从独立 canonical fixture input 构造该
expectation，并只用其 `canonical_bytes` 驱动后续模拟 publisher；不能观察文件后反推。
其 frozen `__post_init__` 必须在对象可见前重新计算并验证上述五字段，不能信任 caller
提供的 hash/count，也不得进行 filesystem observation。

`_H11BorrowedCommitFifoPin` 是 `RetainedH11PermitAuthority` 唯一可签发的 private、
immutable、non-owning FIFO view。issuer 必须在 authority creation thread 要求 exact
ready/permit role、exact authority owner、对应 cell lifecycle/binding 为 `OPEN`、
generation object identity 与 frozen `H11FifoReference` 一致后，才构造
`owner/slot/generation/thread_id/reference`，以及 exact formal→fifo-root retained
parent chain `formal-root[child_name=None] -> fifo-root[child_name="fifo"]` 和 exact
FIFO leaf；reference、parent chain与 current leaf 的 uid/gid 必须都等于 authority/source
shared ownership pair，parent/link policy object identity也必须相同。view 不含 raw descriptor、adopt、detach 或 owner-close
capability；它的 exact typed surface 只有 immutable `expected_payload`、
generation-bound `revalidate()`、`write_commit(actor=...)` 与
`read_commit(actor=...)`。watch set 只借 permit view 并冻结它的 exact reference；
runtime 只在 private fields 保存 ready/permit views。任何一方都不能通过 view 关闭
retained FIFO cell，唯一 closer 仍是 authority 对完整五-cell inventory 的
`close()`；private fifo-root chain 只服务 pin revalidation，不新增第五个 watch、
public binding 或 watch mapping。exact private issuer API 冻结为
`RetainedH11PermitAuthority._borrow_h11_commit_fifo_pin(*, role: str) ->
_H11BorrowedCommitFifoPin`，不接受 descriptor/reference/generation override。

FIFO closed payload/direction map 精确为：

| role | `expected_payload` | writer actor | reader actor |
| --- | --- | --- | --- |
| `h11-ready-commit` | `b"SCION_H11_READY_COMMITTED_V1\n"` | `harness` | `authorizer` |
| `h11-permit-commit` | `b"SCION_H11_PERMIT_COMMITTED_V1\n"` | `authorizer` | `harness` |

未知 role/actor、`write_commit` 的非 writer actor 或 `read_commit` 的非 reader actor
必须拒绝。三个 typed methods 都在任何 syscall 前调用 pin slot `_begin_use`，并让
同一个 active-use guard 覆盖 generation/thread/role/direction、完整 formal→fifo
parent chain、retained FIFO `fstat` 与 current leaf identity proof。`revalidate` 到此
结束并在 `finally` matching `_end_use`；write/read 则在同一 guard 内用 pin
descriptor 只构造 method-local `/proc/self/fd/<descriptor>`，以 blocking
`O_WRONLY|O_CLOEXEC` 或 `O_RDONLY|O_CLOEXEC` 打开 endpoint，立即 local STORE与
typed-reference `fstat` proof。禁止 `O_NONBLOCK`、caller flags、endpoint helper、
raw return/cache 或把 endpoint 交给另一 frame。

`write_commit` 只允许确认 exact payload 长度 `<= select.PIPE_BUF` 后执行一次
`os.write(endpoint, expected_payload)`，返回 byte count 必须完全相等；不得循环、
补写或重试。`read_commit` 只能反复 `os.read(endpoint, select.PIPE_BUF)` 直到真实
EOF，再要求全部 bytes 精确等于 closed expected payload；不得接受 prefix/suffix/
duplicate frame，不得设置 byte cap、timeout、poll 或截断。两者都在离开 pin active
guard 前把 endpoint move-to-local/detach并最多 close 一次；operation failure 保持
same primary，endpoint close failure按序加 note，close-only failure 成为 primary，
不 retry；最外层 `finally` 在 endpoint teardown attempt 完成后执行 matching
`_end_use`，包括 operation/close failure path。返回值只能是 `None` 或 exact immutable payload bytes，retained pin cell
仍由 authority 拥有且 generation 不变。阻塞先后顺序测试必须让两个 actor 使用各自
进程内、creation-thread-bound 的 exact owner/pin；不得为线程调度放宽 slot 的
same-owner-thread guard。该 typed surface 与迁移的 C1b targeted tests 不等于 C3c
receipt consumer：C3a0 production 的 write/read caller 仍为零，read bytes 不在本
切片构造 `H11ExternalPermitCommitReceipt` 或驱动 production chronology。

所有 property 都只返回 immutable value 或独立只读 snapshot：`bindings` 返回不含 raw FD 的 frozen binding tuple，`watch_to_parent` 返回对副本的 `MappingProxyType`，`events` 从当前 `_aggregate.ledger` 逐行构造 frozen `H11AuthorityEventSnapshot` 后返回 tuple；不得返回 `tuple[dict, ...]` 或任何可变 row。唯一 owned inotify descriptor 没有 public property，不能向 caller 暴露这个关闭 capability。不得公开 `_aggregate`、publication token/record 或 provisional identity record，也不得提供 setter。`slots` 不是访问控制；AST 必须额外证明类外没有对这些私有字段的 store/delete/mutating-method call。

`H11AuthorityWatchSet` 本身冻结 creation-thread confinement 与 exact nonreentrant
active-operation gate。`open` 在任何 init/add-watch syscall 前建立 unpublished stable
`self`，一次写入 `_thread_id=current_thread_id`，并把 `_active_operation` 初始化为
exact frozen `kind="open"` record；同时先把 `_descriptor=-1`、
`_active_watch_descriptors=()`、`_poisoned=False`、`_closed=False` 与其他 fields
初始化成 closed-shape empty values。init 成功后第一项 ownership action 是把 raw FD STORE 到
`self._descriptor`；每次 add-watch 返回的值只先存在于 `open` frame 的
`returned_watch_descriptor` local。完成 same-parent post-proof 后，必须在任何相关 field
STORE 前验证它是 exact nonnegative `int`，且未出现在当前 active inventory、mapping 或
registrations；只有 fresh value 的第一项接受动作才是一次 immutable tuple replacement，
把它加入 owner field inventory，之后才能构造 matching mapping/registration。成功 construction 在发布 `self` 前以 exact record 清空
open gate；同步 failure 只进入 `_rollback_open(operation=same_record,
active_error=same_primary)`。

除 `open` 的上述 bootstrap 外，`register_retained_publication`、
`bind_retained_publication`、`drain`、public `poison`、public `close`，以及两个
`_scenario_parent_for_*_fixture` accessor，必须先在任何 owner field mutation 或 syscall
前验证 current thread 与 `_thread_id` 相等且 `_active_operation is None`；需要继续的
live branch 随后以 `_begin_operation(kind=下表中该 qualified caller 的 exact literal)` 唯一 STORE 安装包含 same
owner/thread 与 unguessable token 的 frozen record。terminal repeat close/poison 只在
thread/idle check 后分别 no-op/重抛本次 primary，不调用 begin。wrong-thread 或任何
reentrant/nested entry 在零 field mutation、零 syscall 下拒绝；不得用 `RLock`、递归深度、boolean busy bit 或
“同线程所以安全”代替 exact record identity。只读 properties 也必须在读取私有 state
前做 creation-thread check，但不安装 operation record。fixture accessor 在 record
保护下只读取并返回 exact immutable parent object，成功 return 前 matching
`_end_operation`；它不授权另一个线程使用 lease。

`_H11WatchOperationRecord.kind` 是以下 exact eight-literal closed set；拼写、qualified
caller、success consumer 与 failure consumer 都是 API，不允许实现者另取简称、共享
`"fixture"`/`"mutation"` kind 或新增 `"active_failure"` kind：

| exact `kind` | 唯一 record creator / qualified entry | success consumer | ordinary active failure |
| --- | --- | --- | --- |
| `"open"` | `H11AuthorityWatchSet.open` unpublished bootstrap 直接构造 | `open` 发布前验证 same record并直接清空 | `_rollback_open(operation=same_record, ...)`；不经 `_poison_from_active_operation` |
| `"register_retained_publication"` | `_begin_operation`，唯一 caller `H11AuthorityWatchSet.register_retained_publication` | same qualified method 调用 `_end_operation` | same qualified method 调用 `_poison_from_active_operation` |
| `"bind_retained_publication"` | `_begin_operation`，唯一 caller `H11AuthorityWatchSet.bind_retained_publication` | same qualified method 调用 `_end_operation` | same qualified method 调用 `_poison_from_active_operation` |
| `"drain"` | `_begin_operation`，唯一 caller `H11AuthorityWatchSet.drain` | same qualified method 调用 `_end_operation` | same qualified method 调用 `_poison_from_active_operation` |
| `"_scenario_parent_for_external_fixture"` | `_begin_operation`，唯一 caller `H11AuthorityWatchSet._scenario_parent_for_external_fixture` | same qualified accessor 调用 `_end_operation` | same qualified accessor 调用 `_poison_from_active_operation` |
| `"_scenario_parent_for_retained_publisher_fixture"` | `_begin_operation`，唯一 caller `H11AuthorityWatchSet._scenario_parent_for_retained_publisher_fixture` | same qualified accessor 调用 `_end_operation` | same qualified accessor 调用 `_poison_from_active_operation` |
| `"poison"` | `_begin_operation`，唯一 caller 是 `H11AuthorityWatchSet.poison` live nonterminal branch | 无；same qualified branch terminalize、直接消费 same record并 teardown 后抛 primary | 无 active-failure handoff；terminal repeat 不建 record、只重抛本次 primary |
| `"close"` | `_begin_operation`，唯一 caller 是 `H11AuthorityWatchSet.close` live nonterminal branch | same qualified branch terminalize、直接消费 same record并 teardown | 无 active-failure handoff；terminal repeat 不建 record、无副作用 return |

`_begin_operation` 必须按 qualified caller 精确匹配对应 literal，不能接收 caller-selected
arbitrary string。`_end_operation` 只接受表中五个 nonterminal success kind 的 same
record。`_poison_from_active_operation` 不创建、替换或重命名 record；它只接受表中
register/bind/drain/两个 fixture accessor 的 same active record，并在 terminalize 后
消费它。wrong-thread、reentrant、closed entry 与 terminal poison/close repeat 均不建
record；`open` failure 只由 rollback 消费 `"open"` record。

register/bind/drain 与两个 fixture accessor 的 operation record 覆盖从首个 proof/read
到 success end 或 failure poison 的整个调用；特别是 drain 的 parent pre-proof、一次
`FIONREAD`、至多一次 `os.read`、完整 batch validation/provisional pin、next aggregate
build 与 single STORE 必须属于同一个 exact `kind="drain"` record。内部
`_read_one_snapshot/_validate_complete_batch/_pin_provisional_identity/
_commit_validated_batch/_commit_aggregate` 不另开 nested operation，只验证 caller
仍持有同一个 active record。因此 queue snapshot/validation/commit 不能与
register、bind、close、poison、fixture parent access 或第二次 drain 并发、递归交错。

成功 register/bind/drain/accessor 只由 `_end_operation(operation=same_record)` 清空
gate。active operation 的普通 `BaseException` 绝不能调用 public `poison`；它只能把
same record 与 same primary 交给 `_poison_from_active_operation`。该 seam 先验证
current thread、record object identity、owner/token，以及 kind 精确属于上述五个
active-failure literals，随后把 `_poisoned=True`、
`_closed=True` 写成 terminal state，以一条 `_active_operation=None` STORE 合法消费
当前 gate，再调用 `_close_owned_watches(active_error=same_primary)` 并重新抛出同一
primary。这样 operation failure 不会因自己的 active record 自锁，也不存在绕过 gate
的通用 internal poison。public `poison` 只服务 idle 的 runtime post-watch/pre-wrapper
failure：它安装 exact `kind="poison"` record，terminalize 后消费自己的 record，再调用
同一 teardown helper；已 terminal 时只重新抛出本次显式 primary且无 teardown。
public `close` 对 idle live owner 同样安装 `kind="close"` record，先置 `_closed=True`、
消费 record，再调用 helper；idle terminal close 是无副作用 no-op。若任一 active
record 仍存在，reentrant close/poison 即使看见 terminal flag 也必须先因 active
record 拒绝，不能清除别人的 gate或启动 teardown。active failure 消费 gate 后 owner
已经 terminal，故该极短 terminal→helper 以及 helper execution 区间中的 reentrant
public entry也只能拒绝/no-op，不能启动第二 teardown；creation-thread check同时排除
另一线程与 FD-consuming sequence 并发。

`_H11AuthorityAggregate` 的 immutable 含义必须精确限定为 logical
topology/state/reference/token identity immutable：aggregate、tuple 与各 record
发布后不能就地修改，ledger/provisional scalar values、publication phase、full
reference 与 opaque token identity 都由 replacement-only STORE 更新。但 capability
强引用的 owner、slot 与 generation binding 是 aggregate 外部的 mutable liveness
dependency；owner 可以在 original closer 中合法从 `OPEN` 变为 closed，slot 的
active-use/liveness 也会变化。该变化不修改 aggregate 的逻辑 record，却会使后续
lease validation 失败。因此不得称 aggregate “recursively/deep immutable”，也不得
用“逐字节不变”覆盖外部 owner/slot 状态；测试只能断言 aggregate object identity、
逻辑 tuple/record/reference/token identity 未变，并单独断言外部 liveness gate。

### 5.2 资源所有权

七个 retained directory 的真实 original owner/issuer/closer map 冻结如下；这是
exact closed map，不得把“authority 聚合了 source”误写成它拥有 source 的四个
directory FD：

| directory role | original owner | 唯一 lease issuer | 唯一 closer |
| --- | --- | --- | --- |
| `formal-root` | `ExecutionManifestSource` | `ExecutionManifestSource._borrow_h11_directory_lease` | `ExecutionManifestSource.close` |
| `authority-root` | `ExecutionManifestSource` | `ExecutionManifestSource._borrow_h11_directory_lease` | `ExecutionManifestSource.close` |
| `harness-root` | `ExecutionManifestSource` | `ExecutionManifestSource._borrow_h11_directory_lease` | `ExecutionManifestSource.close` |
| `scenario-root` | `ExecutionManifestSource` | `ExecutionManifestSource._borrow_h11_directory_lease` | `ExecutionManifestSource.close` |
| `input-root` | `RetainedH11PermitAuthority` | `RetainedH11PermitAuthority._borrow_h11_directory_lease` | `RetainedH11PermitAuthority.close` |
| `receipt-root` | `RetainedH11PermitAuthority` | `RetainedH11PermitAuthority._borrow_h11_directory_lease` | `RetainedH11PermitAuthority.close` |
| `fifo-root` | `RetainedH11PermitAuthority` | `RetainedH11PermitAuthority._borrow_h11_directory_lease` | `RetainedH11PermitAuthority.close` |

`scenario-root -> receipt-root` 与 `formal-root -> input-root/fifo-root` 因而是合法的
mixed-owner lease edge。chain 聚合 lease 不转移 ownership：
`RetainedH11PermitAuthority` 不得 adopt、detach 或 close source 的四个 slots，
`ExecutionManifestSource` 不得 close authority 的三个 slots，watch set 也不得 close
任一族；但两族必须共享 source 创建的 exact `_H11OwnershipPolicy` object，mixed edge
不得只比较字段 equality。两个 original owner 各自只关闭自己表中 directory slots；任一 FD 只能由
唯一 closer physical close 一次，禁止 handoff、shadow slot、fallback close 或双
close。上表只是七个 directory 的 ownership map，不是两个 multi-resource owner
的完整 resource inventory，也不得被称为完整七资源 owner inventory。

两个 original owner 都必须在各自第一个 `open` 前先成为稳定 owner object，并预分配
下列 exact literal 五-cell tuple；每一 cell 都是 `_H11RetainedFdSlot`，之后每次
acquisition 都遵循 `descriptor=-1 -> open -> method-local ownership -> exact
cell.adopt -> descriptor=-1`：

- `ExecutionManifestSource` 的完整五 cells 固定为 `formal-root`、`authority-root`、
  `harness-root`、`scenario-root`、`execution-manifest`；
- `RetainedH11PermitAuthority` 的完整五 cells 固定为 `input-root`、`receipt-root`、
  `fifo-root`、`h11-ready-commit` pin、`h11-permit-commit` pin。

同一 pre-open construction phase 还必须为九条 child edge 冻结 exact immutable
`_H11OwnedChildConstructionPolicy` tuple。每项固定 qualified caller、parent role、
child role/name、open flags、object type、mode 与 exact shared ownership-policy object，
运行期不得由 caller 补充或覆盖 uid/gid。source tuple 只有后表四条
`SOURCE_BOOTSTRAP` policy，不含预造 child
reference；authority tuple 只有后表五条 `AUTHORITY_EXPECTED` policy，并逐项强引用
owner/spec 已有的 exact full expected reference。任一 policy、authority expected
reference 或 target slot 未能在第一个 resource open 前冻结，任一 construction policy
的 `ownership_policy` 不是 source 创建且 authority 共享的 exact object，或任一
reference uid/gid 不等于该 pair，整个 owner construction必须零 open 地失败。

formal-root 是唯一 lexical acquisition：`ExecutionManifestSource.open_once` 以 exact
formal path 和 `O_RDONLY|O_DIRECTORY|O_CLOEXEC|O_NOFOLLOW` 打开，要求
ownership-policy-owned directory mode `0711`，并以 before
`lstat`→open→`fstat`→after `lstat` 的三次 exact
identity proof并要求三次 uid/gid 等于 shared pair，在 local 中预构造 reference 后，使用第二类
method-local→formal-slot seam。其余九项只能按
下列 closed construction edge 调用 parent lease `adopt_owned_child`，不得由 owner
直接 `os.open`、不得交换 parent 或顺序：

| qualified construction caller | retained parent → child role/name | frozen flags/type/metadata | proof/reference rule |
| --- | --- | --- | --- |
| `ExecutionManifestSource.open_once` | formal-root → authority-root/`authority` | `O_RDONLY|O_DIRECTORY|O_CLOEXEC|O_NOFOLLOW`；directory，shared ownership pair `0700` | `SOURCE_BOOTSTRAP`；proof 后本地构造 directory reference |
| `ExecutionManifestSource.open_once` | authority-root → harness-root/`harness` | 同上；directory，shared ownership pair `0700` | `SOURCE_BOOTSTRAP`；同上 |
| `ExecutionManifestSource.open_once` | harness-root → scenario-root/exact validated scenario leaf | 同上；directory，shared ownership pair `0700` | `SOURCE_BOOTSTRAP`；同上 |
| `ExecutionManifestSource.open_once` | scenario-root → execution-manifest/`MANIFEST.json` | `O_RDONLY|O_CLOEXEC|O_NOFOLLOW`；regular，shared ownership pair `0444` | `SOURCE_BOOTSTRAP`；read-to-EOF、SHA、size/mtime/identity stability 后本地构造 full-file reference/bytes proof |
| `RetainedH11PermitAuthority.open` | formal-root → input-root/`input` | `O_RDONLY|O_DIRECTORY|O_CLOEXEC|O_NOFOLLOW`；directory，shared ownership pair `0555` | `AUTHORITY_EXPECTED`；匹配 owner/spec exact directory reference |
| `RetainedH11PermitAuthority.open` | scenario-root → receipt-root/`receipts` | 同上；directory，shared ownership pair `0555` | `AUTHORITY_EXPECTED`；匹配 owner/spec exact directory reference |
| `RetainedH11PermitAuthority.open` | formal-root → fifo-root/`fifo` | 同上；directory，shared ownership pair `0711` | `AUTHORITY_EXPECTED`；匹配 owner/spec exact directory reference |
| `RetainedH11PermitAuthority.open` | fifo-root → h11-ready-commit/`h11-ready-committed.fifo` | `O_PATH|O_CLOEXEC|O_NOFOLLOW`；FIFO，shared ownership pair `0600` | `AUTHORITY_EXPECTED`；匹配 owner/spec exact FIFO reference |
| `RetainedH11PermitAuthority.open` | fifo-root → h11-permit-commit/`h11-permit-committed.fifo` | 同上；FIFO，shared ownership pair `0600` | `AUTHORITY_EXPECTED`；匹配 owner/spec exact FIFO reference |

每条 edge 都在 exact parent active-use guard 内执行 before-stat→openat→fstat→
after-stat/full proof→local proof/reference build→target-slot adopt，并要求三次 identity
一致。source 的 locally constructed reference/proof 与 authority 的 expected-reference
match proof 都必须在 adopt 前完成；任一 proof/build/adopt failure 只关闭 method-local
child，一条 edge 成功后才允许签发该 child directory lease或继续下一 edge。
`_H11AdoptedOwnedChildProof` 不是 authority token，不能让 caller 选择
reference/flags/type/metadata policy，也不能被用作绕过 owner/slot/generation 的 lease。

不得先让 `RetainedManifestDirectory`、`RetainedH11Directory`、`PinnedCommitFifo`、
local list 或其他 wrapper 成为独立 physical closer 后再转交。上述三个 shadow-owner
wrapper 类型及其独立 `close` 路径必须删除；若仍需暴露 immutable metadata/view，
它只能引用 exact original owner/slot/generation/reference，没有 descriptor、adopt、
detach 或 close capability。partial construction failure 仍由同一个预构造 owner 对
自己的完整五 cells exhaustive close。

两个 multi-resource closer 在任一 manifest/FIFO/directory detach、close 或其他资源
副作用前，都必须先在 owner creation thread 按 exact literal inventory 顺序对自己的
全部五 cells 完成一轮 side-effect-free `preflight_close`。任一 cell 正在 active use、
处于 `ADOPT_STARTED`、owner/thread 不符时，整个 owner close 必须在零 owner-field
mutation、零 detach、零 physical close 下拒绝；尤其不能先关“不相关”的 manifest
或 commit FIFO cell。preflight 全部成功后，由于 lease/use/adopt/close 都冻结为同一
owner thread，不会有另一线程插入新 use。

随后 exhaustive close 的完整 resource-cell 顺序冻结为：

1. `ExecutionManifestSource`：execution-manifest；scenario-root；harness-root；
   authority-root；formal-root；
2. `RetainedH11PermitAuthority`：`h11-permit-commit` pin；
   `h11-ready-commit` pin；fifo-root；receipt-root；input-root。

每项都只能调用该 cell 的 `_close_once`，由 slot 在 physical close 前 detach；
manifest/FIFO 不再有 wrapper-specific close primitive。某项 close failure 不能提前
终止 sweep，后续 cells 仍按固定顺序各访问一次且不得 retry。已有 operation primary
时，所有 close failure 按顺序作为 notes 附到同一 primary；没有 operation primary
时，第一个 close failure 成为 top-level primary，其余按顺序附为 notes，完整 sweep
后才抛出。重复 close 只访问已关闭状态且无 physical syscall。

跨 owner-family 的外层 teardown 顺序只冻结为 runtime/watch → publication owners →
`RetainedH11PermitAuthority` → `ExecutionManifestSource`。零 partial side effect 的
保证严格是 per-owner 的五-cell preflight，不宣称 source 与 authority 两个独立
`close()` 组成联合原子事务；前一个 owner 已完成 close 后，后一个 owner 的
preflight failure 不回滚前者。

现有 `ExecutionManifestSource.__del__` 必须删除，production 中该 qualified method
和任何替代 finalizer/atexit/weakref implicit close 都为零；不得让 GC 时机形成第二
closer、吞掉 close failure或破坏上述 preflight/exhaustive 顺序。其他 C3a0 owner
同样不得新增有资源副作用的 `__del__`。

`H11AuthorityWatchSet`：

- 拥有唯一 inotify descriptor；
- 拥有该 instance 上四个 watch registration；
- 拥有私有 watch mapping、从 authority 冻结的 exact shared ownership-policy object、expected permit FIFO immutable
  reference 与单一 immutable logical authority aggregate；
- close 时只释放上述自有资源。

`H11AuthorityWatchSet` 借用但不拥有：

- `ExecutionManifestSource` 签发的 formal/authority/harness/scenario leases、
  `RetainedH11PermitAuthority` 签发的 input/receipt leases，以及构成四条 canonical
  ancestor chains 的全部 bind-time full references；
- READY/ledger harness publisher 的同一个 `_H11RetainedPublicationOwner` object、它签发的 generation-bound lease，以及它拥有的 retained pending/final publication slot；
- drain 时传入的 `H11ExternalCommittedPublication` 强引用的同一个 C3c harness-side
  owner、该 owner 签发的 final lease、validated fixed-frame commit receipt 与 independently
  prebuilt expected-publication content authority。

watch set 的 close、poison 或失败回滚不得关闭任何借用 descriptor。

借用不是弱验证。`open()` 必须在每次 add-watch 的紧邻前和紧邻后，对同一个 `H11BorrowedParentIdentity` 各调用一次 `_revalidate_h11_parent_chain`；add-watch 本身只能调用该 parent 的 typed `add_watch`，使 `/proc/self/fd/<retained-target>` 的构造与 `inotify_add_watch` 都位于 target lease active-use guard 内。pre-proof 证明调用前观测点仍是 retained canonical chain；post-proof 只证明调用后观测点仍是同一 chain。若任一 current link 在 post-proof 时仍漂移，必须失败并回滚。

这不是任意瞬变检测器。若 pathname 在 pre-proof 后瞬时 move/replace、又在 post-proof
前恢复为原 retained links，纯 `fstat/stat` 双观测无法检测该 ABA，设计和测试不得
声称可以。安全边界是 add-watch 始终通过 retained target descriptor 的 procfd
注册，所以该 watch 绑定原 target inode而不会被瞬时 replacement 重定向；它不证明
replacement 上的短暂事件被观察。每次 descriptor-relative leaf open、publication
pending proof、final bind、provisional pin、external final binding 和 drain last-use
仍必须先完整重证 root-to-target chain，并通过 typed lease method 让 active-use guard
覆盖完整 FD-consuming syscall。旧 ancestor 与旧 child descriptors 即使仍互相自洽，
也不能替代 canonical current chain；同号同 inode reopen 也不能替代 original generation。

READY/ledger owner 必须在 registration、post-rename binding 与 drain last-use 使用同一 lease 的 typed `fstat/pread` 重读 canonical bytes、验证 SHA-256；`_pread_exact_h11_publication` 只能编排这些 typed methods，不能取得 raw FD。external committed binding 必须在 drain last-use 先要求 `binding.owner is binding.lease.owner`、slot/generation 与 owner 当前 `OPEN` state 精确匹配，再对其 final lease 做同等 revalidation。typed `pread` 必须从显式 offset 读取且不得改变 borrowed open-file-description offset；不得以 `os.read` 加 seek/restore 暂时扰动 owner 的 offset。owner/slot/generation/state、对象、bytes、mode、任一 ancestor/current link 或 final link 漂移均 fail closed。

`ExecutionManifestSource` 与 `RetainedH11PermitAuthority` 都必须活得比 `H11RuntimeOpenAuthority` 和 watch set 更久。READY/ledger 的同一个 publisher owner object 必须至少活到对应 transaction 的 aggregate record 进入 `CONSUMED`；C3c harness-side external binding owner 必须至少活到接收该 binding 的 drain 返回。watch set 对 READY/ledger 保存包含 owner object identity、lease owner/slot/generation identity、私有 token object identity 与 opaque capability 的 aggregate record，对 external PERMIT 只在该次 drain 借用 typed committed-final binding及其明确 owner；任一 owner 提前 close/abort 后，register/bind/drain 必须在 aggregate mutation 前失败。成功或失败后的 borrowed-FD teardown 只能由各 original owner 显式执行，watch set 不取得 ownership。

`H11RuntimeOpenAuthority` 后续在 C3a0 实现中持有一个 `watch_authority`，并继续借用
ready/permit `_H11BorrowedCommitFifoPin`。它不再持有 `watches` 字典或 ledger。
`events` 只能原样只读委托给 `watch_authority.events`；`drain` 仍只把 typed
`external_permit` 原样转发给 `watch_authority.drain`，不得自行比较 FIFO、receipt
或 identity。runtime close 只关闭 `watch_authority`；retained authority 仍是 FIFO
cells 与其他 retained descriptors 的唯一关闭方。

`H11RuntimeOpenAuthority.open` 必须以 unpublished local
`watch_authority: H11AuthorityWatchSet | None = None` 建立 wrapper：先调用一次
`H11AuthorityWatchSet.open(authority)`；成功后立即以该 same object 和 authority
签发的两个 borrowed commit-FIFO pin views 构造 frozen runtime wrapper；wrapper
发布前必须在 authority creation thread 对 ready、permit 各调用一次 typed
`revalidate()` 并证明 closed role/reference pair。若
任一 pin parent/reference 的 ownership-policy object/pair 不等于
`watch_authority._ownership_policy`，wrapper 必须在发布前失败并走 same public idle
poison path。若
watch-set open 自身失败，其内部
rollback 已负责且 runtime 不取得对象；若 watch-set 已成功但 wrapper allocation/
construction/field validation 抛出任意 `BaseException`，runtime 的同一 exception
boundary 必须把 exact primary 传给
`watch_authority.poison(active_error=primary)`。`poison` 完成唯一一次 watch teardown
并重新抛出同一 primary；runtime path 不再执行 `close`、第二次 poison、finally
fallback 或 borrowed FIFO teardown。成功 wrapper 才拥有调用 watch close 的责任。

### 5.3 初始化

`open()` 必须先按 5.1 建立 unpublished stable `self`、冻结 creation thread、安装 exact
open operation record，并把 raw owner fields、`_watch_to_parent` 与 `_bindings` 分别
初始化为 `-1/()/empty mapping/()`，才执行以下步骤：

1. 在任何 init/add-watch 或 borrowed-FD syscall 前要求
   `authority._ownership_policy is authority.source._ownership_policy`，验证 exact
   two-state construction 与 authority 全部五项 spec reference uid/gid 都匹配 shared
   pair，并把 same object一次写入 unpublished `self._ownership_policy`；
2. 验证 closed vocabulary 恰好 20 行且所有 parent/leaf 映射合法；
3. 严格按 5.2 的真实 owner map，从 `authority.source` 的
   `ExecutionManifestSource._borrow_h11_directory_lease` 取得
   formal/authority/harness/scenario leases，从
   `RetainedH11PermitAuthority._borrow_h11_directory_lease` 取得 input/receipt leases，
   再构造四个 typed parent bindings。chain shape 必须精确为：`formal-root =
   (formal-root[canonical])`；`input-root = (formal-root[canonical],
   input-root[input])`；`scenario-root = (formal-root[canonical],
   authority-root[authority], harness-root[harness], scenario-root[H11])`；
   `receipt-root = (formal-root[canonical], authority-root[authority],
   harness-root[harness], scenario-root[H11], receipt-root[receipts])`。方括号表示相对
   上一层的 exact child name；mixed-owner chain 不改变任一 slot owner；
4. 只调用 authority 的 private issuer 取得 exact `h11-permit-commit`
   `_H11BorrowedCommitFifoPin`，先调用一次 typed `revalidate()`，再证明其
   owner/slot/generation lifecycle 与
   `authority.spec.permit_commit_fifo` 的 role/path/device/inode/mode/uid/gid
   完全相同，把 pin 中 exact immutable `H11FifoReference` 冻结为私有
   `_expected_permit_fifo`；不得从 `external_permit` 或 runtime 参数反推 expected
   FIFO；
5. 恰好调用一次 `inotify_init1(os.O_CLOEXEC)`，不得使用 `O_NONBLOCK`；正常返回后
   第一项 ownership action 是 STORE 到 `self._descriptor`；
6. 按固定 parent role 顺序，在每次 add-watch 紧邻前以
   `_revalidate_h11_parent_chain(parent=same_parent)` 完整重证对应 typed chain；通过同一
   parent 的 `add_watch(inotify_descriptor=descriptor, mask=exact_mask)` 在 target-slot
   active-use guard 内注册 watch，其 return 只赋给本 frame
   `returned_watch_descriptor` local；在接受该值或写入 inventory/mapping/registration 前，
   立即以同一 helper、同一 parent object 完成 post-proof；
7. post-proof 成功后仍只读取 local 和当前 unpublished fields，按固定顺序验证
   `type(returned_watch_descriptor) is int`、值 `>= 0`、不在
   `self._active_watch_descriptors`、不在 `self._watch_to_parent` keys，且当前
   `self._bindings` 中没有相同 `watch_descriptor` 的 registration。bool、negative、已有
   inventory entry、已有 mapping key 或已有 registration 任一命中，都以原始 validation
   failure 进入 rollback；该分支不得 append/STORE 任一 inventory、mapping 或 registration，
   不得先删除/覆盖旧 entry，也不得把 duplicate 当成第二份 owned watch；
8. 只有 fresh wd 才先执行唯一一条
   `self._active_watch_descriptors = (*self._active_watch_descriptors,
   returned_watch_descriptor)` tuple replacement；该 STORE 是 wd 的唯一 owner-inventory
   publication。随后才以 immutable replacement 给 `_watch_to_parent` 增加唯一
   `returned_watch_descriptor -> same_parent_role` entry，再以 tuple replacement 给
   `_bindings` 增加唯一、字段完全一致的 private `_H11AuthorityWatchRegistration`。
   mapping/registration build 或 STORE 失败时 inventory 已含该 fresh wd，rollback 必须
   对它恰好一次 rm；不得倒序先发 mapping/registration、in-place overwrite 或二次 append；
9. 四轮完成后要求 inventory 与 registration wd tuple 是按固定 parent 顺序完全相同的
   四个 pairwise-distinct wd，mapping key set 恰好为同一集合且每个 value 匹配对应
   parent role；public `bindings` property 只投影不含 parent/lease 的
   `H11AuthorityWatchBinding` snapshots；
10. 构造 exact empty `_H11AuthorityAggregate(ledger=(), provisional_identities=(), publication_records=())`，只在全部 mapping、binding、lease、expected FIFO 与 descriptor 验证完成后写入 unpublished object；最后以 exact open record 清空 `_active_operation`，之后才发布 `self`。该 initial assignment 不是运行期 batch commit seam。

watch registration mask 只能包含协议需要的 CREATE、MOVED_FROM、MOVED_TO 以及用于 fail-closed 检测的 fatal 状态位。`IN_ISDIR` 是内核附加到 returned event 的 type modifier，不作为订阅扩宽项；其唯一允许语义见 6.3。不能把宽泛 mask 当作可忽略噪声入口。

以下任一情况必须失败：

- init 失败；
- 任意 add-watch 失败；
- returned watch descriptor 不是 exact `int`、是 bool、为负数，或与当前 active
  inventory/mapping/registrations 任一已有 wd 重复；
- 四 watch 或双向 mapping 不完整；
- source/authority/watch-set ownership-policy object identity 不同，`require_root` 不是 exact
  bool/two-state，或任一 formal/source/authority/spec/current observation/reference 的
  uid/gid 不等于 frozen pair；
- 任一 ancestor/target owner/slot/generation/state 不匹配（包括关闭后同号重开同一 inode），或 canonical chain 中任一 current directory entry 在 pre-proof 或 post-proof 观测点不再指向 retained reference；
- authority 的 pinned permit FIFO 与 spec reference 不一致，或 expected permit FIFO
  不能在任何 init/add-watch side effect 前冻结；
- vocabulary 不完整、不唯一或 parent 不匹配。

### 5.4 Publisher identity binding

READY/ledger 与外部 PERMIT 不能共享一个伪造的 pre-rename capability 模型。前者由 harness 同进程 publisher 持有 retained owner/slot/generation lease，可以使用私有两阶段 capability record；后者在 root 侧另一个进程完成 publication，只能在 commit receipt 到达后由 harness 对 final 建立 retained binding。两条边界不得互换。

#### 5.4.1 READY/ledger：同进程私有 owner

targeted publisher 先构造一个 slot empty/unstarted 的 exact
`_H11RetainedPublicationOwner`；此时 slot lifecycle=`UNSTARTED` 且
`owner._reference is None`。它取得
`_scenario_parent_for_retained_publisher_fixture()` 的 same scenario parent，并调用
完整 chain helper 做紧邻 pre-proof，再调用 typed
`parent.adopt_new_publication(owner=owner, pending_name=exact_pending)`。该方法
内部固定 `O_RDWR|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC` 与 mode `0444`，完成
open→local→owner-slot adoption而不返回 raw FD，并要求 created object uid/gid 等于
`same_parent.ownership_policy` pair。publisher 随后只经该 owner 签发的
publication lease 执行 complete-write、`fchmod_0444` 与 `fsync_file`；每一个
syscall 都在独立 active-use guard 内。publication
lease 不接受 flags/mode/callback，watch set 不代替 publisher 写文件。上述
post-write owner-private step 必须是
`owner._prove_and_bind_pending_reference(parent=same_parent,
expected_bytes=exact_canonical_bytes)`。该 method 自己取得 generation-bound lease，
完整重证 scenario chain/current pending link，以 typed `fstat/pread` 读到 exact EOF，
验证 bytes/size/metadata/identity 与 uid/gid policy pair 后在 local 中构造 path 为 exact planned final name 的
完整 `H11FullFileReference` 并 one-shot STORE；fixture 不构造或传入 reference/hash/
proof token。只有该 internal proof-and-bind 成功后才允许调用
`register_retained_publication`；不得把 unbound owner 交给 watch set。

第一阶段发生在 rename 前。harness publisher 已在自己的 slot 中拥有 pending regular-file descriptor/generation，并以同一个具体、module-private `_H11RetainedPublicationOwner` object 调用 `register_retained_publication(owner=...)`。该方法只接受两个精确 pair：

- `PERMIT_READY.pending` → `PERMIT_READY.json`
- `PERMIT-LEDGER.pending` → `PERMIT-LEDGER.json`

registration 必须在一个未 rename 状态中完成全部证明：先要求
`owner._reference is not None`；以 `_revalidate_h11_parent_chain` 重证
formal→authority→harness→scenario 完整 chain；从同一 owner 取得
generation-bound lease，并要求 lease 的 owner/slot/generation/`OPEN` state 与
owner 当前 slot 精确相等；通过 chain 最后一项 retained scenario lease nofollow
检查 exact pending leaf 与 publication lease `fstat` 的 device/inode 相同；检查 exact
final leaf 不存在；证明 regular-file type/mode，且 pending/reference uid/gid 都等于
same scenario parent 的 shared ownership pair；经唯一
`_pread_exact_h11_publication` helper 用 typed lease `pread` 读取完整 canonical bytes
并冻结 SHA-256。helper 以 typed `fstat` size 为精确边界处理 short read、验证 exact
EOF，并在读取后再次 typed `fstat` 排除 size/metadata/identity 漂移；不得设置 byte
上限或截断。该 proof 构造的 full reference 必须与 owner 已绑定的 exact reference
object equality，不能在 registration 中覆盖或重新 bind。

全部 proof 成功后，watch set 创建一个不可猜测 token 与
`_H11OpaquePublicationCapability(owner, lease, token, pair,
reference=owner._reference)`，从当前
`_aggregate` 预构造只增加该 `REGISTERED` immutable record 的 replacement，最后
经唯一 `_commit_aggregate(operation=same_register_record, expected=current,
replacement=next)` 单字段 seam 发布，再以 same record end gate 后返回。
owner 不保存 token 或 publication phase；该 capability/token 不得由 public
constructor、factory、property、getter、return value、fixture argument 或
exception payload 暴露。caller 只能继续持有并再次提交原 owner object。

READY/ledger fixture 的 failure order 也冻结：child open 前失败时 slot/reference 都
保持 unstarted/unbound；open 后 local→adopt 前失败只关闭 local；adopt 后任一
write/chmod/fsync/internal fstat/pread/reference-construction/
`_prove_and_bind_pending_reference`/register failure
都以同一 primary 调用 owner `abort`，slot 单向关闭且 reference 保持 `None` 或已
绑定值，绝不 clear/rebind。register aggregate STORE 前失败时 capability 不发布；
STORE 后、gate clear 前的既定 async failure 按 aggregate one-shot 规则保留完整 record
再 internal poison；gate-clear→return 只适用 8.4 one-shot exit。
任一路径都不能把 unbound/partially proved reference 写入 capability。

targeted READY/ledger publisher fixture 与未来同进程 publisher 必须取得
`_scenario_parent_for_retained_publisher_fixture()` 返回的同一个 frozen scenario
parent object，并在 register 成功后先以完整 chain helper 做 mutation pre-proof，
再依次调用该 parent 的 typed
`rename_child_noreplace(pending_name=exact_pending, final_name=exact_final)` 与
`fsync_directory()`。这是唯一 pending→final mutation path；两次 syscall 各自由
同一 scenario lease 的独立 active-use guard 完整覆盖。不得使用 `Path.rename/replace`、absolute
pathname、raw dirfd、generic rename callback 或由 watch set 代替 publisher 执行。
紧接的 `bind_retained_publication` 必须成为 mutation post-proof，不得在其间执行
其他 filesystem mutation。

第二阶段发生在上述 no-replace rename 与 scenario parent fsync 完成后。
`bind_retained_publication(owner=...)` 必须要求 current aggregate record 中的
`capability.owner is owner`，其 lease 的 owner/slot/generation/`OPEN` state 与
owner 当前 slot 仍精确相等，并调用同一 owner 的
`_prove_final(parent=..., lease=capability.lease)`：再次以唯一 helper revalidate
完整 scenario chain；再次验证 full identity、canonical bytes 与 SHA-256；经
retained scenario lease nofollow 验证 exact final leaf 是 registration 时同一个
device/inode且 pending 已消失。全部成功后，预构造只把该 record 从
`REGISTERED` 替换为 `FINAL_BOUND` 的完整 logical-immutable aggregate，再经同一单字段
seam（`operation=same_bind_record`）发布并 end same gate。新构造一个字段相同的 owner、复用同一 descriptor/reference 但不同
owner/slot/generation 的 lease、错误 pair、重复 register/bind、token/record state
不一致或 final replacement 都必须在 aggregate mutation 前 poison。

drain 验证 READY/ledger transaction 时只能消费 current aggregate 中的私有
`FINAL_BOUND` record，再次要求 owner、slot、generation 与 token object identity
不变，调用只验证不迁移状态的 owner
`_revalidate_final(parent=..., lease=capability.lease)`。每个 transaction 必须是
同一 batch 中 exact contiguous 的 pending CREATE、同 pending MOVED_FROM、final
MOVED_TO 三行，不得插入任何其他 event；三行共享 capability 的同一
device/inode。`FINAL_BOUND -> CONSUMED` 只体现在整批 next aggregate 的 record，
与 ledger/provisional rows 一起由 `_commit_aggregate` 的唯一 STORE 发布；owner
没有 `_mark_consumed` 或第二个 `CONSUMED` store。无效 batch、pre-commit
failure、poison 或 teardown 不得预先推进 aggregate record。已经 `CONSUMED` 的
owner/token/lease 不得重用或倒退。

`_H11RetainedPublicationOwner` 自身不复制 physical state；其 slot lifecycle 只有
`UNSTARTED -> ADOPT_STARTED -> OPEN -> CLOSED`，reference 只有
`None -> exact H11FullFileReference` 且 close 后也不清除；
`REGISTERED -> FINAL_BOUND -> CONSUMED` 是 watch aggregate 中 capability record
的单向状态机。watch set 不接受 caller 构造的 lease/capability/token，也不从
final path 重建 READY/ledger identity。C3a0 production 中 register/bind 仍是零
caller；targeted fixture 模拟未来同进程 harness publisher，并在 watch 完成或
失败后显式调用 original owner 的 close/abort teardown。

#### 5.4.2 PERMIT：跨进程 committed-final binding

root 侧 PERMIT publisher 与 harness 不在同一进程，harness 不可能共享或验证其 pre-rename owner/token/descriptor。因此 PERMIT 明确不使用 `_H11RetainedPublicationOwner`、pending-stage issuance 或 `_H11OpaquePublicationCapability`，也不要求一个不存在的跨进程 object identity。

后续 C3c 必须先在 harness 侧验证并消费 external PERMIT commit receipt；该 receipt 只证明
exact `b"SCION_H11_PERMIT_COMMITTED_V1\n"` frame 与 commit FIFO handoff。C3c 还必须在
任何 final observation/open 前，从 retained authorizer inputs 与 deterministic PERMIT
construction rules独立构造 exact `H11ExpectedPermitPublication`。只有 receipt 与
expectation 都已 independently validated，才以
`_H11ExternalCommittedPublicationOwner(commit_receipt=same_receipt,
expected_publication=same_expectation)` 构造 `_reference=None`、slot=`UNSTARTED` 的同一个
harness-side owner。不得用 receipt digest/count 填 expectation，也不得先读取 final 后反推
expectation。

owner construction 后，以唯一 helper revalidate 完整 scenario chain，并调用该 scenario
parent 的 typed `adopt_external_final(owner=owner, final_name="PERMIT.json")`。该 method
内部固定 `O_RDONLY|O_NOFOLLOW|O_CLOEXEC`，对 exact final 做 descriptor-relative
open→local→owner-slot adoption且不返回 raw FD，并要求 final uid/gid 等于 same scenario
parent shared ownership pair；随后必须立即调用 exact
`owner._prove_and_bind_committed_reference(parent=same_parent)`。该 owner-private method
只用自己的 generation-bound lease typed `fstat/pread`、完整 scenario chain/final-link proof
与 constructor 已保存的 same expectation；typed read-to-EOF bytes 必须 exact 等于
`expectation.canonical_bytes`，其 SHA/length、schema、semantic identity 与 final role/path
全部一致。receipt 只保持 commit handoff/fifo cross-bind，不能进入 JSON byte proof。
method 在要求 lease/final-link/reference uid/gid 全部匹配 same shared pair后，构造并
one-shot STORE full reference。prove method 只接收 same parent；caller 不得传
bytes/hash/reference/expectation/raw/proof token。

只有该 method 成功后才允许 `owner.borrowed_binding()` 签发
`H11ExternalCommittedPublication(owner, lease,
commit_receipt=owner._commit_receipt,
expected_publication=owner._expected_publication,
reference=owner._reference)`。binding 强引用 exact owner，且
`binding.owner is binding.lease.owner`、`binding.commit_receipt is
owner._commit_receipt`、`binding.expected_publication is owner._expected_publication`，
slot/generation/`OPEN` state 与 reference 必须一致。它是 commit 后的 retrospective
retained-final authority，不声称 pre-rename issuance。

`H11ExternalCommittedPublication.revalidate(parent=...)` 必须先证明 binding/owner/lease/
receipt/expectation/reference 全部是上述 same exact objects，再执行 full-chain/final-link 与
typed lease `fstat/pread`；publication bytes只和 expectation比较。它可以验证 receipt 自身仍
是 exact fixed-frame typed value及 FIFO cross-bind，但 receipt digest/count 不得进入 JSON
comparison。任一 equal-but-not-identical replacement、owner field drift或 content mismatch
都在返回前失败。

C3a0 只冻结 receipt/expectation/owner/binding boundary 与 targeted local fixture，不读取 raw
FIFO、不实现真实 receipt consumer或 production expectation derivation，也没有 production
constructor caller。targeted fixture 必须先从独立 canonical fixture input 构造 expectation，
再用 `same_expectation.canonical_bytes` 完成真实 pending write/rename final与模拟 commit；随后
构造只验证 fixed FIFO frame 的 typed receipt，再把 same two objects交给明确 external owner，
并仍通过 retained scenario parent typed `adopt_external_final` 打开真实 final、由该 owner
签发 binding。fixture 不得从 final `stat/open/pread` 或 reference构造 expectation，不得只
拼装 path/reference、返回 ownerless raw descriptor或绕过 retained lease。fixture 在 drain
返回后显式 close owner，构造/drain 失败则显式 `abort(active_error=...)`；watch set 不替它
teardown。真实 receipt 消费、retained authorizer input选择、deterministic PERMIT serializer、
production expectation builder与 owner creation/teardown caller 均由 C3c 设计冻结后实现；
冻结前不得接入 production。

external fixture 的 failure order 同样冻结：independent expectation construction 必须在
任何 write/rename/final observation 前；expectation、publisher write/rename、fixed-frame
receipt validation或 owner construction failure发生时尚无成功 owner。owner construction
成功后的 chain proof failure 必须 abort owner；child open pre-adopt failure先关闭 local再
abort owner；adopt 后任何 internal expectation/fstat/pread/final-link/reference-construction/
`_prove_and_bind_committed_reference`/binding-construction
failure 都以同一 primary `abort` exact owner。`borrowed_binding` 必须在任何 binding
allocation 前拒绝 unbound/rebound/closed owner、receipt/expectation identity drift，只读
owner 中 same receipt、same expectation 与已绑定 reference；失败时不得返回 partial
binding、清除 reference 或把 caller bytes/hash/reference/expectation 写入 owner。

targeted fixture 取得 scenario parent 的唯一方式是 private frozen
`watch_set._scenario_parent_for_external_fixture()`；它只返回 `_bindings` 中同一个
immutable scenario parent object，不构造新 lease、不返回 raw FD，production
caller 为零。后续 C3c 必须在自己的接入设计中冻结 production owner builder，
不能把该 fixture seam 提升为 public API。

`drain(external_permit=...)` 仅在当前 batch 含 exact same-batch contiguous
`PERMIT.pending` CREATE、同 pending MOVED_FROM、`PERMIT.json` MOVED_TO 三行时接受一个
binding。它必须同时 cross-bind：共享队列中的三事件；binding 的 exact external owner
identity及其 owner/slot/generation/`OPEN` lease；owner 与 binding 强引用的 same exact
validated receipt object；owner 与 binding 强引用的 same exact internally consistent
`H11ExpectedPermitPublication` object；receipt 的 exact `permit-committed` phase、fixed
`SCION_H11_PERMIT_COMMITTED_V1\n` frame digest/count，以及 receipt `fifo` 与 watch set 在
`open(authority)` 时冻结的 `_expected_permit_fifo` 完整 immutable reference exact equality；
retained final lease 的 typed read-to-EOF bytes/SHA/length 与 same expectation 完整相等；以及
retained scenario parent 下 exact final link 的同一 inode。receipt digest/count 与
expectation digest/count 属于不同 domain，drain 不得比较两者相等或用前者替代后者。
三行写入相同 device/inode。本批含 PERMIT 而 binding 缺失、无 PERMIT 却传入 binding，
owner/lease 已关闭或被同号同 inode reopen，receipt FIFO 只与 external binding 自称一致却
不等于 authority-frozen expected FIFO，receipt不是 fixed-frame proof，expectation内部不
一致/不是 owner same object/与 final bytes不符，或 receipt/expectation/pair/owner/slot/
generation/reference/final link 任一不符，都必须 poison。watch set 不自行读取 FIFO、从
raw bytes构造 receipt或从 observed final构造 expectation；`H11RuntimeOpenAuthority.drain`
也只转发参数，因而此验证不把 C3a0 扩张成真实 receipt consumer或 production expectation
builder。

## 6. 单队列 drain、ordinal、cookie 与 identity

### 6.1 单次 drain 规则

`drain()` 不得接受 `parent_role` 或任何等价 selector。它必须：

1. 在任何 queue read 或其他私有 state mutation 前通过 creation-thread/idle/live
   checks，并安装唯一 exact `kind="drain"` active-operation record；该 same record
   覆盖后续全部步骤直到 success end 或 active-operation poison；
2. 分别以唯一 helper 完整 revalidate 四个 typed parent chains；
3. 对唯一 inotify descriptor 做一次 `FIONREAD`，取得当前队列字节快照；
4. 若快照为零，要求没有未使用的 `external_permit` committed binding，再清除 exact
   active record并返回空 tuple；
5. 若非零，对同一 descriptor 做且只做一次精确长度 `os.read`；
6. 按返回字节流从头到尾解析 raw inotify records；
7. 用每条 record 的 watch descriptor 从 closed mapping 唯一确定 parent role；
8. 先通过唯一 `_validate_complete_batch` helper 在临时 batch 中完成全部 schema、mapping、mask、cookie、order、object type 与 identity 验证；只有该 helper 可以调用 provisional pin；
9. 在每个 borrowed parent lease 的最后使用点再次以 `_revalidate_h11_parent_chain` 重证相关完整 chain，并 revalidate READY/ledger private issuance record 或 exact-owner external committed-final binding；
10. 仅当整批有效时，先在 local 中完成所有 event rows/ordinals、provisional identities、publication `CONSUMED` records、frozen typed return snapshot 与完整 logical-immutable replacement aggregate；任何 allocation、encoding、copy 或 equality check 都必须在 private state mutation 前结束；
11. 调用唯一 `_commit_aggregate(operation=same_drain_record, expected=current,
    replacement=next)` seam；它先要求 current creation thread、
    `self._active_operation is operation` 与 exact owner/kind/token，再以 object identity
    要求 `self._aggregate is expected`；其唯一 state mutation 是一条
    `self._aggregate = replacement`，没有 owner-phase store、container mutation、
    callback、helper、log 或 syscall；
12. assignment 后唯一允许的动作是
    `_end_operation(operation=same_drain_record)` 验证并清除 exact gate，再直接返回
    已经预构造的本批 frozen `tuple[H11AuthorityEventSnapshot, ...]`；不得再执行 proof、
    allocation、aggregate/owner phase transition 或任何其他 mutation。

`FIONREAD` 只是一次有限队列快照，不是轮询机制。实现不得循环等候更多事件，也不得因为证据缺失而再次读取。尤其是 rename pair 只能在 publisher 已完成 rename、retained parent fsync，并且在该 transaction 定义 commit handoff 时也已完成 handoff、没有并发 publisher 的确定静止协议点 drain；不得在 rename 进行中 drain 后等待 pair 的另一半。缺少必需事件或 batch 在快照边界截断 rename pair时立即 poison/fail closed，由调用协议错误负责，不能重读补齐。

如果 `read()` 返回字节数与快照不一致，或者 raw buffer 被截断、record 长度非法、name 缺少合法终止/编码，必须 poison 并 fail closed。

这里的“单字段 commit”是诚实的 Python object-reference STORE 边界，不宣称
屏蔽异步异常、信号或提供硬件事务。STORE 前可达状态完整是 old aggregate，
STORE 后可达状态完整是 replacement；不存在逐行 append 或多个 owner/map
writer 可见的中间 aggregate。若 `KeyboardInterrupt` 等发生在 STORE 前，旧
aggregate 保持不变；若发生在 STORE 后、return 前，replacement 已提交，但
在 matching gate clear 之前到达 established handler 时，仍由 same drain record 的
internal poison seam terminalize/teardown；若第二个异步异常精确命中
`_end_operation` 已清 gate到 Python public return 之间，则不能伪造旧 active record或
安全重进 poison，正式合同只能是调用失败并 official one-shot exit，authority 不得
reuse。两种情况都不得重读已消费 queue或让同一 owner/token/binding 再次提交。测试和
文档只能声明这一精确边界，不得声称 Python 能消除 STORE/gate-clear/return 周围所有
异步窗口。

### 6.2 Event schema

每个 private ledger record 与 public frozen `H11AuthorityEventSnapshot` 必须恰好
包含以下字段：

```text
ordinal
parent_role
name
mask
cookie
device
inode
```

所有值必须是 canonical scalar strings。不得附加时间戳、来源 helper 名、drain 次数或其他非权威字段。public `events`/`drain` 不得把这些字段复制到 mutable dict；只允许 frozen typed row，或等价实现中逐行独立 `MappingProxyType`，本文冻结实现选择前者。

`ordinal`：

- 从既有 ledger 的下一整数开始；
- 严格连续、单调递增；
- 只按单一 raw queue record 顺序分配；
- 不因 parent、semantic role 或预期协议顺序重排。

多次 drain 共享同一 ledger，后一次从前一次末尾继续编号。

### 6.3 Mask 与 fatal events

可接受的业务事件只有单一语义的：

- CREATE
- MOVED_FROM
- MOVED_TO

raw mask 可以含一个受控 modifier：`IN_ISDIR` 只允许出现在 `(formal-root, frozen)` 的 CREATE event 上。该事件必须通过 retained formal-root lease 做 nofollow relative open，证明 observed leaf 是目录并记录其 provisional device/inode；ledger 的 canonical `mask` 仍写 `CREATE`。其余 19 个 leaf 一旦出现 `IN_ISDIR` 必须失败，并且必须证明它们是 regular files。

除上述唯一 modifier 外，未知业务 mask、多个业务位的模糊组合或附带无法解释的位必须失败。以下 fatal 状态一经观察，无论是否与业务位组合，都必须 poison 并 fail closed：

- DELETE
- DELETE_SELF
- MOVE_SELF
- UNMOUNT
- Q_OVERFLOW
- IGNORED

未知 watch descriptor、已删除 mapping 或未知 `(parent_role, name)` 同样是 authority violation，不能丢弃为噪声。

### 6.4 Cookie 约束

- CREATE 的 cookie 必须为 canonical `"0"`；
- READY、ledger 与 PERMIT 三类 transaction 都必须在同一次 drain 的同一 raw
  batch 中形成 exact contiguous triple：pending CREATE 后一条必须是同一
  pending 的 MOVED_FROM，再后一条必须是获准 final 的 MOVED_TO；三行之间不得
  插入任何其他 parent/name/mask event，也不得跨 drain；
- MOVED_FROM 与紧邻的 MOVED_TO 必须拥有同一非零十进制 cookie；
- rename pair 必须是 closed vocabulary 中获准的 pending/final pair；
- pair 不得跨越其他事件、跨 drain 临时悬挂或事后配对；
- 在当前 batch 中，一个非零 cookie 只能标识当前紧邻且尚未闭合的 pair，任何同时未闭合或当批产生歧义的重用都必须失败；
- pair 一旦在同一 batch 内完成相邻闭合，其 cookie 不进入跨 batch 的全局 `seen-cookie` authority；内核后续 batch 合法重用相同数值必须允许。

任何缺失 triple 中一行、pending CREATE 与 rename pair 间插入事件、跨 drain
拆分、顺序颠倒、cookie 为零、cookie 不同或不相邻的 transaction 都必须失败。

### 6.5 Identity binding

每条已接受事件都必须得到 canonical decimal device/inode。identity 分为 retained transaction identity 与 provisional non-transaction identity，两者不得混用。对于三步 publication transaction，以下三行必须位于同一 batch 且 raw ordinal 位置连续：

1. pending CREATE；
2. pending MOVED_FROM；
3. final MOVED_TO；

三行必须绑定到同一个 retained lease identity。

- READY 与 ledger 使用 watch set 在 rename 前为同一个 private owner 建立、rename 后转为 `FINAL_BOUND` 的私有 aggregate record；record 中 opaque capability 的 owner/slot/generation lease 与 full reference 是 transaction identity 基线，drain last-use 必须通过完整 scenario chain helper、owner/token/slot/generation object identity、`fstat`、`pread` 与 chain 末端 scenario lease nofollow final-link proof 共同 revalidate；
- PERMIT 使用本次 drain 显式传入的 `H11ExternalCommittedPublication`；它不携带 pre-rename
  issuance，而是把只证明 fixed FIFO frame的 validated commit receipt、independently
  prebuilt expected-publication content authority、同一个 harness-side owner及其 retained
  generation-bound final lease/full reference，与经过完整 scenario chain proof 的 current
  final link绑定到同一提交；
- transaction pending 已在 rename 后消失，不得通过 pending pathname 猜测 identity。

非 transaction CREATE，包括 H0、run-main-properties、authorization、其余 manifest output 和 frozen-root，必须在完整 raw batch 已证明不存在对应 DELETE/MOVED_FROM/第二次 CREATE/替换事件后，通过唯一 helper 执行一次 descriptor-relative provisional pin：

```text
openat(retained-parent-dirfd, exact-leaf,
       O_PATH|O_NOFOLLOW|O_CLOEXEC)
-> fstat type/device/inode/mode/uid/gid
-> close only the transient provisional descriptor
```

上述 pin 紧邻前必须通过 `_revalidate_h11_parent_chain` 完成从 formal root 到 retained target parent 的完整 last-use proof，再由 exact parent 的 typed `pin_provisional_child(name=exact_leaf, expected_type=...)` 在 target-slot active-use guard 内完成整段 open/fstat/close。这是 chain 末端 retained-parent descriptor-relative open，不是 lexical/path parent reopen。禁止重新解析 parent path、调用 `Path.open()`、以完整 pathname打开 observed leaf、缓存 borrowed raw integer，或由 caller 提供替代 parent。regular-file leaf 必须证明 regular；`formal-root/frozen` 必须证明 directory 且 raw event 含 `IN_ISDIR`。
该 provisional fstat 的 uid/gid 还必须精确等于 parent 的 shared ownership pair；caller
不能为 observed leaf 传入或放宽 owner pair。

该 provisional descriptor 只存在于 directory lease 的
`pin_provisional_child` frame，由该 sealed method 在一次 active use 内临时拥有。它
必须使用 local `descriptor = -1` discipline：成功 open 后第一项 ownership action
是 local STORE；进入任何 close syscall 前先 move 到 immutable closing local 并把
owner local 置 `-1`；随后恰好调用一次 `os.close`，无论成功或失败都不得 retry。
若 open 失败则没有 owned FD，不执行虚构 close。若 fstat/type/identity validation
已有 primary，close failure 只能按发生顺序附为该同一 primary 的 note；若 operation
成功而 close 失败，该 close failure成为 primary。method 只返回 frozen child
identity，不返回 descriptor；所得 primary 传播到仍持有 exact drain record 的 outer
exception boundary，随后只传给
`_poison_from_active_operation(operation=same_drain_record,
active_error=primary)`，不得调用 public poison，也不得被 watch teardown failure替换。

provisional 双故障测试必须覆盖：open failure；open 后 fstat failure；type/identity failure；成功 validation；并为后三者分别覆盖 close success 与 close failure。断言 transient close 最多一次且 syscall 前已 detach、primary object identity 不变、secondary note 顺序固定、没有 retry、没有 provisional/ledger partial commit，并且 borrowed parent descriptor 仍可 `fstat`。底层 close failure 后 FD 的内核状态不可恢复时只能记录 evidence，不能声称已修复或用重试冒险关闭复用 descriptor。

provisional `(parent_role, leaf, device, inode, type)` 只作为 watch observation 保存到下一 logical-immutable aggregate 的 provisional records 和 event row。H0、run-main-properties、authorization 以及后续 output/frozen source 必须在后续 protocol slice 与各自 retained full reference cross-bind后才能成为最终 evidence；C3a0 不得把 provisional pin 宣称为 source authority。

同字节 replacement 不能逃逸：原对象被 DELETE/MOVED_FROM、替代对象被 CREATE/MOVED_TO 时，完整 batch 的 fatal/非 transaction rename/second-create 规则先失败；若 queue overflow 则直接失败；若路径在 provisional pin 或后续 cross-binding 前更换，device/inode 与 saved provisional identity 不同而失败。后续 cross-binding 不得覆盖或重写 provisional identity。

C3a0 还必须执行 batch-local semantic-object alias 检查。semantic object key 的定义固定为：每个 non-transaction CREATE 的 `(parent_role, leaf)` 是一个对象；每个获准的 pending/final transaction pair 是一个对象，三行共享同一个 key。完整 batch validation 建立临时 `(device, inode) -> semantic object key` 映射；同一 identity 若被不同 semantic object key 使用，必须以 hardlink/alias violation 失败。由同一 transaction 产生的三行共享 identity 是唯一的行级重复许可。不同 parent 使用相同 leaf 名仍然允许，只要 identity 不同。

该规则只封闭当前 drain batch，不能伪称已经实现跨 drain 的全局 alias authority。后续 cross-binding slice 必须把完整 ledger、provisional identities 与 retained full references 汇合，在 evidence/release 前对全部 authority semantic object 做最终全局 identity uniqueness enforcement；它只能比较并拒绝 alias，不得覆盖既有 device/inode。因而跨 batch hardlink 仍由后续 slice 关闭，而不是由 C3a0 静默接受为最终 evidence。

不得以 lexical pathname 重新打开 parent 或 leaf 来获取权威 identity，不得在观察后用一个新 owner/slot/generation 替代原 retained lease，也不得只比较内容哈希或 device/inode 来替代 original-generation binding。

### 6.6 事务性 ledger

raw queue 一旦被读取就已消费。因此 C3a0 必须先验证整个新 batch，再修改 ledger。若 batch 中任意一行无效：

- 本批一行也不得追加；
- `self._aggregate` 必须仍 `is` entry 时的同一个 logical-immutable object；其中
  ledger、provisional records、publisher record topology/reference/token identity
  均不变；外部 owner/slot liveness 另行验证，不属于 deep-immutable 声明；
- READY/ledger physical owner 只做 lease proof，本来就没有 publication phase
  mutation；
- watch set 进入 poisoned 状态并关闭自有 watch 资源；
- 后续 register/bind/drain 必须拒绝执行。

不能重试消费过的队列，也不能跳过坏行后继续建立“部分有效”历史。

`register_retained_publication`、`bind_retained_publication` 与 valid batch commit
都遵循相同 replace discipline：读取一个 expected aggregate；在 local 中构造
完全独立、logical-immutable 的 replacement；完成全部可能失败的 proof、allocation
与 snapshot construction；最后调用唯一 `_commit_aggregate`。该 helper 的
qualified caller 只有上述三个入口，body 中 state Store 精确一条，目标精确为
`self._aggregate`。不得对 aggregate 内部 tuple/mapping/row 做 in-place mutation，
不得在 owner 上复制 publication phase，也不得用“先改 owner、再补 ledger”或
失败补偿恢复。pre-STORE failure 保持 old aggregate object identity；post-STORE
async failure 保留完整 replacement 并立即结束 one-shot authority，不能回退、
重试或部分发布。

## 7. 预期 H11 全序

后续 protocol slice 将基于同一 ledger 验证以下成功前缀：

| ordinal | parent/semantic event |
| --- | --- |
| 1 | H0 CREATE |
| 2 | run-main-properties CREATE |
| 3 | READY pending CREATE |
| 4 | READY pending MOVED_FROM |
| 5 | READY final MOVED_TO |
| 6 | authorization CREATE |
| 7 | PERMIT pending CREATE |
| 8 | PERMIT pending MOVED_FROM |
| 9 | PERMIT final MOVED_TO |
| 10 | ledger pending CREATE |
| 11 | ledger pending MOVED_FROM |
| 12 | ledger final MOVED_TO |

C3a0 不负责执行这些 production protocol 动作，但其纯本地测试必须证明以下准确
chronology：先跨 parent 创建 H0 与 run-main-properties；READY fixture 以 scenario parent
typed `adopt_new_publication` 创建 pending并保持 lease/owner，调用 owner internal pending
proof-and-bind（只传 same parent/canonical bytes）后才在 rename 前 register 同一 owner，再以
同一 parent 的 typed `rename_child_noreplace` 与 `fsync_directory` 完成 publication 后 bind
同一 owner；再创建 authorization。external fixture 必须先从独立 canonical fixture input
构造 internally matching `H11ExpectedPermitPublication`，且此时尚未 write/rename/stat/open/
pread PERMIT final；模拟 root publisher 只用该 expectation 的 canonical bytes 完成 PERMIT
pending write与 rename final，再模拟 exact fixed-frame commit 并构造 validated typed receipt。
随后以 same receipt + same expectation 构造明确 external owner，经 retained scenario parent
typed `adopt_external_final` 打开 final，调用只接收 same parent、无 caller bytes/hash/
reference/expectation/raw 的 owner internal committed proof-and-bind，最后构造同时强引用
same receipt/expectation 的 explicit-owner binding。中间不 drain，第一次把该 external
binding 传给 drain，必须得到 1–9 的真实共享队列顺序。之后 ledger fixture 走同一 typed
pending/write/internal-proof-bind/register/rename/fsync/aggregate-bind path，第二次不带
external binding 的 drain 必须得到连续 10–12。READY、PERMIT 与 ledger 各自三行都必须
在所属 drain batch 内 raw-position exact contiguous；positive chronology 不能替代插入事件、
跨-drain split、receipt/publication-domain confusion或 expectation self-sign negative tests。

测试不得通过交替 write/drain 来预制顺序，不得把 external PERMIT 伪装成 pre-rename shared owner，也不得使用 sleep、poll 或用户态时间戳。

## 8. 失败、poison、close 与 FD rollback

### 8.1 构造失败回滚

若 `inotify_init1`、任一 add-watch 或后续 unpublished validation 失败，`open` 捕获
原始 exception object，且只能调用
`_rollback_open(operation=exact_open_record, active_error=primary)`。rollback 在任何
field mutation 或 syscall 前验证 current creation thread、`self` identity、exact
active record identity/kind/token；随后先把 `_poisoned=True`、`_closed=True` 写成
terminal state，再以一条 `_active_operation=None` STORE 消费 open gate，最后调用
`_close_owned_watches(active_error=same_primary)`。rollback caller 不得读取、复制、
清空或把 `_descriptor/_active_watch_descriptors` 作为 argument 传给 helper。

`_close_owned_watches` 是 watch set 自有 raw teardown 的唯一 method frame，也是
`inotify_rm_watch/os.close` 的唯一 caller。它在任何 rm/close syscall 前要求 current
thread 等于 `_thread_id`、`_closed is True`、`_active_operation is None`；随后在本
frame 无 helper/callback/syscall 地，以一次 destructuring local assignment 从
`(self._active_watch_descriptors, self._descriptor)` 取得 immutable
`(owned_watch_descriptors: tuple[int, ...], owned_descriptor: int)` snapshot，紧接着以
一次 owner-field destructuring assignment 把二者清空为 `((), -1)`。两项 owner field
都完成 detach 后，raw locals 只能
在这个同一 `_close_owned_watches` frame 内按逆序逐项调用一次 rm，再对 nonnegative
descriptor 调用一次 close；raw local 不作为任何 helper parameter/return/container
escape，也不能由 rollback/poison/close caller 预先 detach。前一 rm 失败不能中止
sweep，任何 rm/close 都不 retry。存在 active primary 时，各 secondary 按发生顺序
直接 add-note 且 helper 返回 same primary；close-only path 则第一项 teardown failure
成为 primary、其余成为 notes。helper 不读取或修改 aggregate、mapping 或 borrowed
owner/slot，并且绝不返回 raw integer。

`_active_watch_descriptors` 在所有可达状态都必须是 insertion-order、pairwise-distinct 的
exact nonnegative-int tuple；teardown 不以 `set`/mapping/registration 重建、补充或去重
inventory。因而 reverse sweep 对 snapshot 中每个 wd 只有一个 syntactic/dynamic
`inotify_rm_watch` attempt：第一个 rm 失败也只能记录 failure 并继续下一个不同 wd，不能
再次调用同一 wd。`_watch_to_parent` 与 `_bindings` 只描述已接受 registration，既不授予
第二份 physical ownership，也不是 teardown fallback inventory。

init 自身同步失败时 self fields 仍是 `-1/()`，helper 不执行虚构 syscall。第 N 次
add-watch syscall 自身同步失败时，只有前 N-1 个成功、fresh 且已经 STORE 到 owner field
的唯一 watch 进入 exhaustive inventory。第 N 次 return 后的 post-proof、type/range/
freshness validation failure 也不得接受该 returned wd：invalid returned value 不入 inventory；
duplicate value 只保留此前已经存在的那一份 inventory entry。尤其 duplicate primary 的
rollback snapshot 永远不含同一 wd 两次，即使针对该 wd 的首次 rm 失败，也不得发生第二次
same-wd rm attempt。若 fresh wd 已完成 inventory STORE，随后 mapping/registration build、
STORE 或 final four-registration consistency validation 失败，则它已是 owned inventory 的唯一一项并须恰好
一次 rm；若四次 add-watch 已登记后 final validation 失败，则四个 distinct watches 全部
进入 inventory。

精确落在 init return→`self._descriptor` STORE，或 add-watch return→post-proof→local
type/range/freshness validation→fresh owner-inventory STORE 的异步间隙，可能留下尚未能以
新 inventory entry 显式枚举的 kernel effect；前者只能依赖 official one-shot process
exit，后者因 inotify descriptor 已登记，在一次正常进入 rollback 时至少由同一 inotify
FD close 移除。若 returned wd 是 duplicate，旧 inventory 已经且仍然只含它一次；不得为
覆盖该间隙追加第二份或重试 rm。因此设计不得要求或测试“未登记 fresh watch 也显式 rm”，
只能要求所有既有唯一 inventory entries 各 rm 一次、已登记 inotify FD close 一次以及
abrupt/repeated interruption 时 official one-shot process exit 最终回收。

双故障测试矩阵必须覆盖 N=1/2/3/4 的 add-watch syscall failure、invalid return/freshness
failure 与 post-inventory mapping/registration failure，并对每个 N 注入：无 rollback
failure、一个 rm failure、多个 rm failure、close failure、多个 rm 加 close 同时失败。
另在 N=2/3/4 令 returned wd duplicate 一个 earlier accepted wd；断言 primary 出现在任何
append/related Store 前，snapshot 仍只有 earlier unique entries，且即使 reverse sweep 对
该 duplicate 对应 wd 的第一次 rm 失败，也没有第二次 same-wd call。全部矩阵都断言
rollback 先 terminalize 并消费 exact open gate、caller 未接触 raw、helper 自己在 syscall
前提取并清空两个 owner fields、所有 inventory watch 恰好访问一次、close 恰好一次、没有
retry、primary object identity 保持、secondary notes 顺序稳定、所有借用 leases 仍能经
original owner/slot/generation proof 后 `fstat`。final mapping/registration validation failure
使用同一矩阵覆盖四-watch distinct完整 sweep。

这是局部 FD rollback，不是 filesystem evidence cleanup。不得删除、重命名或改写任何 formal/input/receipt/scenario 文件。底层 close 返回错误后 descriptor 的内核状态可能不可恢复；设计只保证 detach、一次 close、保留 primary 和绝不因重试误关复用 FD，不能伪称 close error 已被修复。

### 8.2 运行期失败

register/bind/drain 中 decode、mapping、mask、cookie、identity、byte-count、owner proof、
aggregate build 或 batch validation 的普通同步失败，两个 fixture accessor 在 begin 后的
binding/policy validation failure，以及单次投递并到达该 active
operation outer exception boundary 的 `BaseException`，都必须捕获原始 object，并调用
exact `_poison_from_active_operation(operation=same_record,
active_error=same_primary)`。它按 5.1 的冻结顺序验证并消费调用者自己的 active gate，
terminalize 后才调用 `_close_owned_watches(active_error=same_primary)`，最终重新抛出
同一个 primary。active operation exception path 对 public `poison` 的 callsite 为零；
因此不会递归 acquire 自己持有的 nonreentrant gate。8.4 所列 CALL→STORE、重复投递
或 handler/teardown interruption 不属于“均可捕获”的虚假声明。

该 path 不改动当前 logical-immutable aggregate；若异常发生在唯一 aggregate STORE
之前，保留 old aggregate identity；若发生在 STORE 之后，则保留已经完整发布的
replacement，不倒退。它不关闭 borrowed owners/slots、不删除 evidence。所有 raw
watch/descriptor detach 与 rm/close 仍只发生在 `_close_owned_watches` 自己的 frame；
active poison seam 及其 caller 都不接收或保存 raw locals。被 queue-consumption
failure 触发时，该 failure 永远是 top-level primary，rm/close failure 只能成为它的
ordered notes。

运行期双故障测试必须分别选取 READY/ledger register/bind owner/lease failure、external
receipt fixed-frame/fifo cross-bind failure、expected-publication internal/content/object-identity
failure、external committed-binding owner/lease/reference failure、两个 fixture accessor 的
policy/binding failure、raw/decode/batch failure、provisional identity failure，以及
next-aggregate 每个构造步骤的 failure 作为 primary，并叠加一个 rm failure、多个 rm
failure、close failure、多个 rm 加 close failure。receipt 与 expectation failures必须作为
两个独立 domain 注入，不能以一个共同 digest mismatch case代替。每种 pre-STORE 情况都
必须断言 `_poison_from_active_operation` 接收/消费 exact record与该 caller 的 exact kind、
重新抛出同一 object、`self._aggregate is old`、helper 自己 detach fields、所有 teardown
secondary failures 直接按序出现在该 object 的 notes、完整 sweep 只发生一次且借用 owners/
slots 存活。另以 private seam test 精确覆盖 successful single STORE 后、matching gate clear
前的 simulated async failure：replacement 全量可见、无 partial row/record、authority
terminal 且不可重入，不得回退或第二次 commit；gate-clear→return gap 只按 8.4 one-shot
contract验收。

显式 idle `close()` 没有既有 operation failure 时，先安装并消费自己的 exact close
record、置 terminal，再由 helper 自己提取/清空 raw fields；第一个 rm/close failure
成为 teardown primary，其余作为 ordered secondary notes。即使抛错，helper 返回前
`_closed=True`、`_active_watch_descriptors=()` 和 `_descriptor=-1` 已成立，因此再次
close 不会 retry。runtime post-watch/pre-wrapper failure 对 public idle
`poison(active_error=primary)` 的唯一调用遵循相同顺序并重新抛出 same primary。

### 8.3 幂等性

`close()` 与 public `poison(active_error=...)` 的自有 watch 资源状态转换必须幂等。
close 后 register/bind/drain/fixture access 必须失败。terminal idle owner 的再次 close 是
no-op；再次 public poison 只重新抛出本次显式 primary，不得复用或改写前一次 failure，
两者均不再次调用 helper。若 exact active record 尚未被它的 operation failure seam
消费，任何 reentrant close/poison 必须零 mutation/syscall 拒绝，不能借幂等性清除
别人的 record。即使 remove-watch 返回“已移除”，首次 teardown 最终仍必须关闭自有
inotify descriptor，并保持借用 owners/slots 可由其 original owner 正常访问和显式
close/abort。publication owner 的四个 qualified close/abort 都必须先 preflight single slot，成功后才 detach-before-close、最多一次 syscall且幂等；它们不由 watch teardown 自动调用，也不删除 staging/final evidence。

### 8.4 同步保证与不可结构化异步边界

C3a0 的 exhaustive rollback、primary preservation、active-use release 与 logical
aggregate 原子替换，保证范围是普通同步执行，以及一次确定性注入且进入既定
`except BaseException`/`finally` 边界的单个 `BaseException`。测试可以在冻结的
且仍持有 exact operation record 的 established boundary 只注入一次预构造
`KeyboardInterrupt`、`SystemExit` 或其他 `BaseException`，证明同一 primary、一次
internal poison/teardown 与 one-shot rejection；命中后文不可结构化 gap（特别是
gate-clear→return）只证明 abrupt one-shot exit，不保证 poison。不得把该测试解释成
可抵御任意重复异步投递。

纯 Python 不能把以下 kernel effect、local/slot STORE 与异常 handler 入口合并为
不可中断原子操作：

1. `inotify_init1` 已返回 owned FD，到 unpublished owner 的 `self._descriptor` STORE；
2. `inotify_add_watch` 已在 instance 上安装/更新 watch，到 return value 进入 local、
   same-parent post-proof、exact-int/nonnegative 与 inventory/mapping/registration freshness
   validation，再到 fresh wd 写入 owner `_active_watch_descriptors` inventory；若 return 是
   duplicate，旧 inventory 仍只含该 wd 一次，不能以第二次 append 伪造这个 gap 已关闭；
3. `ExecutionManifestSource.open_once` 的 formal-root lexical acquisition，九次
   `adopt_owned_child`，以及 `adopt_new_publication`、`adopt_external_final` 或
   `pin_provisional_child` 内 child `os.open` 已返回 FD，
   到 method-local `descriptor` STORE；除 transient provisional pin 外，还存在
   local owner 到 exact slot adoption 的下一边界；一旦 adopt 已写
   `ADOPT_STARTED`，后续异步中断只能 one-shot 退出，不能恢复或 re-adopt；
4. `_begin_use` 已登记 active use，到 typed syscall 返回并由 `finally` 执行
   `_end_use`；一次进入 method 的异常必须 release guard，但第二个异步异常若命中
   cleanup 本身，纯 Python 不能承诺 cleanup 完成；
5. FIFO-pin blocking endpoint `os.open` 已返回到 method-local STORE、one-write/read
   kernel effect 到 exact byte/frame validation，以及 endpoint detach 到 single close；
   这些边界不允许 endpoint/retry 恢复，active authority invocation one-shot 失败；
6. `_begin_operation` 已 STORE exact active record，到 operation 的 proof/syscall/commit
   完成并由 success `_end_operation` 清除；一次已捕获 operation failure 会经 exact
   internal seam terminalize、消费 same record 并进入 teardown，但第二次异步投递可
   命中这些 state STORE 之间，或命中 success gate clear→public return gap；设计不能
   承诺在同进程恢复一个半清除/刚清除 gate，也不能伪造旧 record 后再 poison；
7. outer exception boundary 已捕获 primary，到调用 active-operation poison/public
   idle poison/rollback 并完成 terminalize、gate consumption 与 teardown；再次异步
   投递可以打断 failure handling；
8. `_close_owned_watches` 已在自己的 frame snapshot raw owner fields，到清空 owner
   inventory/descriptor，再到对应 `rm_watch/os.close` 真正完成。raw locals 仍不得
   移交另一 helper；第二次异步投递命中任一段时只能 one-shot exit。

实现只能让正常返回后的下一 ownership action 是相应 STORE/adoption；add-watch 则必须
先完成不可省略的 post-proof 与纯 local/readonly freshness validation，fresh value 的下一
ownership action才是唯一 inventory tuple replacement。creation-thread/exact operation
record 排除正常并发和递归 entry；已登记资源在单次同步 failure 中 exhaustively
teardown，fresh add-watch 未登记窗口最终由同一 inotify FD close 移除，duplicate 则只按
旧唯一 inventory rm 一次。thread confinement/nonreentrant gate 不是 signal mask，
不得把它写成异步异常原子性；实现也不得以临时 handler、retry、poll、finalizer 或
callback 伪称关闭这些间隙。若异步异常精确命中上述间隙或重复命中 teardown，正式
合同是当前 authority invocation 立即非成功终止、不得
reuse/drain/retry；official one-shot 进程退出后由内核回收仍存活的进程 FD 与
inotify watches。不得在同一进程/authority 上继续第二次 root protocol。

跨 private method/ownership boundary 的 raw descriptor AST edge 也必须精确等于三类：
每个 directory/publication lease 或 FIFO-pin typed method 自己调用 `_begin_use` 并在
同 frame 消费其 return；formal-root lexical local、九次 `adopt_owned_child` sealed
local 与两个 sealed publication adoption 把 owned local 传给 exact slot `adopt`；
其中 `adopt_owned_child` 的 parent borrow 是第一类 seam、new child adoption 是第二类
seam，不新增 handoff category。watch-set owned inotify descriptor 沿 exact parent
delegation 传给 lease `add_watch`。FIFO endpoint、`_close_once`、provisional local
close 中的 raw 值都只存在于各自 owner method frame并直接进入 syscall；watch
teardown raw 则只允许 `_close_owned_watches` 在自己的 frame 从 self fields 提取、
清空并直接消费。rollback/active-poison/public-poison/close caller 向该 helper 传递 raw
argument、return 或预先 detached local 的 edge 必须为零；这不是第四类 cross-helper
raw seam。
任何把 borrowed directory/publication/FIFO-pin FD 作为其他 method/function 参数或 return，
或把上述三类误报为“一切 raw int parameter/return 均为零”的 AST 规则，都不合格。

`H11RuntimeOpenAuthority.open` 的 post-watch failure path 只能调用一次上述
`watch_authority.poison(active_error=same_primary)`；该 path 对
`H11AuthorityWatchSet.close`、第二次 poison、authority/FIFO close 的 callsite
必须为零。成功 wrapper construction 后才允许 `H11RuntimeOpenAuthority.close ->
H11AuthorityWatchSet.close`。

`H11RuntimeOpenAuthority.drain` 的 exact signature 只能是 `drain(*, external_permit: H11ExternalCommittedPublication | None = None) -> tuple[H11AuthorityEventSnapshot, ...]`，body 只能把同一个 typed argument 转发给 `self.watch_authority.drain(external_permit=external_permit)` 并原样返回；不能恢复 parent selector、读取 queue、比较 expected FIFO/receipt、验证 identity、重新包装 event 或修改 ledger。

  exact FD，以及只由 `_close_owned_watches` 在本 frame 提取 raw local 后置 `-1`；

## 10. C3a0 明确不接 production

为保持可审计切片，C3a0 禁止修改或接入以下区域：

- `Harness.run()` 或任何 production orchestration 路径；
- READY publication；
- production PERMIT commit receipt consumption、retained-authorizer-input selection、
  deterministic PERMIT serialization与 expected-publication builder；C3a0 只允许
  already-typed fixed-frame receipt + independently prebuilt expected-publication 的本地
  fixture boundary及其 final content validation；
- permit ledger publication；
- commit FIFO release 或 acquisition release；
- final/final-freeze；
- manager/systemd 调用；
- H8 gate、H8 evidence 或 H8 tests；
- output schema 与 manifest schema；
- TASK.md、current-state.md 或其他状态文档。

`open_runtime_authority()` 在 C3a0 后仍必须保持 pure/local seam；production 不得调用它。后续接入必须是单独设计、单独 fixed-SHA 审计、单独接受的 C3 slice。

## 11. 禁止机制

C3a0 formal path、实现和测试均不得引入：

- budget 或 token/runtime budget；
- cap、上限或隐式截断；
- timeout 或 deadline；
- poll、sleep 或高频轮询；
- retry 或 backoff；
- watchdog；
- automatic cleanup；
- callback/hook 驱动的旁路；
- “等待更多事件后再决定”的循环；
- 因未知事件而忽略、降级或 fallback。

测试可以直接构造确定性输入和故障，但不能用上述机制稳定竞态。`FIONREAD` 的一次队列快照不属于 poll；若实现循环调用它，即违反本设计。
