# v0.4 Warehouse Effective-Research Closure Design

*Date: 2026-07-16*
*Status: accepted design; no new generative warehouse root is queued*
*Architecture authority: `scion/design/scion-architecture-v3.md`*

## Decision

Warehouse already proves that the direct-v3 agent can perform substantive
algorithm research. It does not prove that the current warehouse champion has
been improved and retained. Those are different claims and must stay separate.

The next warehouse work is therefore fixed-candidate attribution and
problem-asset correctness, not another open generative campaign. It must not
delay the current CVRP causal program, add warehouse semantics to generic core,
or reintroduce proposal budgets, truncation, retry, mandatory candidate
telemetry, or a heavier gate.

```text
effective research process: proven

```

A negative validation result is useful research. It must not be rewritten as a
solver improvement, and absence of promotion must not be rewritten as runtime
failure.

## W1: Formal Asset Consistency

The operational warehouse launcher uses the top-level files under
`scion/problems/warehouse_delivery/`.

`protocol_prod.yaml` currently asks for:

```text
screening create expansion: 20 cases
validation initial: 6 cases
validation expansion: 12 cases
```

`split_manifest_prod.yaml` actually contains:

```text
screening: 16 cases
validation: 5 cases
```

Its header still says 17 screening cases. Selecting all available cases is not
the same as satisfying a preregistered sample size, and repeating the same
case/seed cells cannot be represented as independent expansion.

The v0.4 default is to align the protocol to the evidence that actually exists:

- correct the manifest comment to 16;
- set create expansion to 16;
- set validation initial and expansion to 5, so validation cannot claim a
  larger independent expansion until new preregistered cases exist;
- preserve modify screening expansion at 14 because 16 distinct cases are
  available;
- add loading tests that fail when any configured stage count exceeds the
  distinct manifest population.

Adding new cases is a later data-design task and requires a new manifest
version. It must not silently change the accepted R3 replay population.

## W2: Constraint Semantics and Coverage

### Locked groups

Current formal behavior in `surrogate/oracle.py` treats
`locked_vehicle_id` as a group identity: all orders with the same value must
remain together, but the complete group may move to another vehicle. The
warehouse provider prompt instead says that every such order must remain in
its original vehicle.

Changing the oracle now would change the problem already used by formal
evidence. v0.4 therefore freezes the current oracle behavior:

```text
same locked_vehicle_id -> indivisible group; group may move together
```

Update the problem-owned prompt/interface description and tests to this
meaning. Baseline operators may remain conservative and skip locked groups,
but the prompt must distinguish a conservative baseline choice from the formal
feasibility rule.

### Directed constraint probes

The current production screening, validation, frozen, and canary instances have
empty `amount_limits`. Do not claim formal amount-limit coverage from them.

Add no-LLM problem-owned probes covering at least:

- nonempty amount limits and the exact `country,ship_method` key;
- indivisible locked groups that remain feasible after whole-group movement;
- capacity, hazard, pickup, and assignment preservation;
- one intentionally infeasible candidate per constraint family.

These probes test the problem contract and adapter/oracle behavior. They do not
become a new per-candidate gate, prompt checklist, or source-code telemetry
requirement.

## W3: Fixed-Candidate Decomposition

Use the R3 formal artifacts to materialize four no-LLM arms:

1. champion;
2. R3 destroy/rebuild only;
3. R3 directed merge only;
4. cumulative R3 destroy/rebuild plus merge.

The existing champion merge source and the R3 formal patch closure make these
identities mechanically reconstructable. Record the exact source hashes and
verify each workspace before evaluation.

Run the arms in balanced serial order on the accepted R3 screening, expanded
screening, and validation case/seed cells using the same scientific solver
limits. Report lexicographic objectives, pair outcomes, runtime, and trajectory
heterogeneity. This is post-hoc attribution; it cannot promote from screening.

Only an exact single arm that passes the corrected independent validation may
enter frozen. If no arm passes, retain the scientifically useful conclusion
that direct-v3 warehouse research behavior works but no current improvement was
retained.

## W4: Future Warehouse Mechanism Attribution

Before another open warehouse generative campaign, add problem-owned automatic
scheduler attribution. Candidate code must not be asked to implement its own
telemetry dialect.

The first packet should distinguish, per operator:

- selected/invoked/completed calls;
- feasible versus rejected output;
- strict/equal/worse lexicographic result relative to input;
- elapsed time;
- adoption into the incumbent or solution pool when observable.

Carry the compact complete aggregate through the existing proposal-only
evidence envelope with:

```text
proposal_visibility_only = true
decision_features_excluded = true
gate_influence = false
```

Do not use top-k selection, per-event prompt dumps, recommendations, thresholds,
or an interactive tool loop. Design this after the CVRP SearchAllocationEvidence
slice establishes the common transport semantics, while keeping warehouse
aggregation problem-owned.

## Sequence and Acceptance

```text
R11c terminal audit
  -> runner-owned solver interchange lifecycle
  -> CVRP SearchAllocationEvidence
  -> W1 formal asset consistency + W2 constraint semantics/probes
  -> CVRP and warehouse no-LLM characterizations on isolated runners
  -> W3 fixed warehouse decomposition
  -> W4 attribution only before a future warehouse generative root
```

Warehouse closeout evidence is sufficient for the v0.4 effective-research
claim when:

- the proof matrix remains reproducible from retained artifacts;
- protocol and manifest cannot claim nonexistent independent cells;
- locked semantics and directed constraint probes agree with the oracle;
- the cumulative R3 result has a fixed-candidate decomposition;
- TASK/current-state distinguish effective research from retained improvement;
- no warehouse-specific semantics or evidence enter generic Decision inputs.
