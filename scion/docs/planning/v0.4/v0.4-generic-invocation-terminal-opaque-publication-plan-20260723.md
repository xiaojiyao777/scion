# Generic invocation terminal and opaque publication slice

*Date: 2026-07-23*
*Status: implementation authorized; formal W3 launch remains locked*

## Authority and purpose

This slice implements the missing problem-neutral durable owner required by
the accepted Warehouse execution-integrity correction. It is subordinate to
`design/scion-architecture-v3.md`, the direct-runtime addendum, and
`v0.4-warehouse-w3-execution-integrity-correction-20260718.md` at raw SHA-256
`8e2a610eeec15ca1bb118d7affa855b753b320be1ae055b2e517613731d10945`.

The existing `SpawnBackend` remains the sole live process/cgroup/capture owner.
The existing `systemd255` value layer remains the sole validator for copied
run/stop-post/final-unit facts. This slice adds one generic durable terminal
and publication owner between those accepted facts and a problem validator.

It does not import Warehouse code, parse row or artifact bytes, acquire
systemd properties, install external authority, claim a production nonce,
schedule a job, start a process, or authorize a formal experiment.

## Public contract

The generic module exposes:

```text
TerminalPolicy
InvocationWriter.open_fresh(root, policy)
InvocationWriter.record_observation(job_ordinal, ClosedSpawnObservation)
InvocationWriter.commit_opaque_row(job_ordinal, observation_digest, row_bytes)
InvocationWriter.finish_raw()
InvocationWriter.mark_incomplete(reason_code)
seal_unit_drained(root, policy, InvocationLineage,
                  StopPostEnvironment, StopPostTopology)
observe_unit_final(root, policy, UnitHandoffProperties)
accept_invocation(root, policy, opaque_problem_acceptance_digest)
publish_opaque_artifact_bundle(root, policy, CompleteFact, named_bytes)
inspect_terminal(root, policy)
```

`TerminalPolicy` binds one accepted authority digest, manifest digest, fresh
nonce, exact positive row count, exact ordered artifact names, and zero
retry/resume/reuse. Its canonical digest is recorded in every durable fact.

`InvocationWriter` is a same-process, final, noncopyable one-use capability.
It accepts jobs only in increasing ordinal order. One exact
`ClosedSpawnObservation` is durably encoded before the corresponding opaque
row can be published. The row is accepted as bytes only; generic code binds
its SHA-256, length and observation digest without JSON or problem parsing.
The settled SpawnBackend cgroup may be removed only after the caller has the
returned durable row fact.

`finish_raw` requires the exact row count and no pending observation. It binds
the complete ordered evidence/row identity sequence and makes further run
writes impossible. A dead writer is not reopened or resumed. `mark_incomplete`
is terminal and cannot be changed to success.

## Durable layout and publication

The caller supplies a fresh root with exact empty `control`, `evidence`, `raw`
and `artifacts` directories. The generic owner uses fixed names only:

```text
control/invocation_started.v1.json
evidence/000000.json ...
raw/000000.opaque ...
control/raw_complete.v1.json
control/incomplete.v1.json
control/unit_drained.v1.json
control/unit_final.v1.json
control/complete.v1.json
artifacts/final/<policy-declared names>
control/closed.v1.json
```

Every individual fact is canonical JSON written through an unnamed
`O_TMPFILE`, file fsync, `linkat` no-replace publication, and directory fsync.
The link first uses `AT_EMPTY_PATH`; an unprivileged process lacking
`CAP_DAC_READ_SEARCH` uses the documented `/proc/self/fd/<fd>` plus
`AT_SYMLINK_FOLLOW` form. Both forms link the same open unnamed inode. There
is no named-temp fallback and no overwrite path.

Artifact files are built under one private root-confined staging directory,
file-fsynced, directory-fsynced, and published as the fixed `final` directory
with `renameat2(RENAME_NOREPLACE)`. A closure marker is then published
no-replace and binds the exact complete/unit/artifact identities. Generic code
requires the policy's exact ordered names but treats every artifact body as
opaque bytes.

## Observation evidence

Generic evidence contains the complete immutable copied
`ClosedSpawnObservation`, including stdout/stderr bytes. Bytes are represented
by canonical base64 objects and tuples by canonical arrays; decoding must
reconstruct an exact `ClosedSpawnObservation` and reproduce its
`observation_sha256`. No FD, path capability, callback or problem type enters
the evidence.

Replay/checking may compare retained evidence, row and terminal bytes without
starting a process. A mismatched observation digest, ordinal gap, duplicate
name, extra file, partial prefix or altered terminal chain is rejected.

## Unit terminal chain

`seal_unit_drained` accepts only exact existing `InvocationLineage`,
`StopPostEnvironment` and `StopPostTopology` values. It requires the same
invocation, successful main selector, an empty supervisor, no job cgroup, and
the sole sealer in `.control`. It binds `RAW_COMPLETE` and publishes
`UNIT_DRAINED`.

`observe_unit_final` requires a successful exact `UnitHandoffProperties` value
for that same unit/invocation and binds the drained fact. It publishes
`UNIT_FINAL` only after the unit is inactive/dead and both main and stop-post
statuses are zero.

`accept_invocation` publishes `COMPLETE` only when RAW, UNIT_DRAINED and
UNIT_FINAL form one exact digest chain. The problem acceptance digest is
opaque and cannot steer generic state. Artifact publication requires that
exact returned `CompleteFact`.

## Fail-closed and non-claims

- No retry, resume, overwrite, row replacement, alternate ordinal or solver
  rerun exists.
- A crash-visible evidence-only, row-only, staging, or partial terminal prefix
  is an integrity hold. This slice does not recover it.
- There is no timeout, polling budget, truncation, content cap, protocol gate,
  Oracle branch or problem-specific artifact name.
- Filesystem durability claims cover file and owning-directory fsync ordering,
  not physical power-loss guarantees outside the accepted filesystem model.
- This slice does not implement external authority/install/projection, nonce
  ledger, systemd acquisition, `ExecStopPost` command wiring or the W3 campaign
  composition. Passing it does not authorize a W3 job.

## Acceptance gates

1. Public API contains only typed generic facts/capabilities and explicit
   functions; Warehouse/CVRP imports and names are absent.
2. Focused tests cover positive 0..N row order, complete observation codec,
   duplicate/gap/digest/type rejection, no-replace behavior, incomplete
   terminality, RAW/UNIT/COMPLETE chain, artifact atomic publication, exact
   names, tampering and read-only inspection.
3. Fault tests cover individual-fact write/link failure, existing target,
   final-directory collision and marker collision without overwrite.
4. The focused suite passes on Python 3.12 and 3.13 with `-W error`, fresh
   basetemps and no pytest cache; H11 oracle/public/official gates remain exact.
5. Compile, diff and prohibition scans pass on one clean pushed source hash.
6. Acceptance records state explicitly that external authority/systemd
   composition and a separate fresh W3 launch review remain outstanding.
