## 1. Decision and authority

This addendum corrects the cross-file integration contract in
`v0.4-w3-generic-formal-fixture-composition-design-20260719.md`. The parent
generic execution contract, the generic-backend correction design and the
accepted production source remain authoritative except where this addendum
explicitly narrows fixture composition.

The first implementation candidate is rejected even though its execution unit
suite reported `290 passed`. Fixed-hash reviews reported:

- formal/B6 review: P0=0, P1=4, P2=1;
- systemd integration review: P0=0, P1=8, P2=1;
- responsibility/complexity review: P0=0, P1=5, P2=1.

Those reports overlap, but establish that the candidate cannot run the formal
and observer protocols it claims, can misclassify H8, and lacks complete
static and D-Bus authority chains. None of the rejected files may be installed,
committed or used as formal evidence until a replacement fixed hash set passes
the acceptance sequence in section 15.

The production `spawn_backend.py` remains frozen at SHA-256
`9c25defcf383046b39e0638f6f3841fca9c47572506a5cd4c3a9fb9c3232f938`.
This addendum does not authorize a production hook, problem import, ordinary
launcher, transient unit or alternate native path.

There is no experiment budget, timeout, deadline, retry, polling loop, cap,
truncation, automatic cleanup, replacement start or automatic restart in this
design. A missing event leaves the root unaccepted; it does not manufacture a
terminal result.

## 3. Entry owners and internal responsibilities

The three unit program entry owners remain unchanged:

1. `generic_backend_formal_case.py --plan` owns B0-B8 and formal H5/H6
   behavior;
2. `generic_backend_unit_observer.py --plan` owns ordinary run, stop-post and
   closer materialization;
3. `generic_backend_adversary.py --plan` owns only its frozen negative and
   descendant scenarios.

The existing system-manager harness is the sole external scenario supervisor.
The existing root installer is the sole tree/install/final-freeze
infrastructure owner. These are not additional unit program entries. No
`helpers.py`, shared schema module, fourth runtime program or generic callable
dispatcher may be added.

Within the harness, narrow frozen dataclasses and transaction objects may split
manifest validation, acquisition, scenario policy, manager events and terminal
collection. They remain in the same tests-only file. Observer and adversary
retain role-local JSON/FIFO code; their duplication is intentional isolation.

## 4. Closed ScenarioPolicy

The harness owns one source-defined `ScenarioPolicy` table. A manifest selects
one row by exact ID and cannot alter any owner, acquisition, manager method,
output, action or terminal rule in that row.

Each row freezes:

```text
scenario_id
run_owner
stop_owner
closer_owner
exact_acquisition_order
exact_required_output_roles
exact_allowed_manager_methods
exact_terminal_policy
formal_case_policy or none
formal_action_policy or none
final_classification
```

The systemd rows are:

| Row | run-main owner | stop owner | closer owner | Classification rule |
|---|---|---|---|---|
| H1 | observer `run-main` | observer `exec-stop-post` | observer `closer` | positive clean behavior |
| H2 | adversary `h2-main-nonzero` | observer `exec-stop-post` | observer `closer` | expected main exit-code evidence |
| H3 | adversary `h3-main-signal` | observer `exec-stop-post` | observer `closer` | expected SIGABRT/core signal evidence |
| H4 | observer `run-main` | adversary `h4-stoppost-failure` | observer `closer` | expected stop-post failure evidence |

H0 is not a normal launch row. It is a pre-start phase emitted for every
system root; an H0-only invocation performs preflight and must not call
`StartUnit`. H12 is also the shared terminal transaction for every referenced
system root after its scenario evidence is durable. H10 uses its own no-ref GC
transaction and cannot borrow a positive H12 claim.

Delegated B0-B8 roots use a second closed family in the same table, not a new
entry program. Their IDs bind one exact formal case/variant. They use the same
installed unit and harness authority protocol as H5/H6; B-specific external
actions are selected only by the source table. A manifest cannot name an
attribute, callable, signal, cgroup path or action implementation.

For H1-H9/H11/H12 the exact outer acquisition tuple is:

```text
run-main -> exec-stop-post or h4-stop-post -> closer or failed-closer
```

H10 is exactly `run-main`. Formal B actions are a separate ordered
`formal_actions` tuple and never appear as an outer lifecycle role. Set
equality is insufficient.

The terminal policy contains exact raw and normalized tuples for run Result,
states, `ExecMainCode/Status`, `ExecStopPostCode/Status`, stop environment,
closer Result/code/status, manager JobRemoved result and, for formal rows, the
case/variant/typed backend outcome. Generic decoders prove representation;
`ScenarioPolicy` proves scenario meaning. No row can inherit another row's
adversary or successful classification merely because its role names match.

## 5. Formal same-PID outer acquisition

Every formal system unit has a top-level `systemd_acquisition`, distinct from
B4/B6 and the four external-topology B7 action FIFOs and from B5 descendant
hold authority. Before opening
`SpawnBackend` or performing any native/cgroup operation, formal-case:

1. validates its static plan and executing program hash;
2. derives boot ID, systemd `INVOCATION_ID`, PID/starttime, normalized unified
   cgroup and service/supervisor directory identities in the same PID;
3. publishes a canonical no-replace
   `scion.generic_backend.formal_run_armed.v1` receipt containing exact
   case/variant, unit, plan/program identities and both FIFO identities;
4. emits the ready permit and blocks on the outer release FIFO;
5. revalidates all identities after exact permit plus EOF;
6. materializes the final config and enters B in the same PID.

The harness accepts this schema only for a formal policy's `run-main`. It pins
the D-Bus ControlGroup, proves exact MainPID/invocation/boot/unit lineage,
calls production `InvocationLineage`, freezes the raw authority and only then
releases formal-case. It never execs or embeds the observer in formal-case.

The formal ARMED schema, observer ARMED schema and adversary ARMED schema are
closed and mutually exclusive. Each exact ScenarioPolicy row identifies the
only legal schema and mode for each role.

## 6. Formal action supervision

The same harness owns all external actions. Every action asset is predeclared,
path-disjoint, identity-pinned before StartUnit and selected by the closed
formal policy:

| Case | Harness transaction |
|---|---|
| B0-B3/B8 | no external action; observe final formal receipt only |
| B4 | prove exact blocked job cgroup, write `cgroup.kill` once, fsync the action ledger, then write exact `JOB_CGROUP_KILLED\n` to the pinned control FIFO |
| B5 | prove descendant receipt/FIFO/job containment; never open the hold FIFO writer; production alone owns kill/drain |
| B6 issuer | pin formal PID identity with pidfd, send SIGUSR1 exactly once, durably publish send receipt, then release the B6 FIFO once |
| B6 storage/close | send no signal; durably freeze the action authorization and release exactly once |
| B7 `tmpfile-unsupported` | no external action; formal-case owns the fixed allowlisted `O_TMPFILE` injection of `EOPNOTSUPP`, `formal_actions=()`, `control_fifo=null`, and proves zero native calls |
| B7 `tmpfile-allocation` | no external action; formal-case owns the fixed allowlisted `O_TMPFILE` injection of `ENOSPC`, `formal_actions=()`, `control_fifo=null`, and proves zero native calls |
| B7 `tmpfile-open` | no external action; formal-case owns the fixed allowlisted `O_TMPFILE` injection of `EACCES`, `formal_actions=()`, `control_fifo=null`, and proves zero native calls |
| B7 `cgroup-inode-drift` | perform only the source-defined cgroup inode replacement, freeze before/after identities, then write exact `DRIFT_APPLIED\n` |
| B7 `unexpected-sibling` | create only the source-defined unexpected sibling cgroup, freeze before/after identities, then write exact `DRIFT_APPLIED\n` |

| B7 `supervisor-extra-task` | place only the source-defined extra task in the supervisor cgroup, freeze before/after identities, then write exact `DRIFT_APPLIED\n` |

The first three B7 rows fail before `BlockedSpawn` and before any job cgroup
exists. Their source-defined formal-case fault proxy is the named action owner;
the harness must reject any action asset or control FIFO for them. The remaining
four B7 policies enumerate their one concrete external topology mutation and
require the pinned control FIFO. No free-form operation name becomes executable.
Root actions use retained dirfds and never reacquire authority from a mutable
path.

The B5 control FIFO is a hold authority, not an acquisition. The harness never
opens its writer. Formal execution uses only the adversary's sealed `--plan`
entry; legacy REQUEST invocation remains debug-only.

## 7. Formal control FIFO and B5 binding

`control_fifo` is `null` or the complete frozen object:

```text
path
device
inode
```

Plan decode proves FIFO type, mode 0600, fixture UID/GID, root-owned parent and
device/inode. Materialized config retains the whole object. Config decode
repeats the closed schema check; it never degrades authority to a path.

B4/B5, the four external-topology B7 variants and B6
`issuer-reaped-populated` open
`O_PATH|O_NOFOLLOW|O_CLOEXEC` and retain the identity FD to terminal outcome.
Every reader/writer open is nofollow, fstat-bound to both plan and pin, and
records exact bytes plus EOF. All control, outer and B6 FIFO paths and
identities are pairwise distinct.

B5 and the B6 descendant variant consume one root-sealed adversary plan. PASS
requires exact cross-binding of plan/program/unit/scenario, materialized
request path/SHA, receipt request path/SHA, formal binding, hold FIFO object,
actor boot/invocation/cgroup, descendant PID/starttime/containment,
`GenericProcessSpec.environment`, process-spec digest and final receipt SHA.
No two merely adjacent receipts establish equality.

Both descendant targets receive the exact sorted environment
`INVOCATION_ID=<formal-run-id>, LC_ALL=C`; the B6 descendant path is not exempt
from B5's invocation transport and receipt cross-binding.

## 8. B6 phase and operation evidence

The 19-row B6 ABI remains closed. An unobservable current-source seam is
`REQUIREMENT_MISSING`, never PASS. Every installable row requires both a
frozen-source callsite proof and executable public-flow trace before delegated
execution.

### 8.1 Reaped-but-populated

`issuer-reaped-populated` reuses the existing
`b7-double-fork-closed-stdio` adversary; no scenario is added. Its sealed plan
binds the run unit, adversary program, request/receipt paths and the complete
control FIFO. The grandchild closes stdio and remains blocked on that FIFO;
the harness never releases it.

At the exact poll-pidfd-close seam, formal-case must prove:

- native leader state is reaped and its `/proc/PID` identity is absent;
- poll pidfd matches the pinned descriptor identity;
- job `cgroup.events` is exactly `populated=1`, `frozen=0`;
- adversary plan/request/receipt are fully cross-bound;
- descendant PID/starttime is live and its unified cgroup is the exact job
  cgroup.

Any missing fact is `REQUIREMENT_MISSING`. The expected first failure remains
`ISSUER_INTERRUPTED/LEADER_REAPED_DRAINING`; later production kill/drain cannot
overwrite it.

### 8.2 Operation receipt

Every B6 acquisition declares a unique `operation_receipt_path`. The exact
hook wrapper inside formal-case publishes canonical, fsynced, no-replace
`scion.generic-backend.b6-operation.v1` with the closed fields:

```text
case_id, variant, fault, declared_phase, hook, target_operation,
planned_ordinal, observed_ordinal, injection_count,
armed_receipt_sha256, actor_pid, actor_starttime,
before_fact_sha256, release_permit_sha256,
operation_state, effect_state, return_type, exception_type, errno,
postcondition
```

`operation_state` is exactly one of `RETURNED`, `RAISED`, `INJECTED_RETURN`
or `POST_COMMIT_UNCERTAINTY`. `effect_state` and `postcondition` are fixed per
hook: authority moved, FD acquired, pinned borrow returned, mask restored and
handler raised, wait fact returned, pidfd closed, original storage write not
called with injected false, or close committed then EIO. Arbitrary `repr`,
object serialization or plan-selected labels are forbidden.

The final typed receipt references the operation receipt SHA. Fail-stop
evidence requires the durable operation receipt, process termination and
absence of a final PASS receipt. `observed_ordinal` equals the plan,
`injection_count=1`, and a second arm/injection rejects. Later ordinary
pass-through calls may be counted but cannot inject again.

### 8.3 Pure seam proof

Pure tests first hash and parse the frozen production AST. Each installable
hook row freezes the owner/function, exact normalized call-node/block hash,
guard predecessor/successor, call chain, operation ordinal and phase. Source
text substring matching is not evidence.

Pure tests then reuse the existing spawn-backend fake kernel/native/cgroup
machinery to drive the real production public flow with the real B6 controller.
Only dependencies below the reviewed target operation may be replaced. Every
row proves wrapper install, exact phase/ordinal, one injection, expected typed
outcome or fail-stop sentinel, exact uninstall identity and rejection of a
second injection. Guard restore rows use separate fresh roots for ordinals 10
and 11. The signal/FIFO test independently proves pending/mask/handler,
send-before-release and restore facts.

## 9. Observer raw authority

The old `raw_text_path` plus `raw_json_path` authority pair is removed.
`systemd-properties-authority` has one `raw_authority_path`, containing the
harness's canonical lossless tagged D-Bus JSON. Human-readable text, if any,
is a non-authoritative sidecar carrying the authority JSON SHA and is never
parsed into a fact.

Before StartUnit the harness decodes every hashed observer plan and proves:

- every plan raw-authority path equals the corresponding manifest output;
- closer `source_selector_path` equals the exact manifest source-selector
  output;
- plan mode/unit/source binding equals ScenarioPolicy;
- request/output/plan/program/FIFO paths and identities are disjoint.

Observer ARMED repeats the exact raw-authority path list and selector path.
The harness cross-binds them, writes and fsyncs the raw authority, calls the
appropriate production decoder and only then releases. Observer reads only
that JSON and revalidates manager owner, boot ID, unit and invocation. Pure
composition tests execute the real post-release observer path rather than
stopping at a fabricated ARMED receipt.

## 10. Manifest prevalidation and state machine

Manifest decoding completes before any FIFO open, journal open, signal match,
Subscribe, RefUnit or StartUnit. It validates:

- exact ordered acquisition and formal-action tuples;
- exact required output-role set for the selected policy;
- exact hashed plan/program/preflight/installer bindings;
- all plan-to-output and selector paths;
- global non-aliasing across static files, inputs, outputs, receipts and FIFOs;
- output parents, ownership/modes and no existing destinations;
- exact allowed manager methods and terminal policy.

Missing, extra, duplicate, reordered or lazy-discovered outputs reject before
side effects. H8 adds its drift/inventory receipt; H10 has only its run,
reloaded/absence, H0, signals, journal and final outputs; formal policies add
their exact action/send/operation outputs.

The harness follows one table-driven state machine:

```text
PREVALIDATED
-> H0_FROZEN
-> SUBSCRIBED_AND_REFED
-> RUN_ACQUIRED
-> optional FORMAL_ACTION
-> STOP_ACQUIRED
-> CLOSER_ACQUIRED
-> TERMINAL_POLICY_FROZEN
-> H12_COLLECTED
```

H10 follows its closed no-ref branch. No state can be skipped, repeated or
entered through fallback. The manifest does not select transition code.

## 11. H0 host evidence

H0 uses the same system-bus connection and pinned host files, without a
subprocess:

- Manager `Version:s` from the frozen unique owner, with exact major 255;
- nofollow `/proc/self/mountinfo` identity and bytes proving one cgroup2 mount
  at `/sys/fs/cgroup`;
- nofollow `/proc/self/cgroup` identity and bytes proving one unified `0::`
  entry;
- nofollow `/sys/fs/cgroup/cgroup.controllers` identity and bytes containing
  `pids`;
- pre-start run-unit raw properties proving literal `Delegate=pids` and
  `DelegateSubgroup=supervisor` configuration.

The pre-start H0 receipt binds manager owner/version, host file
identities/hashes, installer receipt and configured run properties. The later
run acquisition separately proves active `Delegate=true`, effective
`DelegateControllers=["pids"]`, exact supervisor lineage and cross-references
the H0 receipt. A non-255 or non-unified host is `REQUIREMENT_MISSING`, not
weaker evidence.

## 12. Scenario-specific terminal rules

Run terminal properties continue through production
`UnitHandoffProperties`. The closer has no ExecStopPost and therefore uses a
tests-only final `CloserTerminalProperties` in the harness, not a production
change. It strictly consumes unit/invocation/states/Result,
`ExecMainCode/Status` and requires an empty ExecStopPost array.

Ordinary closer is loaded/inactive/dead/success with exited status 0. H9 is
loaded/failed/failed, Result `exit-code`, `ExecMainCode=1`,
`ExecMainStatus=61`, and can only produce `rejected-failed-closer` evidence.
Every other row's exact terminal tuple lives in ScenarioPolicy and is tested by
one accepted vector plus mutations of each semantic field.

H8 recursively inventories the service root, `.control`, `supervisor` and
every direct/nested cgroup with device/inode, events and procs. It must observe
the exact drift inode. It must not call positive `StopPostTopology` acceptance
over an ignored subtree or publish `formal-positive-evidence`. It freezes
`rejected-unexpected-topology/H8_EXTRA_TOPOLOGY`, releases the fixture-owned
hold so terminal evidence and H12 cleanup can complete, and records no leak.

H11 has no product deadline. Before the explicit fixture permit there must be
no accepted terminal receipt. The permit is an operator-owned event in the
manifest protocol and is never automatic.

## 13. Unified manager event ledger

Manager method begins/replies and signals share one monotonic event ordinal.
Every method entry records method, exact signature/arguments, begin ordinal and
reply ordinal plus exact value or D-Bus error. Every signal records the same
ordinal space, unique owner, object path, signature and body.

H7 freezes the one StopUnit reply job and binds it to exactly one JobNew and
one JobRemoved for the exact run unit. Numeric job ID/path agree, ordering is
strict, JobRemoved result is the policy value, and the run-main release writer
was never opened.

For H12, installer object paths are the only allowed unit objects. Terminal
receipts are durable before ResetFailed/Unref. Only failed units reset.
UnitRemoved is unique for each unit/object, later than its Unref reply, and
cannot appear while a ref is held. Post-removal `GetUnit` is called once per
unit and must return exact `org.freedesktop.systemd1.NoSuchUnit`. Early cgroup
FD identity remains stable, mutable path is absent, and every frozen actor
PID/starttime is absent or reused.

H10 binds its original object and UnitRemoved ordinal before its one LoadUnit.
The LoadUnit reply object is frozen and is the only object queried afterward;
the reloaded invocation is empty and states are loaded/inactive/dead. H10
cannot satisfy H12 or any positive row.

## 14. Static authority chain and final freeze

The fixed order is:

```text
prepare tree
-> external author writes all concrete plans/programs/units/manifests
-> seal tree and emit SEAL_RECEIPT
-> shell static preflight and emit PREFLIGHT_RECEIPT
-> installer validates all inputs, copies, Reloads once and Loads each unit
-> harness execution
-> installer final freeze transaction
```

The shell wrapper only performs static preflight. Its root-sealed manifest
enumerates every concrete unit, program, plan, descriptor, installer and
harness path/SHA/device/inode/mode. It rejects any `@` placeholder, any `%`
specifier, a Python path other than exact `/usr/bin/python3.12`, argv other
than exact `-I -B PROGRAM --plan PLAN`, and any program/plan absent from the
sealed inventory. It creates one unique no-replace preflight destination,
fsyncs contents and directories, and leaves a poisoned incomplete destination
on failure. It no longer freezes arbitrary receipt files.

The install manifest consumes TREE, SEAL and PREFLIGHT receipts by
path/hash/device/inode. Before the first fragment copy it validates the entire
unit set, unique roles/names/sources/targets, all hashes and modes, every argv
binding and absence of every target. A later invalid unit cannot leave an
earlier unit copied. After mutation starts, an external I/O failure poisons the
unique root; there is no rollback-and-retry.

The installer receipt freezes installer/install-manifest identities, all three
input receipts, manager owner and one ordered ledger: Reload, then one LoadUnit
per concrete unit, then FragmentPath and NeedDaemonReload queries on each
returned object. Per-unit source/target hash, target identity/mode/owner,
object path, exact FragmentPath and `NeedDaemonReload=false` are mandatory.
The harness validates this full receipt before installing signal handlers.

Final freeze moves to a new transaction of the existing root installer. It
prevalidates the exact policy output set and pins each nofollow source identity
before atomically creating a unique destination directory. It copies and
fsyncs every file, writes hashes, fsyncs directories and creates `FROZEN` last
with no-replace semantics. Failure leaves an incomplete directory without
`FROZEN`; it is never deleted, replaced or retried.

Only after a successful freeze may an explicit, separate root cleanup
transaction remove the exact installed fragments and reload once. Cleanup is
not automatic, is not part of accepted evidence and cannot repair or reuse a
failed root.

## 16. Privileged execution gate

Pure acceptance and a clean build do not authorize a user-manager substitute.
Formal H0-H12 and system-owned delegated B execution require the root installer
and system bus. If noninteractive root authority is absent, the execution
result is `REQUIREMENT_MISSING`; no password persistence, sudo fallback inside
a fixture, transient unit, relaxed claim, retry or default watchdog is
permitted.
