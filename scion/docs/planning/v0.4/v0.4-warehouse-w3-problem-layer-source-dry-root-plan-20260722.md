## Accepted ownership

Warehouse may own only the W3 scientific contract:

- exact W1/W2/R3 ancestry and external-evidence identities;
- fixed arm construction and registry semantics;
- exact case/cell/job schedule and Williams order;
- greedy-initial and directed-pair preflight facts;
- conversion of one copied generic `ClosedSpawnObservation` plus solver payload bytes into one canonical problem row;
- deterministic replay, aggregation, statistical gates, and artifact byte construction.

Generic runtime remains the sole owner of:

- process creation, release, signals, reaping, cgroup and pidfd lifecycle;
- stdout/stderr capture and closed-process observations;
- run and invocation terminal states;
- raw-row and artifact publication, no-replace durability, and final drain.

Accordingly, the Warehouse W3 modules must not expose direct `Popen`, `run_matrix`, `close_matrix`, terminal-marker, raw-publication, or artifact-publication paths.

## Source closure

Every repository-owned input in an accepted dry root must have a provenance descriptor with:

- `kind: git_blob`;
- the exact full source commit;
- repository-relative path;
- Git blob object id;
- raw SHA-256 and byte length;
- sealed root-relative path.

The source commit must be a full 40-hex commit, must equal the checked-out `HEAD`, and must be reachable as the exact Git object used to obtain the bytes. A dirty worktree must not affect sealed repository bytes.

Non-repository inputs must be classified as `external_evidence` and carry their protected-root path, source path, expected SHA-256, byte length, and sealed path. Generated schedule, preflight, and workspace facts must be classified as `generated` and must be reproducible from the sealed inputs.

The source commit used for final acceptance must be clean and pushed. A dry root prepared before the final implementation commit is only diagnostic and cannot be the accepted root.

## Dry-root contract

Preparation may read fixed Git blobs, the frozen W1/W2/R3 evidence, and the fixed case population. It may materialize the four problem-owned solver workspaces and run non-formal preflight computations. It must not start a formal solver job.

An accepted dry root contains:

- a canonical manifest and SHA-256 sidecar;
- all sealed Git-blob and external-evidence inputs;
- the four derived solver workspaces;
- exact 43-cell and 172-job schedules;
- greedy and counter preflight facts;
- an exact prepared inventory;
- `formal_jobs_started: 0` and `formal_execution_authorized: false`;
- a source receipt stating the exact commit and provenance aggregate;
- a prepared marker that explicitly records zero formal jobs.

Verification must rederive the manifest field for field from sealed bytes, reject symlinks and special files, reject extra or missing files, and perform no mutation.

## Observation validation and replay

The dormant validator accepts an exact `ClosedSpawnObservation`, the matching manifest job, and captured solver payload bytes. It rejects:

- a mismatched opaque job key or process-spec digest;
- nonzero/signalled leader outcomes;
- incomplete capture facts;
- payload bytes that do not match the closed stdout capture identity;
- noncanonical, duplicate-key, or nonfinite JSON;
- scientific output that fails the sealed registry, oracle, objective, locked-group, or directed-pair contracts.

It returns canonical row bytes and facts to the caller. It does not write them.

Replay accepts an ordered complete set of canonical row bytes plus their generic publication identities. It validates the exact job bijection and returns deterministic results/report/receipt bytes. It does not read a mutable experiment database, decide paths, or publish artifacts.

## Acceptance gates

Source acceptance requires:

1. no forbidden process/terminal/publication authority in the problem-owned W3 surface;
2. unit tests for Git-blob closure, exact schedule, counter fixtures, observation binding, canonical-row rejection, deterministic replay, and pure analysis;
3. focused tests on Python 3.12 and 3.13 with warnings as errors;
4. the repository's official test command on the clean candidate;
5. a committed and pushed source hash.

Dry-root acceptance then requires:

1. construction from that exact pushed clean source hash into a new absent root;
2. an independent read-only verification process;
3. field-for-field manifest rederivation and exact inventory closure;
4. 43 cells, 172 jobs, four balanced arm positions, and all preflight facts passing;
5. `formal_jobs_started == 0` and no run/terminal/raw/artifact output;
6. a recorded dry-root receipt and hashes in `TASK.md` and `docs/status/current-state.md`.

## Explicit non-authorization

Passing this slice does not authorize a W3 formal launch. Formal launch remains blocked until generic invocation terminal ownership and opaque row/artifact publication are implemented and independently accepted, after which W3 must undergo a separate fresh-root launch review.
