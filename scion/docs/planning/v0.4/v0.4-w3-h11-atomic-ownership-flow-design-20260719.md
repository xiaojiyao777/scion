## 1. 决策摘要

C2e 将当前由 `H11RootAuthorizerSession`、
`H11RootAuthorizerReadyClosure`、`H11RootAuthorizedPermit` 和多个
`RetainedH11Root*` 对象层层转移的 FD 所有权，收敛为一个唯一 owner：

```text
H11RootAuthorizationFlow
  ├── tuple[H11OwnedFdSlot, ...]  # 固定长度、固定角色、固定关闭顺序；唯一 FD owner
  └── _phase_data                # None -> Authority -> Ready -> Permit frozen values
```

每个 `H11OwnedFdSlot` 在 flow 创建时预分配。一个 FD 从 open 到 close
始终停留在原 slot；阶段推进只改变 flow state 和该 slot 所代表对象的
已验证语义，不把 descriptor 整数转移到另一个 owner。

本设计明确选择单一 `H11RootAuthorizationFlow`。不得同时引入或保留
`H11RootAuthorizationFrame`、第二套 slot registry、owner stack 或兼容
adapter。验证对象只能是 immutable value 或只借用 slot 的 typed view，不能
形成第二个生命周期 owner；phase cursor 则只接受第 4.5 节三个 exact frozen
types。阶段语义只经该 predecessor chain 推进，不能散落为 flow optional fields
或靠 phase return object 转移。

C2e 是内部所有权重构，不修改 C2a–C2d 的任何外部协议：JSON schema、
路径、mode/uid/gid、FIFO identity 与方向、精确 frame、事务阶段、原子
publication 顺序、receipt ABI 和 fail-closed 结论全部保持不变。

## 3. 当前结构为何需要替换

当前实现已经具备正确的局部 fail-closed 行为，但 FD ownership 分散在：

- session、authority、READY closure、authorized permit 四层对象；
- source、directory、FIFO、present output、publication 五类可关闭 wrapper；
- READY reader、PERMIT writer 和 staging descriptor 三类局部整数；
- 多个局部 list、tuple 转换、result-owner 转移和异常 rollback 分支。

这造成三个结构问题：

1. 阶段迁移同时也是 owner graph 迁移，验证逻辑与关闭责任互相缠绕；
2. 每新增一个失败点，都必须重新证明 partial list、result object 与旧 owner
   之间没有遗漏、双关或重复 close；
3. public wrapper 通过反复替换 `owner` 表达状态，实际协议状态只能从运行
   时类型间接推断。

C2e 不再修补这些转移分支，而是删除“阶段对象即 owner”的结构。flow
从创建到终止一直拥有同一个固定 slot tuple；阶段只是同一个 owner 内的
单向状态迁移。

## 4. 唯一 owner 与固定 slot layout

### 4.1 `H11OwnedFdSlot`

等价实现必须具有以下最小语义：

```python
class H11OwnedFdSlot:
    __slots__ = ("_role", "_descriptor", "_open_started")

    def __init__(self, *, role: str) -> None: ...

    @property
    def role(self) -> str: ...

    def open(
        self,
        path: str | bytes | os.PathLike[str] | os.PathLike[bytes],
        flags: int,
        mode: int = 0o777,
        *,
        dir_fd: int | None = None,
    ) -> None: ...

    def _bind(self, descriptor: int) -> None: ...
    def borrow(self) -> int: ...
    def detach(self) -> int: ...
```

精确约束：

- 初始 `_descriptor == -1`，`_open_started is False`；
- `_role` 只在 `__init__` 中写入一次，`role` 是无 setter 的只读 property；
  caller 不得改名、交换或重新绑定 slot role；
- `open()` 在 syscall 前要求 slot 从未尝试 open，并先设置
  `_open_started=True`；同一 slot 不存在第二次 open；
- `open()` 以 exact `self._bind(os.open(...))` expression 直接调用 `os.open`，
  不得把返回 FD 赋给 local/attribute/container，也不得接收
  opener/callable/hook；
- `_bind()` 只允许由 `H11OwnedFdSlot.open()` 调用，要求 slot 为空且
  descriptor 是非负 exact `int`；
- `borrow()` 只返回当前 descriptor 供紧邻 syscall 使用，不转移所有权；
- `detach()` 先把 `_descriptor` 写为 `-1`，再返回旧值；空 slot 返回
  `-1`；
- slot 不验证文件语义，不保存 path/reference/raw bytes，也不决定阶段；
- slot 没有 `__del__`、context-manager、finalizer 或隐式 close；
- raw descriptor 不从 flow 的 public API 返回。

`_open_started` 不是 retry counter。它是一次性证据：即使 `os.open`
失败，该 slot 和整个 flow 也不得重试。

以下 private mutation allowlist 是精确闭集，多一个或少一个 qualified writer
都失败：

| field | 唯一允许写入点 | 精确 mutation |
| --- | --- | --- |
| `H11OwnedFdSlot._role` | `H11OwnedFdSlot.__init__` | 未初始化 → exact constructor role，一次 |
| `H11OwnedFdSlot._open_started` | `H11OwnedFdSlot.__init__`, `H11OwnedFdSlot.open` | 未初始化 → `False`；`False` → `True`，且第二步在 `os.open` 前 |
| `H11OwnedFdSlot._descriptor` | `H11OwnedFdSlot.__init__`, `H11OwnedFdSlot._bind`, `H11OwnedFdSlot.detach` | 未初始化 → `-1`；`-1` → exact opened FD；当前值 → `-1` |
| `H11RootAuthorizationFlow._slots` | `H11RootAuthorizationFlow.__init__` | 未初始化 → 第 4.2 节 exact literal tuple，一次 |
| `H11RootAuthorizationFlow._manifest_path` | `H11RootAuthorizationFlow.__init__` | 未初始化 → exact constructor `manifest_path` object，一次 |
| `H11RootAuthorizationFlow._require_root` | `H11RootAuthorizationFlow.__init__` | 未初始化 → exact constructor `require_root` value，一次 |
| `H11RootAuthorizationFlow._phase_data` | `H11RootAuthorizationFlow.__init__`, `_acquire_authorities`, `_consume_ready_commit`, `_publish_permit` | 未初始化 → `None` → exact `H11RootAuthorityPhaseData` → exact `H11RootReadyPhaseData` → exact `H11RootPermitPhaseData`；每个箭头一次且 replacement 紧邻对应 state transition |
| 五类 borrowed view 的 `_flow` | 各 view 自身的 `__init__` | 未初始化 → constructor `flow` 的 exact `H11RootAuthorizationFlow` object，一次 |
| 五类 borrowed view 的 `_slot`/`_parent_slot` | 各 view 自身的 `__init__` | 未初始化 → 第 4.3 节 caller 传入的 exact literal self/optional-parent slot object，一次 |
| 五类 borrowed view 的其余 immutable metadata fields | 各 view 自身的 `__init__` | 未初始化 → constructor 的 exact path/reference/raw/label value，一次；字段名/类型沿用对应 C2a–C2d schema |
| `H11RootAuthorityView` 的第 4.5.1 节 exact fields | `H11RootAuthorityView.__init__` | 每项未初始化 → exact same-flow borrowed view 或 immutable evidence，一次 |
| 三个 phase-data type 的第 4.5.2 节 exact fields | 各自 `__init__` | 每项未初始化 → exact predecessor/new immutable evidence，一次 |

`role` property 只能读取 `_role`；类外及其他 method 对上述字段的
`Store`/`Del`、`setattr`、`object.__setattr__` 或 mutable-container replacement
全部拒绝。`_slots`、`_manifest_path`、`_require_root`、`_phase_data` 以及 view
的 private identity fields 均无 setter，不从 public seam 返回；任何测试
mutation 也只能验证拒绝，不能作为 production state/identity/data 注入 seam。

### 4.2 固定 23-slot tuple

`H11RootAuthorizationFlow` 的 constructor ABI 精确冻结为：

```python
def __init__(
    self,
    manifest_path: Path,
    *,
    require_root: bool = True,
) -> None: ...
```

constructor 必须把 exact `manifest_path` object 与 `require_root` value 分别一次
写入 `_manifest_path`、`_require_root`，把 `_phase_data` 一次写为 exact `None`，
并以一个 literal tuple 预分配以下
23 个 slot。表中顺序同时是 exhaustive teardown 的唯一顺序：

| index | slot role | 成功路径语义 |
| ---: | --- | --- |
| 0 | `permit-writer-endpoint` | PERMIT_COMMITTED 临时 writer |
| 1 | `ready-reader-endpoint` | READY_COMMITTED 临时 reader |
| 2 | `permit-publication` | 同一 FD 原地经历 pending、rename、final retained publication |
| 3 | `present-run-main-properties` | retained present source |
| 4 | `present-h0` | retained present source |
| 5 | `run-armed` | retained ARMED source |
| 6 | `permit-ready` | retained READY source |
| 7 | `permit-commit-fifo-pin` | retained PERMIT FIFO `O_PATH` identity |
| 8 | `ready-commit-fifo-pin` | retained READY FIFO `O_PATH` identity |
| 9 | `directory-fifo-root` | retained directory |
| 10 | `directory-receipt-root` | retained directory |
| 11 | `directory-input-root` | retained directory |
| 12 | `directory-scenario-root` | retained directory |
| 13 | `directory-harness-root` | retained directory |
| 14 | `directory-authority-root` | retained directory |
| 15 | `directory-formal-root` | retained directory |
| 16 | `source-preflight-receipt` | retained source |
| 17 | `source-seal-receipt` | retained source |
| 18 | `source-tree-receipt` | retained source |
| 19 | `source-install-manifest` | retained source |
| 20 | `source-install-receipt` | retained source |
| 21 | `source-harness-manifest` | retained source |
| 22 | `source-authorization` | retained source |

该 layout 按当前 C2a–C2d 的逆所有权关闭顺序冻结。PERMIT writer 必须
先于 publication；publication 必须先于 present、session、authority 与
authorization；present 与 authority 内部仍保持当前逆序。

不得：

- 根据已打开数量构造 slot list；
- 对 owner inventory 调用 `append`、`extend`、`insert` 或 `pop`；
- 为 staging 与 final publication 分配两个 slot；
- 为同一个 FD 创建 shadow slot、frame field 或 fallback owner；
- 在失败时临时扫描 Python 对象图推断哪些 descriptor 需要关闭。

固定 tuple 中未打开的 slot 保持 `-1`。因此任一阶段失败都扫描同一个
23-slot tuple，不需要 partial inventory。

这两个输入 field 在 constructor 返回后不可替换、删除或经 property/callback
改写。`_acquire_authorities` 的 exact signature 是
`def _acquire_authorities(self) -> None`：它只能从同一 `self` 的
`_manifest_path`/`_require_root` 读取输入，不能接受 manifest path、root flag、
config、context 或等价外部参数。production 中 constructor 的唯一 caller 是
第 9 节 exact public wrapper；任何 classmethod/factory、第二 constructor caller、
test-only production adapter 或 phase-time caller injection 都失败。

### 4.3 Typed wrapper 只能借用

directory、FIFO、JSON source、present output 和 publication wrapper 必须分别
收敛并冻结为 `H11RootDirectoryView`、`H11RootFifoView`、
`H11RootJsonSourceView`、`H11RootPresentOutputView` 和
`H11RootPublicationView` 五个 immutable borrowed view：

- 每个 view 都必须保存不可替换的 `_flow` identity reference，以及下表冻结的
  `_slot`/`_parent_slot` `H11OwnedFdSlot` object 引用与 immutable
  path/reference/raw/label；`_flow` 只标识拥有这些 slot 的同一个
  `H11RootAuthorizationFlow`，不拥有 FD、不关闭 flow，也不形成第二生命周期 owner；
- 每次 syscall 紧邻前调用 slot `borrow()`；
- 不缓存第二份 descriptor 整数；
- 没有 `close()`、`poison()`、owner-transfer 或 descriptor setter；
- flow 关闭 slot 后，wrapper 的下一次 borrow 必须 fail closed；
- wrapper 的销毁不产生任何 syscall。

五类 view 都必须是 `@dataclass(frozen=True, slots=True, init=False)` 加显式
`__init__`，或具有 AST 可证明的完全等价 immutable 实现。其 constructor
identity 参数精确为 keyword-only
`flow: H11RootAuthorizationFlow`、`slot: H11OwnedFdSlot`、
`parent_slot: H11OwnedFdSlot | None`。constructor 必须在 field Store 前以 direct
`is` identity comparison 证明 `slot`/`parent_slot` 精确命中 `flow._slots` 中
下表属于该 view class 的一个 literal pair；每个合法 pair 都必须逐项写出，不能
使用 role/path lookup、dynamic index、loop、mapping、resolver 或 helper。只有
identity proof 成功后才分别把三个参数一次写入
`_flow/_slot/_parent_slot`，其余参数只允许是各类既有 immutable
path/reference/raw/label value。不得接受 lifecycle owner、state snapshot、
allowed-state value/container、state callback、slot resolver 或 callable。五类
constructor 的 production caller 与 owning-flow 参数是闭集：

| view constructor | 唯一 production caller | exact owning-flow argument |
| --- | --- | --- |
| `H11RootDirectoryView`, `H11RootFifoView`, `H11RootJsonSourceView` | `H11RootAuthorizationFlow._acquire_authorities` | `flow=self` |
| `H11RootPresentOutputView` | `H11RootAuthorizationFlow._consume_ready_commit` | `flow=self` |
| `H11RootPublicationView` | `H11RootAuthorizationFlow._publish_permit` | `flow=self` |

每个 constructor call 的 `slot=`/`parent_slot=` 必须是同一 caller 的 literal
`self._slots[index]`/`None`，且精确等于下表；禁止从 local、aggregate、role/path
lookup、另一个 flow 或 caller 参数取得。构造后 `view._flow is self`（这里
`self` 是 phase receiver），且两端 slot 属于该同一 flow 的 identity 关系不可
替换；view 不能只比较 flow fields 或复制 `_state` 来伪造这条关系。

view 的 self/parent 组合是以下精确闭集：

| view | exact self slot | exact retained parent slot |
| --- | --- | --- |
| `H11RootDirectoryView` | `15` | 无；formal-root 只允许 canonical path `lstat` |
| `H11RootDirectoryView` | `14,13,12,11,10,9` | 分别精确为 `15,14,13,15,12,15` |
| `H11RootFifoView` | `7,8` | `9` |
| `H11RootJsonSourceView` | `22,6` | `12`；分别是 authorization 与 PERMIT_READY transaction source |
| `H11RootJsonSourceView` | `5,16,17,18,19,20,21` | 无；只允许 canonical path `lstat` |
| `H11RootPresentOutputView` | `4` (`present-h0`) | `10` (`directory-receipt-root`) |
| `H11RootPresentOutputView` | `3` (`present-run-main-properties`) | `11` (`directory-input-root`) |
| `H11RootPublicationView` | `2` | `12` |

每个 parent-bound view 必须同时保存表中的 exact self slot object 与 exact parent
slot object；construction 两端都由 phase method 以 literal `self._slots[index]`
传入，且同一次 construction 必须传 `flow=self`。不得保存 parent index 或 raw parent descriptor，不得运行时按 role/path
查 slot，不得在 revalidation 中退回 absolute-path `stat/lstat`。parent-bound
current-name identity 只能通过表中 retained parent 的 `dir_fd` 证明；只有表中
明确“无 parent”的两类 view 可以使用 canonical path `lstat`。

`H11RootRetainedAuthority` 必须重命名为 `H11RootAuthorityView`，只能聚合
上述 borrowed views 与 immutable values，不能再拥有 close、rollback 或
descriptor。旧 `RetainedH11Root*` class names 不保留 alias；名称不得成为第二
套生命周期状态机。

### 4.4 Exact slot open/borrow caller、index 与 flow-state 闭集

production 中 `slot.open()` 与 `slot.borrow()` 的 caller/index/state 必须精确
等于下表。phase caller 的 index 均必须以 literal `self._slots[index]` 表达；
view caller 只能使用 construction 时由同一 owning flow、literal pair 冻结的
`self._slot`/`self._parent_slot`。不能先把 slot 放进局部 collection、按 role
查找或由 caller 传入 index：

| operation | 唯一 qualified caller | exact slot indexes | 调用时允许的 flow state |
| --- | --- | --- | --- |
| `open` | `H11RootAuthorizationFlow._acquire_authorities` | `22,21,20,19,18,17,16,15,14,13,12,11,10,9,8,7,6,5`，按 C2a 既有依赖顺序 | `NEW` |
| `open` | `H11RootAuthorizationFlow._consume_ready_commit` | `1,4,3`，其中 reader 必须先于两份 present source | `AUTHORITIES_RETAINED` |
| `open` | `H11RootAuthorizationFlow._publish_permit` | `2` | `READY_CONSUMED` |
| `open` | `H11RootAuthorizationFlow._commit_permit` | `0` | `PERMIT_PUBLISHED` |
| `borrow` | `H11RootAuthorizationFlow._acquire_authorities` | initial source targets `5,6,16,17,18,19,20,21,22`；directory/open bridge 与 initial proof parents `9,12,13,14,15` | `NEW` |
| `borrow` | `H11RootAuthorizationFlow._consume_ready_commit` | owned targets `1,3,4`；bridge/revalidation parents `8,10,11,12` | `AUTHORITIES_RETAINED` |
| `borrow` | `H11RootAuthorizationFlow._publish_permit` | owned target `2`；bridge/barrier/transaction/publication parents `10,11,12,15` | `READY_CONSUMED` |
| `borrow` | `H11RootAuthorizationFlow._commit_permit` | owned target `0`；bridge parent `7` 与 transaction parent `12` | `PERMIT_PUBLISHED` 或 writer 已证明后的 `PERMIT_WRITER_OPEN` |
| `borrow` | `H11RootDirectoryView.revalidate` | view construction 时冻结为 `9..15` 中的一个 exact index | `NEW`, `AUTHORITIES_RETAINED`, `READY_CONSUMED`, `PERMIT_PUBLISHED`, `PERMIT_WRITER_OPEN` |
| `borrow` | `H11RootFifoView.revalidate` | self `7` 或 `8`，parent `9` | `NEW`, `AUTHORITIES_RETAINED`, `READY_CONSUMED`, `PERMIT_PUBLISHED`, `PERMIT_WRITER_OPEN` |
| `borrow` | `H11RootJsonSourceView.revalidate` | self `5`, `6` 或 `16..22`；仅 self `22/6` 有 parent `12` | `NEW`, `AUTHORITIES_RETAINED`, `READY_CONSUMED`, `PERMIT_PUBLISHED`, `PERMIT_WRITER_OPEN` |
| `borrow` | `H11RootPresentOutputView.revalidate` | exact self/parent `4<-10` 或 `3<-11` | `AUTHORITIES_RETAINED`, `READY_CONSUMED`, `PERMIT_PUBLISHED`, `PERMIT_WRITER_OPEN` |
| `borrow` | `H11RootPublicationView.revalidate` | self `2`，parent `12` | `READY_CONSUMED`, `PERMIT_PUBLISHED`, `PERMIT_WRITER_OPEN` |

每个 view construction 的 owning flow 必须是 phase receiver exact `self`，其
self/optional-parent slot indexes 也必须是 4.3 表中的 literal pair，并由 AST
与 view class 的允许 edge 做 exact equality；view 不接受 caller-provided
flow/slot/index/parent。
上述九个 borrow caller 是完整闭集，具体 non-open syscall 还必须逐项精确等于
4.4.2；任何新增 helper 必须先修改本设计并重新
审计，不能用 generic dispatch 绕过。

每个 phase method 必须在本表中的第一次 open/borrow 前检查 exact entry state，
并且每次从 syscall 返回后仍在同一 phase exception boundary 内。所有 terminal
state 中 `open` 与 `borrow` caller 数量必须为零；slot 已 detach 时 `borrow()`
自身也必须 fail closed。

五类 view 的 4.4 state 列不是说明性 metadata，而是必须在运行期执行的 gate。
flow 只增加以下 read-only property；它不得有 setter、callback 或返回 mutable
state holder：

```python
@property
def state(self) -> H11RootAuthorizationState:
    return self._state
```

每个 `revalidate()` 的第一项 control action 必须直接读取
`self._flow.state`，并用该 view 行中逐项写出的 literal enum tuple 做 membership
check；不允许时必须在任何 slot `borrow()`、syscall、path lookup 或 decoded-value
validation 前抛出 `InstallerError`。同一次 revalidate 内，每一个后续
`self._slot.borrow()`/`self._parent_slot.borrow()` expression 紧邻前还必须再次
执行相同 direct read + literal-tuple gate，保证任何 borrow 都没有只靠 entry
assertion、cached state 或 caller precondition。允许状态精确为：

| view | 每个 gate 内必须逐项出现的 literal states |
| --- | --- |
| `H11RootDirectoryView` | `NEW`, `AUTHORITIES_RETAINED`, `READY_CONSUMED`, `PERMIT_PUBLISHED`, `PERMIT_WRITER_OPEN` |
| `H11RootFifoView` | `NEW`, `AUTHORITIES_RETAINED`, `READY_CONSUMED`, `PERMIT_PUBLISHED`, `PERMIT_WRITER_OPEN` |
| `H11RootJsonSourceView` | `NEW`, `AUTHORITIES_RETAINED`, `READY_CONSUMED`, `PERMIT_PUBLISHED`, `PERMIT_WRITER_OPEN` |
| `H11RootPresentOutputView` | `AUTHORITIES_RETAINED`, `READY_CONSUMED`, `PERMIT_PUBLISHED`, `PERMIT_WRITER_OPEN` |

gate 不接受 `allowed_states` 参数，不读取 class/module mapping，不调用 helper，
不缓存 constructor/current state，也不通过 callback、policy object 或 dynamic
dispatch 计算允许集合。`_flow` 只能读 state，不能由 view 调用 transition、
close、failure/finish 或 slot mutation；由此它只是 owning-flow identity reference，
而不是第二生命周期 owner。错误 state（包括所有 terminal states）必须产生
零 borrow、零 FD syscall；把原 slot pair 与另一个（即使 input field 值相同的）
flow 配对必须在 constructor identity proof 中拒绝，替换/删除既有 view 的
`_flow` 也必须 fail closed。production 对 read-only `state` property 的 qualified
reader 闭集就是这五类 `revalidate`；flow 自身的 state machine 继续只读 `_state`。

raw borrow 是表达式级临时值，只允许作为同一 expression 中已冻结的
FD-consuming syscall 的 exact positional/keyword argument，或作为 4.4.1 节冻结
的唯一 parent-FD-to-child-open bridge 直接嵌入另一个 exact slot 的 `open()`
参数。其结果不得赋值给
local/nonlocal/global/attribute，不得放入 list/tuple/dict/set，不得 return、yield、
闭包捕获、`partial` 或 log；除 4.4.1 两条 endpoint 的 exact inline formatted
value 外不得 format，也不得传给 caller-supplied callable 或保存到
borrowed view。若 retained wrapper 需要验证，它只保存 4.3 exact slot objects，
并在自己被冻结的 validation method 中以内联 `self._slot.borrow()` 或
`self._parent_slot.borrow()` 完成紧邻 syscall；
validation method 不返回 raw FD。除 4.4.1 与 4.4.2 外不存在“FD-consuming”
概括性豁免；新增 stdlib、ctypes、wrapper 或 syscall consumer 一律是设计变更。

#### 4.4.1 唯一 inline parent borrow → child slot open bridge

一个 slot 的 `open()` 需要 retained parent dirfd 时，禁止把 parent borrow 先
赋给局部变量或交给 helper。唯一允许形状是：

```python
self._slots[CHILD].open(
    EXACT_LEAF,
    EXACT_FLAGS,
    dir_fd=self._slots[PARENT].borrow(),
)
```

READY/PERMIT FIFO endpoint 不是 directory-relative leaf open；它们唯一允许把
pinned FIFO FD 作为 `/proc/self/fd` path 的 inline format value，且整个 formatted
path 必须直接成为 child slot `open()` 的第一个参数：

```python
self._slots[1].open(
    f"/proc/self/fd/{self._slots[8].borrow()}",
    os.O_RDONLY | os.O_CLOEXEC,
)
self._slots[0].open(
    f"/proc/self/fd/{self._slots[7].borrow()}",
    os.O_WRONLY | os.O_CLOEXEC,

```

### 4.5 唯一 immutable phase-data 链

零参数 phase method 不能靠散落的 flow fields 或返回 owner 来传递 C2a–C2c
结果。flow 因此必须且只能增加一个 private data cursor：

```python
self._phase_data: (
    None
    | H11RootAuthorityPhaseData
    | H11RootReadyPhaseData
    | H11RootPermitPhaseData
) = None
```

它不是 owner registry：三个 phase-data type 都是 `@dataclass(frozen=True,
slots=True, init=False)` 加 explicit keyword-only `__init__` 的 value，只强引用由同一个 flow 构造的 borrowed views、
前一阶段的 frozen data 与 immutable decoded/value evidence；没有 descriptor、slot
inventory、`borrow/open/close/poison/detach`、lifecycle state/transition、callback
或 lifecycle method；`transaction_state` 只是 frozen protocol evidence。
flow 的固定 `_slots` 仍是唯一 FD owner，phase-data replacement 只推进 immutable
protocol evidence，不转移任何 FD ownership。

下文 JSON-shaped decoded evidence 使用递归 frozen tuple 表示：object 是按
canonical key order 的 `tuple[tuple[str, H11RootFrozenJsonValue], ...]`，array 是
`tuple[H11RootFrozenJsonValue, ...]`，leaf 只能是 JSON scalar。它没有 backing
`dict/list`、setter、lazy decoder 或 mutable alias；C2a 的 pure canonical decoder
直接产生该 value，后续 phase 只读；`H11RootFrozenJsonObject` 是上述 top-level
object tuple 的 exact type alias。该 notation 是 value schema，不是第四个 owner、
wrapper 或 dynamic dispatch helper。

```python
type H11RootFrozenJsonScalar = None | bool | int | str
type H11RootFrozenJsonValue = (
    H11RootFrozenJsonScalar
    | tuple[H11RootFrozenJsonValue, ...]
    | H11RootFrozenJsonObject
)
type H11RootFrozenJsonObject = tuple[
    tuple[str, H11RootFrozenJsonValue],
    ...,
]
```

```text
H11RootReadyPhaseData.__init__(
    self,
    *,
    authority_data: H11RootAuthorityPhaseData,
    ready_commit: H11RootCommitReceipt,
    partition: H11RootClosedPartition,
    present_h0: H11RootPresentOutputView,
    present_run_main_properties: H11RootPresentOutputView,
    transaction_state: tuple[H11RootTransactionState, ...],
    present_outputs_sha256: str,
    future_absence_sha256: str,
) -> None

H11RootPermitPhaseData.__init__(
    self,
    *,
    ready_data: H11RootReadyPhaseData,
    barrier: H11RootPrePermitBarrier,
    publication: H11RootPublicationView,
    transaction_state: tuple[H11RootTransactionState, ...],

```

| type/field | 唯一 constructor caller | 唯一 post-construction production readers |
| --- | --- | --- |
| `H11RootAuthorityPhaseData.authority` | `_acquire_authorities`，一次 | `_consume_ready_commit`；经 `H11RootReadyPhaseData.authority_data`/`H11RootPermitPhaseData.ready_data` 的同一 object identity chain 被 `_publish_permit`、`_commit_permit` 读取 |
| `H11RootReadyPhaseData.authority_data` | `_consume_ready_commit`，一次，必须是 entry exact `H11RootAuthorityPhaseData` object | `_publish_permit`；经 permit data 的同一 object identity chain 被 `_commit_permit` 读取 |
| `H11RootReadyPhaseData.ready_commit`, `partition`, `present_h0`, `present_run_main_properties`, `transaction_state`, `present_outputs_sha256`, `future_absence_sha256` | `_consume_ready_commit` 同一个 constructor call | `_publish_permit`, `_commit_permit`，只读 revalidation/payload/barrier evidence |
| `H11RootPermitPhaseData.ready_data` | `_publish_permit`，一次，必须是 entry exact `H11RootReadyPhaseData` object | `_commit_permit` |
| `H11RootPermitPhaseData.barrier`, `publication`, `transaction_state` | `_publish_permit` 同一个 constructor call | `_commit_permit`，只读 final revalidation/commit evidence |

每个 phase-data type 的 explicit keyword-only constructor signature 由其上表 field
按顺序逐项生成，return annotation 为 `None`，不允许 positional、额外/optional/
variadic 参数。constructor 必须验证所有新 borrowed views 的 `_flow` 与前一数据
链最终的 `authority._flow` 是同一个 object，并验证 slot pair 精确为 4.3；它不
borrow、不调用 syscall、不关闭旧 data。`authority_data`/`ready_data` 强引用前一
exact object，禁止 flatten/copy predecessor fields、重建旧 data、union dict、
optional scattered fields 或按 `_state` 猜 data type。

AuthorityData 要求 `type(authority) is H11RootAuthorityView`。ReadyData 还要求
ready receipt/partition/transaction evidence exact types、两个 present view 分别
命中 slot `4<-10` 与 `3<-11` 且不 alias、两个 digest 是 canonical SHA-256 hex。
PermitData 要求 barrier/publication/transaction evidence exact types，publication
命中 slot `2<-12`。这些都是 constructor 内 pure type/value/identity checks；不得
重新 decode、revalidate、borrow 或产生 syscall。
`H11RootPrePermitBarrier` 本身继续只保存既有 frozen references/digests/
transaction/future-absence values，不反向引用 flow、ReadyData、view 或旧 closure；
其 evidence 由 `_publish_permit` 直接构造并作为 PermitData value 传入。

constructor validation 的 reader 也属于闭集：AuthorityData 只读
`authority._flow`；ReadyData 只读 `authority_data.authority._flow` 与两个 present
view 的 `_flow/_slot/_parent_slot`；PermitData 只读
`ready_data.authority_data.authority._flow` 与 publication 的
`_flow/_slot/_parent_slot`。此外 constructor 对 predecessor/new evidence 只做 exact
type/value check；其他 attribute reader、helper/callback 或 traversal 为零。

#### 4.5.3 `_phase_data` replacement/read 闭集

| flow method | entry exact `_phase_data` | 唯一允许 replacement | replacement 后下一 statement |
| --- | --- | --- | --- |
| `__init__` | 未初始化 | exact `None`，一次 | 初始化其余 frozen flow fields/state；不得构造 phase data |
| `_acquire_authorities` | exact `None` | 全部 C2a validation 成功后构造一个 `H11RootAuthorityView`，再唯一一次写为 `H11RootAuthorityPhaseData(authority=...)` | exact `NEW -> AUTHORITIES_RETAINED` transition |
| `_consume_ready_commit` | exact `H11RootAuthorityPhaseData` | 全部 C2b validation、reader early close、READY receipt、present/partition/transaction evidence 成功后，唯一一次写为 `H11RootReadyPhaseData(authority_data=entry_data, ...)` | exact `AUTHORITIES_RETAINED -> READY_CONSUMED` transition |
| `_publish_permit` | exact `H11RootReadyPhaseData` | 全部 C2c publication/final revalidation 成功后，唯一一次写为 `H11RootPermitPhaseData(ready_data=entry_data, ...)` | exact `READY_CONSUMED -> PERMIT_PUBLISHED` transition |
| `_commit_permit` | exact `H11RootPermitPhaseData` | 禁止 replacement | 只读该 exact data 完成 C2d |
| `_transition` | 仅 success edges 按第 5.1 节要求 exact Authority/Ready/Permit type | 禁止 replacement | data gate 后才可写 `_state` |
| `_mark_write_in_flight`, `_mark_postwrite` | exact `H11RootPermitPhaseData` | 禁止 replacement | data gate 后才可写 `_commit_boundary` |

四个 phase 都只有 `self`、零外部参数；前三个通过 `_phase_data` 传递语义而
不是 return value。前三个 exact signatures 是
`_acquire_authorities(self) -> None`、`_consume_ready_commit(self) -> None`、
`_publish_permit(self) -> None`，第四个是
`_commit_permit(self) -> H11RootCommitReceipt`。

replacement 与随后的 state transition 之间不得有 syscall、callback、hook、
validation、第二 Store 或可能正常失败的 helper；transition 返回后 method 立即
`return None`。`_fail/_finish/close` 和所有 terminal path 不读写、清空或降级
`_phase_data`；sweep 后它可以继续强引用 views，但所有 FD 仍只在已清空 slots 中，
因此不形成 owner resurrection。除上表四个 `_phase_data` writer 外，Store/Del/setattr、
property setter、container mutation 或 phase-data compatibility adapter 全部为零。

## 5. Flow state machine

`H11RootAuthorizationFlow` 只允许以下状态：

```text
NEW
  -> AUTHORITIES_RETAINED
  -> READY_CONSUMED
  -> PERMIT_PUBLISHED
  -> PERMIT_WRITER_OPEN
  -> PERMIT_FRAME_WRITTEN
  -> COMPLETE

尚未进入 write attempt 的失败       -> FAILED_PREWRITE
进入 write attempt 后结果不确定      -> FAILED_WRITE_AMBIGUOUS
已验证 exact frame 写入后的失败      -> FAILED_POSTWRITE
显式提前关闭且此前无失败             -> CLOSED
```

非 terminal 成功状态只能经一个 private `_transition` method 按上图前进；
terminal 写入只允许由本节冻结的 `_fail`、`_finish`、`close` 完成。不得倒退、
跳过、重入或从任一 terminal state 再运行。

- `AUTHORITIES_RETAINED`：authorization、harness/bound sources、七个
  directory、两个 FIFO pin、READY 和 ARMED 已固定并完成 C2a 验证，
  `_phase_data` exact type 为 `H11RootAuthorityPhaseData`；
- `READY_CONSUMED`：READY endpoint 已 detach 并成功 close，exact frame
  与 receipt 已验证，两份 present source 已固定，C2b 验证完成，
  `_phase_data` exact type 为 `H11RootReadyPhaseData`；
- `PERMIT_PUBLISHED`：slot 2 中的同一 staging FD 已完成 rename、parent
  fsync、final identity revalidation，C2c 完成，`_phase_data` exact type 为
  `H11RootPermitPhaseData`；
- `PERMIT_WRITER_OPEN`：slot 0 已经 blocking open 并按 retained FIFO
  identity 完成 fstat/prove；`_phase_data` 仍是 C2c 构造的同一 Permit object；
- `PERMIT_FRAME_WRITTEN`：唯一 `os.write` 已返回精确 frame 长度；
- `COMPLETE`：writer 已成功 detach/close，固定 slot tuple 已完整 sweep 且
  无 close error，typed commit receipt 才可返回；Permit data identity 未改写。

`FAILED_POSTWRITE` 明确记录外部 harness 可能已经观察到 frame。它不能被
降格为 prewrite failure，也不能允许调用者在同一 root 上重试。

`FAILED_WRITE_AMBIGUOUS` 明确记录 flow 已经越过 write-attempt boundary，但
没有在 Python 中取得并验证 exact byte count。外部结果可能是零字节、partial
frame 或完整 frame；它不声称 exact frame 已发送，却必须与 postwrite failure
一样禁止 receipt、禁止同 root 重试并终止 one-shot 进程。

flow 还必须持有一个不对外暴露的 exact commit boundary：

```text
PREWRITE -- _mark_write_in_flight --> WRITE_IN_FLIGHT
WRITE_IN_FLIGHT -- exact os.write returned len(H11_PERMIT_COMMITTED_BYTES) --> POSTWRITE
```

`_commit_boundary` 初始为 `PREWRITE`。唯一 writer
`H11RootAuthorizationFlow._mark_write_in_flight` 只允许由 `_commit_permit`
在唯一 `os.write` 紧邻前调用，要求 state=`PERMIT_WRITER_OPEN`、boundary=
`PREWRITE`，并只做 `PREWRITE -> WRITE_IN_FLIGHT`。按 Python call 参数求值顺序，
它返回后、进入唯一 `os.write` 前必须先调用且只能调用 direct inline
`self._slots[0].borrow()`；该 call 必须恰好是同一个 `os.write` 的 positional 0，
其返回后立即进入该 `os.write`。除同一 write expression 对 frozen positional 1
frame 的无副作用加载外，中间不得有其他 statement、可观察动作、call、syscall、
comparison、log 或 hook。

`H11RootAuthorizationFlow._mark_postwrite` 同样只允许由 `_commit_permit` 调用，
要求 state=`PERMIT_WRITER_OPEN`、boundary=`WRITE_IN_FLIGHT`，且唯一
`os.write` 已返回并通过 exact byte-count comparison；它只做
`WRITE_IN_FLIGHT -> POSTWRITE` 一次。两个 boundary method 都不是 receipt、
phase 或 caller-settable flag；它们只决定统一失败出口选择哪个不可逆 terminal。

### 5.1 Exact transition API、edge、caller 与 update order

非 terminal 成功边只能经
`_transition(*, expected: H11RootAuthorizationState, target: H11RootAuthorizationState)`。
`_transition` 必须要求当前 state 精确等于 `expected`，并拒绝不在下表的 edge：

| exact edge/update | 唯一 caller | update 前必须已完成 | update 后下一允许动作 |
| --- | --- | --- | --- |
| constructor → `NEW`, boundary → `PREWRITE` | `H11RootAuthorizationFlow.__init__` | exact 23-slot tuple 已构造且全 empty/unstarted，`_phase_data is None` | `_acquire_authorities` 或显式 `close` |
| `NEW -> AUTHORITIES_RETAINED` | `_acquire_authorities` | C2a 全部 open/prove/decode/revalidate 成功，`_phase_data` 已唯一替换为 exact `H11RootAuthorityPhaseData` | `return None` 给 `authorize_once` 继续 C2b |
| `AUTHORITIES_RETAINED -> READY_CONSUMED` | `_consume_ready_commit` | slot 1 已 detach/close 成功，frame/receipt/present/partition 全部有效，`_phase_data` 已唯一替换为 exact `H11RootReadyPhaseData` | `return None` 继续 C2c |
| `READY_CONSUMED -> PERMIT_PUBLISHED` | `_publish_permit` | rename、parent fsync、final-link revalidation 全部成功，`_phase_data` 已唯一替换为 exact `H11RootPermitPhaseData` | `return None` 继续 C2d |
| `PERMIT_PUBLISHED -> PERMIT_WRITER_OPEN` | `_commit_permit` | slot 0 blocking open 后立即 fstat/prove 成功 | 执行唯一 exact write |
| boundary `PREWRITE -> WRITE_IN_FLIGHT` | `_commit_permit` 通过 `_mark_write_in_flight` | writer/flow/publication/partition/transaction revalidation 全部成功 | 下一条 call 必须是唯一 direct positional-0 inline `self._slots[0].borrow()`，其返回后立即进入唯一 `os.write`；除 frozen frame 加载外无其他动作/call |
| boundary `WRITE_IN_FLIGHT -> POSTWRITE` | `_commit_permit` 通过 `_mark_postwrite` | 唯一 `os.write` 已返回 exact frame 长度且 byte-count comparison 成功 | 紧接下一行 state transition；此前不得 close/其他 call/syscall |
| `PERMIT_WRITER_OPEN -> PERMIT_FRAME_WRITTEN` | `_commit_permit` | boundary 已是 `POSTWRITE` | 只允许 exact slot-0 early close，然后返回预构造 receipt 给 `_finish` |
| any nonterminal → `FAILED_PREWRITE` | `authorize_once` 的唯一 `except BaseException` 经 `_fail(active_error)` | boundary 仍为 `PREWRITE` | terminal-before-sweep；sweep 后重抛同一 primary |
| any nonterminal → `FAILED_WRITE_AMBIGUOUS` | 同上经 `_fail(active_error)` | boundary 已为 `WRITE_IN_FLIGHT` | terminal-before-sweep；无 receipt/重试，sweep 后重抛同一 primary |
| any nonterminal → `FAILED_POSTWRITE` | 同上经 `_fail(active_error)` | boundary 已为 `POSTWRITE` | terminal-before-sweep；sweep 后重抛同一 primary |
| `PERMIT_FRAME_WRITTEN -> COMPLETE` | `authorize_once` 经 `_finish(receipt)` | `_sweep_slots(active_error=None)` 已完整返回且无 close failure | 返回同一 typed receipt |
| `PERMIT_FRAME_WRITTEN -> FAILED_POSTWRITE` | `_finish(receipt)` | finish sweep 已完整访问所有 slot并以首个 close failure 退出 | 重抛该同一 close primary，不返回 receipt |
| `NEW` 或任一 boundary=`PREWRITE` 的 active state → `CLOSED` | 显式 `close()` | full sweep 已完整成功 | terminal；重复 close 为无副作用 no-op |
| `NEW` 或任一 boundary=`PREWRITE` 的 active state → `FAILED_PREWRITE` | 显式 `close()` | full sweep 已完成但至少一个 close 失败 | 重抛第一个 close failure |
| 任一 boundary=`WRITE_IN_FLIGHT` 的 active state → `FAILED_WRITE_AMBIGUOUS` | 显式 `close()` | 先构造固定 write-in-flight misuse primary，再以该 primary 完整 sweep | 重抛 misuse primary；首个 close failure仅为 note |
| `PERMIT_FRAME_WRITTEN` → `FAILED_POSTWRITE` | 显式 `close()` | 先构造固定 early-close misuse primary，再以该 primary 完整 sweep | 重抛 misuse primary；首个 close failure仅为 note |

`_transition` 对成功 edge 还必须在写 `_state` 前检查 exact data type：前三条
phase edge 分别要求 Authority/Ready/Permit data；
`PERMIT_PUBLISHED -> PERMIT_WRITER_OPEN` 与
`PERMIT_WRITER_OPEN -> PERMIT_FRAME_WRITTEN` 都要求 exact Permit type。
`_mark_write_in_flight` 与 `_mark_postwrite` 也只接受 Permit type，均不得写它；
从 C2c 后 writer allowlist 为零静态证明这些方法观察的是同一 object identity。
错误 data type 在 state/boundary mutation 前拒绝，不能由 transition 根据 state
合成或修复 data；`_finish` 只依赖已冻结 state/boundary，不读写 phase data。

`_fail(active_error)` 必须接收并保留 exact `BaseException` object；先根据
`_commit_boundary` 把 `_state` 精确写为 `FAILED_PREWRITE`、
`FAILED_WRITE_AMBIGUOUS` 或 `FAILED_POSTWRITE`，再调用
`_sweep_slots(active_error=active_error)`，最后重新
抛出同一 object。它不得从 `sys.exc_info()` 猜 primary，也不得让 teardown
failure 改写 boundary 或 terminal state。

`_finish(receipt)` 要求 state=`PERMIT_FRAME_WRITTEN`、boundary=`POSTWRITE`。
它必须先调用 `_sweep_slots(active_error=None)`；只有该 sweep 全部成功后才写
`COMPLETE` 并返回原 receipt。若 sweep 抛出首个 close failure，`_finish`
必须在不重扫的前提下写 `FAILED_POSTWRITE` 并重抛同一 close object。

显式 `close()` 在 `NEW` 时也按内部 23-slot tuple 执行一次 empty sweep，成功
后进入 `CLOSED`；再次 close 不访问 slot。对其他 prewrite active state，成功
sweep 后进入 `CLOSED`，close failure 则进入 `FAILED_PREWRITE`。boundary 为
`WRITE_IN_FLIGHT` 时不能洗成 `CLOSED`，必须构造 exact
`InstallerError("H11 authorization flow closed while permit write outcome is ambiguous")`，
先写 `FAILED_WRITE_AMBIGUOUS`，再以该 object 作为 active primary sweep 并重抛。
在
`PERMIT_FRAME_WRITTEN` 调用 close 不能把已发送 frame 洗成 `CLOSED`，必须按
上表先构造 exact `InstallerError("H11 authorization flow closed after permit frame write")`，
将 state 写为 `FAILED_POSTWRITE`，再以该 object 作为 active primary sweep 并
重抛同一 object。`COMPLETE`、`FAILED_PREWRITE`、
`FAILED_WRITE_AMBIGUOUS`、`FAILED_POSTWRITE`、`CLOSED` 上的 close 均为无
syscall no-op；任何 terminal
state 都禁止 transition、open、borrow、write、publication 或 receipt reuse。

private state mutation allowlist 同样是闭集：`_state` 只能由 `__init__`、
`_transition`、`_fail`、`_finish`、`close` 写；`_commit_boundary` 只能由
`__init__`、`_mark_write_in_flight` 与 `_mark_postwrite` 写。类外 Store/Del/setattr、第二个 transition
helper、直接把 `COMPLETE` 写在 sweep 前或依据 `_state` 猜测 write boundary
全部失败。

`_phase_data` mutation/read 必须另外精确等于第 4.5.3 节；state transition
不能创建、转换或清空 data。任一 FAILED/COMPLETE/CLOSED terminal 保留当时 exact
phase-data object identity、只由 slot sweep 清空 FD；terminal writer 对
`_phase_data` 为零。

## 6. C2a–C2d 原地阶段迁移

### 6.1 C2a：authority/session acquisition

flow 在任何 open 前已拥有完整 23-slot tuple。所有 source、directory 与
FIFO open 都必须由第 4.4 节冻结的 phase method 对 exact literal slot
expression 调用 `slot.open()`；phase method 以同一 literal slot expression
直接构造 frozen borrowed view，其他验证 helper 只接收 immutable metadata；
需要 FD 的 acquisition 只能由 4.4.2 冻结的 phase rows 或五个 exact
borrowed-view `revalidate` rows 以内联 borrow 完成。helper 返回
decoded/immutable reference 或构造 borrowed view，
不返回 owned descriptor，也不得自行选择、替换、borrow 或打开 slot。

五个 bound source、七个 directory、两个 commit FIFO、READY 与 ARMED 必须
按现有验证依赖顺序逐一填入其固定 slot。后续对象依赖 parent descriptor
时，只能使用 4.4.1 表中的 exact inline parent-borrow bridge。任何错误直接进入 flow 的唯一失败出口并
扫描全 tuple。全部成功后 `_acquire_authorities` 才以 4.5.1 的全部 exact named
fields 构造唯一 `H11RootAuthorityView`，将 `_phase_data` 从 `None` 唯一替换为
`H11RootAuthorityPhaseData(authority=authority)`；下一 statement 必须执行 exact
`NEW -> AUTHORITIES_RETAINED`，然后立即 `return None`。

不得先把 descriptor 放进局部 list，再在阶段末转换为 tuple；不得以
`result is not None` 选择两套 rollback，也不得把 C2a evidence 散写到 flow 的
其他 field。

### 6.2 C2b：READY consume 与 present source

entry 必须同时要求 state=`AUTHORITIES_RETAINED` 且
`type(self._phase_data) is H11RootAuthorityPhaseData`，并把该 exact object 绑定为
local `phase_data`；任何 mismatch 在 borrow/syscall 前拒绝。

READY reader 只能以 4.4.1 冻结的 exact
`self._slots[1].open(f"/proc/self/fd/{self._slots[8].borrow()}", ...)` 打开 slot 1。它继续使用 blocking
`O_RDONLY|O_CLOEXEC`、retained FIFO identity 的立即 fstat/prove、读取到
EOF、要求 exact `H11_READY_COMMITTED_BYTES`。

顺序冻结为：

```text
`self._slots[1].open(...)`
-> fstat/prove borrowed endpoint
-> read until EOF
-> `self._close_slot_once(self._slots[1])`
-> validate exact frame
-> construct READY commit receipt
```

fstat/read primary 加 reader-close secondary 时，primary object 不变，
close failure 只形成确定性 note。正常 EOF 后 close 本身失败时，该 close
failure 是 primary，且不构造 READY receipt。

READY receipt factory 与 caller ABI 精确冻结为：

```python
@classmethod
def ready_committed(
    cls,
    fifo: H11RootFifoView,
    payload: bytes,
) -> H11RootCommitReceipt: ...
```

它的唯一 production caller 是
`H11RootAuthorizationFlow._consume_ready_commit`，调用恰好一次。caller 在 factory
call 前必须先完成以下 direct identity gate，失败时 factory call count 为零：

```python
fifo = phase_data.authority.ready_commit_fifo
if (
    fifo is not phase_data.authority.ready_commit_fifo
    or fifo._flow is not self
    or fifo._slot is not self._slots[8]
    or fifo._parent_slot is not self._slots[9]
):
    raise InstallerError(...)
receipt = H11RootCommitReceipt.ready_committed(fifo, payload)
```

`payload` 必须是 reader EOF 后验证为 exact `H11_READY_COMMITTED_BYTES` 的同一
bytes object。factory 本身不读取 `_flow/_slot/_parent_slot`、不判断 canonical
phase-data identity；它只验证 FIFO role/reference 与 exact payload 后构造
immutable receipt。factory 不接受 slot、raw descriptor、owner、callback 或其他
参数，不 open/borrow/close/transition。identity gate 成功后的下一项 call 必须是
上述 factory call，中间不得 reselect FIFO、调用 helper/callback 或执行 syscall。
旧 `RetainedH11RootFifo` 不得出现在其 annotation、body、caller 或任何
production/test compatibility alias 中。

两个 present source 直接进入 slots 4 和 3；其角色与 slot index 固定，
H0 slot 4 只能绑定 retained receipt-root slot 10，run-main-properties slot 3
只能绑定 retained input-root slot 11；不能按 caller array、path branch 或动态
parent index 扩展 owner inventory。完成 closed partition、
transaction phase 和 alias 验证后，`_consume_ready_commit` 才把 `_phase_data`
唯一替换为 4.5.2 exact
`H11RootReadyPhaseData(authority_data=phase_data, ready_commit=receipt, ...)`；下一
statement 必须执行 exact `AUTHORITIES_RETAINED -> READY_CONSUMED`，然后立即
`return None`。

### 6.3 C2c：staging 与 permit publication

entry 必须同时要求 state=`READY_CONSUMED` 且
`type(self._phase_data) is H11RootReadyPhaseData`，并把该 exact object 绑定为
local `phase_data`；C2c 的所有 authority/READY evidence 只能经此前驱链读取。

`PERMIT.pending` 与 `PERMIT.json` 共用 slot 2。`_publish_permit` 必须以
4.4.1 冻结的 exact slot-12 `dir_fd` inline bridge
`self._slots[2].open("PERMIT.pending", ..., dir_fd=self._slots[12].borrow())`
原地打开它；所有 staging FD syscall 都由该 method
对 `self._slots[2].borrow()` 内联执行，named-staging validation helper 只接收
immutable plan/stat/raw value，禁止自行 open/borrow 或返回裸 descriptor：

```text
slot 2 openat PERMIT.pending O_RDWR|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC
-> existing canonical-publication complete-write loop
   (memoryview + short-write forward progress until empty)
-> fchmod 0444
-> lseek/read back/fstat/revalidate
-> fsync borrowed staging FD
-> renameat2 RENAME_NOREPLACE while slot 2 remains bound
-> fsync borrowed scenario-parent FD
-> nofollow final stat proves same inode
-> publication view continues borrowing slot 2
```

C2c 的 canonical JSON publication 明确保留基线已有的完整写循环：每次
`os.write` 消耗 memoryview 已写前缀，short write 只要大于零就继续向前，
zero/negative progress 才 fail closed。现有 short-write progress 行为与测试
必须原样保留。该循环写的是尚未 rename 的 regular staging file，不是
PERMIT commit frame 的外部线性化点，因此不受 C2d one-write 禁令约束。

rename 只是 slot 2 所绑定对象的命名阶段改变，不是 FD ownership transfer。
不得创建 `staging_slot`、`publication_slot` 两份引用或在 rename 后 reopen。

pre-rename failure 可以留下 pending；post-rename failure 可以留下 final；
两者都进入 `FAILED_PREWRITE`、不发送 PERMIT frame、不删除文件、不重试。
全部成功后 `_publish_permit` 才执行 exact
4.5.2 `H11RootPermitPhaseData(ready_data=phase_data, barrier=...,
publication=..., transaction_state=...)` replacement；下一 statement 必须执行
`READY_CONSUMED -> PERMIT_PUBLISHED`，然后立即 `return None`。

### 6.4 C2d：exact write linearization

typed PERMIT receipt factory 与 caller ABI 精确冻结为：

```python
@classmethod
def permit_committed(
    cls,
    fifo: H11RootFifoView,
    payload: bytes,
) -> H11RootCommitReceipt: ...
```

`_commit_permit` entry 必须同时要求 state=`PERMIT_PUBLISHED` 且
`type(self._phase_data) is H11RootPermitPhaseData`，绑定 exact local
`phase_data` 并在 C2d 全程只读、绝不替换它。factory 的唯一 production caller
是该 method，调用恰好一次；caller 在 factory call 前必须执行：

```python
fifo = phase_data.ready_data.authority_data.authority.permit_commit_fifo
if (
    fifo
    is not phase_data.ready_data.authority_data.authority.permit_commit_fifo
    or fifo._flow is not self
    or fifo._slot is not self._slots[7]
    or fifo._parent_slot is not self._slots[9]
):
    raise InstallerError(...)
receipt = H11RootCommitReceipt.permit_committed(
    fifo,
    H11_PERMIT_COMMITTED_BYTES,
)
```

factory 本身不读取 `_flow/_slot/_parent_slot`、不判断 phase-data identity；它只
验证 FIFO role/reference 与 exact frozen `H11_PERMIT_COMMITTED_BYTES` 后构造
immutable receipt。factory 不接受 slot、raw descriptor、owner、callback 或其他
参数，不 open/borrow/close/transition。identity gate 成功后的下一项 call 必须是
上述 factory call，中间不得 reselect FIFO、调用 helper/callback 或执行 syscall。旧
`RetainedH11RootFifo` 在 annotation、body、caller 或 compatibility alias 中必须
为零。

`H11RootCommitReceipt.permit_committed(...)` 必须在打开 writer 前由上述唯一
caller 预构造，但不能在成功终止前返回。

slot 0 通过 retained FIFO slot 7 的 `/proc/self/fd/<fd>` identity blocking
open；唯一表达式是 4.4.1 冻结的
`self._slots[0].open(f"/proc/self/fd/{self._slots[7].borrow()}", ...)`，使用
`O_WRONLY|O_CLOEXEC` 并立即 fstat/prove。成功后先执行 exact
`PERMIT_PUBLISHED -> PERMIT_WRITER_OPEN`，之后重新验证 flow、publication、
closed partition 与 exact `permit-committed` transaction phase。

线性化点只能是这一条 `os.write`；其前必须先登记 attempt，并让 writer FD
只在该 write expression 的 positional 0 原地借用：

```python
self._mark_write_in_flight()
written = os.write(
    self._slots[0].borrow(),
    H11_PERMIT_COMMITTED_BYTES,
)
```

不得使用循环、`writev`、第二次 write 或补写。按 Python 参数求值顺序，
`_mark_write_in_flight()` 返回后的下一条 call 必须是上述 direct inline
`self._slots[0].borrow()`；它必须恰好占据唯一 `os.write` 的 positional 0，且
borrow 返回后立即进入该 `os.write`。两者之间除同一 call expression 对 frozen
`H11_PERMIT_COMMITTED_BYTES` positional 1 的无副作用加载外，不得插入其他
statement、可观察动作、call 或 syscall。frame 小于
`PIPE_BUF`；只有返回值精确等于 frame 长度时，紧接 byte-count comparison 的
第一项状态动作才可调用 `_mark_postwrite()`；其后紧接执行
`PERMIT_WRITER_OPEN -> PERMIT_FRAME_WRITTEN`。两者之前不得调用任何 helper、
close、log、hook 或其他 syscall。

一旦 `_mark_write_in_flight()` 返回，inline slot-0 borrow exception、`os.write`
exception、EPIPE、short write、zero write、byte-count check failure，或 write 已产生
kernel side effect 后到 `_mark_postwrite()` 之间的异步 interruption，都必须由统一 failure boundary
进入 `FAILED_WRITE_AMBIGUOUS`。这些结果可能对应 0、partial 或 full frame；均
无 receipt、无第二次 write、无补写且同 root 永不重试。只有 exact byte count
经 Python 验证后才进入 `POSTWRITE`；这不声称把 syscall side effect 与 Python
state update 原子化。

成功 exact write 后：

1. 已先写入 `POSTWRITE` boundary 并进入 `PERMIT_FRAME_WRITTEN`；
2. 用 exact `self._close_slot_once(self._slots[0])` detach 并对 writer 做一次 close；
3. 若 early close 失败，将其作为 operation primary 交给统一失败出口；
4. `_commit_permit` 成功只把预构造 receipt 交给 `_finish`；
5. `_finish` 按内部固定 tuple 完整关闭余下 slot；
6. 只有 sweep 全部成功才进入 `COMPLETE` 并返回预构造 receipt。

exact write 成功后的 writer-close、publication-close 或后续 retained FD
close failure 都发生在线性化之后：不得伪称 frame 未发送，不得返回
receipt，也不得重试 authorizer。writer-close failure 是当前 operation
primary；后续 slot 关闭失败中只有按固定顺序遇到的第一项成为唯一
secondary note，其余仍访问和记录在 syscall trace 中，但不扩张 exception ABI。

## 7. 两个且仅两个关闭 primitive

C2e 必须冻结两个关闭 primitive，不能再增加 endpoint-specific close、
wrapper close 或复制的 detach/close 分支。

### 7.1 `_close_slot_once(self, slot, *, active_error=None)`

该 primitive 是唯一允许执行以下动作的函数：

1. 调用 `slot.detach()`，在 syscall 前清空 slot；
2. empty slot 直接返回 `None`；
3. 对非负 descriptor 调用一次且仅一次 `os.close`，捕获该调用产生的任意
   `BaseException` 作为 close failure；
4. close 成功返回 `None`；
5. close 失败时，若有 `active_error`，把该 close failure 作为确定性 note
   添加到 active primary；
6. 无论是否有 active primary，都返回观察到的 close exception，供 caller
   决定是否已记录本轮第一个 teardown failure。

它不循环、不 retry、不 sweep，也不自行替换或重新抛出 active primary。
READY reader 与 PERMIT writer 的正常 early close 必须调用它；caller 在无
active primary 时若收到 close exception，就把同一 exception 作为 operation
primary 抛给 flow 的统一失败出口。receipt 必须在 early close 成功后才可
形成或返回。

### 7.2 `_sweep_slots(self, *, active_error=None)`

该 primitive 不接收 `slots`、iterable、slice、caller-selected tuple 或 start
index；它只能读取 `self._slots`，并按该 tuple 顺序逐 slot 调用
`self._close_slot_once`。它不得直接调用 `detach`、`os.close` 或 `add_note`，
不得复制 7.1 的任何关闭逻辑。

伪代码语义固定为：

```text
first_close_error = None
for slot in self._slots:
    observed = self._close_slot_once(
        slot,
        active_error=(
            active_error
            if active_error is not None and first_close_error is None
            else None
        ),
    )
    if first_close_error is None and observed is not None:
        first_close_error = observed

if active_error is None and first_close_error is not None:
    raise first_close_error after the complete sweep
```

有 operation primary 时，只有第一个 close failure 获得 note；后续 close
failure 不替换 primary、不追加第二条 note，但 sweep 仍继续。无 operation
primary 时，完整 sweep 后抛出第一个 close failure，后续 close failure 同样
不作为 note 附到第一个 failure。该“最多一个 teardown secondary note”是
当前 C2d receipt/error ABI，C2e 只能保持，不能借重构扩张为多 note 聚合。

### 7.3 Early close 与 full sweep 的组合

READY 正常 EOF 后由 `_consume_ready_commit` 以 exact expression
`self._close_slot_once(self._slots[1])` 关闭 reader；PERMIT exact write 且
POSTWRITE boundary/state 已写入后，由 `_commit_permit` 以 exact expression
`self._close_slot_once(self._slots[0])` 关闭 writer。两个 caller 都不得传局部
alias、role lookup 或 caller-provided slot。
early close 在任何 `os.close` 前已经 detach。若它成功或失败，后续 full
sweep 看到的 endpoint slot 都是 empty，因此只访问 slot、不会发生第二次
physical close。

fstat/read/write 等 operation primary 发生在 endpoint 仍绑定时，则失败出口
直接调用 `self._sweep_slots(active_error=primary)`；sweep 通过
`_close_slot_once` 关闭 endpoint，并将首个 close failure记为 note。

exact qualified caller allowlist 冻结为：

| callee | 唯一允许 caller |
| --- | --- |
| `H11RootAuthorizationFlow._close_slot_once` | `H11RootAuthorizationFlow._sweep_slots`，receiver 来自 `for slot in self._slots`；`H11RootAuthorizationFlow._consume_ready_commit`，参数 exact `self._slots[1]`；`H11RootAuthorizationFlow._commit_permit`，参数 exact `self._slots[0]` |
| `H11RootAuthorizationFlow._sweep_slots` | `H11RootAuthorizationFlow._fail`、`H11RootAuthorizationFlow._finish`、`H11RootAuthorizationFlow.close`；三者均不得传 slot 参数 |

`authorize_once` 的异常出口只调用 `_fail(primary)`；成功出口只调用
`_finish(receipt)`。`_fail` 与 `_finish` 不得自己 detach/close/add-note，
只能按第 5.1 节的顺序设置 terminal state/commit completion 并调用
`_sweep_slots`。特别地，`_fail` 是 terminal-before-sweep，`_finish` 是
sweep-before-COMPLETE；finish teardown failure 必须进入 `FAILED_POSTWRITE`。

note 文本沿用 C2d 已冻结形式：

```text
H11 ownership teardown secondary: <ExceptionType>: <message>
```

所有 slot 即使前一个或多个 close 失败也必须被访问。每个已绑定 descriptor 只有
一次 physical close attempt。close 返回错误后不得假定内核状态，也不得
用相同整数再 close；detach-before-close 防止数字复用后误关新对象。

现有转换边界保持：已经规定 `OSError -> InstallerError` 的 open/pin/
revalidate 路径继续转换并保留原异常为 `__cause__`；非 OSError primary
保持对象 identity。teardown failure 不替换 primary，不建立新的 wrapper
exception。

## 8. 同步异常保证与纯 Python 异步边界

### 8.1 C2e 能提供的保证

对普通同步执行，slot 在 syscall 后的第一条所有权动作就是 bind。只要 FD
已经 bind，之后任意同步 `BaseException` 都进入 flow 的唯一失败出口，
完成固定 tuple sweep、primary 保真和 deterministic note。

slot 的 precondition 在 `os.open` 前完成；`_bind` 对一个正常 `os.open`
返回值没有可失败的外部调用。因此同步异常模型中不存在“open 成功但后续
验证发生在登记 ownership 之前”的 helper 窗口。

### 8.2 不能声称的保证

纯 Python 至少有三类不能与 kernel side effect 合并的 bytecode 边界：

1. `os.open` 已分配 FD 到 `_bind` 把 descriptor STORE 进 slot；
2. `os.write` 已经产生 0/partial/full 外部结果到 Python 验证 byte count 并执行
   `_mark_postwrite`；C2e 只能在 syscall 前先写 `WRITE_IN_FLIGHT`，不能知道
   中断点的 exact byte outcome；
3. `slot.detach()` 已把 slot 清空到 `os.close` 真正执行；若异步异常精确落在
   这里，固定 sweep 只会看到 empty slot，不能再安全使用可能已复用的整数。

任意 Python 实现都不能仅靠 class、`try/finally`、context manager 或赋值写法，
把这些 kernel effect 与 Python field/state update 合并成不可中断原子操作。
因此 C2e 不宣称能够结构化恢复精确落在上述间隙的异步异常，包括默认 SIGINT
转换成的 `KeyboardInterrupt`、外部信号触发的 Python handler、trace/profile
注入、线程级异步异常或 task cancellation。通过
signal mask、临时 handler、native shim、
`ExitStack`、finalizer 或重试来掩盖该边界均不在本设计内。

write gap 由预先登记的 `WRITE_IN_FLIGHT` 保守分类，不伪称 exact frame；
detach→close gap 中 descriptor 最终只能依赖 official one-shot 进程退出由内核
回收，flow 不 retry close、不恢复整数，也不允许当前进程继续处理第二个 root。

### 8.3 官方 one-shot authorizer 进程合同

`authorize-h11-release` 的官方执行合同是：

- 一个新进程只处理一个 manifest、一个 formal root 和一次 flow；
- 进程内单线程同步执行，不运行 event loop，不接受 task/thread cancellation；
- 不安装或替换应用级 Python signal handler，不改变 signal mask，不启用
  trace/profile；解释器默认 SIGINT 行为保持不变；
- 不加载 caller callback、plugin 或 hook；
- public call 返回后进程正常结束，不复用 flow 或 slot；
- `authorize_once` 的唯一 `except BaseException` 必须捕获所有正常到达 Python
  exception boundary 的 primary，包括默认 SIGINT 产生的 `KeyboardInterrupt`
  和任何其他 `BaseException`；它调用 `_fail(active_error=primary)` 后重新抛出
  同一 object；
- `authorize_h11_release`、CLI `authorize-h11-release` 分支及更上层 CLI
  dispatch 不得捕获后吞掉、改写为成功、记录后继续或启动第二个 flow；任何
  从 C2 seam 逃出的 `BaseException` 都必须终止该 CLI 进程，不能产生成功
  receipt 或第二个 flow；默认 SIGINT/普通 failure 的进程状态必须非成功；
- 精确落在 open→bind、write→POSTWRITE 或 detach→close 不可结构化间隙的
  信号，或不进入 Python exception boundary 的其他外部信号终止，均按
  conservative process failure 处理；write attempt 已登记为
  `FAILED_WRITE_AMBIGUOUS`（若 exception boundary 可达），detached descriptor
  最迟由进程退出回收，任何情况都不会制造成功 receipt；
- abrupt failure 后该 root 保守地不接受，调用方不得在同一 root 重启或
  重试 authorizer。

这条进程合同不是 timeout、watchdog 或 signal 屏蔽机制。它诚实地界定纯
Python 能证明的同步异常范围，并以 one-shot 进程退出语义覆盖不可结构化的
异步终止。

## 9. Public one-shot flow

`authorize_h11_release()` 必须收缩为唯一 production callsite：

```text
authorize_h11_release
  -> flow = H11RootAuthorizationFlow(manifest_path, require_root=require_root)
  -> flow.authorize_once()
     -> acquire C2a
     -> consume C2b
     -> publish C2c
     -> commit C2d
     -> exhaustive close
     -> return typed receipt
  -> return receipt.reference
```

`authorize_h11_release` 必须构造且只构造一个
`flow = H11RootAuthorizationFlow(manifest_path, require_root=require_root)`，随后以该 exact local receiver 调用一次
instance method `flow.authorize_once()`。`authorize_once` 必须是普通 instance
method；不得是 `@classmethod`、`@staticmethod`、constructor/factory 或返回新 flow
的入口，method body 内也不得再次构造 `H11RootAuthorizationFlow` 或调用任何
等价 flow factory。

唯一 try/except failure boundary 属于该 instance method。public wrapper 不维护
`owner` union，不按阶段替换对象，不直接调用任何 phase/finish/failure/close，不
直接 close FD，也没有 fallback `finally` 或 exception handler。

其控制形状必须等价于：

```python
def authorize_h11_release(
    manifest_path: Path,
    *,
    require_root: bool = True,
) -> dict[str, Any]:
    flow = H11RootAuthorizationFlow(
        manifest_path,
        require_root=require_root,
    )                                       # state NEW, boundary PREWRITE
    receipt = flow.authorize_once()
    return receipt.reference


def authorize_once(self) -> H11RootCommitReceipt:
    if self._state is not H11RootAuthorizationState.NEW:
        raise InstallerError(...)          # one-shot rejection; no phase/sweep
    try:
        self._acquire_authorities()
        self._consume_ready_commit()
        self._publish_permit()
        receipt = self._commit_permit()
    except BaseException as primary:
        self._fail(active_error=primary)   # NoReturn, rethrows same object
    return self._finish(receipt)            # outside except; sweep before COMPLETE
```

前三个 phase call 的 return value 都是 exact `None`；`authorize_once` 不得把它们
赋给 local、按返回类型分派或把一个 phase object 传给下一 call。每次 call 返回时
`self._phase_data` 与 `_state` 必须已经是 4.5.3/5.1 对应的 exact pair；下一 phase
只从同一 `self` 读取 frozen predecessor chain。只有 `_commit_permit()` 产生 local
typed receipt，且 `_phase_data` 仍是同一 `H11RootPermitPhaseData`。

public ABI 必须保持现有 `dict[str, Any]` 返回签名；typed
`H11RootCommitReceipt` 只在 flow 内部闭合 commit，wrapper 对外仍精确返回
`receipt.reference`，不得返回 receipt object，也不得把 C3 的 full-file reference
type 引入 C2 authorizer API。

`_finish` 必须位于上述 `except BaseException` 之外，避免 finish teardown 已经
完整 sweep 后又进入 `_fail` 做第二次 sweep。instance `authorize_once` 的 entry
precondition 必须在 try/phase/open 之前要求 `self._state is NEW`。同一个 instance
成功后为 `COMPLETE`，失败后为 exact FAILED terminal，提前显式 close 后为
`CLOSED`；任一 terminal 或其他 non-`NEW` state 的第二次/迟到调用都必须在任何
phase、open/borrow/write/close、`_fail` 或 `_finish` 前拒绝，且不能创建第二 flow。
`authorize_h11_release` 与 CLI
只允许把成功 reference 返回；它们不得捕获从 `authorize_once` 或 `_finish`
逃出的 `BaseException` 后继续运行。

wrapper 与 flow constructor 的 signature/default/argument binding 必须逐 token
等于上述形状：`manifest_path` 是唯一 positional-or-keyword 参数，`require_root`
是唯一 keyword-only 参数且 default 为 exact `True`。wrapper 不做 normalize/copy，
constructor 保存 exact 两个输入；`_acquire_authorities(self)` 为零外部参数并只读
这些保存值；constructor 同时将 `_phase_data` 初始化为 `None`。缺参、多参、位置传 `require_root`、另一个 config/context 参数、
wrapper 外 constructor caller 或向 `_acquire_authorities` 传任意实参均失败。

production 中 `H11RootAuthorizationFlow` constructor 与 instance
`H11RootAuthorizationFlow.authorize_once` 都只有 `authorize_h11_release` 一个
caller；后者的 receiver 必须是前一条 assignment 由该唯一 constructor 绑定的
exact local `flow`。`authorize_h11_release` 也仍只有 CLI
的 `authorize-h11-release` 分支调用。任何测试需要阶段观察时，使用明确的
private test seam 和 fake syscall，不新增第二个 public phase API。

authorizer 的成功结果仍只是 PERMIT_COMMITTED receipt。它不写 release
FIFO、不调用 manager/systemd、不发布 ledger、不进入 C3 watch 或 H8。

### 9.1 Reachable C2 seam 与 FD-producing closed allowlist

本节的 AST scope 精确以 production `authorize_h11_release` 为唯一 root，递归
包含它唯一构造的 flow instance、该 instance 的 `authorize_once`，以及后者在
同一 module 内静态可解析调用到的
`H11RootAuthorizationFlow`、`H11OwnedFdSlot`、borrowed-view 和 C2a–C2d
validation/publication helper body，直到只剩 stdlib/syscall/value-type leaf。
禁止 callback、dynamic dispatch、callable alias 或反射，因此 reachability 必须
可由 AST 的 exact qualified-name graph 穷尽。shared helper 只因从该 root
可达而纳入；module 中其他 installer、freeze、cleanup 或非 authorizer 路径
若不从该 root 可达，明确不在 C2e AST closure 内，不能因本设计被误判或改写。
唯一 syscall-leaf 例外是 4.4.2 已冻结的 direct `libc.renameat2` call shape；它
不能被赋给 local/global callable alias、不能接收 callback，也不扩张为通用
ctypes dispatch。AST 将该 exact call 作为 leaf 并检查两个 dirfd borrow 参数。

在这条 reachable seam 中，能产生新 FD 的 operation 是闭集：

| FD-producing operation | exact allowed qualified caller/count |
| --- | --- |
| `os.open(...)` | 仅 `H11OwnedFdSlot.open` 的一个 callsite；AST exact parent 必须是 `self._bind(os.open(...))`，不得先赋给 local/attribute/container |

该唯一 `os.open` 的 `dir_fd` 或 endpoint path 可以接收 raw borrowed parent FD，
但调用链只能是 4.4.1 的 exact nested expression：parent literal slot 的
`borrow()` AST node 直接嵌在 child literal slot 的 `open(..., dir_fd=...)`
keyword，或直接嵌在作为 child `open()` 第一参数的 exact `/proc/self/fd`
formatted value。bridge 中间不能出现 assignment、named expression、local
format path、helper parameter、return、container 或 callable；4.4.1 表外的
borrow→open edge 为零。slot `open` 内部仍只有上述一个 `os.open` callsite，
因此 bridge 不形成第二条 FD-producing seam。

除此之外，reachable seam 中所有第二 FD、file-object ownership 或等价入口的
callsite 必须为零，至少包括 `os.dup`、`os.dup2`、`os.dup3`、`os.pipe`、`os.pipe2`、
`os.openpty`、`os.posix_openpt`、`os.memfd_create`、`os.eventfd`、
`os.pidfd_open`、bare/built-in `open`、`builtins.open`、`io.open`、
`pathlib.Path.open/read_bytes/read_text/write_bytes/write_text`、`os.fdopen`、
`tempfile.TemporaryFile/NamedTemporaryFile/mkstemp`、`subprocess.Popen`、
`socket.socket`、`socket.socketpair`、
`socket.fromfd`、socket `accept`/`create_connection`、`fcntl.fcntl` 的
`F_DUPFD`/`F_DUPFD_CLOEXEC`，以及经 import alias、`getattr`、ctypes 或 wrapper
间接调用的 open/openat/dup/pipe/socket 等等价 producer。不得把 borrowed FD
包装为另一个会拥有/关闭它的 file/socket object。

`H11OwnedFdSlot.open` 是唯一 adoption seam：precondition 与
`_open_started=True` 必须在 `os.open` 前，正常返回后下一项 ownership action
只能是 `_bind`。FD-producing audit 不扩张到 module 其他不可达路径，但任何
新调用边只要使其从 `authorize_h11_release` 可达，就立即进入本闭集审计。

## 13. 运行期验收矩阵

### 13.1 Slot 与 acquisition

- wrapper 以 exact `(manifest_path, *, require_root=True)` ABI 构造唯一 flow；
  `_manifest_path/_require_root` 保存 exact 输入且 constructor 后不可替换，
  `_acquire_authorities(self)` 不接受外部参数；
- flow 创建即有 exact 23-slot layout，role/index/order 不可变；
- flow 创建时 `_phase_data is None`；C2a/C2b/C2c 成功后依次且各仅一次变为
  exact `H11RootAuthorityPhaseData`/`H11RootReadyPhaseData`/
  `H11RootPermitPhaseData`，replacement 后下一 statement 是对应 state transition；
- `role`/flow `state` property 只读，`_role`、`_descriptor`、`_open_started`、
  `_slots`、`_manifest_path`、`_require_root`、`_phase_data` 的每个非法
  Store/Del/setattr、role 交换、tuple
  replacement 与输入 field replacement 都被拒绝；
- 每个 slot 初始 empty/unstarted；每个成功 open 只 bind 一次；
- 第 4.4 节每个 open/borrow caller-index-state 组合各有正向 case，并覆盖错误
  index、错误 state、terminal state、borrow 已 detach slot、raw borrow
  assignment/return/container/callback escape 的 negative；
- 第 4.4.1 节每个 inline bridge 都逐行覆盖 child/parent/leaf-or-proc-path/state：
  六条 directory-chain edge、两条 commit-FIFO pin edge、READY source 12→6、
  present exact `10→4`/`11→3`、publication 12→2、READY
  endpoint 8→1 与 PERMIT endpoint 7→0；
- 对每条 bridge 注入 wrong parent、swapped endpoint pin、dynamic index、borrow
  local assignment、local formatted `/proc/self/fd` path、borrow return/cache、传给
  helper/callback/generic opener 等 negative，并断言 slot open 在错误 flow state
  与所有 terminal state 均未发生；slots 15/16–22/5 不得出现伪造 parent bridge；
- 第 4.3 节每个 view 都断言 immutable `_flow` 是构造它的 phase receiver exact
  identity 且不拥有 FD，每个 self/parent edge 都有正向 identity case；覆盖 swapped/
  missing parent、dynamic parent index、parent raw cache、parent path replacement 与
  absolute-path fallback，以及 `_flow` replacement/deletion、foreign flow 与原
  slot pair 混配、field-equal-but-not-identical flow 与原 slot pair 混配、
  state snapshot/callback/dynamic allowed-state
  negative，特别是 directory chain、FIFO `7/8<-9`、
  transaction source `22/6<-12`、present `4<-10`/`3<-11`、publication `2<-12`；
- 五类 view 对 4.4 各自每个允许 state 都有 revalidate 正向 case；每个错误 active
  state 和所有 terminal state 都在 revalidate 的首项 control gate 拒绝，且
  syscall trace 证明零 borrow/零 FD syscall；每一个 view borrow node 前还断言
  direct `self._flow.state` + exact literal-state tuple gate，不能由 entry assertion、
  cached state、helper、mapping、callback 或 caller precondition 替代；
- 第 4.4.2 节每行逐项断言 qualified caller、literal index、exact syscall、参数
  位置、静态 borrow node count、正常运行 count 与 state；read/complete-write loop
  还断言 only-final EOF/empty-view termination。新增 consumer、少/多一次 syscall、
  wrong positional/keyword argument、generic helper 或 parent path fallback 均失败；
- 对 C2a 每个 open/fstat/prove/decode/revalidate 边界注入 primary；
- 对每个 primary 再分别注入首个、中间、末尾 slot close secondary；
- 断言 primary identity 或既有 InstallerError cause identity、确定性 note、
  所有已绑定 FD 各 physical close 一次、未绑定 slot 无 close；
- authority views 在 flow close 后 borrow 失败；不存在第二 owner 可再次 close；
- `H11RootAuthorityView` exact fields 全量等于 4.5.1，两个 FIFO 是 named canonical
  slot-8/slot-7 views；缺失/多余 field、swapped/aliased FIFO、foreign-flow nested
  view、mutable decoded JSON、tuple/list role selection 均在 constructor 拒绝；
- 三个 frozen/slots phase-data constructor、field 和 reader 精确等于 4.5.2；
  `authority_data`/`ready_data` identity 原样保留前一 object，所有 view 最终指向
  同一 flow，value objects 没有 descriptor、owner/close/borrow、writable lifecycle
  state/transition/callback；
  对 AuthorityView 与三个 data 的每个 field 做 ordinary assignment/Del/setattr
  replacement negative，均不得改变 identity/value，production AST 中 constructor
  外 `object.__setattr__` call 为零；
- 对三次 replacement 前每个最后验证点注入 failure，断言 `_phase_data` 保持 entry
  object；在 replacement 后的同步 transition seam 验证下一动作确为 exact
  transition且无可注入 helper/syscall。任一 FAILED/COMPLETE/CLOSED terminal 不再
  写或清空 `_phase_data`，但 sweep 后所有 referenced slots 都 empty；
- 对每条 success transition 与两个 write-boundary mark 注入 wrong data type，
  断言在 state/boundary mutation 前拒绝；
  正向路径断言从 PERMIT_PUBLISHED 到 COMPLETE 始终是同一 Permit data identity；
- 所有 source/directory/FIFO/present identity 与 alias negative 保持 C2a–C2b
  当前结果。

### 13.2 READY endpoint

- reader-first 与 writer-first 两种 blocking schedule；
- exact frame + EOF 才产生 receipt；wrong/missing/prefix/suffix/duplicate 拒绝；
- open OSError 维持既有转换；fstat/read primary + close secondary 保真；
- EOF 后 close failure 自身为 primary且无 receipt；
- endpoint slot 在 close syscall 前已 detach，physical close 恰好一次；
- READY 完成后 slot 1 empty，其他 retained slots 仍绑定且可 revalidate。
- `H11RootCommitReceipt.ready_committed` signature 精确接收
  `(fifo: H11RootFifoView, payload: bytes)`，唯一 caller 是
  `_consume_ready_commit`；在 factory 前分别注入 noncanonical view、foreign flow、
  wrong self slot/parent slot，断言 caller identity gate 拒绝且 factory call count
  为零。factory direct tests 只断言 role/reference/payload value validation，并证明
  body 不读 flow/slot；wrong payload/role/reference 无 receipt，旧 FIFO owner
  annotation/alias 为零。

### 13.3 Publication

- slot 2 从 pending open 到 final retained publication 始终是同一 descriptor、
  device/inode 与 slot object；
- 每个 pre-rename failure 保留 pending、无 frame；
- rename-success/parent-fsync 或 final-revalidate failure 可保留 final、无 frame；
- race、same-byte replacement、wrong owner/mode/inode 与 existing final 拒绝；
- 任一 publication failure 完整扫 slots，文件系统 evidence 不被 cleanup。

### 13.4 Exact PERMIT write 与 teardown

- `H11RootCommitReceipt.permit_committed` signature 精确接收
  `(fifo: H11RootFifoView, payload: bytes)`，唯一 caller 是 `_commit_permit`；在
  factory 前分别注入 noncanonical view、foreign flow、wrong self slot/parent slot，
  断言 caller gate 拒绝且 factory call count 为零。factory direct tests 只覆盖
  role/reference/payload value validation并证明不读 flow/slot；旧 FIFO owner
  annotation/alias 为零；commit receipt 在 writer open 前已构造，失败时不返回；
- writer-first 与 reader-first blocking schedule；
- 单一 exact `os.write`，frame 与 byte count 完全相等；
- open/fstat/prove failure 仍为 `FAILED_PREWRITE`；mark 后 inline slot-0 borrow
  exception、write exception、short-write、zero-write、EPIPE 与
  write-return→mark interruption必须是
  `FAILED_WRITE_AMBIGUOUS`；全部无 receipt、无重试；
- prewrite primary + writer-close secondary：primary 保真、无成功 receipt、
  writer 最先且仅 close 一次；
- `WRITE_IN_FLIGHT` 的 post-mark inline borrow failure，以及 write 的
  0/partial/full 三种 deterministic fake outcome 各有 case，都保留同一 primary、
  完整 sweep、state=`FAILED_WRITE_AMBIGUOUS`；
- 每种 ambiguous primary 再覆盖首个及两个以上 close failure：只把固定顺序的
  第一个 teardown failure 记为同一 primary 的唯一 note，其余 slot 仍访问一次；
- 一个 fake 必须保存真实 `os.write`，对真实 pipe/FIFO writer 调用它写入 exact
  frame，确认 reader 已收到 bytes 后立即从同一 fake 抛出预构造
  `KeyboardInterrupt`。断言 top-level 仍是同一 object、无 receipt、state 精确为
  `FAILED_WRITE_AMBIGUOUS`、所有 slots empty/各 close 至多一次且第二 flow 为零；
- exact write + writer-close failure：reader 收到 exact frame、无 receipt、
  writer-close 是 primary；
- exact write + writer-close failure + publication-close failure：最终异常是
  writer-close，同一对象带 publication-close note，随后所有 FD 仍各扫一次；
- exact write + writer-close failure + 两个或更多后续 close failure：writer
  close 仍是同一 top-level object，只有按 slot 顺序遇到的第一个后续 close
  failure 形成唯一 note，其余 failure 不形成 note，但对应 slot 仍全部访问并
  detach/close 一次；
- exact write + later retained close failure：exact frame 可见、无 receipt、
  第一 close failure 在 full sweep 后抛出；
- `_finish` 中两个或更多 retained close failure：第一项是同一 top-level
  close object、零 secondary note，后续失败不记 note但全部访问，state 精确为
  `FAILED_POSTWRITE`，从未出现瞬时 `COMPLETE`；
- prewrite operation primary 加两个或更多 teardown close failure：只把首个
  close error 作为冻结文本 note 附到同一 primary，后续错误不 note但 sweep
  完整；
- 显式 `close()` 覆盖 NEW→CLOSED、重复 CLOSED no-op、prewrite active→CLOSED、
  prewrite close failure→FAILED_PREWRITE、in-flight close misuse→
  FAILED_WRITE_AMBIGUOUS，以及 postwrite close misuse→FAILED_POSTWRITE；每类均
  覆盖单个和多个 close failure 的 primary/note ABI；
- write trace 必须精确为 `_mark_write_in_flight`、direct positional-0 inline
  `self._slots[0].borrow()`、唯一 `os.write`；borrow 与 write 之间不得出现其他
  可观察动作/call。exact write 的返回值检查后，第一项 state action 必须是
  `_mark_postwrite`，第二项是 `PERMIT_FRAME_WRITTEN` transition，任何 early
  close/full sweep 都只能在两者之后；
- 成功只返回一个 typed receipt，所有 23 slots empty，第二次调用拒绝且没有
  open/write/close side effect。

### 13.5 Public one-shot

- `authorize_h11_release(manifest_path: Path, *, require_root: bool = True)` 与
  `H11RootAuthorizationFlow.__init__(manifest_path: Path, *, require_root: bool = True)`
  的 signature/default/argument binding 精确相等；wrapper 运行时恰好构造一个
  `H11RootAuthorizationFlow(manifest_path, require_root=require_root)`，下一项
  flow action 是以同一个 object 调用一次 instance `flow.authorize_once()`；wrapper
  不直接执行 phase、finish/failure/close，也不构造或切换第二 flow；
- public call 的唯一成功 trace 严格为 C2a→C2b→C2c→C2d；
- 四个 phase 与 `_finish` 的 receiver 始终是 `authorize_once` 的同一个 `self`；
  四个 phase 都零外部参数，前三个 return exact `None` 且不被赋值/传递，
  `_commit_permit` 才返回 receipt；前三次成功语义只经同一 flow 的 frozen
  `_phase_data` predecessor chain 传递。任一阶段失败只经过该 instance method 内
  一个 flow failure boundary；
- public wrapper 不直接 open/close/write/rename，也不持有 owner union；
- 同一 instance 在成功、任一 FAILED terminal、显式 `CLOSED`，以及由 private test

## 14. AST/tokenize 验收
