## 1. 决策摘要

本文是
`v0.4-w3-h11-atomic-ownership-flow-design-20260719.md`
的窄修正 addendum。原设计同时冻结了以下要求：

1. `H11RootAuthorizationFlow` 只有固定 23 个 slots；
2. `authorize_h11_release` reachable seam 只有
   `H11OwnedFdSlot.open` 一个 FD-producing callsite；
3. C2a–C2d 的旧 authority、bytes/hash、mode/owner 与 alias 协议不减少；
4. authorizer 不保留动态 scratch owner、第二 FD registry 或 legacy reopen helper。

实现审计证明：TREE/SEAL/PREFLIGHT/INSTALL receipts 间接引用的
prepare manifest、seal manifest、sealed assets、inventory、unit sources 与
installed unit targets 数量是动态的，而固定 23-slot tuple 不拥有这些对象。
在禁止第二 FD 和 path read/open 的条件下，authorizer 可以重新观察这些对象的
当前 identity/type/mode/owner，却不能重新读取它们的当前 bytes 并计算 hash。

因此本文明确选择：

```text
direct retained source bytes
    -> 由固定 slot 保留的 raw + FD identity 作为当前 bytes 权威

indirect file bytes/hash
    -> 由 direct retained TREE/SEAL/PREFLIGHT/INSTALL receipts
       的闭合 cross-binding 作为 snapshot 权威

indirect current filesystem object
    -> 由 authorizer 当次 Path.lstat 证明 type/device/inode/mode/uid/gid
       与 snapshot reference 相等
```

authorizer 不再声称验证间接文件“此刻的 bytes/hash”。它验证的是：

- direct retained receipts 自身的当前 bytes/identity 未漂移；
- receipts 对间接 bytes/hash 的声明形成一个 exact、无别名、无缺项的闭合快照；
- 每个当前路径在它自己的顺序 `Path.lstat()` observation event上仍指向该快照声明
  的同一 filesystem object，且 type/mode/owner 未漂移。

这也意味着 C2e 不再 replay 三个 upstream producer 已完成但未被 receipt 完整复制
的输入语义：

- 不重新 decode TREE `prepare_manifest` 的 schema/root/user/group/FIFO/receipt path；
- 不重新 decode SEAL `seal_manifest` 的 schema/root/TREE/files；
- 不重新 decode PREFLIGHT inventory 的 header、asset role/kind/order、destination
  与 TREE row；
- 不重新读取上述对象或 unit source/target 的 current bytes/hash。

这些语义的 authority 是 `prepare_tree`、`seal_tree`、static preflight producer 与
`install_units` 成功生成的 root-owned receipt。C2e 必须保留这些 producer 的既有
实现与测试，且验证 receipts 的 direct current bytes、producer phase、closed
cross-binding 与当前实体 metadata；它不是第二个 producer replay engine。

这个选择不修改 JSON schema、FIFO、路径、mode/uid/gid、receipt ABI 或
publication 顺序；它修正的是 root authorizer 对既有 receipt 证据的解释边界。
若未来必须抵抗 root 对 0444 文件的原地 bytes 改写，必须另行扩展 schema 以携带
可独立验证的内容证明，或设计动态 retained owner；不得在 C2e 中偷偷恢复
legacy reopen。

## 3. 三层 authority 模型

### 3.1 Direct retained bytes authority

以下对象已经由固定 slot 持有 FD、raw 与 actual reference：

| slot | direct authority |
| ---: | --- |
| 5 | run ARMED |
| 6 | PERMIT_READY |
| 16 | PREFLIGHT receipt |
| 17 | SEAL receipt |
| 18 | TREE receipt |
| 19 | INSTALL manifest |
| 20 | INSTALL receipt |
| 21 | harness manifest |
| 22 | AUTHORIZE-RELEASE |

这些对象继续执行完整 current-byte validation：retained FD readback、SHA-256、
device/inode、mode、uid/gid 与 canonical path/reference 全部相等。本文不降低该层。

`H11RootAuthorityView` 的 exact fields/signature 仍完全等于 base design §4.5.1：
九个 source views、七个 directory views、两个 FIFO views、四个既有 decoded
objects、fixture uid/gid 与 validated FIFO tuple；本文不增加 aggregate field。
INSTALL/TREE/SEAL/PREFLIGHT 的其他 frozen decoded values 是 `_acquire_authorities`
与 pure proof 的 construction-local 输入，proof 完成后丢弃。不得把它们放进
flow optional fields、第二 aggregate 或 aggregate 构造后的 lazy decoder。

`H11RootAuthorityView.__init__` 只保留 base design冻结的same-flow、slot topology、
exact type与immutable field-construction invariant。§5–§6 的receipt protocol与
projection由§4.1 builder在首个indirect observation前唯一证明；aggregate
constructor不得再次decode retained `raw`、重复cross-binding或成为第二validator。

### 3.2 Indirect snapshot bytes authority

以下对象没有 fixed slot，其 bytes/hash authority 来自 direct receipts：

- TREE `prepare_manifest`；
- SEAL `seal_manifest`；
- SEAL `files` 中的 installer、inventory、static plans/programs 与 unit sources；
- PREFLIGHT `inventory_manifest`；
- INSTALL unit targets。

对这些对象，authorizer 必须证明所有 direct receipts **实际携带的字段** 对同一
snapshot 的声明 exact cross-bind。opaque reference 没有携带的 manifest schema、
inventory rows 或 current bytes 不是 C2e 可恢复的证据，不能在 acceptance 中继续
声称已验证。它不得：

- 调用 `_read_regular`、`_bound_json_input`、`Path.read_*`、bare `open` 或
  任何第二 FD producer；
- 把 receipt 内部自洽当成充分条件而跳过与 actual retained reference 的绑定；
- 重新构造一个 field-equal receipt 代替 entry object；
- 接受 direct receipt inventory 自身的重复/invalid role、path、identity或 mutable
  alias。数量与顺序按各 schema分别处理：TREE FIFO 是 exact sorted 8 rows；INSTALL
  units 与其 manifest/harness闭集等长同序；SEAL files 允许 legacy producer 的任意
  非空唯一 rows与输入顺序，observation另按 role canonical排序。不得把 SEAL合法
  extra row或原始顺序误判为污染，也不得借此声称看见 opaque inventory内部行。

### 3.3 Indirect current object authority

每个 indirect equivalence class 还必须由当次 exact `Path.lstat()` 证明：

- 路径仍存在且是 exact expected object type；
- `(device, inode)` 等于 snapshot reference；
- mode 等于该 reference schema 或 legacy receipt 明确携带的冻结值；
- uid/gid 等于该 reference schema 或 legacy receipt 明确携带的 root/fixture policy；
- 不与其他 semantic object 共享 `(device, inode)`；
- 观察前后的 direct retained authority 未发生 state/identity 漂移。

这里的 observation primitive 只能是 lexical canonical `Path` 上的
`Path.lstat()`；禁止 default-following `Path.stat()`/`os.stat()`、
`resolve()` 后再 stat、`follow_symlinks=True` 或任何先追随 symlink 再比较目标实体的
等价写法。`Path.lstat()` 不产生 FD，也不返回 bytes。prepare/seal manifest
reference 不携带 mode/uid/gid，legacy bound-input 也未冻结这三个字段；对它们只验证
regular type 与 device/inode，不得新造 mode/owner 协议。实现、测试与文档不得把
这层描述为 current-content validation。

owner policy 精确保持 legacy，不由 observation caller临时扩大：

- schema携带 uid/gid 的 object（TREE FIFO、INSTALL target）总是比较 current
  observation与receipt value；
- fixture-owned work/FIFO 必须等于 retained TREE `fixture_uid/fixture_gid`；
- `require_root=True` 额外要求 legacy root-owned TREE formal/sealed/input/fifo/
  authority directories、retained H11 harness/scenario/receipt directories、commit
  FIFO、SEAL files、INSTALL source/target 与 direct installer/install-manifest 为
  `(0,0)`；work directory仍按 fixture uid/gid；
- `require_root=False` 不把 TREE-only/root-production owner扩张成全局policy：
  sealed directory、SEAL files与unit sources不检查owner；但formal/authority/input/
  fifo directory与retained H11 directory-chain合并后，仍必须等于chain携带的
  uid/gid，harness/scenario/receipt direct-only directories也继续验证chain uid/gid；
  work directory仍必须等于fixture uid/gid；INSTALL target仍比较receipt携带的uid/gid；
- 非root测试中，receipt声明为root-owned的commit FIFO允许current owner为
  `(0,0)` 或 `(geteuid(), getegid())`，但其receipt owner/uid/gid字段仍必须是
  `root/0/0`；这是唯一test-mode owner translation；
- prepare/seal manifest没有mode/uid/gid字段，只验证regular type/device/inode。

由此生成spec的exact metadata table为：

| equivalence class | kind | mode | accepted owners |
| --- | --- | ---: | --- |
| TREE formal-root | directory | `0711` | exact retained chain uid/gid；root模式必须 `0:0` |
| TREE sealed-root | directory | `0555` | root-only iff `require_root`，否则 `None` |
| TREE input-root | directory | `0555` | exact retained chain uid/gid；root模式必须 `0:0` |
| TREE work-root | directory | `0700` | exact fixture uid/gid，所有模式 |
| TREE fifo-root | directory | `0711` | exact retained chain uid/gid；root模式必须 `0:0` |
| TREE authority-root | directory | `0700` | exact retained chain uid/gid；root模式必须 `0:0` |
| direct-only harness/scenario/receipt dirs | directory | `0700/0700/0555` | direct retained chain exact uid/gid；root模式必须 `0:0`；不另发indirect spec |
| ordinary TREE FIFO | fifo | `0600` | exact fixture uid/gid |
| root-declared commit FIFO | fifo | `0600` | root-only；非root模式为§4.1 closed pair tuple |
| prepare/seal manifest | regular | `None` | `None` |
| each SEAL file / INSTALL source | regular | `0444` | root-only iff `require_root`，否则 `None` |
| each INSTALL target | regular | `0644` | exact receipt uid/gid；root模式还要求其为 `0:0` |

这里的 `None` 是“不存在legacy检查”，不是 wildcard owner/mode；proof必须按spec字段
的presence规则执行，不得由actual值回填expected。

这层是逐class、顺序发生的C2a observation events：每个class只在自己的
`Path.lstat()` event上得到证明。本文**不证明**存在一个所有indirect classes同时
匹配的共同原子时点；direct source前后revalidation bracket也不能把这些路径观察
原子化。indirect object没有retained FD，因此证明更不持续到PERMIT commit；后续
阶段只继续重验direct retained sources。C3 watch、动态retained owner或另行设计的
双轮metadata protocol才可能扩张这个边界，C2e acceptance与最终结论必须保留该
per-class event限定。

## 4. Immutable value boundary

### 4.1 `H11RootIndirectAuthoritySpec`

首个 observation 前必须由一个 pure builder 形成 exact immutable inventory：

```python
@dataclass(frozen=True, slots=True)
class H11RootIndirectAuthoritySpec:
    semantic_role: str
    equivalence_class: str
    install_ordinal: int | None
    path: Path
    kind: str
    device: int
    inode: int
    mode: int | None
    accepted_owners: tuple[tuple[int, int], ...] | None
```

`kind` 是 `directory|fifo|regular` closed literal。`mode=None` 只允许用于 upstream
reference schema与legacy validator确实未冻结mode的对象；
`accepted_owners=None` 只允许用于legacy没有owner检查的对象。其余owner policy均
编码为canonical、无重复的closed tuple：普通exact owner只有一个pair；
`require_root=False` 的root-declared commit FIFO精确为去重后的
`((0, 0), (process_euid, process_egid))`，按numeric pair排序。不得用 `None` 表达
“root或test owner”，也不得把receipt声明的root/0/0改写为process owner。
`install_ordinal`只允许INSTALL target classes使用，值为receipt中的zero-based
ordinal `0|1|2`；其他所有classes exact为`None`。

唯一 pure builder seam 名为 `_build_h11_indirect_authority_inventory`，只有
`_acquire_authorities` 一个 caller。它只接收已经由 retained source decode得到的
frozen direct receipts/references、九个 actual source references、retained directory/
FIFO references、exact root/path values 与 frozen owner policy，不执行 syscall。
owner policy exact携带 `require_root` 及 `_acquire_authorities` 在进入builder前一次性
取得的process euid/egid；builder本身不得调用 `os.geteuid/getegid`。
它在首个 observation 前独占完成以下协议责任：

1. TREE/SEAL/PREFLIGHT/INSTALL 以及 harness/READY/ARMED/AUTHORIZE-RELEASE 的
   exact keys、schema、phase、closed role/path/layout、unit与manager-ledger检查；
2. §5–§6 的每个 projection、receipt cross-binding、SHA/mode/uid/gid声明、closed
   accepted-owner policy、
   cardinality/order 与 producer snapshot certificate检查；
3. 将同一 semantic object 的全部 member references先 exact cross-bind，再合并为
   一个 equivalence class；禁止把同一 class 的第二个 reference展开为第二个 spec；
4. 在 class层完成 duplicate role/path与 expected identity闭包，并构造 immutable
   expected metadata；只有完整 inventory验证成功后才返回。

builder允许调用按TREE、SEAL、PREFLIGHT、INSTALL、harness/READY/ARMED分域的
private pure helpers，以避免形成超大单函数；这些helper必须无owner/FD/lifecycle、
无syscall/decode、只接收/返回frozen typed values，每项protocol check只归属一个
helper，且caller只能是builder或同域helper。它们的exact nodes/edges由§8 oracle
addendum冻结；builder仍是唯一orchestration seam，不能并存第二validator。

它的 exact 返回值是
`(fixture_uid, fixture_gid, validated_fifos, indirect_specs)`：前两个是 exact `int`，
后两个分别是 `tuple[H11RootValidatedFifo, ...]` 与
`tuple[H11RootIndirectAuthoritySpec, ...]`。函数边界不得出现 mutable
`dict/list/set`；body内用于验证的临时 collection不得逃逸或被spec引用。不得另保留
旧 `_validate_h11_retained_authority_values`、adapter或第二个协议 validator。

spec canonical order按 **equivalence class** 冻结为：六个 TREE directory classes
按literal `formal-root,sealed-root,input-root,work-root,fifo-root,authority-root`顺序；
八个 TREE FIFO classes按 role；prepare-manifest class；
seal-manifest class；preflight-inventory class；剩余 SEAL file classes按 role；最后
INSTALL target classes按 install receipt unit ordinal。`preflight-manifest` SEAL row
是 preflight-inventory class 的 member；每个 INSTALL unit source是相同 role SEAL
file class 的 member；两者只做 cross-binding，不产生第二 observation spec。
SEAL receipt的合法原始 row顺序不参与拒绝，builder只在合并后按上述规则规范化。
不同 equivalence classes出现相同 path或expected `(device,inode)`时，在首个
observation 前拒绝；同 class member必须在所有共同携带字段上完全相等。

### 4.2 `H11RootObservedPathIdentity`

实现必须使用一个 frozen+slots、无 owner/FD/lifecycle 的 observation value，语义为：

```python
@dataclass(frozen=True, slots=True)
class H11RootObservedPathIdentity:
    semantic_role: str
    equivalence_class: str
    install_ordinal: int | None
    path: Path
    kind: str
    device: int
    inode: int
    mode: int
    uid: int
    gid: int
```

`kind` 是 exact closed literal：`directory`、`fifo`、`regular`。不得保存
`os.stat_result`、descriptor、callback、allowed-state 或 mutable reference。

该 type 只表达一次完成的 filesystem observation。它不提供 `revalidate`、
`close`、`borrow` 或 lazy property。

### 4.3 Pure observation proof

最终 pure proof seam exact 为
`_prove_h11_indirect_observations(indirect_specs, observed_identities)`，只有
`_acquire_authorities` 一个 caller。它与 builder的责任不可重叠：

- 只接受同序 exact immutable tuples，不接收 receipt、decoded JSON、root、
  `require_root`、callback 或 caller-provided iterable；
- 只证明 tuple type/length、逐 ordinal 的 semantic role/equivalence class/
  install_ordinal/path/kind相等，actual device/inode等于spec，spec非 `None` 的mode等于actual，且
  `accepted_owners`非 `None` 时actual `(uid,gid)`是其exact member；
- 再证明不同 equivalence classes 的 actual `(device,inode)` pairwise distinct；
- 不执行 filesystem/syscall、decode raw、open/read、schema/phase/unit/ledger/
  projection validation 或 dynamic dispatch；
- exact返回 `None`，不得重新计算或返回 fixture uid/gid/FIFO inventory。

caller只能使用 builder已返回的 `(fixture_uid, fixture_gid, validated_fifos)` 构造
`H11RootAuthorityView`。builder负责 expected protocol，observation seam负责取得
actual metadata，proof只比较两者；三层之间不得有 fallback或重复验证。

### 4.4 Observation seam

indirect `Path.lstat()` 只允许在 `_acquire_authorities` 的一个 closed observation
阶段发生。该阶段先由 frozen receipt values 构造 exact semantic inventory，随后
逐项观察；inventory 完整构造与 alias/path closed checks 必须发生在首个indirect
`Path.lstat()` observation前。

observation 由 direct source revalidation bracket 包围：先按 slots
`22,21,20,19,18,17,16,6,5` 顺序各 revalidate一次，再按 §4.1 canonical spec顺序
观察全部 indirect rows，随后按同一 slot顺序再 revalidate一次；下一动作才是 pure
proof 与 AuthorityView construction。九个 source view construction、两轮 caller/
order/count与每个 fault site全部冻结，不允许用一个 generic dispatcher隐藏。

不得把观察逻辑做成接受 caller-provided iterable/path 的通用 helper。若实现使用
一个 private observation leaf，它的 caller 必须只有 `_acquire_authorities`，输入
必须是一个exact `H11RootIndirectAuthoritySpec`（含role/class/ordinal/path/kind与
expected metadata），返回
`H11RootObservedPathIdentity`。leaf只允许class-qualified lexical call
`Path.lstat(spec.path)` 一次，并从该结果判定 `directory|fifo|regular`；禁止
instance-method receiver推断、`Path.stat`、`os.stat`、`resolve` 或第二次路径观察。
static AST ledger中必须恰好一个observation leaf和一个canonical
`pathlib.Path.lstat` external call；runtime observe event count/order才与
`indirect_specs`相等。dynamic site identity由该static callsite ordinal、semantic
role/equivalence class、nullable install ordinal与dynamic semantic ordinal组成，不能要求static AST node count与
动态inventory count相等。

## 5. Exact retained cross-binding

### 5.1 TREE

必须证明：

- exact keys、schema、`tree-prepared` phase；
- formal/sealed/input/work/fifo/authority 六目录的 exact path/reference shape；
- fixture user/group/uid/gid canonical，fixture uid 非 root；
- `prepare_manifest` 是 exact full reference；C2e 不重新 decode其内容；
- FIFO rows exact shape、按 role 排序、role/path/identity 唯一；
- 整个 H11 TREE FIFO inventory 恰好是两个 commit FIFO 加六个 acquisition FIFO
  的 exact 8 rows；额外、缺失或重复 row fail closed；
- 每个 FIFO owner、uid/gid、mode 与 role policy 相等；
- TREE formal root 与 INSTALL/SEAL/PREFLIGHT direct authority 相等。

当前实体观察必须覆盖六目录、全部 TREE FIFO 与 prepare manifest reference。

### 5.2 SEAL

必须证明：

- exact keys、schema、`static-authority-sealed` phase；
- formal root 与 TREE actual authority 相等；
- TREE reference 等于 direct TREE actual reference 的 required projection；
- `seal_manifest` 是 exact full reference；C2e 不重新 decode其内容；
- files 非空，role/path/identity 唯一，SHA canonical，mode `0444`；
- file path 只位于 exact sealed/input roots；
- installer-program row 等于 INSTALL receipt installer reference；
- 每个 INSTALL unit source 与相同 role 的 SEAL row 全引用相等；
- PREFLIGHT inventory reference 等于唯一 `preflight-manifest` row；
- real H11 harness 的 `descriptor`、`harness_program`、`static_inventory` 均必须是
  non-null exact `{path,sha256}` hashed references；它们分别等于唯一
  `start-descriptor` row、唯一 `harness-program` row与
  `preflight-manifest`/PREFLIGHT inventory class 的 `{path,sha256}` projection；
- harness `static_roles` 是exact三项有序闭集：
  `(run-main, run_unit, adversary, h11-unbounded-hold)`、
  `(exec-stop-post, run_unit, observer, exec-stop-post)`、
  `(closer, closer_unit, observer, closer)`；每项plan/program都是exact
  `{path,sha256}`，六个path互异并各映射唯一SEAL row；每个logical
  `<static-role>:plan|program`各自形成独立semantic class，六个matching SEAL rows

  `preflight-manifest`、三个unit-source以及其他命名SEAL classes全部不同；
- slot 5 RUN ARMED的 `plan_path/plan_sha256` exact等于run-main static-role plan
  `{path,sha256}`；其 `program.path/program.sha256` exact等于run-main static-role
  program，并且 `program.identity.{device,inode,mode}` 经canonical int/mode转换后
  exact等于该SEAL full row的device/inode/mode；这些都是同一run-main plan/program
  classes的member，不另发observation spec；
- synthetic C2a fixture必须构造上述真实references；不得以当前fixture中的 `None`
  作为production acceptance或跳过对应cross-binding；
- semantic objects 之间无 hardlink identity alias。

### 5.3 PREFLIGHT

### 5.5 Semantic equivalence classes 与 alias

同一 filesystem object 在多个 receipts 中重复引用时必须先归一为一个 exact
semantic equivalence class，再执行 actual identity alias 检查。允许的相等闭集为：

#### 5.5.1 九个 direct source classes

- `authorization-source`：slot 22 actual full source；
- `harness-source`：slot 21 actual full reference
  `{path,sha256,device,inode,mode,uid,gid}` == AUTHORIZE-RELEASE
  `harness_manifest` == PERMIT_READY `harness_manifest`；
- `install-receipt-source`：slot 20 actual `{path,sha256}` == harness
  `installer_receipt`；
- `install-manifest-source`：slot 19 actual
  `{path,sha256,device,inode,mode}` == INSTALL receipt `install_manifest`，并满足
  §6 的 slot 20 path与slot 19 decoded `receipt_path`闭包；
- `tree-receipt-source`：slot 18 actual base
  `{path,sha256,device,inode}` == INSTALL receipt/manifest `tree_receipt` == SEAL
  `tree_receipt`；PREFLIGHT `tree_receipt`必须是该base加literal `mode="0444"`；
- `seal-receipt-source`：slot 17 actual base
  `{path,sha256,device,inode}` == INSTALL receipt/manifest `seal_receipt`；PREFLIGHT
  `seal_receipt`必须是该base加literal `mode="0444"`；
- `preflight-receipt-source`：slot 16 actual base
  `{path,sha256,device,inode}` == INSTALL receipt/manifest `preflight_receipt`；其
  `{path,sha256}` == harness `preflight_receipt`；
- `permit-ready-source`：slot 6 actual full reference == AUTHORIZE-RELEASE
  `permit_ready`，且path == harness permit-authority `permit_ready_path`；
- `run-armed-source`：slot 5 actual full reference == AUTHORIZE-RELEASE `run_armed`
  == PERMIT_READY `run_armed`。

各 member只比较其schema实际携带的 exact closed projection；较窄 projection不能
补造字段，也不能使较宽 actual reference跳过其自身完整验证。READY/ARMED/harness
projection属于该 alias oracle，不得留给 aggregate constructor偶然验证。

#### 5.5.2 Directory、FIFO 与 indirect file classes

- 九个 directory classes是TREE六目录与retained/harness directory-chain按相同
  semantic role合并后的闭包：formal/authority/input/fifo各自合并；sealed、work、
  harness、scenario、receipt各自独立；
- 每个 FIFO role恰好一个class，合并TREE row、PREFLIGHT row以及harness/ARMED中
  该role的 acquisition或commit reference；
- TREE `prepare_manifest`单独一个class；SEAL `seal_manifest`单独一个class；两者
  不与任何SEAL file或direct source合并；
- 每个SEAL role恰好一个class：`installer-program` class还包含INSTALL receipt
  `installer`；每个unit-source class还包含INSTALL same-role source；
  `preflight-manifest` class还包含PREFLIGHT `inventory_manifest`与harness
  `static_inventory` projection；`start-descriptor`与`harness-program` classes各自包含
  harness同名hashed reference；六个static-role plan/program各自并入一个未被任何
  其他named/static member使用的唯一path+SHA匹配SEAL row，形成六个独立classes；
  唯一额外member是run-main plan/program classes分别包含RUN ARMED的path/SHA与
  program full-identity projection；
- 每个INSTALL target恰好一个独立class，按unit ordinal排序，不与source合并。

同 class 的所有 references必须先在共同携带的path/SHA/device/inode/mode/uid/gid
字段上 exact相等，然后只生成一个 observation spec。较窄 reference不产生第二
spec。除上述同 class相等外，下列class的expected与actual `(device,inode)` 均必须
pairwise distinct：九个 direct sources、九个directories、八个FIFOs、prepare
manifest、seal manifest、每个SEAL file、每个INSTALL target。INSTALL target不得与
其source alias；不同unit targets不得互相alias。alias oracle按equivalence class
比较，不能按“字段曾在哪个receipt出现”比较，否则会误拒合法cross-reference。

## 6. Dynamic install-manifest path

slot 19 的 path authority 来自 retained slot 20 install receipt：

```text
harness installer_receipt {path, sha256}
    == slot 20 actual reference projection {path, sha256}

slot 20 decoded install_manifest {path, sha256, device, inode, mode}
    == slot 19 actual reference projection {path, sha256, device, inode, mode}

slot 19 decoded receipt_path
    == slot 20 canonical path
```

projection key sets是 literal closed sets；不得用 intersection、`.get`、field-present
loop或 caller-provided key list。slot 19 actual reference 的 uid/gid 继续用于 direct
source current identity validation，但不伪造为 install receipt 未携带的字段。

`H11RootJsonSourceView.__init__` 对 slot 19 只负责：

- exact flow/slot19/parent=None/label；
- path 是 absolute canonical lexical path，parts 中无 `..`；
- raw/source reference 自洽且 immutable；
- 不硬编码 basename 或 `formal_root.parent`。

§4.1 builder在首个indirect observation前唯一负责上述三向cross-binding；
`H11RootAuthorityView.__init__` 不重复decode或比较它。constructor仍按base design在
任何field Store前证明same-flow、exact slot/view topology、field type/order与
immutable boundary。其他parentless sources继续按原设计冻结exact canonical path。

接受测试必须包含至少两个不同的合法 install-manifest 位置。negative 必须包含：

- slot 19 coherent rebind、slot 20不变；
- slots 19/20 coherent rebind、harness不变；
- foreign-flow 19、foreign-flow 19+20；
- hardlink same inode wrong path；
- receipt reference 任一字段缺失、多余或漂移。

## 7. Teardown note 的可表达边界

`_close_slot_once` 的核心顺序保持：detach → one close → 捕获 close failure →
best-effort first note → 返回同一 close failure。

note 文本 exact 为
`"H11 ownership teardown secondary close failure"`，不能格式化或调用 secondary
`__str__/repr`。唯一写入 shape 是
`BaseException.add_note(active_error, <exact literal>)`，不得调用 instance override；
该 call 必须被独立 `try/except BaseException` 包围。note channel 自身失败不得：

- 替换 operation primary；
- 替换 observed close failure；
- 中断 `_sweep_slots`；
- 建立 side owner、error list 或第二 aggregation ABI。

普通可写 primary 必须得到一条 exact note。若 hostile primary 使 `__notes__`
不可写，则该 exceptional case 允许无 note；仍必须扫完 exact 23 slots并最终抛出
同一 primary。primary identity 与 exhaustive resource release 高于不可表达的 note。

测试必须覆盖 hostile secondary `__str__`、primary `add_note` override、poisoned
`__notes__`、23 个 close failure index、first/middle/last 多 failure 与无 active
primary 的 first-close identity。

## 8. Exact reachable graph 与 external leaf ledger

AST 不再接受 `safe_roots`、`safe_methods_by_type` 或 annotation 即 authority。
从 `module.authorize_h11_release` 出发，每个 reachable `Call` 必须唯一进入：

1. `internal_edges`：exact qualified caller → exact qualified internal callee；或
2. `external_leaves`：exact qualified caller、canonical spelling、lexical spelling、
   same-caller occurrence。

否则进入 `unresolved`。acceptance 同时要求：

- reachable node set exact；
- internal edge Counter exact；
- external leaf Counter exact；
- `unresolved == ()`；
- annotation 只做一致性检查，不提供 receiver provenance；
- import alias、shadow、branch merge、unknown receiver、callable alias、`getattr`、
  callback 与 wrapper-returned callable 全部 unresolved 或改变 exact ledger；
- occurrence 使用同一 function direct evaluation-order traversal 的稳定序号，
  不使用绝对行号/column 作为设计 identity。

expected authority 必须独立于被扫描 production AST：测试模块保存人工审阅的
literal `C2E_EXPECTED_REACHABLE_NODES`、`C2E_EXPECTED_INTERNAL_EDGES` 与
`C2E_EXPECTED_EXTERNAL_LEAVES`。scanner 只能读取这些 constants做 equality，
不得从当前 AST snapshot生成、更新或 fallback到 expected。任一 expected constant
变更都需要新的 design correction、fixed hash与两份设计审计；“先打印候选图再
粘贴为 expected”不是接受依据。fixed-hash implementation review 必须逐项查看
新增/删除的 external leaf，而不能只看数量。

本文只冻结oracle的语义与结构，**不授权implementation开始**。下一设计工件
`v0.4-w3-h11-c2e-implementation-oracle-design-20260720.md`必须在rejected candidate
恢复或任何进一步production/test实现编辑前，以accepted commit `cad8980c`的
source/graph加本文的人工设计delta
写出以下完整literal内容：reachable nodes、带multiplicity的internal edges、带
caller/spelling/occurrence的external leaves、C2a static boundaries、indirect role
rules、每个fixture-owned expected class tuple以及每个fixture的exact runtime
boundary-execution tuple。该工件不得读取或由rejected dirty
candidate AST/trace生成；它必须另取fixed hash与两份P0/P1/P2=0审计。实现测试中的
constants必须逐项等于已接受oracle工件；若实现无法满足，只能先修oracle设计并重审，
不能从candidate输出反推expected。

external leaf ledger 直接证明 FD 闭集：

- 唯一 FD producer 是 `H11OwnedFdSlot.open -> os.open`；
- 唯一 owned close 是
  `H11RootAuthorizationFlow._close_slot_once -> os.close`；

## 9. C2a exact fault inventory

测试必须以独立于 production AST/trace 的 literal design oracle 为第一权威：
`C2E_EXPECTED_C2A_STATIC_BOUNDARIES` 冻结 open/fstat/prove/decode/revalidate的
qualified callsite与顺序；`C2E_EXPECTED_INDIRECT_ROLE_RULES` 冻结六目录、八FIFO、
prepare manifest、seal manifest、preflight-inventory class、其余每个SEAL class与
exact三个INSTALL target怎样各展开为一个observe site。INSTALL source只作为
same-role SEAL class member，不能展开第二site。production AST inventory只与static
oracle比较；一次无故障runtime enter序列只与该fixture的独立literal execution
oracle比较，二者不能互相生成expected。每个site identity包含：

```text
static callsite ordinal
qualified caller
boundary kind: open | fstat | prove | decode | revalidate | observe
qualified callee/external leaf
same-caller occurrence
literal slot或semantic receiver provenance
dynamic semantic role（非observe site为 `None`）
dynamic equivalence class（非observe site为 `None`）
dynamic install ordinal（仅INSTALL target observe为 `0|1|2`，其他site为 `None`）
dynamic semantic ordinal（observe site为其在canonical `indirect_specs`中的zero-based
ordinal，非observe site为 `None`）
```

`site_identity`允许在runtime重复执行；它描述语义边界，不假装是execution唯一键。
每次runtime进入boundary时必须构造exact frozen：

```text
boundary_execution = (
    site_identity,
    execution_ordinal,
)
```

`execution_ordinal`是该flow无故障evaluation order中所有`enter` event的zero-based
全局ordinal，不按site重置。每个fixture在oracle addendum中手写独立literal
`C2E_EXPECTED_C2A_EXECUTIONS_BY_FIXTURE`；因此同一source view在pre/post两轮
revalidate中的内部fstat/prove即使site identity相同，也有不同execution ordinal。
primary injection target、trace prefix与“最后一个primary”全部按exact
`boundary_execution`选择，不能只按site identity或第一次匹配。

每个canonical/expanded/reordered fixture还必须在test source中手写一个独立literal
`expected_indirect_classes` tuple，逐项给出equivalence class、semantic role与
INSTALL ordinal（非target为`None`）。fixture builder可以消费这份literal来创建
输入，但expected tuple禁止读取production builder result、observed identities、
AST inventory或runtime trace。production `indirect_specs`与无故障observe trace要
分别独立等于该fixture-owned tuple；漏掉/重复SEAL class或改变target ordinal不能
让expected同步漂移。

exact比较projection冻结为：

```python
tuple(
    (spec.equivalence_class, spec.semantic_role, spec.install_ordinal)
    for spec in indirect_specs
) == expected_indirect_classes

tuple(
    (
        event.execution.site.equivalence_class,
        event.execution.site.semantic_role,
        event.execution.site.install_ordinal,
    )
    for event in golden_trace
    if event.event_kind == "complete"
    and event.execution.site.boundary_kind == "observe"
) == expected_indirect_classes

tuple(
    event.execution
    for event in golden_trace
    if event.event_kind == "enter"
) == C2E_EXPECTED_C2A_EXECUTIONS_BY_FIXTURE[fixture_name]
```

trace event exact为`(event_kind, boundary_execution)` frozen value；无故障trace对
每个execution有一对nested `enter/complete`，observe projection只取一次
`complete`，不得把enter与complete重复计数。spec、observe-complete与runtime-enter
三个actual tuples分别独立比较各自literal expected，不能互相比对后只断言相等。

不得用绝对 lineno/col_offset 作为 site identity。每个runtime execution的site
static component必须映射到一个static boundary或literal indirect role rule；每个
static boundary的runtime multiplicity由fixture execution oracle明确冻结，不能把
同一site的两次执行折叠，也不能存在oracle未声明的runtime execution。

dynamic SEAL receipt inventory不设置数量cap。每个具体fixture展开并覆盖其全部
SEAL rows；测试至少包含canonical H11 fixture、增加合法非unit SEAL assets的
protocol-valid expanded inventory与不同SEAL输入顺序但同canonical observation
顺序的fixture。INSTALL inventory固定为exact三roles，禁止伪造expanded INSTALL
case；target observe sites始终exact三项并按该fixture的receipt ordinal展开。

metadata/alias negative必须逐class覆盖：path替换、symlink指向原实体、wrong kind、
device/inode/mode漂移、适用时owner漂移、跨class hardlink alias。symlink case即使
default-following `stat` 会得到完全正确的目标metadata也必须失败，且external leaf
ledger只允许 `Path.lstat` spelling。owner positive/negative还必须证明：非root
commit FIFO只接受去重后的root/process owner闭集；非root sealed directory、SEAL
files与unit sources不新增owner限制；formal/authority/input/fifo以及direct-only
harness/scenario/receipt directories仍匹配retained chain；work、普通FIFO与
INSTALL target仍执行各自exact owner检查。

本文新增的每个 indirect `Path.lstat()` observation 也属于 C2a exact site，
`boundary kind` 记为 `observe`；它与原设计列出的五类 boundary 一样进入完整
primary/secondary 矩阵。不得因为 observation 在循环内共享一个静态 call node，
就把多个 semantic role 合并成一个代表 case；site identity 必须包含 semantic
role/class/semantic ordinal，execution另由global execution ordinal唯一化。

参数矩阵精确为：

```text
每个 exact primary boundary_execution
    -> primary-only（所有close成功）
    -> 若该点前零已绑定FD：额外断言 no-bound-secondary，不伪造close失败
    -> 若已有bound FD：再分别组合 first/middle/last close secondary
```

每例使用全新 flow。验收：

- trace 使用嵌套栈事件 `enter(execution)`、`complete(execution)`、
  `fail(execution)` 与 `unwind(execution)`。golden trace 的 enter/complete必须
  正确嵌套；失败于内部
  fstat/prove 时，允许存在 exact pending ancestor stack（例如外层 revalidate）。
  failure trace 必须等于 golden evaluation-order prefix 至
  `enter(failing_execution)`，随后是一次 `fail(failing_execution)` 与 pending
  ancestors的exact reverse-order `unwind`，之后零boundary event；failing
  execution无complete，
  已completed executions的投影是golden completed的strict prefix。这样内部site的
  任意一次execution与最后一个primary都可表达，不能用flat
  attempted/completed等式忽略祖先；
- 无 retry/reopen，后续 site 未执行；
- 原 primary identity保持；需要转换时 `InstallerError.__cause__` 是同一 primary；
- secondary 不替换 primary，普通 primary只有一条 fixed note；
- 所有此前已绑定 descriptor按固定 sweep顺序各 close一次，未绑定 slot零 close；
- 23 slots最终 empty，state=`FAILED_PREWRITE`，phase data保持 entry value；
- descriptors 均已 EBADF；第二次 authorize 在零 syscall下 one-shot拒绝；
- 双 Python 收集的 site IDs与数量完全相同；零 skip/xfail。

- budget、cap、timeout、deadline、retry、poll、sleep、watchdog；
- 自动 cleanup、evidence 删除/改写、失败后 reopen；
- schema 扩展、C3 watch、manager/H8/release side effect；
- compatibility alias、legacy validator fallback、test-only production hook；
- 为通过 AST 而忽略 helper、module attr、annotation 或 import alias。

## 12. 接受结论

本文通过后，C2e 的准确声明是：

> 一个固定 23-slot 的 root authorization flow 当前保留并重验 direct receipt
> bytes；以这些 receipts 的闭合声明作为间接 bytes/hash snapshot authority；
> 对每个间接class在其自己的C2a `Path.lstat()` event以无FD metadata observation
> 证明路径当时仍指向同一受保护实体（不宣称全inventory存在共同原子时点，也不
> 宣称证明持续到commit）；并在 exact
> internal/external call closure 下完成 one-shot publication与 exhaustive teardown。

它不声明：

- authorizer 重新读取并验证每个间接文件的当前 bytes；
- receipt 可以替代当前 object identity/mode/owner检查；
- root 攻击者原地改写 0444 inode 后仍可由 C2e 单独检测；
- C2e 已实现 C3 watch、release、manager或ledger消费。
