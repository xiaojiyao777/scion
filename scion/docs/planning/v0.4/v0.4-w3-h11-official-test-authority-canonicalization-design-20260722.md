## 3. Production authority cleanup and ABI corrections

Canonicalization exposed three production facts. They must be corrected before
the old tests can be classified honestly.

### 3.1 Remove test-only phase and publication authority

`_H11_TRANSACTION_PHASES` currently declares five phases while the public Flow
uses only `authorizer-input` and `permit-committed`. Replace the dictionary with
these exact live-owner values:

```python
_H11_AUTHORIZER_INPUT_TRANSACTION_STATE = (
    "present", "absent", "present", "absent", "absent", "absent", "absent"
)
_H11_PERMIT_COMMITTED_TRANSACTION_STATE = (
    "present", "absent", "present", "absent", "present", "absent", "absent"
)
```

The first symbol has exactly two production loads in `_consume_ready_commit`
and `_publish_permit`; the second has exactly three, in `_publish_permit` and
twice in `_commit_permit`. `_H11_TRANSACTION_PHASES` must be absent, not reduced
to a two-key dictionary. No phase selector or generic validator survives.
`pre-start`, `ready-visible` and `ledger-committed` move to an expected-literal
test catalogue and the actual READY/ledger tests; that catalogue executes no
production decision and is not a second protocol authority.

`_H11_PUBLICATION_PAIRS` and `_H11_PUBLICATION_TEST_FAILURES` are referenced
only by deleted legacy tests and must be removed from production. The Flow owns
the literal `PERMIT.pending -> PERMIT.json` transaction. READY and LEDGER pair
semantics belong only to the eight-case test-local immutable/pure-fake model in
section 4.4. No generic production publication helper, caller-selected pair or
test failure hook is authorized.

`H11RootNamedStagingPlan` is also a test-only orphan: it has no production
caller and still carries caller-selected names and `test_failure`. Delete the
class and remove it from oracle nominal/generated-class registries. The oracle
must assert all four old symbols are absent as module attributes:

```text
_H11_TRANSACTION_PHASES
_H11_PUBLICATION_PAIRS
_H11_PUBLICATION_TEST_FAILURES
H11RootNamedStagingPlan
```

This explicitly supersedes the atomic design section 10 statement that a
staging-plan value type must remain. The accepted Flow has no plan consumer:
slot 2 owns one literal PERMIT pair and exact source-shape oracle checks own its
flags/order. `H11RootPrePermitBarrier` and the other live immutable value types
remain. Keeping an unconsumed caller-selected plan would contradict the same
atomic section's ban on test-only production publication authority.

### 3.2 Restore the PERMIT writer OSError boundary

The old writer owner converted both blocking endpoint-open and its immediate
`fstat` `OSError` to:

```text
InstallerError("cannot open H11 PERMIT commit writer") from exc
```

The atomic Flow design preserved that boundary, but current `_commit_permit`
can leak the raw `OSError`. The correction is narrow and inline: one `try`
covers only the exact slot-0 open through slot-7 `/proc/self/fd`, followed by
the immediate slot-0 `fstat` and FIFO-reference proof; one `except OSError`
raises the exact `InstallerError` above from the original object. The outer
Flow failure owner performs the only sweep.

The correction adds no helper, retry, fallback, second close or alternate
endpoint. An `OSError` raised by open, fstat, or the proof call receives the
same exact conversion and cause identity. A non-`OSError` proof failure retains
object identity. All three failures are `FAILED_PREWRITE`, return no receipt,
write no frame and close every bound slot once.

This does not change the initial JSON source-open raw-`OSError` boundary, READY
reader raw `fstat/read` primary ABI, the five transaction non-`ENOENT`
conversions, or write-ambiguous classification.

### 3.3 Explicitly supersede the teardown note text

This design explicitly supersedes only the dynamic note text in atomic design
section 7.3. The exact secondary note remains:

```text
H11 ownership teardown secondary close failure
```

It must not interpolate the close exception type or message. Teardown must not
invoke an adversarial close exception's `__str__` or `__repr__` while trying to
preserve a different primary. The existing base-class `BaseException.add_note`
channel, at-most-one note, detach-before-close, fixed sweep order, complete
visitation and close-once behavior remain normative. This is an explicit ABI
decision, not permission to weaken any close matrix.

### 3.4 Supersede the old official private-seam requirement

This design also explicitly supersedes the atomic design sections 10.1 and
13.6 only where they require official C1a/C1b tests to call private phase seams
or inspect slot/phase-data identity. The single public Flow has replaced those
objects. Official behavior now observes public Flow state, artifacts, frames
and captured real syscall FDs. The 456 oracle is the sole test owner for
internal phase-data type/value identity, slot topology and call order.

No production-only test seam, private phase caller, raw-FD accessor or
compatibility API may be added to reproduce the old observation surface. The
underlying cleanup, fault-position and state assertions remain and are mapped
individually in Appendix A.

## 5. Public observation and fault rules

An official Flow test may enter only through
`H11RootAuthorizationFlow.authorize_once()` or
`authorize_h11_release()`. It may observe:

- `flow.state`, returned receipt or raised value and `__cause__`;
- exact PERMIT artifacts and canonical bytes;
- READY/PERMIT peer frames and EOF;
- captured real syscall descriptors and physical close counts.

The exact eight `TL:READY`/`TL:LEDGER` cases in section 4.4 are the sole
exception to the public-Flow entry rule. They may observe only their immutable
fake artifact model, exact raised value and event trace; they may not observe
or claim production Flow state/frame state and never receive a real Flow FD.

It may not call a private phase method, capture `_slots` or `_phase_data`, use a
removed Session/Closure/Permit type, mutate a private cached object, or add a
production test hook. Faults are injected at the exact public producer input or
real OS boundary. Each test freezes its phase-specific artifact position,
frame presence, state, cause/primary ABI and close-once evidence.

No retry, timeout, polling, sleep, `O_NONBLOCK`, compatibility wrapper, skip,
xfail, budget, truncation or privileged action is authorized.
