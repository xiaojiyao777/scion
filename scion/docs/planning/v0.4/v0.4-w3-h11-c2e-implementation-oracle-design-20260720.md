## 3. Scanner grammar

下文用 `M` 仅作排版缩写；它在 test constants中必须展开为完整字符串：

```text
M = generic_backend_root_installer
```

这是设计逻辑qname；test loader的临时`_fixture_`前缀必须在scan前精确剥离一次，
不得把runtime module name或文件路径混入expected。

production root exact为：

```text
M.authorize_h11_release
```

### 3.1 Resolved call record

每个 reachable `ast.Call` exact生成：

```python
H11ResolvedCall(
    caller_qname: str,
    target_kind: Literal["internal", "sensitive", "pure-value"],
    canonical_target: str,
    lexical_target: str,
    same_caller_occurrence: int,
    rule_id: str,
)
```

必须同时成立：

```text
unresolved == ()
multi_target == ()
unclassified == ()
resolved_call_count == reachable_ast_call_count
```

lexical target exact为 `ast.unparse(call.func)`；绝对line/column不进入site identity。

### 3.2 Call traversal 与 occurrence

scanner使用一个固定 evaluation-order visitor：

1. statements按body source order；
2. assignment先visit RHS，再targets；
3. call先visit callable expression中的nested call，再按source order visit positional/
   starred arguments与keyword values，最后记录enclosing call；
4. attribute/subscript只visit其value与index expression；
5. list/tuple/set/dict literals按source order；
6. sensitive call禁止位于lambda、comprehension、generator、bool-op、conditional
   expression或decorator中；这些位置出现即失败，而非尝试推测短路顺序；
7. pure-value occurrence只输出供review，不参与equality。

`same_caller_occurrence`在相同
`(caller_qname, canonical_target, lexical_target)` 内按上述顺序从零计数。

### 3.3 Canonical qualified names

internal：

```text
M.<function>
M.<Class>.<explicit-method>
```

external：

```text
builtins.<name-or-exact-builtin-method>
<public-stdlib-api-origin>.<qualname>
M.<generated-frozen-dataclass>.__init__
M.InstallerError
```

hash method使用API-origin canonical
`hashlib.sha256.hexdigest`，不使用CPython私有 `_hashlib.HASH`；native symbol使用
`ctypes.CDLL.renameat2`，不伪称它是普通Python method。

### 3.4 允许的窄 provenance

annotation永远不单独提供authority。允许的 provenance只有：

| rule id | exact source | exact result |
| --- | --- | --- |
| `IMPORT` | module import中唯一且未shadow的name | exact module/API name |
| `DIRECT_CLASS` | class-qualified explicit method/constructor | exact local class target |
| `SELF_RECEIVER` | 当前explicit instance method的首参必须拼写为`self`；class没有runtime替换/注册 | 当前定义class；只解析该class或其constructor-frozen field的explicit method |
| `ONE_ASSIGN` | exact constructor/direct value的一次local assignment且零重赋值 | 同一 exact target/value type |
| `TUPLE_UNPACK` | frozen fixed-shape tuple direct unpack且零重赋值 | 逐ordinal exact provenance |
| `LITERAL_CONTAINER` | literal list/tuple/set创建 | exact builtin container type |
| `LITERAL_SLOT` | `self._slots[INTEGER_LITERAL]`，receiver exact Flow，index `0..22`，tuple由Flow constructor唯一写 | exact `H11OwnedFdSlot`与literal slot/role |
| `FROZEN_FIELD` | exact view/phase class的constructor-frozen field chain；每层field只在exact constructor写一次 | field声明的exact nominal class；必须同时验证constructor caller/value provenance |
| `MONO_PARAM` | private function参数的全部reachable callers都传同一exact nominal class且无external caller | 该exact class；仅允许§3.5列名参数 |
| `NATIVE_SYMBOL` | local `libc = ctypes.CDLL(None, use_errno=True)`唯一赋值，随后direct `libc.renameat2(...)`，零alias/escape | exact native symbol `ctypes.CDLL.renameat2` |
| `HASH_RESULT` | exact nested `hashlib.sha256(raw).hexdigest()`，hash result不赋值/返回/escape | `hashlib.sha256.hexdigest` |
| `REGEX_API` | direct `re.fullmatch(EXACT_LITERAL_OR_MODULE_CONSTANT, value)` | `re.fullmatch` |

`FROZEN_FIELD`不是type-wide method allowlist：scanner必须从exact class constructor
Store、caller与传入value回溯；任一field多写、`setattr/object.__setattr__`、mutable
replacement或unknown caller都失败。

- `owner.close()`、`spec.path.lstat()`、`cls(...)`；

## 5. Canonical codec 与 pure support graph

### 5.1 唯一 direct-source decoder

exact signature：

```python
def _decode_h11_canonical_frozen_object(
    raw: bytes,
    *,
    label: str,
) -> H11RootFrozenJsonObject:
```

body顺序与外部leaf exact为：

```text
text = bytes.decode(raw, "utf-8", "strict")
parsed = json.loads(text)                         # 无 callback/hook
encoded = str.encode(
    json.dumps(
        parsed,
        ensure_ascii=True,
        allow_nan=False,
        separators=(",", ":"),
        sort_keys=True,
    )
    + "\n",
    "ascii",
)
require type(parsed) is dict and encoded == raw
frozen = _freeze_h11_json_value(parsed)
require exact top-level frozen-object shape
return frozen
```

duplicate key会因last-value parsed的canonical re-encode不可能保留duplicate row而
`encoded != raw`；`NaN/Infinity`会在`allow_nan=False` re-encode失败；因此不需要
`object_pairs_hook`或`parse_constant` callback。异常转换继续服从既有
`InstallerError`与`__cause__` ABI。

`_freeze_h11_json_value`是唯一codec subhelper，递归exact type闭集：

```text
None | bool | int | str
list -> tuple(frozen items)
dict[str, value] -> tuple((key, frozen value), ...)按已canonical key顺序
其他type失败
```

它不得调用filesystem/process/hash/regex/callback，不返回或保存parsed dict/list。
codec exact support graph：


## 6. Sensitive capability ledger

### 6.1 Record 与shape rule

一条call可具有多个capability；record exact为：

```text
(
  frozenset(capabilities),
  caller_qname,
  canonical_target,
  lexical_target,
  same_caller_occurrence,
  shape_rule_id,
)
```

不使用generic AST string作为argument authority。每个`shape_rule_id`对应本节或
base table一条exact structural predicate；scanner直接验证positional/keyword数量、
literal slot/path provenance、constant与nested borrow shape。starred/`**kwargs`在
sensitive call中一律失败。

capability闭集：

```text
FD_PRODUCE, FD_CLOSE, FD_READ_WRITE, FD_IDENTITY,
FS_METADATA, FS_MUTATION, FS_DURABILITY,
PROCESS_ID, EXCEPTION_NOTE, DYNAMIC_NATIVE, DATA_CODEC
```

### 7.0 Execution authority、scalar helpers 与 direct FIFO policy

## 8. C2a schedule authority

### 8.1 Boundary model

本文恢复correction design冻结的六类语义boundary，不把每个read chunk、lseek、
current-name stat/lstat或builder内部scalar call扩成第二套full occurrence gate：

```text
open | fstat | prove | decode | revalidate | observe
```

site identity exact为：

```text
(
  static_site_rule,
  caller_qname,
  boundary_kind,
  callee_qname,
  literal_slot_or_receiver,
  occurrence_label,
  semantic_role_or_none,
  equivalence_class_or_none,
  install_ordinal_or_none,
  semantic_ordinal_or_none,
)
```

runtime key仍为`BoundaryExecution(site_identity, execution_ordinal)`；ordinal是六类
boundary `enter`的global zero-based序号。`open`拥有并覆盖唯一nested `os.open`；
`observe`拥有并覆盖唯一nested indirect `Path.lstat`，两者不产生第二runtime site。
read/lseek/stat/direct lstat仍由§6 static ledger与base focused syscall tests逐callsite
验收，但不进入本节primary×teardown矩阵。

### 8.2 Independent macro grammar

test-side oracle逐字实现以下pure macros；大写名不是production helper：

```text
CALL(site, children):
  emit enter(site)
  expand children in listed order
  emit complete(site)

OPEN(slot, role, optional_parent_slot):
  CALL(open: exact phase -> H11OwnedFdSlot.open/os.open [slot,role,parent], [])

PIN_JSON(slot, role):
  # pre-name metadata; OPEN; fstat; complete EOF read; fstat; post-name;
  # canonical decode; reset.  Only six-class boundaries are emitted:
  OPEN(slot, role, parent-if-any)
  CALL(fstat [slot,pin-pre], [])
  CALL(fstat [slot,pin-post], [])
  CALL(decode [JsonSource,slot], [])

REVALIDATE_JSON(slot, wave):
  # accepted syscall order remains fstat -> current-name metadata ->
  # lseek/read-to-EOF/lseek.  Only revalidate/fstat are emitted:
  CALL(revalidate [JsonView,slot,wave], [
    CALL(fstat [slot,revalidate,wave], [])
  ])

DECODE_DIRECTORIES:
  for slot in (15,14,13,12,11,10,9):
    CALL(decode [DirectoryReference,slot], [])

  OPEN(slot, role, parent-if-any)
  CALL(prove [DirectoryReference,slot,pre-open], [])
  REVALIDATE_DIRECTORY(slot, initial)

REVALIDATE_DIRECTORY(slot, wave):
  CALL(revalidate [DirectoryView,slot,wave], [
    CALL(fstat [slot,revalidate,wave], []),
    CALL(prove [DirectoryReference,slot,opened,wave], []),
    CALL(prove [DirectoryReference,slot,current,wave], [])

  for slot in (8,7):
    CALL(decode [FifoReference,slot], [])

    CALL(prove [FifoReference,slot,opened,wave], []),
    CALL(prove [FifoReference,slot,current,wave], [])
```

### 8.4 Factored fault proof，不做笛卡尔积

event kind仍为`enter|complete|fail|unwind`；failure trace是golden prefix至
`enter(failing)`、同一execution一次`fail`、pending ancestors逆序`unwind`、之后零
event。

fault coverage按唯一实现路径因式分解，不是预算、采样、代表性category或截断：

1. canonical fixture对每个distinct six-class primary execution跑primary-only；
2. expanded fixture只对新增两个semantic observe classes补primary-only；其余
   execution必须先证明`fault_equivalence_key`与canonical逐项相等；
3. reordered fixture无新增key，完整golden trace仍逐项比较，但不重复相同primary；
4. 跨fixture的site projection从§8.1 tuple只删除fixture-local
   `semantic_ordinal`；`BoundaryExecution.execution_ordinal`本来就在site外，也不进入
   projection；static rule/caller/kind/callee/slot/occurrence label/role/class/
   INSTALL ordinal全部保留。observe的occurrence label固定为
   `inventory-observe`，不得编码semantic ordinal；
5. `fault_equivalence_key` exact为
   `(cross_fixture_site_projection, bound_slot_bitmap, flow_state,
   commit_boundary, exact_phase_data_type)`；因此expanded的15个ordinal-shifted既有
   classes与canonical相等，只有两个新class产生新key；
6. 每个§6 sensitive record必须在独立literal
   `C2E_SENSITIVE_FAULT_OWNER`中唯一映射到：六类boundary、base focused syscall
