## 1. Decision and boundary

This contract closes only the first native W3 slice: one CPython extension
that creates a blocked child atomically inside an already-open cgroup-v2
directory with `clone3(CLONE_INTO_CGROUP | CLONE_PIDFD)` and owns the exact
leader pidfd/release/capture/wait lifecycle.

The rejected r3 candidate with C SHA
`11491f2b796a0b33d8352028b7e3ba5c5c28f87c987e503c5a3fb307a2a3a8e8`
and rejected r4 candidate with C SHA
`cab294b79c8d8d00612ead95bb1afa9b3aae97f94340a8804a5a46749ab981c9`
remain diagnostic only. R3 allowed loss of reap authority, embedded a mutable
host RPATH and lacked positive delegated execution. R4 could die from
`SIGPIPE`, retained authority after `fork`, preserved inherited ignored signal
dispositions and implemented only three delegated fixtures.

This replacement deliberately removes the rejected full descendant file
trace, root-owned build verifier/classifier and complete compiler/loader input
closure. They exceeded the parent design's minimum trusted execution boundary
and would turn ordinary toolchain reads into a W3 launch gate. Build-time
`strace`, dependency scans and compiler diagnostics may be retained as
non-authoritative debugging evidence, but cannot accept or reject a source
candidate.

The accepted threat boundary is the parent's trusted research-code boundary:
exact pushed source, declared tool identities and artifacts are hashed before
and after use to catch accidental drift. This slice does not claim protection
against root compromise, hostile same-UID mutation during a build, compiler
backdoors or in-process memory corruption.

There is no fallback, retry, resume, runtime timeout, output cap, truncation,
seccomp/audit gate, model gate, problem logic or alternate process lifecycle.
This contract does not accept a generic guardian, cgroup-empty proof, systemd
projection, Warehouse validation, materialization, closure, dry root or
experiment launch.

## 2. Exact source and lightweight build receipt

Acceptance binds one pushed Git commit and tree plus exactly these source
blobs beneath its `scion/` tree:

- `pyproject.toml`;
- `scion/runtime/native/__init__.py`;
- `scion/runtime/native/spawn_into_cgroup.c`;
- `scion/tests/unit/runtime/test_native_spawn_into_cgroup.py`;
- `scion/tests/fixtures/native_spawn_probe.c`.

The first three form the wheel surface. The last two are test authority only
and are never packaged or imported by Scion runtime. A single immutable
extraction is created with `git archive <accepted-commit>:scion`, and each
build receives a fresh disposable copy. Tests read the exact immutable
extraction test blob directly. Working-tree, editable,
in-place, generated-checkout and untracked files are forbidden. The checkout
and immutable extraction remain free of `.so`, `.o`, `build/`, `dist/` and
`*.egg-info`; disposable copies may contain build output and are destroyed

One canonical environment receipt records and prehashes:

- canonical installed-distribution file manifests and raw hashes for pip

  `1.6.0`, iniconfig `2.3.0`, packaging `25.0` and pygments `2.19.2` from the
  accepted `claw` environment under isolated Python;

## 4. Native ABI and lifecycle

Before `clone3`, native must:

1. require exactly one `/proc/self/task` entry;
2. require `SIGCHLD` exactly `SIG_DFL` without `SA_NOCLDWAIT`;
3. record creator PID and enumerate every queryable catchable signal;
4. validate and deep-copy exact bytes/tuple executable, argv, environment and
   absolute cwd, rejecting NULs, duplicate environment names and drift;
5. validate and duplicate an already-open cgroup-v2 directory FD;
6. open `/dev/null`, require character device `1:3`, create blocking
   stdout/stderr pipes, a blocking Unix stream socketpair release channel and
   a close-on-exec exec-error pipe;
7. require `FD_CLOEXEC` on every native-owned source/parent authority FD,
   including both release ends, capture ends, exec-error ends, duplicated
   cgroup FD and returned pidfd;
8. allocate every object needed by the parent return path;
9. block the complete queryable catchable signal set in the creating thread and
   retain its exact prior mask.

The clone call fixes ABI v2 size 88, flags
`CLONE_INTO_CGROUP | CLONE_PIDFD`, `exit_signal=SIGCHLD`, the duplicated cgroup
FD and kernel-written pidfd. Every clone failure is returned exactly. No path
uses `fork`, `vfork`, ordinary `clone`, `posix_spawn`, `subprocess`,
`pidfd_open`, `kill(pid)` or a write to `cgroup.procs`.

Before release, the child has only FDs 0 through 4: verified `/dev/null`,
blocking stdout/stderr writers, release reader and `CLOEXEC` exec-error writer.
It closes all other FDs, resets every queryable catchable disposition to
`SIG_DFL`, clears its inherited mask, and reads exactly byte `0x01`. It then
closes release, changes to the copied cwd and calls exact `execve` without PATH
or shell lookup. The target therefore begins with empty signal mask and default
catchable dispositions, including signals CPython normally ignores.

Failure writes this fixed 12-byte record then `_exit(127)`: magic `SCXE`,
version 1, one-byte stage, two zero reserved bytes and little-endian uint32
errno. Stages are 1 dup error, 2 stdin, 3 stdout, 4 stderr, 5 release,
6 close-range, 7 disposition reset, 8 mask clear, 9 release read,
10 release byte, 11 release close, 12 chdir and 13 execve. Successful exec
produces clean exec-error EOF.

After clone, the parent closes child-only copies and restores its exact prior
signal mask before returning the handle. Every ordinary error restores the
mask before returning an exception. The restore uses a fixed valid
`pthread_sigmask(SIG_SETMASK, ...)` call; an impossible defensive failure after
clone kills and settles the still-blocked leader then calls `abort()` rather
than returning authority. Any other post-clone parent construction/cleanup
error first creates an internal BLOCKED owner, closes release, settles the
exact leader by pidfd and only then returns an exception; settlement
uncertainty calls `abort()`. No runtime fault-injection seam is added for these
defensive out-of-threat-boundary branches.

The unforgeable, non-subclassable, non-copyable and non-pickleable handle:

- binds `take_capture_fds`, `release`, `dup_pidfd`, `send_signal`, `peek_wait`
  and `reap` to the creator PID and rechecks one-task plus SIGCHLD authority;
- retains the exact kernel PID, original pidfd and one-shot release authority;
- transfers three nonblocking capture readers exactly once;
- releases by one `send(..., MSG_NOSIGNAL)` byte on the Unix socket and closes
  it; any send/close uncertainty reaches distinct POISONED state without
  generating, consuming or changing issuer `SIGPIPE` state;
- uses only pidfd for signaling and wait authority;
- peeks with `waitid(P_PIDFD, WEXITED | WNOWAIT | WNOHANG)` and caches one
  coherent `siginfo` terminal tuple;
- refuses public reap until that exact terminal fact is cached, then consumes
  it once with `waitid(P_PIDFD, WEXITED)`; public reap never waits for a live
  child;
- refuses capture transfer/release/reap repetition and pidfd duplication after
  reap;
- never interprets leader terminal/reap as cgroup empty or descendant cleanup.

The formal issuer is trusted sealed single-process code. From spawn through
reap it keeps one task, preserves exact SIGCHLD authority and never consumes
the child through another wait/signal path. A duplicated pidfd is poll-only
evidence. Same-process hostile code is outside the parent threat boundary.

After `fork`, a copied handle has no authority. Every public method rejects
before changing state or duplicating/transferring/touching an authority FD;
the non-creator destructor closes only that process's inherited FD copies.

Creator destruction is state-specific and fail-closed:

- REAPED closes remaining local FDs and returns;
- BLOCKED closes release and first performs nonblocking
  `waitid(P_PIDFD, WEXITED | WNOWAIT | WNOHANG)`. A terminal leader is exact
  reaped directly. A live leader receives pidfd SIGKILL; success, or a
  race-consistent ESRCH followed by a pidfd terminal observation, advances to
  exact reap. Every other signal/wait authority error calls `abort()`;
- RELEASED or POISONED calls `abort()` rather than waiting for arbitrary
  executed code or pretending descendant containment. Normal explicit
  `peek_wait`/`reap` may transition a terminal leader to REAPED before the job
  cgroup is empty. The later generic `SpawnBackend` independently retains that
  cgroup authority, checks `cgroup.events` after leader reap, kills/drains when
  populated and never treats REAPED as containment proof.

## 5. Required executed tests

No-clone tests cover exact types, embedded NUL, empty/relative/mismatched argv,
duplicate environment names, invalid/non-cgroup/boolean FDs, custom or ignored
SIGCHLD, multi-task state and FD counts across every rejection.

Positive tests require one fresh empty systemd-255 delegated cgroup-v2 fixture.
The harness opens and retains the original directory FD, records device/inode,
reads controls relative to that FD, and uses the path only for initial open.
Fixture absence is a diagnostic skip in development and a formal blocker.

The fixed native probe provides reviewed roles for raw FD/signal observation,
binary stdout/stderr emission, exact exit/signal facts and a setsid descendant.
Python or shell startup cannot substitute for probe signal/FD evidence. The
formal transaction executes and proves:

- loaded module/probe hashes and paths match the accepted build receipts before
  and after all tests;
- a blocked leader is already in the exact retained cgroup FD, while target
  sentinel/output is absent;
- handle construction, subclassing, copy and pickle fail; every illegal repeat
  or nonterminal reap leaves state and FD count unchanged;
- with parent custom and ignored user-signal dispositions, signaling a still
  BLOCKED child terminates it by the default signal before exec; no inherited
  handler behavior or target sentinel occurs;
- nontrivial issuer masks are bit-identical after successful spawn, validation
  failure and denied clone; a parent blocked/pending signal is absent from the
  post-exec probe while the parent's pending fact is preserved;
- exactly one release byte starts one exec and a second release is rejected;
- dead-reader release under SIGPIPE default, ignored, custom-handler and
  blocked/pending states returns exact EPIPE, reaches POISONED, never calls the
  handler and preserves disposition, mask and prior pending fact;
- successful exec gives clean error EOF; nonexistent executable and invalid cwd
  give exact stage/errno records and exit 127;
- dropping BLOCKED proves no exec/sentinel, exact leader settlement and no FD
  leak, including the case where the BLOCKED leader is already terminal before
  drop; dropping RELEASED/POISONED in an isolated fixture process fail-stops,
  after which fixture-only cgroup cleanup prevents pollution;
- inherited parent FDs are absent after exec, stdin is verified `/dev/null`,
  child stdout/stderr are blocking, parent capture readers are nonblocking, and
  target mask is empty with every queryable catchable disposition default;
- a before/after `/proc/self/fd` inventory plus `fcntl(F_GETFD)` proves every
  new hidden parent FD, transferred capture reader and duplicated pidfd is
  `FD_CLOEXEC`; a fork-exec probe observes none of those parent authorities;
- binary stdout/stderr larger than the observed pipe capacity are drained
  byte-for-byte without cap or truncation;
- exit 0, nonzero exit, leader signal and available core-dump facts produce one
  coherent peek/reap result; second reap and post-reap pidfd duplication fail;
- invalid/denied clone creates no child and leaks no FD;
- live SIGCHLD or task-count drift is rejected before every authority method;
- a forked copy invokes each public method and proves rejection, unchanged
  state/FD count and no effect on the creator's complete lifecycle; its
  destructor is close-only;
- a setsid descendant proves leader terminal/reap can coexist with retained
  `cgroup.events populated=1` and native reports no empty proof. Fixture-only
  harness code then kills/drains the test cgroup; that cleanup is not native
  API or accepted guardian evidence.

Tests may use a diagnostic deadlock guard, but runtime contains no timeout.
EACCES-only probes, skipped delegated tests and traces of rejected clone calls
never substitute for positive execution.

## 6. Acceptance and continuation lock

One exact contract SHA and one corrected five-source hash set require two
independent P0=0/P1=0 reviews. The exact double-build/install/import/test
transaction then runs once on those final hashes. If delegated execution is
unavailable, the source may be committed only as a reviewed candidate, never
as native acceptance.

Native acceptance authorizes only the next generic SpawnBackend/cgroup/systemd
slice. `TASK.md` and `current-state.md` continue to state that W3 dry-root and
formal solver launch are locked until all later parent-design layers pass.
