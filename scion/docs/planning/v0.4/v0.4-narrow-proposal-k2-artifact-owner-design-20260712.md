# Scion v0.4 Narrow Proposal K2 Artifact-Owner Design

*Date: 2026-07-12*
*Status: owner audit and implementation design; no production changes*
*Inputs: v3 architecture, narrow-kernel design, K0 characterization, current source*

## Decision

K2 should not create a `ProposalAttemptStore`, reuse the agentic session store,
or add proposal fields to a second database. The smallest coherent ownership is:

```text
PromptTurnSnapshot          exact in-process provider-visible rendering
trace + embedded manifest  durable request/response/error and visibility audit
HypothesisStore             sole hypothesis identity and lifecycle owner
LineageRegistry             append-only proposal-attempt transition owner
StepRecord                  compact pointer to the committed transition
formal candidate artifact  canonical replay patch only after formal screening
```

The attempt transition is an audit projection and join record. It must not be
used to reconstruct or mutate the canonical hypothesis, replace the formal
candidate patch, drive Decision, or resume a planner loop.

This design adds no prompt budget, truncation, top-N selection, omission,
provider-visible prompt change, or new research gate. Existing diagnostic size
accounting in prompt manifests is left unchanged and is not promoted into
policy.

## Current Owner Audit

| Field or artifact | Current owner | Gap found | Minimal K2 change |
| --- | --- | --- | --- |
| Exact system blocks, user prompt, structured-context digest | `proposal/engine/facade.py::PromptTurnSnapshot` | Direct `ProposalPipeline` calls convenience methods and receives no durable receipt | Build one snapshot per direct call and pass that same object to manifest, trace, and provider |
| Provider prompt hash, raw response, provider error, usage metadata | `proposal/engine/trace.py::_TraceWriter` | `_call_with_trace` returns only parsed output; the direct caller cannot name the trace | Return a small immutable call receipt containing trace id/ref, prompt hash, request kind, success, and error classification |
| API-visible sections, visibility ledger, context inventory | `proposal/prompt_manifest.py::build_api_visible_prompt_manifest` | Persistence is currently wired through agentic scratch artifacts | For direct calls, embed the manifest in the existing trace and reference `trace_ref#/prompt_manifest`; use `attempt_id` as the existing manifest correlation id |
| Hypothesis identity, parent link, classification, lifecycle status | `core/models.py::HypothesisRecord` plus `lineage/branch_store.py::HypothesisStore` | Direct record has no attempt/artifact link, and `_hypothesis_record` leaves `base_champion_version` at the default `0` | Keep the schema unchanged; join by `hypothesis_id`, and set the already-owned champion version from the same snapshot used to build context |
| Hypothesis proposal before approval | Provider trace, then in-memory `HypothesisProposal` | No durable direct transition after parsing/quality checks | Append one `hypothesis_generated` or `hypothesis_failed` lineage event referencing the trace and optional `hypothesis_id` |
| Patch proposal before formal screening | Provider trace, then in-memory `PatchProposal` | No durable parsed-patch digest/ref; a code failure can leave a stale hypothesis-only ref | Append one `code_generated` or `code_failed` lineage event with patch digest and trace response ref; do not copy full patch into another store |
| Canonical replayable patch after screening | `core/formal_candidate_artifacts.py::FormalCandidatePatchArtifactRecorder` | It can join only by branch and hypothesis | Add attempt/event ids as references in metadata and index; it remains the only canonical full-file replay patch |
| Attempt id, runtime mode, phase transition, failure lane | No mode-neutral owner | Agentic output owns agentic session state only; direct has none | Record a versioned `proposal_attempt_transition` in the existing append-only `LineageRegistry` |
| Campaign, problem, split, seed, branch, champion anchors | Pipeline/config/context objects; agentic request/output in agentic mode | Direct artifacts do not commit the complete anchor set | Copy scalar ids/hashes into the lineage audit payload; do not copy source manifests or metrics |
| Durable pointer exposed to the explore step | `StepRecord.proposal_session_ref` and `StepResult.proposal_session_ref` | Field and producers are agentic-named; direct usually exposes only context metadata | Keep the field name for compatibility in K2, but store a mode-neutral `proposal-attempt-ref.v1`; rename only after consumers migrate |
| Agentic transcripts, tool observations, self-check and recovery state | `FileAgenticSessionArtifactStore` and `AgenticSessionStore` | Tempting but incorrect place for direct artifacts | Leave agentic-only; adapt its final output to the compact common ref only for cross-mode reporting |
| Failure routing input | `core/models.py::FailureEvent` | Ephemeral and too coarse to be the durable attempt record | Keep it ephemeral; commit the attempt failure first, then call `FailureLifecycleService` |
| Selected recovery/lifecycle event | `FailureLifecycleService` plus `LineageRegistry` | Only some recovery actions emit an event; no prompt/attempt refs | Do not expand it into proposal storage; correlate through the already-committed attempt ref |

`scion/memory/hypothesis_store.py` is a compatibility re-export, not another
owner. It must not receive K2 behavior.

## Mode-Neutral Transition Contract

Use one append-only `experiment_events` row per terminal phase transition. The
row owns only normal lineage columns plus `audit_payload_json`:

```python
ProposalAttemptTransitionV1(
    schema_version="proposal-attempt-transition.v1",
    attempt_id=...,
    campaign_id=...,
    branch_id=...,
    runtime_mode="direct_v3" | "agentic_ablation",
    phase="hypothesis" | "code",
    status="generated" | "failed",
    transition_reason=...,
    failure_lane=None | "infra" | "proposal_repair" | "research_iteration",
    hypothesis_id=None | ...,
    hypothesis_digest=None | ...,
    patch_digest=None | ...,
    prompt_call={
        "request_kind": ...,
        "context_digest": ...,
        "prompt_hash": ...,
        "trace_ref": ...,
        "prompt_manifest_ref": "<trace_ref>#/prompt_manifest",
        "raw_response_ref": "<trace_ref>#/response",
    },
    anchors={
        "problem_id": ...,
        "problem_spec_hash": ...,
        "split_manifest_hash": ...,
        "seed_ledger_hash": ...,
        "champion_version": ...,
        "champion_weight_revision": ...,
    },
    tainted_artifact_refs=(...),
)
```

Rules:

- `attempt_id` is created before the hypothesis call and retained through the
  approved code call. A later retry is a new attempt, not a mutation.
- Exactly one terminal hypothesis transition and at most one terminal code
  transition are written per attempt. No mutable attempt row is introduced.
- The transition contains digests and refs, not a second full hypothesis or
  patch payload. The trace owns the tainted raw provider response.
- `hypothesis_id` references the existing `HypothesisRecord`; it is not an
  alternate identity. `HypothesisStore` remains the only status owner.
- A successful formal screen references the attempt/event ids from its
  canonical candidate metadata. The attempt artifact never becomes the formal
  patch.
- Public refs are campaign-relative and path-confined through the existing
  public-ref rules. Absolute host paths are not exposed in summaries.
- Attempt data is excluded from `DecisionFeatures` and all deterministic gate
  inputs.

The compact ref placed in the existing step field is:

```python
{
    "schema_version": "proposal-attempt-ref.v1",
    "attempt_id": ...,
    "runtime_mode": ...,
    "phase": ...,
    "status": ...,
    "transition_reason": ...,
    "failure_lane": ...,
    "lineage_event_id": ...,
    "hypothesis_id": ...,
    "artifact_ref": ...,          # latest trace ref
    "prompt_manifest_ref": ...,
}
```

Existing consumers should read these generic fields first and retain fallback
reads for old agentic refs during K2. The common ref must not acquire planner
diagnostics merely to satisfy those fallbacks.

## Commit Ordering and Failure Lanes

Direct success ordering:

```text
render snapshot once
  -> build manifest from that snapshot
  -> trace start
  -> provider call and trace finish
  -> parse + existing problem-quality hook
  -> append lineage transition (commit)
  -> publish compact ref / return proposal
  -> existing outer Contract, Verification, Protocol, Decision
```

Direct failure ordering:

```text
trace finish with error or raw invalid response
  -> append failed transition (commit)
  -> publish compact ref
  -> FailureEvent -> FailureLifecycleService / circuit breaker / status
```

The commit is required for production-ready `direct_v3`; it must not be a
best-effort `try/except: pass`. If the transition cannot be committed, stop the
proposal step as an infrastructure failure before observer/status publication.

Lane meanings are accounting semantics, not new gates:

| Lane | Use | Examples |
| --- | --- | --- |
| `infra` | The research proposal was not meaningfully completed because infrastructure/provider availability failed | transient provider error, rate limit, trace/transition persistence failure, balance stop |
| `proposal_repair` | A provider response existed but failed parsing, schema, boundary, or the existing problem-quality hook | invalid tool payload, illegal locus, invalid patch shape |
| `research_iteration` | A valid committed proposal entered the unchanged scientific pipeline and produced a genuine research result | later Contract/Verification/Protocol/Decision outcome; not a provider retry |

K2 records `infra` and `proposal_repair` at the proposal seam. The existing
outer step owns whether a valid attempt counts as `research_iteration`; the
proposal kernel must not guess this from a model error. This prevents an infra
retry from consuming research-iteration accounting without altering current
campaign limits or adding any new limit.

## What May Be Reused from Agentic Artifacts

Reusable:

- campaign-relative public refs and root path confinement;
- atomic artifact-write mechanics if a generic helper is needed elsewhere;
- prompt manifest builder, trace writer, stable digest conventions;
- the idea of projecting a large mode-specific artifact into a compact step
  ref;
- agentic `output.json` as the agentic adapter's own tainted artifact ref.

Do not reuse by importing private helpers from `agentic_artifacts.py` or
`agentic_artifact_payloads.py`; extract a genuinely generic helper only if K2
needs it.

Must not be copied into direct mode:

- session/request/idempotency replay state;
- compact transcript and transcript digest as a proposal requirement;
- tool-loop configuration or usage counters;
- observation, tool-selection, retry, and failure ledgers;
- planner termination diagnostics, target-intent state, self-check, preview,
  repair-loop, or resume projections;
- agentic index semantics or the `agentic_proposal_session` artifact kind.

Agentic mode may later map `session_id`, final artifact ref, status, and failure
classification into `proposal-attempt-ref.v1`. That adapter references the
agentic ledger; it does not duplicate it.

## K2.1 — Exact Prompt Call Receipt

Scope:

1. Add a frozen, mode-neutral `PromptCallReceipt` beside
   `PromptTurnSnapshot`.
2. Let `CreativeLayer` return parsed value plus receipt through new explicit
   snapshot methods; keep current convenience methods as compatibility
   delegates.
3. Build the direct prompt manifest from the exact snapshot and embed it in the
   trace.
4. Assert snapshot prompt hash = manifest prompt hash = trace prompt hash.
5. Expose only refs/digests and error state; no prompt selection policy, budget,
   truncation, tool selection, or provider-visible content change.

K2.1 does not yet change launcher defaults, outer gates, `HypothesisStore`, or
formal candidates.

## K2.2 — Append-Only Attempt Join

Scope:

1. Add a small `ProposalAttemptRecorder` that validates the transition schema
   and delegates persistence to `LineageRegistry.record_event`; it has no
   database, query API, or mutable state store of its own.
2. Carry one branch-local pending `attempt_id` from hypothesis to approved code
   generation and clear it on terminal failure/completion.
3. Commit the transition before failure handling, status, or returned step
   summaries.
4. Publish `proposal-attempt-ref.v1` through the existing
   `proposal_session_ref` compatibility seam and migrate readers to generic
   fields first.
5. Set the existing `HypothesisRecord.base_champion_version` correctly; do not
   add attempt columns to the hypothesis table.
6. Add attempt/event reference fields to formal candidate metadata/index only;
   do not change candidate patch content or replay identity.

K2.2 does not switch prepared launchers and does not change Contract,
Verification, Protocol, Decision, failure routing policy, or campaign limits.

| Test | K2.1 | K2.2 | Required assertion |
| --- | ---: | ---: | --- |

| CVRP direct success | yes | yes | Same anchors and approved target source survive; no target-intent/tool-selection call |
| Snapshot identity | yes | | Exact system/user bytes and all three prompt hashes match |
| Hypothesis transient provider failure | yes | yes | Trace error exists; committed `infra` transition precedes failure handler; no hypothesis record |
| Hypothesis parse/quality failure | yes | yes | `proposal_repair`; raw response remains referenced; no fake research iteration |
| Code transient provider failure | yes | yes | Same attempt/hypothesis ids; code failed transition replaces stale hypothesis-only step ref |
| Patch quality failure | yes | yes | Hook called once; `proposal_repair`; no formal candidate artifact |
| Lineage write failure | | yes | Proposal step stops as infra before status/observer publication |
| Hypothesis lifecycle | | yes | One `HypothesisStore` row; correct champion version; attempt event cannot update status |
| Formal candidate join | | yes | Existing patch/replay bytes unchanged; metadata references attempt/event ids |
| Agentic compatibility | | yes | Existing agentic artifacts unchanged; common ref is a pointer, not copied ledgers |
| Public-ref hygiene | yes | yes | No absolute host path or hidden metrics in compact refs/summaries |
| Outer-boundary regression | | yes | Contract -> Verification -> Protocol -> Decision inputs and outcomes unchanged |
| No-control-noise regression | yes | yes | No new budget/truncation/selection behavior and no new research gate |

Owning tests should use deterministic fake creative/provider seams for both
warehouse and CVRP, plus write-order spies for lineage, failure handling, and
status. A short runtime smoke may follow K2.2, but launcher switching remains
K3 and requires the full narrow-kernel preconditions.

## Acceptance and Rejection

Accept K2 only when a failed direct code call leaves a durable, current code
failure transition linked to the approved hypothesis and exact prompt trace,
while the hypothesis database and formal candidate artifact remain the only
domain owners of their respective lifecycle and replay data.

Reject K2 if it creates a proposal-attempt database, writes direct artifacts
under the agentic session schema, copies planner ledgers, stores a second
mutable hypothesis/patch truth, changes prompt bytes, adds a limit or
truncation rule, weakens an outer gate, or lets observers publish before the
attempt transition commits.
