## Decision

The current lossless-direct patch is a functional transition, not the final
architecture. It removed active evidence truncation, but propagated a
`lossless` boolean through dozens of helpers. That repeats the patch layering
and cross-module policy drift that this refactor is intended to remove.

K4 replaced the propagated mode flags with one authoritative, complete, safe
proposal-context snapshot and one isolated legacy agentic projector. The
projector is now explicitly transitional: the V3/K6 audit selected one
two-round production runtime and physical APS deletion as the final state.

```text
campaign state
  -> SafeProposalInputExtractor
  -> ContextManager.build_*()
       -> ProposalContextSnapshot
            |-> direct_v3 renderer
            `-> LegacyAgenticProjector -> agentic_ablation renderer
```

Only `ProposalPipeline` resolves and routes the runtime mode. `ContextManager`,
problem-owned context builders, and their helpers do not receive a runtime mode
or a `lossless` flag.

## Why This Shape

Rejected alternatives:

1. Replacing `lossless: bool` with a policy enum still propagates one control
   decision across the same helper graph.
2. Separate direct and agentic ContextManagers duplicate safety extraction and
   create two truth stores that can drift.
3. Keeping the current transition indefinitely makes tests prove a growing
   branch matrix rather than a small architectural boundary.

The selected design follows the useful common structure in Pi and Claude Code:
durable/full state is separate from the model-facing projection, and legacy
compaction is a boundary projection rather than a property of every producer.
Scion does not adopt automatic compaction for `direct_v3`.

## Owners

### `SafeProposalInputs`

The only input to proposal-context assembly. It admits screening and explicitly
safe pre-protocol facts. Its type surface cannot contain validation/frozen
results, raw pair metrics, BKS/holdout details, prompts, LLM text, or
DecisionFeatures.

Safety filtering happens once before this object is created. A renderer or
projector cannot reach raw `StepRecord` objects.

### `ProposalContextSnapshot`

One immutable context product per phase:

- phase and stable identity;
- canonical static sections;
- canonical evidence sections;
- `SourceLedger`;
- safety manifest;
- non-provider-visible primitive projection inputs needed only for exact legacy
  reproduction.

The snapshot contains authoritative structured payloads, not both a payload and
a second rendered full-text copy.

### `SourceLedger`

Every source path has one full-content owner with digest, provenance, and
visibility status. Owner priority is:

1. approved target;
2. branch-current integration;
3. branch helper;
4. champion/API support.

An API manifest may use a signature/ref only when the same path already has a
full-content owner. An API-only path must receive its own full-content owner.
No renderer performs content-hash guessing to decide ownership.

### `LegacyAgenticProjector`

The sole owner of historical compact/top-N/character-limit behavior:

- `project_hypothesis(snapshot)`;
- `project_code(snapshot)`.

It projects from complete, safe primitive inputs in the historical order.
`direct_v3` never invokes it.

Named recent windows that express an actual time/control view remain explicit
derived views. They cannot be the only owner of the underlying evidence.

## Canonical Ownership Rules

- `branch_dossier_payload` owns branch dossier facts; rendering is derived.
- `cross_branch_research_payload` owns cross-branch facts; rendering is derived.
- portfolio, coverage, lesson, and guidance records point to canonical source
  refs rather than copying complete upstream records.
- exact duplicates use an explicit owner ref and full SHA-256; semantic-near
  duplicates are not silently collapsed.
- each provider-visible source body appears exactly once.
- direct output normalization preserves complete schema-valid provider values;
  invalid values fail explicitly and are never silently truncated or dropped.

## Migration Slices

### K4.0 Freeze

Freeze real warehouse, CVRP, initial, and continuation provider-request
fixtures. Agentic fixtures are byte authorities. Direct fixtures are semantic
leaf/source-owner authorities.

### K4.1 Safe inputs and snapshot shell

Introduce typed `SafeProposalInputs`, `ProposalContextSnapshot`, and safety
manifest wrappers around the current output without changing provider bytes.

### K4.2 Legacy projector

Move legacy filtering, compact schemas, truncation markers, and ordering into
one `LegacyAgenticProjector`. Agentic provider requests must remain byte-for-
byte identical.

### K4.3 Authoritative producers

Make feedback/dossier, cross-branch/portfolio, runtime/guidance, measurement,
and code-source producers always emit complete safe facts. Remove their mode
and `lossless` parameters from leaves toward the entry point.

### K4.4 Source ledger and renderer cleanup

Replace renderer-local source deduplication with `SourceLedger`; remove repeated
string/payload views and direct-vs-legacy branches from renderers.

### K4.5 Route and delete

Superseded by K6: first close the direct CVRP outer, multi-file, interruption,
and launcher gaps; then remove the mode branch, legacy projector, APS graph,
all production `lossless: bool` parameters, and transition compatibility
wrappers. Do not retain the projector as a permanent second runtime.

## Acceptance

### Bytes and semantics

- K4.0 agentic provider requests remain the historical characterization
  authority; K5.5 source/output semantics may migrate those bytes explicitly,
  and K6 deletes the runtime rather than preserving obsolete compact bytes.
- Direct authoritative leaf content, order, and count match the accepted
  lossless transition.
- Direct byte differences only remove an already-owned duplicate body and must
  add/retain its explicit owner ref.
- every old-boundary tail sentinel remains visible exactly once;
- each source body is visible exactly once;
- direct hypothesis/code schema changes occur only through K5's explicit V3
  governance reset; hidden retry identities are deleted, not silently drifted.

### Safety

- validation, frozen, raw pair/calibration metrics, BKS, holdout, prompts, and
  LLM text remain absent from both modes;
- DecisionFeatures fields and inputs remain unchanged;
- unreadable/symlink/source-digest and branch-current provenance boundaries
  remain fail-closed.

### Structure

- production proposal context/engine helpers contain zero `lossless: bool`
  parameters;
- during transition, runtime-mode decisions exist only at the pipeline route
  and legacy projector entry; after K6, neither branch remains;
- `ContextManager.build_*` produces one authoritative snapshot per phase;
- there is no second ContextManager or second durable truth store;
- production code is expected to shrink by about 320-460 net lines after all
  transition branches and duplicate views are deleted.

## Run Lock

Do not prepare or launch the formal warehouse control from the transition
implementation. K4 must pass its byte, semantic, safety, source-owner, replay,
and outer-pipeline acceptance on the final integrated worktree first. CVRP
production launcher switching remains after the warehouse control result.
