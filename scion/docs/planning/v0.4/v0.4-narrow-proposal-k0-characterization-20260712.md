# Scion v0.4 Narrow Proposal Kernel K0 Characterization

*Date: 2026-07-12*
*Scope: synthetic ProposalPipeline seams only*
*Design: `v0.4-narrow-proposal-kernel-design-20260712.md`*

## Boundary of This Evidence

K0 adds tests only. It does not switch launchers, add a runtime mode, change
provider-visible prompts, or add context budgets, truncation, selection, or
omission.

The agentic comparison uses an injected two-step continuation session. Its
zero provider calls are a property of injection, not a measurement of the real
`AgenticProposalSession` planner call graph. Real target-intent, tool-selection,
repair-loop, prompt-manifest, and artifact parity remains open.

## Characterized Matrix

The focused test constructs one small warehouse runtime (`order_level`) and one
small CVRP runtime (`solver_design`). Each has a deterministic legal hypothesis
and patch plus a problem-owned counting quality adapter.

| Observation | Warehouse direct | CVRP direct | Warehouse injected agentic | CVRP injected agentic |
| --- | ---: | ---: | ---: | ---: |
| creative/provider seam call kinds | `hypothesis, code` | `hypothesis, code` | none, injected | none, injected |
| hypothesis main calls | 1 | 1 | 0 | 0 |
| code main calls | 1 | 1 | 0 | 0 |
| target-intent calls | 0 | 0 | 0, bypassed | 0, bypassed |
| tool-selection calls | 0 | 0 | 0, bypassed | 0, bypassed |
| injected session transitions | n/a | n/a | awaiting approval, complete | awaiting approval, complete |
| hypothesis quality hook | 1 | 1 | 1 | 1 |
| patch quality hook | 1 | 1 | 1 | 1 |
| returned hypothesis record and patch | yes | yes | yes | yes |

Direct therefore already has the intended two-main-call control flow at the
`ProposalPipeline` seam. It does not call target-intent or tool selection.
R3.2 also makes the injected continuation run hypothesis quality once before
approval and patch quality once after code; it does not repeat hypothesis
quality during the approved code continuation.

## Anchor and Outer-Boundary Findings

Direct mode passes branch and champion into both problem-runtime context
builders and passes the approved hypothesis into the code builder. The
pipeline object also owns campaign/problem/split/seed configuration. Those
anchors are not committed with the returned direct `HypothesisRecord` or
`PatchProposal`.

Injected agentic requests carry campaign, branch, champion, problem id/spec,
split, and seed anchors in both the hypothesis and approved-code requests.
Their compact session ref records `partial_hypothesis_only`/`completed` and the
termination reason. With an injected session and no artifact store,
`artifact_ref` is empty.

K0 calls `generate_hypothesis`, treats its returned value as approved, and then
calls `generate_code`. It does not run materialization, Verification, Protocol,
feature extraction, or Decision. This proves only that `ProposalPipeline`
returns the existing tainted hypothesis/record/patch shapes; it is not evidence
that the full outer pipeline is already parity-tested between modes.

## Failure-Lane Characterization

A synthetic transient code-provider interruption in both seams produces only:

- `FailureEvent(category="infra", detail=...)`;
- no circuit-breaker failure;
- no patch-quality call.

Direct mode emits no durable attempt/session ref for that failure. In the
injected agentic seam, the stored ref remains the earlier
`partial_hypothesis_only / hypothesis_awaiting_approval` record with an empty
failure category after the code exception. It does not commit the code failure
transition.

Current code therefore has coarse `infra` versus `proposal` routing, not the
designed `infra | proposal_repair | research_iteration` attempt lane with a
named transition reason.

## K1/K2 Gaps Exposed

1. Mode selection is still implicit: `agentic_session is not None` enables the
   agentic path even independently of the boolean. There is no resolved
   `direct_v3 | agentic_ablation` campaign field.
2. Direct `CreativeLayer` can render a `PromptTurnSnapshot`, but
   `ProposalPipeline` does not emit or attach the API-visible prompt manifest,
   inventory/trace ref, or append-only attempt artifact for direct calls.
3. Direct records lack runtime mode, prompt snapshot refs, complete anchors,
   transition reason, failure lane, and tainted artifact refs.
4. Direct transient failures are not durably recorded; injected code
   exceptions can leave a stale hypothesis-only session ref.
5. Actual `AgenticProposalSession` provider call kinds/counts and target/tool
   selection behavior are not established by the injected test and must not be
   inferred from its zero-call result.
6. Full Contract -> Verification -> Protocol -> Decision parity is not covered
   by K0 and remains a production-switch prerequisite.

These gaps support K1 explicit mode plumbing and K2 reuse of existing snapshot,
manifest, trace, and artifact owners. They do not justify copying planner
ledgers into the direct path or changing launcher defaults yet.
