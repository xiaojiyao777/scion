  `DecisionFeatures`.
- Suggested command:
  `pytest scion/scion/tests/test_config.py scion/scion/tests/test_problem_bridge.py scion/scion/tests/test_cvrp_formal_readiness.py`

## Governing Constraints

- Preserve the v3 boundary: LLM output is tainted, and Decision reads only
  deterministic `DecisionFeatures`.
- Keep CVRP/VRP semantics problem-owned. BKS, gap, case hardness, runtime model,
  and measurement readiness may guide proposals and preflight, but must not
  become generic Decision inputs.
- Do not treat "no promotion" as a framework failure without the 2026-06-09
  audit checklist: copied configs, prompt visibility, pair-level metrics,
  Protocol evidence, safe features, and branch state must be reconciled.
- Runtime-improvement promotion remains a valid VRP research mode when quality
  is tied or non-regressive and runtime evidence is complete and materially
  better.

## V0.4 Repair Tracks

### R1 Measurement And Practical Delta

Goal: know what each problem/protocol can detect before spending long rounds.

- Add problem-owned measurement/readiness declarations for effect scale,
  practical deltas, pairing validity, runtime model, and calibration refs.
- Replace the hard-coded `ProtocolConfig.min_practical_delta == 0.001` with
  resolved problem/protocol values.
- Build A/A noise-floor calibration for CVRP and warehouse using champion
  replays, producing MDE and false-pass estimates.
- Surface measurement diagnostics in preflight/status/proposal context, not
  `DecisionFeatures`.

Exit criteria:

- CVRP and warehouse have full calibration reports. The calibration tool exists
  and smoke-passes; formal reports are not complete from the smoke alone.
- CVRP 6/10 screening failures can be explained as below/above measured MDE,
  not only by aggregate win-rate labels.

### R2 Runtime Governance For Budget-Exhausting Solvers

Goal: make anytime ALNS/VNS runtime evidence meaningful.

- Add `runtime_model: comparative | budget_exhausting` semantics.
- In `budget_exhausting`, treat saturation as expected info unless there is a
  timeout/crash or budget violation.
- Disable meaningless `RUNTIME_TIE_FRESH_CHAMPION_REQUIRED` replay paths for
  budget-exhausting tie cases.
- Preserve quality-tie runtime speedup promotion when candidate/champion quality
  is non-regressive and runtime evidence is fresh enough for the declared model.
- Mark saturated runtime-regression-rate style fields as not-applicable when
  they compare millisecond jitter near the time limit.

Exit criteria:

- Focused tests cover both comparative and budget-exhausting runtime semantics,
  including V9 budget-compliance behavior.
- CVRP reruns no longer spend effective rounds on runtime replay that cannot
  add decision evidence.

### R3 Branch Depth And Mechanism Continuity

Goal: Scion should pursue a research direction deeply enough to learn.

- Add branch-depth distribution and mechanism-family x effect summaries to
  campaign status/summary.
- Adjust low-signal lifecycle defaults so marginal/non-regressive evidence can
  drive same-mechanism follow-up rather than immediate churn to shallow sibling
  branches.
- Keep clear regressions and boundary/runtime failures fail-closed.
- Ensure next-hypothesis context shows branch-local failures, mechanism ids,
  and follow-up constraints as concise research guidance.

Exit criteria:

- Post-run analysis can reconstruct branch depth, mechanism continuity, and
  whether follow-up hypotheses used prior evidence.
- A focused campaign demonstrates at least one branch with meaningful depth
  beyond one-off attempts without violating v3 Decision boundaries.

### R4 Context Signal Density

Goal: the agent sees enough research signal without drowning in governance logs.

- Profile hypothesis/code prompts by block category: source, governance,
  tool observations, branch-local history, runtime/screening feedback, and
  cross-branch lessons.
- Compact cross-branch maps and runtime feedback into mechanism-level guidance.
- Keep full artifacts for audit, but avoid rendering duplicate raw logs as
  default model-visible context.
- Do not remove active solver facts, target source, branch state, or feedback
  merely to reduce token count.

Exit criteria:

- Prompt profile reports show improved research-signal ratio.
- Focused prompt tests confirm compact research signals are visible before
  broader rules, safety invariants remain present, and prompt manifests report
  research-signal/governance ratios. End-to-end campaign smoke remains a follow-up.

### R5 Focused VRP/Warehouse Validation

Goal: v0.4 must still show meaningful research on current problem families.

- After R1-R4, run focused CVRP/VRP campaigns that explicitly test:
  quality improvement, quality-tie runtime speedup, and branch-depth research.
- Revisit warehouse under the current framework: verify whether it can produce
  repeated promotions or whether stagnation has a measurement/context cause.
- Audit every run with the 2026-06-09 guide and pair-level metrics.

Exit criteria:

- Either VRP produces valid improvement/runtime evidence, or the report
  quantifies why the current protocol cannot detect it and what variant is
  needed.
- Warehouse has a reproducibility/stagnation analysis, not just a one-run
  promotion anecdote.
