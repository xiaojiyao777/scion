## 1. 决策摘要

`v0.4-w3-h11-c2e-implementation-oracle-design-20260720.md` §7.4 同时把三条
协议检查分配给两个 helper：

- PREFLIGHT 内嵌 TREE/SEAL source projection 已由 direct helper 对 actual retained
  slot 18/17 source reference 唯一证明，又列入 PREFLIGHT axes；
- PREFLIGHT/TREE FIFO exact equality 已由 TREE helper 唯一证明，又列入 PREFLIGHT
  axes；
- PREFLIGHT inventory reference 已在 SEAL `preflight-class` equivalence-class merge
  中证明，又列入 PREFLIGHT axes。

冻结的 PREFLIGHT signature 又没有 TREE/SEAL actual source references，因此它不可能
独立重做前两条 proof。继续按旧 axes 编码只会得到重复 validator、无效参数和由前置
helper 偶然兜底的假 owner test。

TREE fixed-hash implementation review 又暴露两个独立的 oracle 缺口：

- top builder 只比较 indirect↔indirect path/identity，未把九个已验证 direct source
  classes 纳入 alias closure；
- TREE candidate 把 actual observed path/identity/mode/owner 漂移登记为 TREE builder
  negative，实际拒绝 owner 却是 `_prove_h11_indirect_observations`。

这两项同样属于 proof owner，而不是 TREE 局部补丁；本文一并冻结唯一归属。

本文选择最小、单 owner 修正：

```text
actual retained source projection       -> direct
TREE/PREFLIGHT FIFO exact equality       -> TREE
SEAL preflight-manifest class/member     -> SEAL
PREFLIGHT receipt 自身字段与剩余闭包     -> PREFLIGHT
direct-only vs indirect alias            -> top inventory builder
actual observed metadata equality        -> final observation proof
```

不新增 helper、context、adapter 或 source reference；PREFLIGHT helper 删除两个已失去
职责的参数。PREFLIGHT required negative axes 从 11 条改为 9 条，五个 domain helper
registry 总数从 75 改为73；top alias两轴与 final observed四轴单独登记，不冒充某个
domain helper。数字变化是 owner 去重的结果，不以补造检查维持旧计数。

## 3. Exact semantic owner partition

### 3.1 Direct helper

`_prove_h11_direct_authority_bindings` 继续唯一证明：

- 九个 direct source reference 的 exact fields、canonical path/hash/identity/mode 与
  pairwise distinctness；
- PREFLIGHT `tree_receipt` 等于 slot 18 actual base reference 加 literal
  `mode="0444"`；
- PREFLIGHT `seal_receipt` 等于 slot 17 actual base reference 加 literal
  `mode="0444"`；
- INSTALL receipt/manifest 对 slot 16 PREFLIGHT source 的 full base projection。

以下一条从 direct 迁移给 PREFLIGHT，不得保留双重检查：

```text
harness_manifest["preflight_receipt"]
    == {path, sha256} projection of preflight_receipt_source_reference
```

direct 的 `harness-projection` axis 仍存在，因为它还拥有其他 harness direct source、
directory、permit 与 transaction projections；只删除上述 PREFLIGHT manifest member
subcase。

### 3.2 TREE helper

`_build_h11_tree_indirect_specs` 继续唯一证明：

- PREFLIGHT `fifos` 与 TREE exact 8-row inventory 全字段、顺序和值相等；
- 每个 FIFO 与 harness acquisition、RUN ARMED ready/release、两个 retained commit
  references 的闭包。

PREFLIGHT helper 不再读取或比较 `fifos`，也不接收 `validated_fifos`。

### 3.3 SEAL helper

`_build_h11_seal_indirect_specs` 的 `preflight-class` 唯一证明：

- SEAL files role/path/identity 的全局唯一性已经成立；
- 恰好一个 `role="preflight-manifest"` row；
- 该 row 是唯一 `preflight/inventory` equivalence class；
- PREFLIGHT `inventory_manifest` full five-field reference与该 row相等；
- harness `static_inventory` 的 exact `{path, sha256}` projection与该 row相等；
- 该 class只生成一个 indirect observation spec。

PREFLIGHT helper 不再重复选择、计数或比较 `preflight-manifest` row。

`preflight-class` 的 owner-isolated subcases至少包含：

- 唯一 `preflight-manifest` role缺失；
- PREFLIGHT inventory full five-field reference逐字段 single delta；
- harness `static_inventory` path-only与SHA-only delta；
- PREFLIGHT+SEAL coherent decoy replacement，但 harness direct anchor保持原值；
- positive结果中 `preflight/inventory` spec恰好一个。

每个 negative都必须证明 direct、TREE已完成，SEAL是首个拒绝 owner，PREFLIGHT与
INSTALL均未执行。

### 3.4 PREFLIGHT helper

`_prove_h11_preflight_snapshot_bindings` 只证明：

1. 顶层 exact key set为以下十项，按 frozen object canonical order传给
   `_h11_exact_object_fields`：

   ```text
   asset_count, close_unit, fifos, formal_root, inventory_manifest,
   phase, run_unit, schema, seal_receipt, tree_receipt
   ```

2. schema exact为 `PREFLIGHT_RECEIPT_SCHEMA`；
3. phase exact为 `static-preflight-complete`；
4. retained PREFLIGHT source path exact为
   `formal_root / "authority" / "preflight" / "PREFLIGHT.json"`；
5. harness `preflight_receipt` 是 exact ordered `{path, sha256}` projection，且等于
   retained PREFLIGHT source reference；
6. formal root exact等于 builder传入的 `formal_root`；
7. `run_unit`、`close_unit` 都符合 existing systemd unit closed regex，且二者不同；
8. 两个 unit 分别等于 harness `run_unit`、`closer_unit`；
9. `asset_count` 是 canonical uint，且 exact等于 `len(seal_receipt.files) - 1`。

第 9 条以 SEAL helper 已证明“files非空、roles唯一、恰有一个 preflight-manifest”为
前置合同；PREFLIGHT helper只读取 validated frozen tuple 的长度，不重复解释 rows。
它不读取 inventory bytes，不生成 spec，也不调用 TREE/SEAL helper。

## 4. Corrected signature and graph

PREFLIGHT signature改为：

```python
def _prove_h11_preflight_snapshot_bindings(
    *,
    preflight_receipt: H11RootFrozenJsonObject,
    seal_receipt: H11RootFrozenJsonObject,
    harness_manifest: H11RootFrozenJsonObject,
    preflight_receipt_source_reference: H11RootFrozenJsonObject,
    formal_root: Path,
) -> None:
```

删除 `tree_receipt` 与 `validated_fifos` 两个参数。top builder调用顺序保持
`direct -> TREE -> SEAL -> PREFLIGHT -> INSTALL`；internal edge数量与 caller不变。
不得通过 `**context`、aggregate 或 compatibility wrapper保留旧 signature。

### 4.1 Top builder direct-only/indirect alias closure

direct helper已经分别验证九个direct source references与retained directory chain；
其中formal/authority/input/fifo directories会与TREE spec合并，不能再次当作direct-only
class。真正不生成indirect spec的closed set exact为：

```text
九个 direct source classes
harness-root directory
scenario-root directory
receipt-root directory
```

九个source彼此的path/identity唯一性仍只由direct helper拥有，top不得重复。top
builder在拼接`indirect_specs`后必须construction-locally证明：

```text
3 direct-only directory identities × each other
3 direct-only directories × 9 direct sources, path and identity
12 direct-only paths       × every indirect spec path
12 direct-only identities  × every indirect spec (device, inode)
```

三个direct-only directory paths的exact hierarchy已由direct layout唯一证明，top不得
重复directory↔directory path检查；directory identity不由layout证明，仍由top闭合。

实现对source直接使用frozen reference tuple member；对三个directory使用已typed
reference fields；随后与已typed spec比较。source对spec的形状例如：

```python
("path", str(spec.path)) in reference
("device", str(spec.device)) in reference
    and ("inode", str(spec.inode)) in reference
```

不得再次调用 scalar validator、构造第二aggregate或为direct-only class生成spec。
现有 indirect↔indirect path/identity closure继续保留；两层检查各只有一个 owner。

top alias exact cases单独冻结为：

```python
(
    "direct-only-path-alias",
    "direct-only-identity-alias",
)
```

两个axis都至少覆盖source↔indirect、directory↔indirect、directory↔source；identity
另覆盖directory↔directory。indirect subcase令TREE prepare manifest只与
authorization source或harness-root共享目标字段；internal subcase只改一个direct-only
directory reference的identity。direct与对应domain helper必须成功，top builder必须
在五个domain helpers按
`direct, TREE, SEAL, PREFLIGHT, INSTALL`完成后拒绝，observation/final proof不得执行。

这些是pure inventory construction-boundary adversarial cases，不宣称是producer-valid
filesystem fixture：regular source与directory在同一真实时点不能共享kind/path/inode，
但retained authority graph仍必须静态拒绝root时序置换后形成的cross-category semantic
alias。测试从canonical fixture派生，只伪造目标typed expected metadata；修改directory
reference时同步matching `permit_authority.directory_chain` row，修改source projection时
同步其全部direct members，使pure direct helper真实执行并成功。不得添加production
hook或跳过direct；top必须是首个拒绝owner。§5的PREFLIGHT
`manifest-source-binding`仍必须使用完整producer-valid真实source传播链，不适用本段
adversarial exception。

### 4.2 TREE builder 与 final observation proof

TREE的22个domain axis名字保持不变，但所有“篡改 synthesized observed tuple”的
subcase移出TREE test：

```text
directory identity/mode/owner observed drift
FIFO path/identity/mode/owner observed drift
```

TREE `directory-mode` 改用 retained direct-directory reference的mode policy delta；
`directory-owner` 使用 pure `require_root=True` canonical metadata baseline，再只改一个
direct directory owner。sealed/work expected owner仍由positive exact spec assertion
冻结。FIFO四项继续用wire/direct/acquisition/PREFLIGHT projection delta。

actual observation由独立constant登记：

```python
FINAL_PROOF_OBSERVED_AXES = (
    "observed-path",
    "observed-identity",
    "observed-mode",
    "observed-owner",
)
```

每例先用canonical builder生成specs与完全相等的observed tuple并证明positive；再只改
一个row的一个字段，直接调用`_prove_h11_indirect_observations`并失败。调用期间禁止
TREE builder、observer及其他domain helper；tuple长度、顺序与其他字段全部不变。
这四项不计入五domain helper的73轴。

## 5. Corrected semantic matrix

PREFLIGHT exact axes改为：

```python
(
    "exact-key-set",
    "schema",
    "phase",
    "path",
    "unit",
    "manifest-source-binding",
    "formal-root-binding",
    "harness-unit-binding",
    "asset-count",
)
```

隔离规则：

| axis | minimum single delta |
| --- | --- |
| `exact-key-set` | 删除一个非目标字段或增加一个 unknown key |
| `schema` | 只替换 schema literal |
| `phase` | 只替换 phase literal |
| `path` | 创建真实 sibling decoy source并重绑所有 direct upstream members，使 direct通过但固定布局失败 |
| `unit` | 分别令run、close非法；另一个subcase令run/close相同 |
| `manifest-source-binding` | producer-valid harness source链分别制造path-only、SHA-only delta；direct中的原检查必须已删除 |
| `formal-root-binding` | 只修改 PREFLIGHT formal_root为另一 canonical absolute path |
| `harness-unit-binding` | run mismatch、close mismatch；另有coherent closer rebind：修改harness closer/static role，PREFLIGHT保留旧close unit |
| `asset-count` | canonical但错误的数值；另一个 subcase覆盖 noncanonical uint |

每例必须调用 top builder，并记录：前置 owner helpers完成、PREFLIGHT helper被调用、
INSTALL helper未执行。对 `path` 与 `manifest-source-binding`，还必须证明移除目标
PREFLIGHT gate后 delta可以进入后续 domain，避免由残留 direct clause形成假 owner。

`manifest-source-binding` delta必须来自真实重写后的harness source，并重新计算传播
`harness_source_reference`、AUTH/PERMIT_READY harness full projection、更新后的
PERMIT_READY source reference及AUTH对它的引用；最后必须重写实际AUTH source并重算
`authorization_source_reference`。九个decoded documents都必须逐一来自各自真实source
bytes/reference。唯一故意错误仍只是harness
`preflight_receipt`与slot16 source的`{path,sha256}`不等。禁止只修改construction-local
decoded object而制造producer不可能产生的decode/reference分裂。

`DOMAIN_NEGATIVE_AXES` 的 helper顺序不变；registered总数 exact为73。测试不得保留
`tree-projection`、`seal-projection`、`fifo-equality`、`inventory-reference` 四个
PREFLIGHT axis名字，也不得用新名字包装相同重复检查。

## 7. 接受结论

本文把 domain proof从“上游投影重复验证、top alias不闭合、actual drift挂错owner”
收窄为明确的单owner链。PREFLIGHT从重复验证上游已证明投影的聚合器变成一个
problem-owned receipt proof：它只验证自身 shape、source layout、harness unit/source
成员与 asset-count公式；actual source、FIFO与preflight inventory class分别由
direct、TREE、SEAL唯一拥有；top builder闭合direct↔indirect alias，final proof只拥有
actual observed metadata。这样保留 fail-closed边界，同时减少参数、噪声和重复gate。
