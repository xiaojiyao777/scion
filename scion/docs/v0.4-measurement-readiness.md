# Scion v0.4 Measurement Readiness

Phase 3 adds a minimal, problem-owned declaration and status layer for
measurement calibration. The problem spec owns:

- `measurement.runtime_model`
- `measurement.pairing_validity`
- `measurement.effect_scale`
- `measurement.calibration_ref`
- `measurement.calibration_max_age_days`
- optional reduced `measurement.readiness_summary`

`scion.measurement.readiness.measurement_readiness_status()` resolves the
calibration ref relative to the problem root, checks that the A/A artifact is
fresh and compatible with the declared problem id, metric, and unit, and then
reduces the artifact to status fields:

- `status`
- `reason_code`
- `calibration_age_days`
- `mde_at_power_80`
- `noise_band_p90_abs`
- `effect_to_mde_ratio`
- `signal_to_noise_tier`

Missing refs, missing files, stale artifacts, unreadable artifacts, incompatible
artifacts, and incomplete artifacts are explicit readiness statuses. Raw pair
rows, per-case calibration diagnostics beyond the reduced noise band, and
free-form explanations stay in problem-owned diagnostics and do not enter
`DecisionFeatures`.

Generic core consumers may read only the reduced enum/numeric readiness payload
on `ProtocolConfig.measurement_readiness`. Proposal context may also see the
problem-owned `calibration_ref`, but it is marked tainted and
`decision_features_excluded`.
