## Measurement And Runtime

- Phase A/B/C baseline-strength work established that ALNS-only lowers some
  CVRP noise but is materially worse than canonical ALNS+VNS. It is a research
  surface, not a baseline replacement.
- Runtime/measurement repairs clarified practical deltas, budget-exhausting
  runtime interpretation, stage-transition drain behavior, and WSL config/data
  root handling.
- Formal CVRP and warehouse production assets now have tests proving
  problem-owned measurement declarations feed deterministic protocol config
  fields while raw calibration diagnostics remain outside `DecisionFeatures`;
  warehouse specs use relative surrogate paths so WSL checkouts resolve the
  same calibration asset.
- WSL coordination uses git for code and rsync for experiment artifacts. The
  reusable channel pattern is documented in the historical handoff:
  `/home/clawd/research/scion-experiments/v04-cvrp-phaseB-wsl-handoff-20260614T095900Z/WSL_EXECUTION.md`
  and `RSYNC_PATHS.md`.

## Warehouse Frontier

- Warehouse has the current positive v0.4 research-path checkpoint. The
  validation-transfer rerun promoted champion `v2`, and the cost-compression
  telemetry repair keeps split-preserving cost improvements visible as real
  mechanism effects when cost/improving-move evidence is positive.
- This proves a useful warehouse path, not long-run continuous promotion. The
  next warehouse question is whether `v2` enables follow-on improvement.

## CVRP Frontier

- CVRP now shows useful research-loop behavior: target-intent can pivot away
  from stale directions, branch lessons reach prompts, material solver code is
  generated, formal screening completes, mechanism telemetry is preserved, and
  weak/negative hypotheses can be rejected with evidence.
- CVRP has still not met v0.4 effective-research acceptance because no current
  solver-design branch has produced continuous improvement or promotion.
- Rejected/default-avoid directions: broad VNS removal, pure ALNS/no-polish,
  simple initial-VNS disablement, raw cadence-2, recent-best/stall gating,
  fixed early-8, tested share70 cap/rescue variants, unchanged route-merge
  absorption, unchanged `demand_slack_regret_insertion`, unchanged
  `cross_route_2opt_reconnect`, unchanged `cluster_biased_worst_removal`, and
  unchanged `route_limit_seed_diversification`.
- Construction seed/portfolio effects now require a same-run seed baseline or
  same-mechanism accepted delta; fallback activation is only design evidence.
- Active CVRP solver context now exposes the existing size70 two-opt fallback
  as an active fact and readable scheduler slice; future proposals should treat
  it as a known mechanism unless they change its trigger, budget behavior, or
  polish implementation with direct effect evidence.
- CVRP proposal context now has problem-owned measurement/opportunity
  diagnostics for MDE-vs-practical-delta, low-SNR interpretation, aggregate
  screening headroom, default-avoid mechanisms, and measurable opportunity
  classes. This is proposal-only context and does not feed Decision, Protocol,
  lifecycle, scheduler, or promotion.
- CVRP large-instance two-opt postrun briefs now expose
  `cvrp_large_twoopt_summary`, requiring current-run evidence, review inputs,
  and a large/two-opt protocol-effect row signal before calling the bounded
  two-opt follow-up review-ready. Research-continuity family mentions remain
  context only and cannot by themselves prove pair-level two-opt effect
  evidence.
- Prepared launch `research_focus` now bridges into hypothesis prompt compact
  research signals as proposal-only context. Prepared prompt readiness audits
  both the source-side bridge and real launch environment markers, including
  `launch.env` assignment and generated `run.sh` export of
  `PREPARED_RUN_MANIFEST`. Launch readiness now requires
  `prompt_context_readiness_complete=ok`, including artifact identity for the
  current root/manifest, so this audit is enforced by the operator-facing
  readiness tool before launch.

## Continuation And Reporting Repairs

- Copied campaigns now restore enough champion, branch, workspace, hypothesis,
  patch, and branch-evidence state for focused follow-up instead of treating
  resume data as current-run research evidence.
- Postrun analysis now separates current-run protocol evidence, prompt/source
  visibility, branch continuity, measurement effect-vs-MDE, runtime feedback,
  and proposal-quality taxonomy without exposing raw prompts, responses,
  patches, logs, or source bodies as status material.
- These repairs are report/continuation scoped. They do not change Decision,
  `DecisionFeatures`, Protocol, scheduling, gates, budgets, lifecycle policy,
  proposal-context semantics, or problem semantics.
- Prepared launch and postrun readiness now fail closed on stale copied roots,
  missing current-run evidence, wrapper/postrun status failures, missing
  source-visibility proof, and interpretation-specific review gaps. Exact guard
  fields belong in current test/report artifacts, not this milestone index.

## Runtime Semantics Repair

- Budget-exhausting solver runtime semantics are now narrower and less
  misleading for CVRP-style anytime runs. High aggregate
  `runtime_regression_rate` and comparative runtime-ratio slowdown no longer
  block low-SNR trajectory-divergent screening expansion, create lifecycle
  soft-abandon/repeated-signal noise, assign a proposal feedback
  `runtime_regression` tier, veto low-signal `retain_head` workspace
  preservation, or create strong prompt actionability when the problem declares
  `runtime_model=budget_exhausting`.
- This is a deterministic runtime-model interpretation repair, not a generic
  gate tightening, budget change, prompt truncation, or DecisionFeatures change.

## Low-Signal Scheduling Repair

- Low-signal no-effect branches can receive one same-mechanism observation
  sample before a later clean fork, and that selected action is now reported as
  `refine_active` rather than `repair_diagnostic`. Treat true repair diagnostics
  separately from scheduler-selected low-SNR research continuation when reading
  status, lineage, or research-efficiency artifacts.
- Current active no-effect branch-local lessons now become advisory
  `same_branch_refinement` proposal requirements, so same-mechanism follow-up
  must contrast the prior no-effect evidence without converting that lesson
  into Decision input.
- Trajectory-divergent all-tie screening now enters the low-SNR expand/continue
  path when quality and runtime evidence are non-regressive; negative, loss-heavy,
  failed, and runtime-vetoed candidates still fail closed.

## Launcher And Infrastructure State

- Launchers and wrappers now support prepare-only roots, completion preflight,
  secret-safe API-key env routing, runtime-source guards, campaign copy/resume,
  prepared-run manifests, prepared handoff briefs/inventories, strict postrun
  rebuild/readiness, and wrapper status escalation when postrun acceptance fails.
- `check_launch_readiness.py` is the operator-facing authority for prepared
  roots. Active roots are launchable only when static checks pass and real
  completion preflight makes `launch_ready=true`.
- Prepared-only and preflight-failed roots remain non-current research evidence:
  copied resume data belongs under `resume_snapshot`, and current-run analysis
  claims require post-launch protocol evidence.
- Current WSL auth state, active prepared roots, and exact launch commands are
  intentionally tracked only in [`current-state.md`](current-state.md).
