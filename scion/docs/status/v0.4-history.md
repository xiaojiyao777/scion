## Measurement And Runtime

- Phase A/B/C baseline-strength work established that ALNS-only lowers some
  CVRP noise but is materially worse than canonical ALNS+VNS. It is a research
  surface, not a baseline replacement.
- Runtime/measurement repairs clarified practical deltas, budget-exhausting
  runtime interpretation, stage-transition drain behavior, and WSL config/data
  root handling.
- Formal CVRP and warehouse production assets now have tests proving
  problem-owned measurement declarations feed deterministic protocol config
  fields while raw calibration diagnostics remain outside `DecisionFeatures`;
  warehouse specs use relative surrogate paths so WSL checkouts resolve the
  same calibration asset.
- WSL coordination uses git for code and rsync for experiment artifacts. Current
  WSL references:
  `/home/clawd/research/scion-experiments/v04-cvrp-phaseB-wsl-handoff-20260614T095900Z/WSL_EXECUTION.md`
  and `RSYNC_PATHS.md`.

## CVRP Frontier

- CVRP now shows useful research-loop behavior: target-intent can pivot away
  from stale directions, branch lessons reach prompts, material solver code is
  generated, formal screening completes, mechanism telemetry is preserved, and
  weak/negative hypotheses can be rejected with evidence.
- CVRP has still not met v0.4 effective-research acceptance because no current
  solver-design branch has produced continuous improvement or promotion.
- Rejected/default-avoid directions: broad VNS removal, pure ALNS/no-polish,
  simple initial-VNS disablement, raw cadence-2, recent-best/stall gating,
  fixed early-8, tested share70 cap/rescue variants, unchanged route-merge
  absorption, unchanged `demand_slack_regret_insertion`, unchanged
  `cross_route_2opt_reconnect`, unchanged `cluster_biased_worst_removal`, and
  unchanged `route_limit_seed_diversification`.
- Construction seed/portfolio effects now require a same-run seed baseline or
  same-mechanism accepted delta; fallback activation is only design evidence.

## Runtime Semantics Repair

- Budget-exhausting solver runtime semantics are now narrower and less
  misleading for CVRP-style anytime runs. High aggregate
  `runtime_regression_rate` no longer blocks low-SNR trajectory-divergent
  screening expansion, creates lifecycle soft-abandon/repeated-signal noise, or
  creates strong prompt actionability when the problem declares
  `runtime_model=budget_exhausting`.
- This is a deterministic runtime-model interpretation repair, not a generic
  gate tightening, budget change, prompt truncation, or DecisionFeatures change.
- Key report:
  [`../experiments/v0.4/v04-budget-exhausting-runtime-regression-semantics-repair-20260618.md`](../experiments/v0.4/v04-budget-exhausting-runtime-regression-semantics-repair-20260618.md)
