# P3：H/C 公开观察、权限投影与交接

*2026-11-15 · 编码前实施合同；进度与测试结果只在 TASK/current-state*

依赖 [P0](v0.5-p0-interface-and-boundary-contract.md)、[P1](v0.5-p1-public-problem-execution.md)
和 [P2](v0.5-p2-isolated-observation-execution.md)，落实 V3 已采纳的 §4/5/14–16 扩展。
本模块完成 O 的工程接入；不实现 P4 的跨 attempt/campaign 材料延续，不证明研究效果。

## 1. 接口、配置与唯一负责组件

- CampaignManager 接收可选 `public_research` 配置；CLI 使用 `--public-research` 严格
  JSON 文件。省略或 O/M 均关闭时不加载 provider、闭包或新 session，不改变旧 provider
  请求。启用必须已有显式 CodeResearchLimits，且完整提供 P2 ObservationBudget。
- 配置为 `{public_observation_enabled, research_materials_enabled, budget}`；关闭能力
  只需两个 false 开关。P3 的 O-only 边界保持；M 行为由 [P4](v0.5-p4-material-continuity.md)扩展，
  不暗中当成 O。budget 使用
  P2 实际字段：per_action/checker 各为 RunLimits，含固定 scratch_bytes；CPU 为正整数。
  agent limits 只有 wall/cpu/memory/output，scratch 由配置供给，不能提升。
- composition 创建唯一 ObservationService 与 PublicResearchController；后者只负责
  会话可见文件、源码选择、动作和投影。所有 H/C 共用 P2 计数器；session 切换只重置
  局部动作数。配置/能力不支持产生 NOT_EVALUATED 的 typed setup failure，首次 dispatch 前停止。
- `open_session(phase, source_root, initial_source, approved_hypothesis?, handoff?)`
  仅供 host 调用；provider 不传路径、branch、hypothesis 身份或 config。
- H/C session 接受可选 observation session；在既有 deliberate-turn loop 分派新增四个
  动作。没有独立 agent loop、provider retry 或新的调度入口。

## 2. H/C 权限与 draft 绑定

|调用|允许源码|可读材料|禁止|
|---|---|---|---|
|H subject|当前 host 选定的 branch tree；无 branch tree 才用当前 champion|当前 H 自建文件、当前 H 输出、声明公开 fixtures；M 开时另见 P4 历史|draft/base、未允许的历史、正式数据|
|C subject|同一 approved H 绑定的 base；或当前最新 draft|显式冻结 handoff、当前 C 文件/输出、公开 fixtures|current、兄弟/旧 attempt、任意历史|
|analysis|H current 或 C base 的只读副本|显式 input_refs 和 script_ref；脚本须 kind=script|用脚本替换正常 subject；修改 executable head|

H 与 C 通过既有 host 控制流共享同一选定源码根。H finalize 时保存普通 source 条件；
C 开始前检查传入 H 与本次导出值相等，源码选择未漂移；不是身份、receipt 或权限令牌。
H Contract 拒绝则不调用 C。伴随材料通过 ProposalAttempt 传到 Contract 后的 C 调用，
不进入 HypothesisProposal 的科学字段，也不写研究历史/Decision。

draft：使用选定 base 的精确公开闭包创建临时副本，再经现有 materializer 应用完整
PatchProposal；每个观察从 base 开始，不能累积重复 patch。复用现有 action/target/surface
绑定检查和 development_safety_preflight_failure，不调用 provider、不 import candidate。
沿既有 workspace 配置同步函数更新必要配置；不在 generic observation 推导算子语义。
problem provider 用纯 `source_config(available_files, initial=...)` 选择实际运行模式；
初始配置模式在 composition 时固定；其文件后来丢失也不能切换到 defaults。
缺失物化配置不能回退初始 defaults。预检只返回枚举错误，不改变已测试 revision、
ready_patch 或 exact-falsifier 拒绝集合。观察成功不能建立 readiness 或清除 veto。

## 3. 正式文件排除清单

来源是当前加载的 SplitManifest 四个集合、实际 Protocol SplitManager 的
get_cases/get_canary_cases/safe_data_roots、问题声明的 canary_case_path，以及
operator 传入的 protocol/split/seed 配置文件。CLI 将实际文件路径传入；嵌入式调用中
未从文件加载的配置为内存值，没有可挂载文件。不是搜索历史实验目录或按名字猜私有性。

相对 case 路径在问题根、初始输入根、当前 champion/branch/base 根和 safe_data_roots
下展开；同时排除绝对规范路径和现存 inode。每次选 source 时刷新其相对排除路径，
防止复制到新 workspace 后丢失排除条件。准备阶段通过 P2 copier 校验实际文件集合；
composition 在首次 dispatch 前校验初始公开闭包，后续每次观察再次校验实际 source。
symlink/hardlink/非普通文件一律拒绝。缺闭包不自动选择另一棵 source。

仅声明 fixture 和代码依赖可进入执行树；整个 data、formal、metrics、lineage、home
或 framework 控制目录均不通过目录挂载获得访问。排除机制不是内容相似性检测：
它不声称能够识别人手工改名复制、且另行声明为公开的私有内容。问题的公开声明由
维护者审核；不引入 hash/identity 注册层。清单不投影给 provider。

## 4. 材料与安全投影

host 保存普通 append-only 文件及其完整索引。每条索引只有 ref/kind/bytes/phase、
source 条件、可选 supersedes_ref；引用不是 bearer capability。读、搜、执行输入和
handoff 都检查当前允许集合；同名猜测不授予权限。supersedes 不隐藏旧记录。

内部执行目录不直接作为材料目录暴露。公开观察视图从 P0 的允许 host 字段构造：
mode、execution/capture/data/reason、相对 output refs、源码角色/revision 和资源计数。
raw payload/check/stdout/stderr 是单独 tainted 文件，只可按允许 ref 分页读取；不把
其任意字典键合并进 context。主进程路径、record 内部文件表和整个 source snapshot
不自动给 C。检查结果也不变成 Verification 或 ProtocolResult。

配置另存 configuration.json；每个会话保存材料索引及共享 usage 取样，单次后端
记录保留阶段实耗。取样不假称包含该记录写入自身的成本，内存共同计数继续结算。
每次 provider turn 重新构建 detached、不可变的三个顶层字段：public_observation、
research_material_index，以及 C 的 research_handoff；复用递归敏感字段校验，不全局
放宽 context。新增动作结果和正文放在 user 工具数据段，不能混入 system 指令。
索引完整，结果/读取有显式上限；超出已有 context cap 就停止，不能 top-k 或截断。
读输出用 base64 保留精确字节；analysis 输入以 `{ref: {encoding, data}}` 显式传入，
不偷偷把任意输出解释为可信配置。分析脚本通过 wire.read_request 读请求、wire.emit 提交结构化产物或打印文本。

## 5. 导出与交接时序

H finalize（或 K2 select）允许可选 `handoff_refs`，默认空。仅能选当前 H 生成的
材料；公共 fixture 不需交接，既往历史不在选集。每个观察的公开 request 记录标明
input/script refs；若需正文必须显式选中，host 不自动扩大集合。

先完成 H 本身的 schema/research-basis 检查和 ref 检查，再将选中文件复制进临时
handoff 目录，保存普通索引，rename 一次发布，然后返回唯一 H 与伴随集合。任何
复制/索引失败不得返回 H；非法 ref 是开放会话反馈。原件与 handoff 均保留，费用
计入共享存储；被拒绝 H 的材料仍供审计，M 关闭时不会出现在 fresh H；C 仍只见明确交接集合。

ExploreStep 在 H Contract passed 后才传递伴随集合给 C。C 获得文件副本，不可补充
未选材料、改写原 H、重新导出 H 或重绑 base。C 新文件只属于本次 C。退出后的
session 关闭，已有终态不恢复；下一个 attempt 重新建立允许集合，共同额度不重置。

## 6. 失败路由

沿用 P0 表：非法动作/ref/input/过大请求、source 缺失、draft preflight/H binding
拒绝返回枚举反馈；算法/checker/analysis 错误及局部执行超限保留输出后可继续。
PROPOSAL_LOCAL_LIMIT → RESEARCH_REJECTED；GLOBAL_RESEARCH_LIMIT/INITIAL_CONTEXT_LIMIT
→ RESOURCE_EXHAUSTED；隔离/闭包/持久化故障 → BLOCKED_INFRA；未知内部错误 →
NOT_EVALUATED；中断 → INTERRUPTED。仅 pipeline 形成 ExecutionOutcomeRecord。
配置错误在 composition 抛带同一 typed outcome 的 setup error；CLI 以启动失败报告，
不会构造已运行的 step。所有 observation formal count=0。

每个新增动作在解析/权限拒绝前计局部 action；provider 成本仍由既有 turn 计。
源码准备、预检、投影、交接失败的已耗 host 时间/存储也计费；无自动重试。后端
terminal 原因在本次 session 立即向外传播，不因 begin_session 而消失。退出清理
只删临时 draft，不能删负面输出或回滚正式 Decision。
