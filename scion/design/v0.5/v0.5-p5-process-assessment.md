*2026-11-15 · 先设计后实施；P5b 八槽位已处置，本批未满足 E2，独立第二评审待补*

具体冻结参数见[启动记录](../../docs/experiments/v0.5/v05-p5b-process-study-preregistration-20261115.md)，

## 1. 要检验什么

P5a 交付公开诊断题、隔离的评审参考、评审表和离线完整性检查，以及可执行资源配置。
P5b 使用真实 provider，完成下列固定矩阵，检查自主调查、解释修正、条件化材料复用。
P5a 工程通过不能勾选 P5b。不是要求模型每题都修改算法；正确拒绝外推、保存反例或
abstain 可以有信息量。不能只拿一个成功例子关闭矩阵。

诊断题给普通完整 solver 工作区、问题与原始公开数据，不给必改文件、目标机制、
调查步骤或答案。提供的两份解是**待核验的公开样本**，不是两棵真实 solver 的输出
或已执行的计时。agent 自行决定计算参考值、运行当前算法、构造反例或提出 H。
这些微型题主要诊断事实解释和外推边界；开放研究承担算法发现能力的检验。

## 2. 固定任务矩阵与参考答案

数据位于 `scion/experiments/v0.5/p5/`，按问题分别维护 `public/tasks.json` 和
`evaluator/answers.json`。公共题编号不编码答案类别。评审侧另有显式任务清单。

|题目|公开问题/材料|评审参考及允许的结论|不能声称|
|---|---|---|---|
|cvrp-01|3–4–5 三角形，capacity=2、allowed_routes=2；分开访问与合并访问两份解|距离 14→12，均可行且 fleet violation=0；只支持该输入这两份解的改善|证明一种算法普遍更优或完整运行更快|
|cvrp-02|同一实例，正向/反向访问；另给显式等价单位的合成工作量模型|距离均 12；局部计算 100→40，但模型总成本 120→130；无实际计时|局部减少就是净收益，或把计数模型当作实际 solver 时间|
|cvrp-03|同一问题，capacity 改成 1；给出旧容量下的样本|合并解违反容量，分开解距离 14 可行；旧输入上的收益不能搬到当前输入|把不可行的距离 12 当成有效收益|
|warehouse-01|两个同类订单各一板；两辆 T3 与合为一辆|subcategory_splits 1→0，cost 1600→800；按问题字典序改善|仅凭节约 800 外推完整 solver retained superiority|
|warehouse-02|同实例；单辆 T3 中订单顺序互换；另给合成工作量模型|splits=0、cost=800 均相同；局部 60→20，总模型成本 100→110；无实际计时|忽略 packing/grouping 成本，或输出顺序变化说明收益|
|warehouse-03|每订单数量改成两板；旧单车样本及分车样本|T3 容量为 3，单车四板不可行；分车可行；旧结论不可直接复用|仅比较价格而忽略 feasibility 或首要目标|

每题都允许“已有样本不能证明完整算法收益”。01 是局部正例，02 是局部无收益，
03 是条件失效/对当前算法收益证据不足，不能把 03 记录为当前 solver 已被证伪。
参考由独立几何/车辆容量和冻结 checker 双重核对；不是用当前求解器输出生成答案。
02 的各项成本是明确可加的**合成单位**，不由 checker 检验也不称实测 CPU；独立算术
核对总和，用来检查 agent 是否忽略完整范围或把模型外推成性能证据。
答案附带适用范围、关键反例和错误外推，评审不按固定措辞或算法名称匹配。

六题各一个诊断运行，O+M 均开启，原始正式历史为空，选择同一冻结版本的问题默认
完整源码。顺序固定为 cvrp-01、warehouse-01、cvrp-02、warehouse-02、cvrp-03、warehouse-03。
03 在相应 01 结束后启动 fresh campaign，显式导入 01 **实际产生的**公开材料；
只导材料，初始源码仍是本次声明的默认树，不导入 01 的候选或状态。导入全集，
不挑选“好笔记”。01 没写材料则记录 M 机会缺失，不能由评估者补写正确笔记。
每个 fresh H 仍可能看到本 campaign 已关闭 attempt 的材料；评审记录实际读取发生
在何处。一次 campaign 的多次调用不能计作多次独立诊断重复。

另有两个开放研究运行：open-cvrp、open-warehouse，依次执行，无诊断答案/材料导入。
总计八个预定运行，不能为了凑齐 O/M 成功轨迹追加。诊断题是固定便利样本，
不估计总体成功率；新设计需另立下一批，不能改写本批。

## 3. 公开导出与评审接口

离线工具 `scion/tools/p5_assessment.py`，不被 Campaign/Proposal/Decision import。

- `export TASK OUTPUT`：从显式题库选出一题，输出已有 `research_input` 格式
  `{current_question, observations}`，拒绝覆盖文件；不把整个实验目录交给 agent。
  六题示例完整序列化进 current_question，observations 保持空数组；后者是已有
  problem-owned 历史投影接口，不接收任意诊断 schema。两个 open 题只导出问题。
- `template OUTPUT`：生成八个槽位的离线评审表，默认全部 `not_run`，未知成本为 null。
- `review SHEET --evidence-root ROOT`：核对清单全覆盖、唯一行、引用及双评审结构，
  输出所有槽位、分歧及缺失；**不输出自动 E2_PASS，也不写 runtime**。

每行记录 `run_id/status/terminal_ref/interventions/costs/reviews`。
status 是离线报告分类：`not_run/completed/resource_stop/provider_failure/infra_failure/interrupted/boundary_failure`，
不是新的 runtime 状态。具体 typed outcome 仍以 terminal artifact 为准；人工核对两者。
无候选单列在终态/评审说明，不伪造 solver score。所有已启动行需终态证据及已知成本；
缺失必须显式列在 `missing_costs`，null 不是零。边界泄漏影响本批哪些证据由审计说明。

成本字段：physical_calls、input_tokens、output_tokens、reasoning_tokens、cache_tokens、
research_cpu_seconds、research_wall_seconds、test_wall_seconds、formal_wall_seconds、
total_wall_seconds、storage_bytes；硬件/线程及 provider 原始 usage 字段在运行记录中保存。
provider 不报告某 token 细项则 null+原因，不能从其他字段猜值或双重相加。

评审引用是 `{path,start,end,quote}`：相对 evidence-root 的普通文件、UTF-8 字节范围
及准确原文。工具只读 operator 明确指定的证据根中的引用，不执行脚本、不跟随
symlink；operator 评审可见原始 trace，此根绝不能当作 provider 材料根导入。
引用给出 terminal、工具请求/响应和材料文件的原始位置；不能用另一份人工总结
代替原轨迹。若 trace 缺失，允许报告观察事实，但不能补造外显预测或实际 read。
工具只证明“引用存在”，不认证作者、时序或语义；这些由两名评审独立核对。
不引入签名、identity、receipt 或闭包证明。评审材料本身不向 agent 导入。

## 4. 评审 rubric、分歧与 E2 判定

五维分别评 `supported/contradicted/insufficient/not_applicable`，必须附理由；除
insufficient/not_applicable 外必须引原始证据。无加权总分、无关键词自动判分。

|维度|supported 所需证据|contradicted 或 insufficient 示例|
|---|---|---|
|investigation|调查前外显的可区分解释/预测，实际自主请求与对应输入|只调用工具；事后把结果写成预测；人工指定每一步|
|interpretation|核对实际 source/config/input、seed、完成状态、原始数值及参考适用范围|把 timeout 当零收益；只引用脚本 PASS；把样本解称实际 solver 输出|
|revision|先前解释→观察→修正解释→下一行动的可核对顺序；变化确由结果支持|同一说法反复写；弱化原命题后声称原命题成立；只有正确最终答案|
|conclusion|参考范围内正确且有信息量的判断，明确未知项；可为负面或不确定|强行正收益；越过可行性/字典序；完整 solver 外推|
|continuity|实际跨 attempt/跨 fresh campaign read，核对旧/新 source/input，之后行动据此改变|索引里有文件但没有读；未核对条件；重复旧断言|

continuity 仅在 03 和开放任务适用；没有材料或没有读取记 insufficient，不能 N/A。
revision 没有发生记 insufficient，不因为最终正确就补齐；不要求每题都发生修正。
人工给下一步建议、修正解释或补代码是 scientific intervention：该运行仍报告，
不能作为自主 O/M 见证。纯运维中止/故障注明，不自动把已有全部研究事实作废。

两名评审独立填写，评审者先看到去除 provider/模型/臂标签的任务和证据副本，
再核对原始映射；工具调用本身可能暴露能力，记录无法完全盲评的限制。
分歧保留双方评分及原始引用；第三人可给另附裁决说明，不覆盖初评，也不取平均。
只有双方同意且原始依据充分的见证可进入本阶段 E2 能力判断；争议未解决记不足。

E2 通过条件：八个预定槽位有完整处置报告；两问题的诊断参考核验正确；至少一条
自主 O 轨迹支持前四维（含真实解释修正），至少一条 M 轨迹支持条件化跨 attempt 复用；
两个开放运行完成其预定有界研究并保留真实 H/C 或无候选事实、成本、干预记录，
两问题原边界无未处理故障。开放运行须展示自主调查及有信息量的范围结论；只有
脚本化 H/C 或调用成功不够。资源耗尽但预定研究未完成记 incomplete，而非有效负结果。
若闭环未出现，就报告 E2 未满足/不足，不追加预算直到成功。不要求诊断六题全部
revision supported，也不因有效负结果阻止阶段判断。E3/E4 仍单独开放。

## 5. 具体资源、停止与计数

这里给出**首批可行性研究的上限**，依据是约束最多八个短研究运行和已有接口，
不是统计功效计算或算法有效阈值。机器可读配置在 `config/`，两类分别为 diagnostic/open。

|额度（每运行，非每 attempt）|diagnostic|open|
|---|---:|---:|
|physical provider calls（含 redispatch）|48|192|
|outer hardwall 秒（含 formal）|1800|7200|
|formal round 目标 / per-solve 秒|1 / 1|3 / 5|
|subject / analysis / checker 次数上限|24 / 24 / 24|96 / 96 / 96|
|公开研究累计 wall / CPU 秒|300 / 180|1800 / 1200|
|公开材料存储|512 MiB|2 GiB|
|每份完整 source / 文件数|64 MiB / 4000|64 MiB / 4000|

每次 subject/analysis：wall 15s、CPU 10s、AS 512MiB、输出 1MiB、scratch 16MiB；
checker：wall 3s、CPU 2s、AS 256MiB、输出 64KiB、scratch 1MiB；准备 wall 2s。
输入 256KiB、JSON depth 30/items 20000；每 session 128 个材料/观察动作，
分页读 64KiB、search 最多 100 matches/1MiB 扫描。具体字段在配置中全部给定。
H/C 每 session 最多 24 个 deliberate turns；read/search 各 16 次；test_patch 最多
2 次、每次 suite 30s/总 60s；transcript cap absent，其他显式字段由配置完整展开。
这不要求使用满额度；满局部额度走现有 RESEARCH_REJECTED、新 H 仍受共享 cap。

Provider SDK retries=0，Scion transient redispatch=0，避免首批受重试机制混淆。
不新增 token 总量 gate；按物理调用和 hardwall 限额，记录实际 token。模型所需
max output tokens、context ceiling、价格及账户 spend cap 在启动记录中冻结；缺失时
不能声称已有精确货币预算。六个诊断+两个开放共至多 672 次 dispatch、7 小时
outer wall、3480 秒公开 CPU、7 GiB 研究材料；不能把未用额度转给另一槽位。

test_patch 和正式评估的成本独立报告；其科学限制继续来自实际 problem/protocol，
不是免费额外研究资源。正式评估被 outer hardwall 截断时保留 partial，不能为达到
round 目标追加时间。P5 外部独立确认次数 **0**，不宣称 E4；未来 P7 另冻结确认预算。

停止取最先发生者：formal 目标完成、outer hardwall、共享 provider/研究资源耗尽、
auth/quota、infra/isolation/persistence 故障、用户中止、边界违规。action 错误可由
agent 在剩余预算内调查，不自动重试；任何“看起来有希望/没希望”不触发追加或早停。
未启动的后续槽位保持 not_run 及原因。隔离泄漏立刻停止本批，界定污染范围后再另立批次。

## 6. 开放研究与跨问题控制

open-cvrp：默认完整 CVRP baseline，公开问题是“在当前公开环境与计算预算下，
当前完整求解算法的主要限制是什么，哪些改动值得正式检验？”
open-warehouse：同样的问题，换成 Warehouse 完整默认算法和其公开环境。
这不是 R26 续跑，不绑定 cache/successor/target，不导入诊断参考或历史私有结果。
默认 source 的实际完整副本、registry/config 和框架 dirty diff 随启动归档；不能把
当前默认树冒称 R22 C3 或 unchanged B0。后续正式 history 保持原有边界。

两运行都走普通 CLI、O+M、三个 active branch 默认值、parameter_search=false；
不是一个研究运行加一个只 import 成功的 smoke。跨问题核对实际输入/配置绑定、
H/C 权限、材料继承、失败路由、formal counting 和原科学链。不同 objective 的解释
由各自题库/评审承担，core 不出现 fleet、cost 或题目答案分支。
若没有提交候选，明确列出未覆盖的 Contract/Verification/Protocol 路径，不能把
没有执行的边界勾成真实运行通过；已有工程测试只支持相应 E1。

启动前另存具体 run record：代码版本+diff、完整 source/公开材料位置、实际
problem/protocol/split/seeds 路径与内容副本、formal 与公开数据排除核对、provider/
model/reasoning/sampling/output/context、Python/依赖/硬件/线程、顺序/配置、fresh
输出根和实际 CLI 参数。先用当前 CLI parse；不写新的 launcher 或 readiness authority。
本设计成稿时，工作树仍在修改，provider/model、正式数据根、精确 run record 尚未
冻结，因此本文件是具体设计和开发配置，**不是 preregistration**。后续用户明确
授权 P5b 后，另立上方链接的实际冻结记录；工程验证和真实研究的证据仍分别报告。

## 7. V3 对齐、失败路由与验收用例

V3 §1/§5：不给步骤/目标算法，仍最多一个 H/绑定 C；§4：评分不进 Safe Features；
§8/§10：参考仅用于诊断，不能改 frozen oracle 或替代 Protocol；§11/§15：实际材料
读取不恢复状态、不成为必用历史 gate；§12/§13：停止沿用现有 typed 资源/故障路径；
§14：原文件引用不产生身份；§21：不以正收益循环加预算。P5 不增加生产数据权限，
只在 V3 采纳段补充离线评审的解释和入口，不新增 runtime 权威扩展。

|用例|预期与验证层|
|---|---|
|D01|六题参考值由独立手算和两个问题的真实隔离 checker 核验，负例不可行；E1|
|D02|export 仅生成允许的 research_input，未知题/重复写拒绝；评审答案不在 public closure；E1|
|D03|配置能被现有解析器读取，全部上限显式，O/M 开启且 transcript cap absent；E1|
|D04|review 保留八个槽位，缺行、重复、额外题拒绝；未运行/无候选/故障不丢弃；E1|
|D05|篡改引用、越界字节、缺文件、symlink、负值/NaN 成本拒绝；unknown 保留原因；E1|
|D06|双评审 supported/contradicted 分歧保留，未评审不是通过；不自动生成 E2 或 solver 分数；E1|
|D07|引用正确不等于解释正确；人工复核正/负/不足样例及先预测后观察的顺序；真实评审待 P5b|
|D08|两题真实 runner/checker 可执行；完整 solver、source_config、资源记录对得上；E1|
|D09|01→03 实际导入/读旧材料、条件失效后解释和行动变化；真实 provider，待 P5b|
|D10|开放研究两问题全部轨迹、成本、停止及干预报告；真实 provider，待 P5b|
|D11|工具不接入生产 imports/Decision/Protocol；题库不进入正式 split；E1 + 启动人工核对|
|D12|完整矩阵判读 O/M 存在或未满足，不因局部 PASS 宣称可靠性或 CVRP retained；报告审核|

实施顺序：先题库与参考隔离/导出，验证 D01–03；再离线评审和缺失处理，验证 D04–06；
最后真实隔离输入回放 D08，核对 D11。D07/D09/D10/D12 的真实材料不能由脚本测试替代。
