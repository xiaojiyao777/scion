# v0.5 验收与机制对照设计

*2026-11-15 · 分层验收合同；模块测试结果见 TASK，尚无新研究效果实验*

配合[机制设计](v0.5-continuous-algorithm-research-design.md)阅读。
v0.4 已获用户认可按阶段规则收官，原科学成功验收部分达成；本文件定义 v0.5
怎样交付、怎样检验、怎样有限收官，不能把设计完成写成实现完成或科学成功。
当前运行边界仍以 [V3](../scion-architecture-v3.md) 及
[direct-runtime addendum](../scion-architecture-v3-v0.4-direct-runtime-addendum.md) 为准。

## 1. 四层验收分别给结论

|层次|要回答的问题|支持通过的证据|不能据此声称|
|---|---|---|---|
|E1 边界工程|能力实现是否正确、隔离且职责清楚？|预定行为矩阵通过，资源与异常路径有证据；共享变更完成适当回归和独立问题包控制|agent 会有效研究或 solver 有收益|
|E2 研究过程能力|agent 能否自主调查、依据结果修正解释并延续研究？|真实 provider 轨迹中存在可核验的自主调查、有效观察、解释修正与下一行动；材料功能另有跨 attempt 条件核对及复用证据|该行为可靠、优于 v0.4 或产生独立算法收益|
|E3 机制效果|公开观察、材料延续是否在可比资源下改善研究？|预注册重复对照分别估计 B−A、C−B；全部分配重复、成本与不确定性公开，主效果满足预定实际意义与区间要求|具体 solver 已独立保留收益或对未测问题族普遍有效|
|E4 独立算法收益|完整 solver 是否稳定优于指定基线？|通过原有科学链；事先提名的实际完整候选在未暴露独立确认中满足既定 Protocol 标准|观察/记忆是因果原因，或其他基线上的目标也已完成|

每层分别记录通过、未通过或证据不足。E2 的一条完整轨迹只能说明能力存在；
可靠性、达成率和资源代价须由 E3 的重复检验支持。E3 可能支持研究诊断改善而
E4 没有收益；E4 可能有正结果而 E3 不能说明是新机制带来的。两种情况都如实记录。

E2/E3 的过程评估是框架研发评价，不成为生产 H/C 的评分器或额外 Contract gate。
不能要求每个有效 H 都必须带实验、否定过假说或引用若干条历史。

## 2. E1：边界行为矩阵

可执行用例进一步映射到 [P0 的 C01–C12](v0.5-p0-interface-and-boundary-contract.md)和
[P1 的 P1-01–14](v0.5-p1-public-problem-execution.md)。P1a 的纯数据检查与
P1b/P2 的真实隔离执行分别验收，不能用前者代替后者。
执行部分进一步由 [P2 的 S01–S12](v0.5-p2-isolated-observation-execution.md)覆盖；
H/C 权限、handoff、exact-falsifier 和真实 context 路径对应
[P3 的 T01–T12](v0.5-p3-session-permissions-and-handoff.md)。脚本化 provider 的外层
测试属于工程证据；材料延续和 fresh import 对应 [P4 的 M01–M12](v0.5-p4-material-continuity.md)。
E2 仍需真实 agent 轨迹。

这些测试应针对行为及失效风险，不只照抄字段实现。修改公共边界时，先做相关
focused checks，再执行适当 full regression；跨问题控制至少覆盖一个独立问题包，
确认 core 没有依赖 CVRP/Warehouse 特有语义。

|行为|必须观察到的结果|
|---|---|
|H 请求任意 source/path/patch/entrypoint|拒绝越权；subject 仍绑定选定初始 baseline/当前 verified head，记录区别，不能暗中换算法|
|分析脚本 monkeypatch、伪造输出、打印 promote 指令|不能影响 subject interpreter 或 host envelope；只产生 tainted 分析文件|
|C 在无 approved H/无 draft 时请求 draft，或改动越界|对应执行不能开始，保留原 H/C 状态，返回有限原因|
|C 修改合法 editable 文件，但不符合 approved-H action/target/surface|纯结构绑定检查拒绝执行；安全 preflight 不被误当成 H 绑定检查|
|C 读取自己的新观察/脚本或另一 attempt 的材料|前者在当前会话允许，可继续分析/生成公开输入；后者未经交接不可读|
|C revise 后读旧观察并运行新观察|旧记录保留原 source/revision；新观察绑定新精确值，不迁移旧检查结果|
|failed falsifier → 正观察 → ready|同一 executable value 仍受原 veto；观察不写 last_test/ready 状态|
|负/零观察、AssertionError、timeout|分别记录数据、执行错误、资源结果；不自动成为 scientific rejection 或 formal round|
|C 请求未交接材料、整个 history/research 根|拒绝且无内容或私有路径泄露；只读 H 冻结的集合|
|私有数据、formal 目录、路径穿越、symlink、特殊文件|mount/read/write/回收各边界均不能逃逸；host 异常不暴露 traceback|
|child 输出伪造 host 状态文件；合法执行记录带宿主路径|child 不能写最终记录区；provider 只能见允许相对引用，不能经合法记录打开宿主路径|
|输出恰好到上限、超一字节、无效编码/数据|完整性和错误状态准确；保留已捕获原字节，不删值后宣称成功|
|大输出分页、长文本、重复或负面材料|允许原件可无损恢复；无按结果筛选、top-k 或摘要替换|
|子进程异常、超时、输出爆发、中断|进程组清理，实际调用/资源计数，部分记录保留；无静默 retry|
|source/公开依赖缺失、保存失败|typed unavailable/incomplete，不回退宿主目录/champion，不重建旧 patch 冒充原树|
|O-only 运行后关闭 attempt|实际 source/input/script 与原始输出仍供审计追溯；未开 M 仅影响后续 agent 暴露|
|更正解释、重跑修正脚本|原脚本、结果和解释保留；新版本不覆盖旧证据|
|导入同名文件、旧 local ref、失败 draft|导入集合区分来源，缺依赖明确；失败 draft 不能成为 executable base|
|终态后导入普通材料到 fresh campaign|所有执行状态从新开始；不恢复 ready、provider 会话、队列、预算或 stage|
|材料声称已晋升、已解决问题或改变算法|branch/champion、Safe Features、Protocol、Decision 均不受其控制|
|存储耗尽或材料保存发生在 Decision 之后失败|停止相关材料动作并说明缺失；不改写已经完成的科学裁决|
|合法公开实验、H→C 交接及 O/M 关闭路径|能力开启时数据可实际取得并使用；关闭时保留旧路径，不新增数据/预算依赖|
|源码改变、sibling 材料与 stale reconcile|旧观察仍绑定原条件；不自动合并、不换 base，源码缺失明确 unavailable|

E1 失败先限定受影响范围。隔离错误可能使相关实证不可用；普通工具不可用不能
被计成算法无收益。不能让测试脚本打印的一条 PASS 代替对实际状态/文件/权限的断言。

## 3. E2：怎样判断 agent 实际在研究

本层的具体任务、参考答案、逐维 rubric、首批资源和停止规则见
[P5 合同](v0.5-p5-process-assessment.md)。六项诊断加两个完整 solver 开放运行是
有界能力研究，不能作为 P6 的功效样本量或 E3 对照。离线引用检查不自动判定 E2。
P5b 已完成矩阵处置但未满足 E2，独立第二评审仍待完成。
[P5c](v0.5-p5c-question-session-and-materials.md) 因此先设计实验回读与持续问题会话；
A/B 已接入测试材料回读、实际测试源码保留和材料延续；C 在 V3 显式采纳后接入
持续问题上下文与 investigation 主动结束。Q01–Q15 的工程验证和保留失败见
TASK/current-state。这些检查不能替代真实自主使用证据。新的前瞻研究必须重新
声明当前会话/停止干预和 A/B/C 差异；旧 P5b 不补跑、不追溯改臂标签。

任务只给持续算法问题、初始完整 source 和公开环境，不给目标机制、指定必改文件
或必做实验序列。使用真实 provider 的工具请求与实际材料作为证据；人工逐步带做
或 host 代选机制的轨迹不计自主研究能力。

|能力|核验依据|反例或证据不足|
|---|---|---|
|选择能区分解释的调查|调查前可见材料、agent 的可核验预测、实际请求；必要时用问题包参考计算验证|只调用工具，或实验结果不可能区分它声称的解释|
|理解实际观察|实际 source/input/script、退出/完整性、原始数值和独立参考核对|脚本自报成功、错误 comparator、未完成却当作完整测量|
|修正解释与行动|观察前后结论和下一行动的变化；允许否定、收窄或保留不确定性|忽略反例，换成弱命题却仍声称原假说被证实|
|产出有信息量的结论|可核验的适用范围、反例、无净收益原因或候选判断|只有长报告、pass 数量、工具次数或不可复查的自评|
|跨 attempt 继续问题|实际读取旧材料，核对 source/input 条件，新行动据此变化|只保存未读，误把 sibling 结果套到当前算法，重复过时断言|

至少分别取得 O（观察）与 M（材料延续）的真实能力轨迹；“自主修正”须有由实际
结果促成的解释变化，“复用”须跨 attempt 而非同一上下文中的复述。它们可以出现在
不同轨迹，不能为了拼出一条故事隐去失败尝试。所有预定能力运行均归档并列明外部干预。
可用有独立答案的小型诊断任务核验路径覆盖、局部节省与总成本、参考范围等，
覆盖有收益、无收益和证据不足三类，避免奖励“一定做出改进”。

这些是研究能力诊断任务，不是开放 CVRP 发现的替身。评估人员掌握的参考答案
不得混入 agent 的公开输入，亦不与正式 solver held-out 人口混用。结论由可核验
事实与预定 rubric 支持；评审可盲于臂标签的部分应盲评，并记录判断分歧。
E2 不要求模型表演固定思考格式，只核对已经外显的预测、工具、结果和行动。
能力交付还需一项预定预算的真实完整 solver 开放研究试验，报告全部结果及外部
干预，并对另一问题包做边界控制；小型诊断任务不能代替这项证据。开放研究不要求
必有正收益，也不能由一条轨迹推出可靠性。任务数量、预算和停止规则先于运行固定。

## 4. E3：分开估计观察与材料延续

|条件|A：v0.4 能力基线|B：公开观察|C：公开观察＋材料延续|
|---|---|---|---|
|完整算法 source、现有安全正式历史、screening 回流|相同|相同|相同|
|H 新实证观察|无|有|有|
|C 在 approved H 内观察 base/draft|保留现有 test_patch|新增观察，保留 test_patch|与 B 相同|
|当前 attempt 的新增研究文件、H→C 安全交接|现有能力|有|与 B 相同|
|新增脚本、公开结果、解释/问题跨 attempt 可读|无新增能力|审计保存，不向后续 attempt 新增暴露|有|
|模型、起始材料、科学 gates、预算和 branch 策略|共同冻结|共同冻结|共同冻结|

主 contrast 是 **B−A：O 整组能力（观察＋本次材料＋H→C 交接）的效果**，以及 **C−B：专门研究材料延续的
附加效果**。B 保留既有 H/正式历史，不能人为删掉历史来放大 C 的价值。B 的新
观察仍保存用于审计；关闭的是后续 attempt 的新材料访问，不是抹除已发生的工作。
H 正文自然携带认识属于所有臂已有机制，因此 C−B 不是“有无一切记忆”。
B−A 不能单独归因于 `observe` 工具；需要这种声明时另设消融。

可以先完成 O 的 A/B 检验，再加入 M 的 B/C 检验；后一阶段须有同期 B 对照，
不能用不同模型/预算/时期的旧 B 当唯一对照。若同轮 A/B/C，则统一随机化与分析。

source/context 表示、轻索引、无损按需正文如有优化，应对所有臂共同应用，准确称
A 为“v0.4 能力基线”，不声称是完全相同的旧二进制；或者单独消融。不能同时换
模型、增加分支/多 agent/预算，再把总变化归给 observation 或 persistence。

### 4.1 指标与统计单位

主过程指标建议是**在预定资源内得到独立核验的有效研究结论的任务比例**。
启动前须固定“有效”的 rubric、每个任务的可核验标准、处理不确定结论的方法、
最小有意义差异与区间要求。错误解释率、跨 attempt 条件核对/复用、外部干预、
重复计算和成本作为预定次指标；不能事后挑一个显著指标宣布机制全面胜利。
成本与收益多目标并列报告，除非启动前声明权重/价格，不把它们捏成任意总分。

框架比较的独立单位是**研究任务/campaign 重复**，按任务和初始 source 区组分配。
不同重复拥有独立研究上下文，C 材料不能跨独立重复串用。同一 campaign 的候选、
162 次 provider 调用、324 行 pairs 或多次 expansion 都不能当作独立框架重复。
算法 Protocol 仍按声明的 case/seed 聚合；层次分析保留相关结构，不混淆统计单位。

两个主 contrast 与多个主指标需预先声明层级或 multiplicity 方法。重复数、精度/
功效与最小实际差异不能凭一条成功轨迹确定；公开 pilot 用于估计变异和耗时，
其选择过程与数据另行披露，不复用为未暴露确认集。
正式运行前用已知正/负/缺失的构造数据验证分析脚本和 rubric 应用，记录评审分歧
处理规则；不能看过正式结果后再决定什么叫“有信息量”。

### 4.2 资源与缺失

共同预算是相同允许额度，不是要求实际消耗相同。至少记录 physical calls、
provider-reported input/output/reasoning tokens（含可取得的 cache 使用）、公开
subject/analysis/test 的 CPU 与 wall、正式评价及独立确认成本、总 wall、存储和
人工干预。观察计算计入共同研究额度；正式评价与独立确认的预留预算单列，
不得因某臂更会探索就免费追加，也不能事后把未用预算转给表现较好的臂。

冻结硬件、线程、per-solve 限制与时钟策略，平衡或随机化运行顺序，隔离并发竞争。
框架 campaign 分臂与 solver 公平计时分别设计；同 seed 不能消除计时顺序影响。

主报告包含所有预先分配的重复，分别列出无候选、abandonment、provider failure、
resource stop、基础设施失败和边界违规。无候选可按 preregistration 在“成功产出率”
中计未成功，但不能伪造一个负 solver score。只在产出候选者中分析质量须标为
条件分析并说明选择偏差。失效 run 不能悄悄删除后再补到满意样本数。

重复实验不天然是坏事：核验噪声、source/input 改变、独立复测均可能必要。
“无目的重复”的评分需看条件与研究理由，不能以相同文件名或重复次数作 gate。

## 5. E4：候选选择与独立确认

机制评估建议每个 campaign 在确认结果不可见时提名**一棵实际保存的完整 verified
source**，使用一次事先规定的独立确认。启动前选定采用正式 champion 还是 agent
提名的已有 verified tree；不能看过确认后在两者中择优。提名只用于评测，不修改
branch/champion/promotion；该对照不是新 production 候选门槛。

内部 Protocol validation/frozen 额度与外部独立确认额度分别声明。若允许多候选、
多次 held-out look、扩样或顺序设计，必须事先写总次数、触发规则和错误率处理。
不能写“需要时再确认”。确认结果在机制研究结束前不回流 agent；向开发者披露
并据此改设计的数据也不再称为未暴露确认集。

独立确认使用明确人口、case/seed grids、完整 pairs、相同预算、冻结的可行性/
objective 规则和原有统计方法。不得删损失/失败 case、合并扩样重跑格、把
champion-first 的累计对照解释为单补丁因果效应，或用新 seeds 冒充 unseen cases。

### 5.1 CVRP 跨版本继续保留的科学目标

**未完成目标：Scion 自主产出的完整 CVRP solver，在声明人口与计算预算下，经
完整科学链及独立确认，取得对明确原始基线的 retained superiority。**
v0.4 stage closeout 不勾选此项；Warehouse 已接受的独立收益继续保留。

|对照|可以支持的声明|不能代替|
|---|---|---|
|新候选 vs 完整 R22 C3|对当前研发起点的增量完整 solver 优势|对原始 B0/B0-fixed 的独立收益|
|新候选 vs B0-fixed|相对含 constructor 工程修复基线的收益，修复贡献单列|unchanged original B0 的历史目标|
|新候选 vs unchanged original B0|声明人口/预算上的原始基线独立保留收益|新框架机制的因果优越性|

原始 B0 若无法提供完整有效 comparator evidence，就记录 incomplete/unconfirmed，
不能删除无效 case 或将 B0-fixed 改名为 B0。项目可以前瞻地另定 B0-fixed 主研究
目标，但必须同时保留旧目标未完成的事实；本次没有自动替换它。
R3i development promotion、R4 未确认、R20 validation uncertain、R24–R26 的
本地 C3 结果，见[当前状态](../../docs/status/current-state.md)及其精确 postrun 引用。

## 6. 启动前必须冻结的参数

本次是详细机制与验收设计，尚不是可直接执行的 preregistration。不能无依据填一个
重复数或观察时长；也不能带着空项启动正式机制实验。公开 pilot 与预算核算后，
正式 preregistration 必须逐项给定：

1. 实际代码状态、A/B/C 工具开关、上下文投影、H→C 和跨 attempt 暴露差异。
2. 完整初始 source、parent/comparator 保存规则和全部初始公开材料。
3. 任务人口与抽样/生成方式、区组、独立重复数、随机分配与执行顺序。
4. 模型、provider、reasoning/sampling、transport 和 redispatch 配置。
5. provider/token、subject/analysis/test、wall/CPU/内存/输出/存储额度；正式与确认预留及 stop 行为。
6. 主/次 estimands、rubric、实际意义阈值、统计单位、聚合、区间、精度/功效和 multiplicity 方法。
7. 无候选、故障、缺失、invalid pair、timeout、异常值、重复格与外部干预处理。
8. 候选提名规则/数量、全部 held-out looks、扩样规则和结果回流边界。
9. 每个 solver contrast 的精确 comparator、case/seed grids、执行次序、per-solve 限制与科学 gates。
10. 哪些结果支持/不支持/保留哪些声明，何时停止，以及结果允许支持的后续决策。

不以“多跑几次看看”代替采样计划。未预注册顺序分析时，不因中途显著、正信号或
失望提前结束/追加。合法停止包括计划完成、显式资源边界、真实基础设施/auth/quota
故障、用户中止或预声明的边界违规停止。

## 7. v0.5 何时完成，如何避免再次无期限延长

模块到验收的对应关系见 [P0–P7 计划](v0.5-v3-alignment-and-module-plan.md)。
列出验收标准不等于标准已满足；各模块需先满足设计退出条件，再实施并提交行为证据。

设计完成、能力实现、机制优越性、算法收益各自有状态。建议阶段里程碑是：

- **设计交付**：机制与验收可评审、权威差异及待冻结参数明确；按模块先设计后实施，具体已验收范围只在 TASK/current-state 记录。
- **能力交付**：O/M 实现完成，E1 通过，E2 有真实可核验轨迹，原边界仍成立。
- **阶段收官**：完成预先约定的 E3 比较及 E4 评估/未产出说明，给出全部结果、成本、限制与下一判断；不要求它们都为正。
- **效果成功声明**：只有满足 E3 的预定要求才声称对应机制优于基线；只有满足 E4 才勾选该 solver/基线的 retained 目标。

若工程边界失败，先修复并界定受影响证据，不能直接科学收官。若计划因资源或
基础设施未完成，记为 incomplete，不能冒充有效负结果。有效完成但未达主效果
门槛记为不支持；区间仍兼容重要正负效应记为证据不足，不能把“不显著”当成等效。
这些是研究报告结论，不要求实现新的 runtime 状态机。

一次按预定矩阵完成的有效负面/不确定研究，足以作阶段决策，不要求继续修补直到
获得正结果。下一步应由结果决定是保留、缩小、撤回机制，还是提出新的独立问题；
新的比较另行预注册，不把不断重跑隐藏在同一次“尚未成功”的验收里。
未完成的 CVRP 独立收益目标继续显式跟踪，而不是成为每个版本永远无法结束的唯一条件。
