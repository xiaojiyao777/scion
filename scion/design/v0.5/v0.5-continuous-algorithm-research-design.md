# v0.5：围绕持续算法问题的研究机制

*2026-11-15 · 详细设计初稿*

已接受：v0.4 按阶段规则收官，保留未完成的 CVRP 科学目标；进入持续算法研究的
v0.5 机制设计。本文件把方向展开成可评审契约，**尚不是已实现或已验证有效的能力**。
唯一架构权威仍是 [V3](../scion-architecture-v3.md)，实际实现仍以
[direct-runtime addendum](../scion-architecture-v3-v0.4-direct-runtime-addendum.md) 为准。
这里的动作名、文件布局和字段均为拟议接口；实施前需要明确采纳并同步权威契约。
验收见[配套设计](v0.5-research-mechanism-acceptance.md)。

## 1. 要改变的机制与可证伪判断

研究的中心应是一个尚未解决的算法问题。例如：“局部计算确实减少了，为什么完整
solve 仍无净收益？”agent 应能自行检查调用范围、构造公开输入、测量完整路径、
比较解释、修改认识，然后决定是否值得提交正式 H/C。问题可以延续到多个 attempt，
也可以因负证据而收窄或放弃；无需每次观察都制造一个 patch。

v0.4 已有完整算法工作区、verified source continuation 和必要科学边界。
[R26 审计](../../docs/experiments/v0.4/v04-cvrp-r26-scope-and-net-benefit-autonomous-postrun-20261114.md)
也已经发现真实缓存复用及 changed-path gain/retention 见证。
设计不能再把“开放完整源码”或“允许真实路径测试”当成全部新意。
现有不足是：H 不能主动取得运行观察，C 的执行结果偏向有限测试结论，研究材料的
延续弱于源码延续，解释修正主要依赖后续正式评价或 Scion 外部分析。

本设计包含三个最小变化：

1. 在正式提交之前，提供有隔离、有资源记录的公开观察与分析动作。
2. 把脚本、实际输出、解释、反例和未决问题作为普通研究文件保存并供后续 H 使用。
3. 允许 approved H 向 C 交接本次研究中明确选择的公开材料，保持正式科学裁决独立。

需要检验的判断是：这些能力能否在可比资源下改善诊断、解释修正和后续研究选择，
并最终支持完整 solver 的独立收益。负面观察、少写一个无效 patch 可以是有用研究，
但不能因此宣布 retained improvement 已完成。

## 2. 工作单元与权限分工

|对象|承担的职责|延续方式与边界|
|---|---|---|
|算法问题 question|agent 正在调查的问题、竞争解释、适用条件和未决事项|普通研究内容，可有多个问题、跨 attempt/branch/campaign 阅读；不新增 QuestionController、完成状态机或调度评分|
|branch|从选定完整 baseline 开始，承载后续 verified executable head，按现有规则继续或 reconcile|材料引用不能改 head；兄弟分支材料不会自动合并算法；旧结果适用的 source 必须可辨|
|attempt|一次有限 Creative 调查与正式提案机会|最多导出一个 H，以及 H approved 后最多一个绑定 C；开放草稿可修订，导出后不可修复/重放|
|campaign|拥有现有调度、正式轮数、资源和终态|终态不恢复；fresh campaign 可显式导入普通材料，但重新开始队列、计数与预算|

问题文本不是 host 选择算法的入口。core 不分类“有希望的机制”、不规定必须研究的文件，
不根据笔记是否完整、是否新颖、是否“用过历史”来拒绝 H 或安排资源。
问题自有算法、objective、feasibility、数据与 telemetry 含义仍归 problem package。
fresh campaign 的初始 baseline 是显式选定的普通完整源码，不因被选作起点就声称
通过了本 campaign 的 Verification；后续 verified head 仍由原有路径产生。

最小研究过程是：

```text
当前完整算法 + 可见历史 + 持续问题/材料
  -> H: 读源码/材料，选择公开调查，观察，修正解释
  -> 可继续调查，或 abstain，或导出一次正式 H
  -> 原有 H Contract
  -> C: approved H + 原始 base + 选定公开交接材料
  -> 开放 draft 的实现/观察/现有 test_patch
  -> 原有 ready -> 一个绑定 C
  -> Contract -> Verification -> Protocol -> deterministic Decision
  -> 正式历史由原有路径写入；研究材料供 fresh attempt 继续使用
```

这是能力路径，不是每次 H/C 必须完成的步骤清单。agent 可以只读源码后提出 H，
可以观察后 abstain，也可以保留不确定性。观察次数、报告篇幅或“完成一次反例”
都不是新的候选门槛。没有 formal evaluation 的调查不消耗正式 round 计数，
但消耗真实研究资源；达到共同资源上限即按资源语义结束，不能无限调查。
只完成调查、没有达到正式轮数目标的 campaign 不能被改写成 requested_rounds_completed。

例如，H 调查“缓存是否值得”，自行测得重复查询多但 key 构造昂贵，便保存这一
观察并提出具体 H。C 实现后发现完整调用反而变慢，可以在 approved H 内修正；
若需要换研究方向则结束该 attempt。下一次 H 读取负结果、核对当时 source 和输入，
选择调查另一解释；未验证 draft 不成为新 base。即使最终没有提交候选，这次调查
仍可留下有用反例。这个例子说明能力，不作为 host 指定的研究脚本或每次必走流程。

## 3. 公开观察：测量对象与分析脚本分开

### 3.1 两种动作

拟议 `observe` 有两种明确模式，避免把任意脚本输出都当成当前算法的测量：

|模式|输入|执行主体|输出的可解释范围|
|---|---|---|---|
|`subject_run`|允许的 source role、公开 fixture 或有界合成数据、seed、problem-owned 调用参数、资源请求|host 从选定 source 启动独立子进程，经 problem-owned 入口调用完整算法|记录实际选定的 source/input 和真实执行状态；solver 自报指标、诊断与含义仍是 tainted 开发观察|
|`analysis`|agent 编写的脚本、明确列出的公开输入/观察文件、资源请求|隔离分析进程，可计算参考值、分析数据、运行 toy model 或仪器化实验|全部是 self-authored/instrumented 分析；不能自动证明未经改动的算法会产生同样行为|

readonly 源码挂载不能防止 Python 脚本在内存里替换函数。因此 `subject_run`
不在 agent 脚本的 interpreter 里 import/call solver，不加载脚本、callback、pickle
或动态可执行 fixture；只跨进程传递经过 problem-owned schema 校验的普通数据。
若需要合成实例，agent 可先由 `analysis` 产生数据文件，再显式调用 `subject_run`。
每次动作独立记录和计费。

算法本身仍是研究对象，不是可信测量器。子进程隔离说明“执行的是所选源码”，
不能证明该源码打印的路径计数或 objective 正确。参考计算、开发可行性检查、重复
计时和完整 solver 对照需要 problem-owned 方法核验；它们仍不替代正式 Verification/Protocol。
若 runner 提供 profiling 模式，必须明确记录模式和开销；profiled time 不能冒充
普通 solve time。agent 自己插桩的运行仍归 `analysis`，不能重标为原样 subject 测量。

### 3.2 source selection

|阶段|允许的 subject role|含义|
|---|---|---|
|H|`current`|本 attempt 选定的初始完整 baseline 或该分支最后的 verified head，记录二者区别；H 不改变这个 executable base|
|C|`base`、`draft`|approved H 所绑定的完整 base，或在该 base 上物化的当前精确 draft；未产生 draft 时不能请求 `draft`|

host 根据当前角色解析 source，agent 不传任意宿主路径。C 的 draft 先经过现有安全
preflight，以及 approved-H action/target/surface 绑定的现有纯结构检查；前者不代替
后者，不新增性能或研究质量检查。通过公开观察不使它成为 verified head。一个动作使用启动时冻结的 source
副本，不能在执行过程中更换。`base`/`draft` 比较分别执行并分别记录；seed 相同不等于
计时噪声消失，局部 probe 正值也不等于完整 solver 净收益。

旧 parent/sibling 的完整源码可以作为研究证据保存和读取，但首个切片不增加任意
历史 executable subject 选择器。后续若需要受控历史对照，只能使用实际保存的完整树、
明确其 diagnostic 角色并单独设计暴露范围；不能由历史 patch 重建、自动 merge，
或在缺失时拿当前 champion 冒充旧对象。

### 3.3 请求与返回契约

通用请求只表达机制无关事实。以下是字段意图，不是新增算法配置语言：

```text
observe(mode, source_role?, input_refs, script_ref?, seed?, public_args?, limits)
  -> status, complete, source_ref?, input_refs, execution_ref,
     captured_output_refs, usage, error_kind?, truncation?
```

`public_args` 的允许键、输入形状、solver entry、输出数据含义由 problem package
声明。core 只处理权限、序列化、资源和文件，不认识 CVRP move/cache/route、
Warehouse 分组或任何收益阈值。不得扩展 `OperatorConfig` 等现有算法形状债务。
`script_ref` 只能指向本阶段允许的普通研究脚本，不能是任意 shell 命令或宿主路径。

host 写入的 execution record 至少包含：阶段/attempt、模式、实际 source role
与普通快照路径、实际输入/脚本副本、seed/允许参数、开始结束时间、退出状态、
请求与实际资源、输出文件位置及完整性。它不写“解释正确”“算法改进”或 promotion。
agent 的预测、解释和研究问题写在自己的文件中，不能冒充 host 执行事实。
实际宿主绝对路径只保留在 operator 侧；provider 可见记录仅给允许的相对引用/虚拟
路径与公开条件。`execution_ref` 只解析到这个安全视图，不能打开宿主原件。
此投影不压缩或删减允许的原始公开测量；私有路径本来不属于允许暴露集合。

大结果通过完整目录索引和按字节区间读取取得，返回 `offset/next_offset/total_bytes`；
被保留内容可以无损拼回。摘要可以由 agent 写成笔记，但原始允许材料保持可取，
不做 top-k、自动语义排名或摘要替换。

### 3.4 隔离与暴露

复用现有开发执行的隔离设施和 `development_closure_boundary`，新增动作不能扩大
为挂载整个 campaign。subject sandbox 只见所选算法的声明公开闭包、公开开发 fixture、
必要依赖和独立输出目录。analysis sandbox 另见显式选择的允许研究文件；两个进程
均无网络、无 provider 凭证、无宿主 home、无框架源码、无正式结果目录，环境清理后
只提供必要的显式值。文件引用校验包含路径穿越、symlink、特殊文件及数量/大小限制。
child 只能写临时 scratch 或受控输出 descriptor，不能写最终 `observations/`、
source 保存目录或 host execution record。host 校验并复制允许输出，另行写执行记录；
child 生成名为 `status.json` 的文件也只是输出，不能覆盖 host 状态。

screening 可见历史继续由原有投影提供给 H；**不因此挂载 screening 原始文件或
实例目录**。首个切片延续公开 development closure 与 screening/validation/frozen/canary
文件隔离。agent 可自己生成 synthetic 数据，不能请求 held-out case、seed 或结果。
公开观察数据与正式确认人口保持声明的分离。

宿主错误只返回枚举和允许的相对路径，不能把宿主 traceback、环境或私有路径混入
可见文件。sandbox 原始 stdout/stderr 是 tainted 数据；只有确实在上述隔离中产生的
输出才能暴露，不能事后靠关键词清洗一个混有私有数据的全量目录。

### 3.5 资源与失败

每个动作必须显式拥有 wall/CPU、内存、进程、输出字节、文件数、存储上限；
campaign 另有总 provider、研究计算与 wall 资源。动作开始前检查剩余额度并预留其
最大允许开销，完成后记录实际开销并释放未用预留；并发仍受共同额度约束。
首个切片顺序执行，不为观察新增多 agent 或并行调度器。
现有 `test_patch` 的 10 秒 probe 上限不暗中变成新 observation 的上限。
具体数值须由公开 pilot、资源约束与 preregistration 冻结；未配置完整额度时不启动动作。

|结果|解释与后续|
|---|---|
|正常退出且输出完整|只说明执行完成；零增益、反例、与预测相反都不是工具失败|
|请求/路径/数据不合法|未执行，返回枚举；消耗已发生的 provider 与调度成本，不能计作一次算法负结果|
|异常退出|记录可见异常种类与实际输出；脚本错误不是当前算法无收益|
|timeout / CPU / memory / output / storage limit|记录实际资源、已捕获部分、`complete=false` 和明确限制；未完成不能当成零收益|
|底层隔离/持久化故障|单列 infrastructure failure；不伪造观察成功，不重写科学历史|
|全局预算耗尽、auth/quota 或中断|保留现有 typed stop 语义；不静默加预算或根据正负信号自动重跑|

输出超过上限时终止收集/执行，标为 `OUTPUT_LIMIT`；明确哪些前缀被保留、哪些内容
未捕获，不能截断后声称完整。后续分页读取保证的是“所有已保留字节可取”，不是
恢复从未捕获的数据。新材料不能以静默删除原件满足容量限制。
执行状态与捕获/解析状态分别记录：退出 0 不代表输出完整或结构化数据有效。
无效编码、JSON、非有限数或 schema 越界返回 data-invalid，并保留受限原字节；
不能静默删字段、换值后声称完整。
研究子进程失败是否继续当前会话，沿用开放会话的枚举反馈和显式 local limits；
预算不足与基础设施故障不进入 scientific Decision。公共实验不会免费获得额外计算。

## 4. 研究材料延续

### 4.1 三类内容只有各自的 writer

|内容|唯一 writer|作用|
|---|---|---|
|问题、预测、解释、脚本、复盘与修订|agent，经受控普通文件写入动作|可错、可更正、可跨 attempt 复用的 tainted 研究内容|
|实际执行请求、副本、状态、资源与原始输出|host 执行路径；输出内容来自相应 sandbox|说明实际做了什么；不认证研究解释或 solver 自报数值|
|正式 screening 历史、Protocol 结果与 Decision|现有正式执行路径|继续保持既有暴露和裁决职责；不在研究目录另建权威总账|

建议物理布局只需普通文件，序号用于定位，无注册/签名/identity 服务：

```text
research/
  attempts/0001/
    h/notes/ scripts/          # 问题/解释/脚本的修订，不覆盖旧实验依据
    h/observations/0001/       # host 请求、source/input 引用、执行记录、输出
    h/handoff/                # H 导出时冻结的允许材料副本/引用
    c/notes/ scripts/
    c/observations/0001/
  sources/                    # 实际完整 source 的普通保存副本，非执行 head
```

这是存储建议，不强制 agent 写固定 research report。提供 list/read/search/write
这些普通动作即可。H 仅向本 attempt 的 h notes/scripts 追加，C 仅向本 attempt 的
c notes/scripts 追加；均不能覆盖旧材料或写其他阶段、host observations、sources、
冻结 handoff 和正式历史。问题内容放在 H notes 中，无共享 current/latest 问题状态。
修改解释生成新修订并可指向旧文件，保持原材料可读。
资料索引列出可见材料及类型、长度、时间、source/input 引用等定位信息，
不反复塞入全部旧正文；可访问集合完整，未读取的文件不能被描述为已被 agent 使用。

### 4.2 不同阶段的可见集合

|读者|可访问集合|
|---|---|
|H|当前普通源码、现有 H-only 安全正式历史，以及本 campaign 明确允许/导入的完整公开研究材料；每份材料保留原 branch/attempt/source 条件|
|C|approved H、绑定 base/draft、现有公开开发支持、该 H 显式选择并冻结的本次 H 公开材料，以及当前 C 自己的 notes/scripts/已完成 observations；没有通用 research/history 浏览权限|
|后续 fresh H|已关闭 attempt 中允许的 H/C 笔记、脚本、公开观察；导出失败也不抹去实际研究结果|
|formal Protocol/Decision|不读取这些研究笔记；输入继续由原有正式路径生成|

最小 H→C 交接只允许**当前 H 的**公开 observation/script/note 文件和必要的公开输入、
source 条件。H 可根据过去材料形成新的解释，或显式复测旧观察；不把所有历史目录
或其他 H 的正式记录交给 C。以后若要直接交接旧 observation 文件，需单独审查这项
暴露变化，不能由宽泛路径引用悄悄开放。

交接在 H 导出时冻结，host 只检查引用属于允许集合、类型/大小/路径合法，不能评分
内容或要求必须交接。非法引用返回开放会话反馈，不能静默删项后称“完整交接”；
导出后不补写、不重新绑定。H 的自然语言可能受旧历史影响，这不是零信息传递保证；
要约束的是 C 实际可读取的集合。交接也不变成第二次 H approval 或新的 authority 对象。

### 4.3 源码与研究记忆分别延续

研究材料不能代替完整 executable source。branch head 仍由原有 Verification/Decision
路径决定；笔记中的代码、失败 draft 或“建议采用”不能物化为新 base。
旧研究记录必须能追到当时的实际 source/input/script；O 切片就保存每次 subject 运行
所用完整执行树、实际输入和脚本，关闭跨 attempt 暴露也不减少审计保存。
M 再增加材料跨 attempt 可读，以及持续研究需要的长期 verified-parent 保留；
相关实际树必须在现有 workspace cleanup 前保存。
同一已冻结树可以用普通路径复用，不引入 hash 身份或去重闭环。

完整保存与公开暴露是两件事：保存树中可能有 problem runtime/config，H/C 仍只读
声明允许的 source projection。不能为了可复现向 agent 开放整个保存目录。
启动前不能保证必要 source/输入保存就不启动该观察；若执行后产物落盘失败，记录
incomplete 及可用范围，不能声称材料完整。正式 Decision 已经完成时，随后材料
保存失败不会倒改 Decision，只使相应研究引用 unavailable 并影响后续使用。

历史缺失的树明确返回 `source_unavailable`；只能保留当时的解释与 patch 作历史阅读，
不能宣称可执行重现。R26 六棵 superseded heads 的缺失不因本设计自动修复。

### 4.4 跨 campaign 的延续

fresh campaign 的三个输入分别声明：完整初始算法、H-only formal history、公开
research materials。选择其中一个不隐式导入另两个。operator 指定允许材料的普通
目录；host 按公开格式和暴露边界构造导入视图，不扫描旧 campaign、私有 traces 或
终态状态。导入保留缺失依赖标记，不因某份笔记写“已晋升”而恢复 champion/version。

不提供 terminal resume，不恢复 provider 会话、队列、budget、branch mutable state；
依靠新的 H 阅读完成的材料继续同一个算法问题。手写或外部导入的笔记仍是不可信的
研究输入，格式校验不能证明其内容真实，也不能保证作者未在文字里写入私有知识。
受控导出必须从源头只选择允许材料；不得声称能够自动净化任意旧目录。

## 5. 必须保持的控制边界

1. 新动作与材料只进入 Creative。Contract、Verification、Protocol、held-out、
   feasibility/objective、Safe Features 和 deterministic Decision 不接受笔记替代输入。
2. H 只能调查当前 source，不能绕过 approved H 导出代码；C 只能围绕该 approved H
   在开放 draft 上工作。analysis 里的候选想法不自动成为正式 C。
3. `test_patch` 的现有 exact-draft failed-falsifier veto 保持。新观察正常退出、
   后来弱化 probe、改笔记或一次漂亮计时，都不能清除同一 executable value 的失败。
   真正改变 executable value 后才按现有流程评估新 draft；ready 仍使用最新精确草稿。
   允许观察被 veto 的 draft 来调查失败原因，但不能恢复其提交资格。若 C 需要改变
   approved H 的方向，只能结束当前 attempt，让 fresh H 继续，不能修改已批准 H。
4. 材料完成、问题“已解决”、probe 数量、研究质量与新颖性不进入 runtime gate，
   不影响正式轮数或 branch/champion 选择。效果评价只在框架研发中离线开展。
5. 新增资源限制是明确的执行边界，不是 host 依据机制内容分配预算。所有真实
   provider dispatch 和研究计算计费；保留现有 typed redispatch 与 quota stop。
6. 没有 Trust/Hash authority、identity、lease、signing、registration、receipt、
   duplicate closure，亦不增加部署、打包、build 或服务体系。

## 7. 实施顺序与本阶段交付

|切片|具体交付|进入下一步的条件|
|---|---|---|
|D：设计|本机制文件、四层验收、权威差异、所有待冻结参数的清单|具体契约评审并采纳；当前只完成设计初稿|
|O：观察|subject/analysis 分离；H current 与 C base/draft；当前 attempt 文件及 H→C handoff；实际 source/input/script 审计保存；资源和失败记录|边界工程检查通过，真实 provider 能完成有效公开调查；不声称优于 v0.4|
|M：材料|跨 attempt 公开材料读取、解释修订延续、长期 verified-parent 保留；显式 fresh-campaign 导入|来源/权限/缺失/终态检查通过，真实轨迹证明有条件地复用材料|
|E：效果|预注册 A/B/C 重复对照，独立提名与确认规则|按预定矩阵完成并报告支持/不支持/不确定；不以正结果才允许结束|

O 和 M 的开关必须能分别控制。O 的当前 attempt 材料在审计端保存，但关闭 M 时
不向下一个 attempt 暴露新增材料接口；现有正式历史仍完整提供。
共同隔离实现的修改需要合适的 focused/full regression 与独立问题包控制，
具体测试以配套验收文件为准；不能用单个 CVRP trace 宣称问题中立性成立。

尚未定数值的是资源上限、pilot/正式重复数、任务分布、实际意义阈值、确认人口和
统计精度；这些需要公开 pilot 与预算依据，启动正式实验前全部冻结。
这不是继续设计一个无限平台的理由。第一项实现应直接打通“agent 自选公开调查
→ 实际输出 → 据此行动”的最小纵向能力，再检验材料延续的附加贡献。

本文件不授权启动新实验，也不改变 v0.4 的既有科学结果。CVRP 未完成目标和
v0.5 的关闭/成功口径在[验收文件](v0.5-research-mechanism-acceptance.md)中分别记录。
