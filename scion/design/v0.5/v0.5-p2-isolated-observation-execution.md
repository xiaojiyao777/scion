# P2：隔离观察执行与资源计数

*2026-11-15 · 实施合同；与 P1b 联合验收，P3 接入 agent 另行跟踪*

依赖 [P0](v0.5-p0-interface-and-boundary-contract.md) 和
[P1](v0.5-p1-public-problem-execution.md)。V3 已明确采纳公开研究扩展。
首个纵向实现面向 host 调用，不自动向 H/C 开放；Contract、Protocol、Decision
和 existing exact-falsifier 状态没有新增 writer。

## 1. 组件和接口

- `observation/source.py`：根据已加载 provider、冻结问题根、已选 source 根和
  显式禁止文件集合，展开并复制公开执行闭包。先拒绝非法路径、symlink、非普通
  文件、hardlink/同 inode 的正式数据别名，再保存普通源码副本；不重放 patch。
- `observation/sandbox.py`：只接受已准备的只读目录、固定入口、显式 limits；
  运行一个隔离进程，捕获原始 bytes 和 host 资源事实，不解释问题 objective。
- `observation/service.py`：校验输入、预留共同额度、绑定 source/config，依次
  subject→checker（或独立 analysis），持久化请求/源码/输出/host 记录，再返回。
- `observation/materials.py`：当前研究材料的追加、精确字节读取和字面分页搜索；
  不实现跨 attempt 暴露策略或 H→C 交接，后两者归 P3/P4。
- 两个 problem package 的 `public_runner.py` / `public_checker.py`：固定协议，
  问题算法/解/目标语义全留在问题包；host 不 import candidate。

host 调用携带 `SourceBinding(root, role, source_ref, config)`：root 来自现有
workspace/materializer；role/current/base/draft 的权限及 H 绑定由 P3 session 检查。
本地 backend 不接受 agent 的 filesystem path，也不能把一个普通 binding 当权限
证明。P3 必须在调用前执行已有 C preflight、H binding 与 refs 可见性检查。

输入为受限 JSON bytes，args 和 seed 另经严格校验。输出分为 host execution/capture/
usage 与 tainted payload/check，不合并字典。没有通用 argv/shell/module 参数。
一次动作只有一次执行，无自动 retry。

## 2. 文件闭包和 source/config 条件

workspace 路径只从选定源码树复制；frozen package/checker 路径从问题原始根复制；
两个固定入口从安装的 adapter 包复制；中立支持只复制已声明的具体文件。声明
代码目录只递归纳入 `.py`，排除运行生成的 `__pycache__`；其他数据文件须逐文件
声明。不能把“目录可读”扩展为整个问题数据根或 framework。
所有路径的每级组件不得是 symlink；普通文件多硬链接拒绝，正式输入的 inode
集合和路径集合同时检查。边界检查不是只看文件名中的 validation/frozen 字样。
复制前后检查文件元数据变化；源码改动期间的准备失败，不替换成 champion。

实际执行仅使用保存的副本；源目录随后变化、sibling 改动或 cwd/env 变化均不得
影响一次观察。保留 source_ref/role、实际文件列表、普通源码内容、seed、args 和
配置模式。source_ref 是普通定位字符串，无 identity/receipt 语义。
内部原件保存位置不投影给模型；安全视图只用相对 ref。正式数据路径清单由 host
从现有 Protocol/split/canary 配置提供；P3 composition 必须接入真实清单。

provider 增加纯 `validate_source_config(config, available_files)`。CVRP 只允许 `{}`；
Warehouse 使用 `{"operator_selection":"registry"|"defaults"}`。registry 模式必须
存在实际 `registry.yaml`；defaults 只允许 host 明确选择的初始默认 source，且
发现 registry 时拒绝 defaults。候选从已有 materializer 取得 registry，不由观察
服务再推导 operator_pool。固定 runner 仅按已验证模式运行；缺配置明确失败。

## 3. 隔离机制与实际保障范围

Linux bubblewrap：`--unshare-all --as-pid-1 --die-with-parent --new-session --clearenv`，
新 PID/network/IPC/user/mount namespace；caps 全部丢弃。执行根只挂载：

|路径|权限/内容|
|---|---|
|`/subject`|只读选定算法闭包；checker 中为空|
|`/runtime`|只读、精确冻结依赖和固定入口；checker 使用独立集合|
|`/input`|只读当前请求和实例；analysis 只含所选材料与脚本|
|`/public`|只读声明的开发 fixture；checker 中为空|
|`/scratch`|唯一可写 tmpfs，容量显式限制；不直接挂 host 记录目录|
|Python 标准库/必要动态库|只读运行环境，site-packages 默认不挂载|
|显式第三方依赖|仅已审查的 pydantic 依赖或 yaml，不能加载安装的 scion/插件|

Python `-I -S -B`，固定 bootstrap 设置 import roots；不继承 PYTHONPATH、凭证、
数据根变量或用户 site。不挂载宿主 `/home`、`/tmp`、`/proc` 或全 framework。
需要时新 namespace 的 proc 也不提供；不提供宿主 shell 可执行目录。
CVRP 的 `context.instance_path` 指向 `/input/instance.json`，内容是可直接重读的
实际实例；传输 envelope 单独放在 `request.json`，不能用 envelope 冒充实例文件。

bootstrap 在加载目标前安装 seccomp：禁止 socket、fork/vfork/clone/clone3、exec、
ptrace、namespace/mount 修改及资源上限修改。首版每个运行只有 **1 个研究进程**，
不支持内部线程/多进程求解器；其请求返回不支持，不假称支持进程组内任意并发。
这使 RLIMIT_AS/CPU 覆盖完整研究计算，而非仅一个进程。它是公开的首版能力限制，
后续并行 solver 支持需要实际 cgroup 等可用后端；不能只放开 fork。

seccomp 安装失败时固定退出并记 ISOLATION_UNAVAILABLE；任何 bootstrap 或 bwrap
启动失败都不执行候选，也不回退到 subprocess 裸跑。隔离防止跨进程/文件访问，
不宣称防御 Linux 内核漏洞。subject JSON 可伪造但无法获得 host 记录写权。
bootstrap 在加载目标前写一个字节的启动事实并关闭独立 pipe；目标无法写这条
已关闭的通道。它只区分隔离启动失败与目标运行错误，不构成权限、身份或 receipt。

## 4. 输出与 checker

stdout/stderr 各自 pipe 捕获；结构化结果使用单独继承的 pipe FD，不能与日志混合。
所有 pipe 非阻塞读取，总捕获字节共用 output cap；达到上限后杀掉 namespace，
保存准确前缀及 partial，不把前缀当完整 JSON。不存在 child 指定的 host 输出路径。
首版不回收任意 scratch 文件；analysis 的产物须通过结构化结果/文本输出提交。
执行结束后整个临时 namespace 销毁，不留后台子进程。

subject 正常返回后，在新进程加载冻结 checker，只传 instance + solution；不传
subject 的 objective/feasible 作为真值。checker 没有 candidate、analysis 或 subject
进程的内存/import 状态。checker 失败/错型/超限单独记录，不默认为 pass。
feasibility=false 是有效开发反例；未定义 objective 用 null，不能伪造 0。

## 5. 额度与测量

单进程 limits：wall 秒、CPU 整秒（Linux RLIMIT_CPU 粒度）、memory bytes、output
bytes、scratch bytes。CPU 请求须为正整秒；不暗中将小数预算向上取整。RLIMIT_AS
限制地址空间，**不是 RSS 保证**；峰值 RSS 由 host wait4 的 rusage 单独记录。
明确 SIGXCPU 报为 CPU_LIMIT；SIGKILL 或 launcher 的 137 状态报 PROCESS_KILLED，
execution=error、capture=partial，原因未确定。CPU 硬限仍生效，但 wait4 接近限额
不证明 kill 原因；实测 1 秒硬限可报告 0.998921 或 0.987590 秒，不能用任意容差
断言 CPU/OOM。保留原始退出码与 rusage，不把实耗补成限额。MemoryError 可被算法
捕获，不能仅凭 child 自报计成 host MEMORY_LIMIT。受控忙循环测试独立检查硬限
实际终止及计费，不要求生产路径猜测无法取得的内核原因。

每次 observe 在执行前为 subject 和 checker 的最坏 wall/CPU/output/storage 预留；
analysis 只预留自身。同步串行执行，共同计数器不由新的 session 重置。实际启动
才加 subject/analysis/checker 计数，失败也计费。host wait4 读取本次隔离进程的
CPU、max RSS；不可取得用 null，不用全局 RUSAGE_CHILDREN 差值冒充单次测量。
文件准备/解析/落盘 wall 计入观察总 wall，solver 与 checker 的时间分别保存。
请求 RunLimits 是一次观察的总 wall/CPU/output 上限。subject 先扣除固定 checker
额度和显式 preparation wall 余量；不能给两个进程各一份完整请求预算。内核 CPU
限制有整秒和调度粒度，实际 CPU 全额记账；不把限制值当成实耗。
实测默认 bubblewrap 监控层的 wait4 不含完整 target CPU，故首版必须使用
`--as-pid-1`，并以 CPU 忙循环验证计量。rusage 的峰值包含启动器/执行进程，不能
宣传为纯 solver RSS；AS 限制、峰值观测与 child 自报 MemoryError 分开记录。
整个服务调用的 wall 预算需包含准备/持久化余量，超出共同额度后停止后续调用。
共同 CPU 另计本次 host 校验/准备/解析/保存的 process_time；输入校验拒绝和初始
staging 目录创建失败也计入已消耗的 host wall/CPU。单动作记录在最后 record
写入前取样，共同计数继续包含该写入及 rename。文件数上限覆盖 host 物化/捕获的
文件，scratch 的独立硬限制是 tmpfs 数据字节和单文件 FSIZE；首版没有独立的
tmpfs inode/kernel-memory 配额，不能把它说成 cgroup 总内存保证。

额度不足但余额非零：LIMIT_NOT_AVAILABLE，允许缩小请求；共同必需额度耗尽：
GLOBAL_RESEARCH_LIMIT。动作额度预检前也计当前 session 的 action 次数。存储 cap
包括 source/request/material/output/record；不能删掉负面旧材料来腾出“成功”空间。
磁盘实际失败：PERSISTENCE_ERROR，停止；已发生的运行仍计数，不恢复额度为零。
运行失败、资源超限与科学失败完全分离；外层 typed outcome 映射归 P3。

## 6. 持久化和访问

host 分配普通顺序目录，先写临时目录再 rename 发布；其中有 request、source
副本、stdout/stderr/result 原始 bytes、checker 输出与 host record。child 无权挂载
这些目录。中断/落盘失败不发布“完整”索引；保留已捕获事实供诊断，不恢复会话。
当前材料追加后只返回相对 ref；读按 byte offset/base64 分页，搜索按字面字节与
稳定顺序，游标含文件和 byte offset。跨页匹配不能漏掉；索引与读取都须经过
调用方允许集合过滤。P2 不自行决定 H/C/跨 campaign 谁能读什么。
backend 的返回值保存分阶段 usage、tainted payload/check 和普通文件 refs；P3
据此构建 P0 的 provider-visible envelope/完整安全索引，不能直接把整个 backend
返回值或运行目录塞进 context。材料的 supersedes 关系、阶段 metadata 和 handoff
引用由 P3/P4 的普通材料投影接入，不从文件名或笔记推断权限。

## 7. 联合验收

|用例|关键刺激 → 证据|
|---|---|
|S01|真实隔离 CVRP/warehouse baseline → runner 和独立 checker 均完成|
|S02|P1-05/06/08/09 数值、重复/遗漏/不可行解 → 独立重算/明确错误|
|S03|P1-07 主算法失败 → 无 fallback；P1-10 registry 特殊算子 → 实际配置生效|
|S04|源树准备后被改写、missing source/registry → 使用保存副本或拒绝，无替代|
|S05|私有 sentinel、env、socket、fork、exec、framework import、写只读 source → 拒绝|
|S06|subject 污染模型/oracle、自报 objective → checker 仍给冻结答案|
|S07|wall/CPU/output/scratch/memory 压力 → 有界结束、保留捕获状态和实际计数|
|S08|余额不足/耗尽、失败重试、checker 预留 → 无免费执行/超额第二阶段|
|S09|symlink/hardlink/formal alias/非普通文件/坏入口 → 执行前拒绝|
|S10|隔离不可用/持久化失败/中断 → 不裸跑、不伪造完整记录|
|S11|analysis 读允许 input/source，修改内存 → 与正常 subject 分离，不声称正式性能|
|S12|分页 Unicode、同文件多匹配、扫描上限 → 原字节可重组、结果无隐式遗漏|

P1-01–14、P0 C04/C06–08/C12 的执行部分与这些用例交叉覆盖；H approval、handoff、
failed-falsifier veto 和完整 context 的 C01–03/C05/C09–11 由
[P3 的 T01–T12](v0.5-p3-session-permissions-and-handoff.md)进一步集成验收。
单机隔离验证不等于 agent 研究有效或完整 O/M 已开放，也不关闭 CVRP 科学目标。
