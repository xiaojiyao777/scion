## 1. 判断、证据强度与本轮选择

**研究工作的连续性应由可复查的问题、实验和解释承载；H/C 是研究产生正式候选的
出口。** 当前实现虽开放 O/M，实际提示、动作结果和 campaign 目标仍围绕 H/C
产出组织。新增工具可用，不等于 agent 已能持续研究；也不等于应强制使用这些工具。

|P5b 事实|支持的判断|尚不能推出|
|---|---|---|
|298 次上下文都开启 O/M；observe 为 0|本批未展示新 O 的实证调查能力|O 无效、模型不能使用工具，或某句提示是唯一原因|
|open-cvrp 明说 prior probe 不在 visible research index；源码确认只回传 bounded diagnostic|自己的实验脚本回读存在实际断点|恢复脚本一定改善研究质量|
|三次 failed probe 包含错误参考或作用域混淆|自写断言失败需要复核测试本身|由 host 自动判定“测试错了”并解除 veto|
|有历史材料机会的三个槽位未读旧内容；P4 清理前源码保留实际有效|存储和实际使用必须分别验收|材料丢失，或 open-warehouse 故意忽略了一个并不存在的后续 H 机会|
|第二次 CVRP H 利用既有正式历史收窄解释并换研究方向|存在有限的旧反馈研究能力|已满足新 O/M 的 E2，或机制因果效果已确认|

选择三项有限交付：A 打通本会话实验回读；B 绑定实际测试源码并复核错误测试；
C 明确持续问题的工作上下文与主动结束研究的语义。不得把它们并成“修几处提示后
重跑八项”，也不引入问题评分器、强制实验次数、必读笔记或新颖性门槛。

## 3. A：测试请求和反馈成为可回读材料

### 3.1 接口与数据

provider 的 `test_patch(falsifier_source?)`、`read_research`、`search_research`
保持现有字段。O 或 M 开启时自动保存实际 test_patch 材料；无需再发一次
write_research，也不能因忘记手动保存而丢失失败脚本。O/M 均关闭时保持旧请求、
结果与计费路径。M-only 保存材料不要求运行 observation runner。

host-only A 实际接口（源码条件由材料 session 选择，调用方不传宿主路径）：

```text
PublicResearchSession.begin_development_test(
    draft_revision, public_draft_files, falsifier_source, max_result_chars
) -> request_ref

PublicResearchSession.finish_development_test(
    request_ref, bounded_result, execution_state, callback_wall_seconds
) -> result_ref
```

这两个调用只能由 C 运行路径触发，不能由 provider 自报 execution_state。
ref 是普通文件定位，不是身份、许可、ready token 或恢复句柄。严格使用允许字段
构造数据；不序列化整个内部对象、provider trace 或 callback 返回的任意 mapping。

|文件/字段|来源与允许内容|限制|
|---|---|---|
|request，kind=request|host：`schema_version=1`、`operation=development_test`、session 内序号、draft_revision、script_ref/null、draft_files、source_condition、base_source_condition、capture_scope|draft_files 逐项给出 file_path/action/ref；序号不跨会话控制状态；不是新 observation 成功事件|
|script，kind=script|agent 本次提交的原 UTF-8 falsifier_source|精确字节，不重新排版；其内嵌输入、参考值和断言保持原样，不由 host 抽取“正确预期”|
|draft，kind=source|本次实际 PatchProposal 中 provider 已可见的相对文件名、动作和最终文件正文；删除动作另列|只保留可见 editable 源码；不用 test_hint/evidence_refs 冒充源码；不是 verified tree|
|result，kind=output|host：request_ref、原 `_bounded_test_projection` 的允许结果、独立 execution_state、usage、capture_scope|host checks 与 falsifier outcome 分开；不把 host checks passed 写成 falsifier passed|
|解释/更正，kind=note|agent 自写预测、范围、证据引用、替代解释、下一问题|均 tainted；supersedes 只关联修订，不覆盖失败原件|

`execution_state` 区分 `not_started`、`returned`、`interrupted`、`unknown`；
`callback_entered` 只作正在调用时的内部暂态。调用 callback 不能证明子进程已开始；
A 只能记录自己知道的边界。callback 异常、反馈格式无效或超出原 test-result cap
时结果 feedback 为 null，保留请求与已知执行状态，不复制不安全/越界反馈。主异常
继续向外传播，补记结果失败不掩盖中断等原始异常。
没有脚本时 script_ref 为 null；callback 不可用时仍保留请求与 unavailable 反馈，
不能写成已执行。request 与 result 通过普通 dependencies 相连。材料沿用 P4 的
kind 集合，不加新格式类别；正文自身带 schema_version/operation。

下一 provider turn 的有限工具反馈给出 `request_ref/result_ref`，材料完整索引也
包含它们。正文走已有 user 工具数据段，不塞入 system 指令；ref 不能替代原结果。
保留 `max_test_result_chars` 对原反馈的约束，新定位字段及索引也计入实际 context/
transcript 上限。超限明确停止，不 top-k、隐藏失败或自动摘要。

### 3.2 源码条件：A 不冒充完整实验复现

A 保存“请求了哪份 draft”，并指向当前绑定 base 的允许条件；不调用 observation
物化器重造测试源码。结果正文 `capture_scope=request_only` 明确表示未保存实际测试
scratch，不能标 retained 或用它声称可执行重现。P4 中实际完整 base 的 private
retention 仍保持，但 development scratch 与 base+patch 不是同一保存对象。

P4 索引的 `source_availability` 继续只取 retained/projection_only/unavailable；
请求中的代码是 projection_only，不能因 base 已保留而标成完整 draft retained。
source_condition.role 仍用 base/draft，普通 source_ref 指向各自实际请求/保存范围，
不复用一个含糊的“当前 source”标签。导入缺依赖的处理保持 P4；正文所记的原始
捕获事实不证明导入端还拥有那些依赖，读取时须同时核对当前索引可用性。

B 完成后可补充新的实际 tested_source_refs，既有 A 记录保持原缺失状态；不得从
P5b traces 回灌成当时 agent 可读材料，更不能由旧 patch 重建当时被测树来补证。

### 3.3 权限、计费与写入时序

|读者|范围|
|---|---|
|当前 C|自己的全部请求、脚本、draft 和有限结果；原 H handoff 集合不变|
|后续 H，M 开|已关闭 C 的上述安全材料、依赖及明确缺失；失败/abandon 同样发布|
|后续 H，M 关|无新增可见集合；O-only 仍保留 operator 审计材料|
|另一 C|不能直接读取；H 可据旧材料形成自己的新说明并按 P3 交接，不能把历史 ref 直接交给 C|
|Protocol/Decision|不读取这些材料；不改变 head、ready、formal round 或 champion|

先解析动作、检查 draft/脚本/原 test 配额 → 预留完整请求和有界结果文件空间 →
持久化请求 → 原 test callback → 原 feedback 校验与 veto 更新 → 持久化结果 →
下一 provider dispatch。任何中间失败均不得带着未检查的材料故障继续 ready。
不得把 finish 回调放在会阻止已知 failed-falsifier 写入拒绝集合的位置；若反馈
校验本身失败，关闭会话，不通过重试恢复同一未结算测试。

请求未发布不能执行 test；执行后保存失败保留已发生的状态与成本，阻止下一
dispatch，不自动重跑。磁盘完全不可写时只能保留可写部分及外层 typed stop，
不能承诺一个并未成功落盘的 incomplete 文件。

A 的材料落点是 `observation/development_materials.py`，经现有 session 的 host-only
入口调用。普通路径为 `development-tests/session-N/序号/{request.json,falsifier.py,
draft-N.txt,result.json}`；生成路径不使用 C 提供的文件名，原文件名只在 metadata 中。
A 原有及无实际捕获的结果保留 `capture_scope=request_only`、`tested_source_refs=[]`；
B 实际捕获后使用 §4.1 的阶段 source record。请求原件仍为 request_only，不回写
历史文件。代码材料不序列化 test_hint/evidence_refs，不改变原 PatchProposal。

原 test_call/timeout 负责执行；复制、索引、公开导出计入现有共同材料 CPU/wall/
storage。自动落盘不额外消耗 provider turn，也不伪装为 observe action 或 subject
run。每个显式 read/search 仍按原局部动作预算收费。不得把整个 test elapsed 再记
为材料 CPU；A 记录实际 callback wall，无法取得的 child CPU/完整阶段耗时用
null+原因。精确子进程计量另作有限实现项，不能把 parent process_time 当 child CPU。

空间预留必须含请求、script/draft 字节、有限 result 上界及索引更新开销；当前
test 总 timeout、最大文件数与大小继续有效。材料开关开启产生的额外开销须在新
冻结预算中披露，不能挪用原 P5b 未用预算或静默提升任一 cap。

A 在顺序 callback 前检查整个请求、剩余 test-result 字符额度、固定结果 envelope
和两次索引写入的保守空间上界；复用 max_source_bytes/max_files_per_action 与共同
存储 cap。结果 envelope 留 2 KiB，索引为实际候选条目大小加 512 bytes 的 usage
余量。这是空间预留，不是自动增加配置额度；可以比最终实际占用更早拒绝。
预留期间没有并行材料动作，写入仍逐次检查共同上限。自动保存不扣 public action
次数；显式读取/搜索照常计数。callback wall 由原 test 时钟记录，材料计时只围绕
复制/索引/故障记录。有限反馈沿原 code tool-result 路径，加上的两个 ref 计入原
tool/transcript 上限；脚本/源码等正文仍只经 user 工具数据块显式读取。

## 4. B：实际测试源码与错误测试复核

### 4.1 实际源码保留

在 DevelopmentEvaluator 的实际 prepared scratch 通过现有安全预检后、probe
执行前保存测试所用源码；若未通过预检则记录未执行，不制造 source snapshot。
保存失败不启动测试。记录正文以 `source_kind=development_draft` 区分 observation draft、
原始完整 base、正式 verified candidate，不新增可供 agent 选择的 executable role。
索引 role 仍为 draft；保存允许源码后结果 capture_scope 为 public_test_source，
不因此宣称已公开全部执行依赖或已保留完整普通算法树。

保留在实际执行之前完成，避免 candidate 修改 sandbox 可写副本后污染起始证据。
probe 与 host suites 的输入阶段不同，审计记录区分两者；host checks 的 suite/
runtime 路径只在 operator 侧。安全投影只含本 C 原本可读的算法源码和明确公开
依赖，继续用实际 formal 排除清单与无链接 copier。完整 prepared scratch 的
私有保存不是完整 ordinary algorithm workspace，也不能冒充其替身。
允许的初始输入、脚本、配置和源码必须有原件/缺失说明；不开放测试 harness 原始
日志、异常消息或任意已挂载目录。清理前完成保存，沿 P4 导出安全材料。

B 实施接口：`evaluate(..., capture_source=None)` 接受 host-only 回调；仅在
O/M 会话存在时接入。回调接收实际 workspace、problem runtime root、阶段
`probe` / `host_checks`、算法路径与声明依赖及其原始 root。probe 文件写入后、
`run_probe` 前保存第一阶段；suite closure 复制后、`run_development_checks` 前
保存第二阶段。无 probe 时仅第二阶段；预检拒绝没有 snapshot。每阶段重新计算
剩余原测试时间，保留工作不能延长测试额度。`captured_before_execution` 只说明
保存时点，不保证该阶段进程已启动（后续超时/中断仍可能发生）。

完整 scratch 写入不入索引的 `private-development-tests/.../tree`；公开副本按
workspace/problem 两类原路径保存，正文 `source.json` 列出原字节引用、source
条件、request/script 依赖。原宿主绝对路径、suite 内容与运行布局只写私有审计。
原始 root 的 formal 路径同时映射到实际 scratch，防止复制后 inode 变化绕过排除。
每阶段私有副本与公开副本合计受 source 字节/文件额度约束，目录遍历有界；复制、
索引和后续 result 预留受共享存储约束。回调 wall 是包含保存工作的既有测试计时，
保存 CPU/wall 另计材料额度，二者是重叠口径，不能相加为进程耗时。

保存错误沿 `PublicResearchStop` 回到既有材料失败路由，不被 evaluator 转成
普通 preflight 拒绝；未完成公开索引不发布，禁止对应阶段启动。先前完成的阶段
和 request 保留。结果通过至多两个 source record 引用连接实际文件，避免将源码
列表挤入有限测试反馈。A/旧记录和未执行回调仍明确 `request_only`，不事后补造。

### 4.2 复核路径及 veto 选择

推荐把“探索一个未确定的解释”放在现有 `observe(analysis/subject_run)` 中，
把 `test_patch` 留作其已声明的最终开发检查路径；这是工具职责说明，不是强制
顺序或要求 agent 先证明改进。analysis 可算独立参考值或检验自写模型，但不能
把分析脚本伪装成未插桩 solver。无需新增名为 review_test 的质量裁判。

失败后的合法路径：读原 script/request/result → 检查参考值与调用范围 → 可写
新的 script/input 并使用现有公开观察 → 追加解释修订。agent 自行选择是否进行
这些动作。结果可为算法反例、错误参考、错误测量范围或仍未知；host 不分类其真伪。
不同结论和零收益都保留原材料。没有公开输出的数据不能由行号“推测还原”。
原 pytest 脚本不自动转换成 analysis 程序；若要在 analysis 中复核，agent 必须
使用该工具现有入口实际调用自己的计算，不能把仅定义 test 函数的空运行算作复测。

**本设计的 A/B 保留 exact executable value 的 session-local veto。** 即使复核
证明原自写参考错了，同一 C 中该精确草稿仍不能 ready；允许继续调查、改进算法
或 abandon。不能为了逃避 veto 建议无意义代码改动。fresh H/C 仍按既有规则从
host 选定 base 开始；材料不能自动重放旧 draft，也不引入跨会话 blacklist。

|可选边界|取舍与本轮决定|
|---|---|
|保留 veto，先使错误测试可复查；开放调查用 O|本轮选择；解决失去实验材料的问题，但不声称消除错误测试误拒草稿的代价|
|agent 写理由/再 PASS 即解除 veto|不采纳：同样允许弱化反例绕过既有保证；文本或 PASS 无法证明原测试错误|
|把所有 agent tests 改为普通观察，只由 host checks 建立 ready|可作为未来独立边界提案；会退役 Post-R3 safeguard，须明确替代风险与反例，不能伪装成 A/B 实现细节|

因此 B 的验收是“能发现并解释错误测试，且权限不变”，不是“复核后同一草稿
获准提交”。后者若仍必要，另行采纳 V3 变化；不会在本切片悄悄实现。

## 5. C：以持续问题组织会话

### 5.1 工作内容与上下文

问题沿用 research_input.current_question。agent 可用普通 note 保存：当前解释、
可区分解释的预期、已有实验引用及适用 source/input、仍未知的事项、下一选择。
这是建议内容，不是必填 JSON、问题完成标记或新的 H Contract。完整材料索引与
正文按需读取不变；旧 note 不被 host 选成“最佳答案”，也不自动注入全部正文。

O/M 启用时 H 会话的目标说明调整为“调查当前算法问题；在有值得正式检验的候选
时导出 H”；同时说明可读旧实验和当前源码的不同条件。C 仍只实现 approved H，
可调查失败与收窄结论，不能在 C 私自换问题/绑定。常规直接提交 H/C 仍合法。
不要求固定实验顺序、必须否定一次解释或至少读 N 份笔记。全局资源与当前 phase
的可用动作明确可见，不把即将耗尽预算隐瞒成无限研究机会。

旧 H `failure_frontier` used/rejected 的强制闭合是现有债务，不扩展到新材料；
本切片不同时重构它，也不把它作为新能力必须遵守的 V3 不变量。

### 5.2 已采纳停止合同：调查任务可以有无候选结论

仅改提示仍不能解决现有 abstain → RESEARCH_REJECTED → fresh H 的循环。
增加显式 operator 配置 `run_intent=formal_target|investigation`，默认前者。
这属于 operational 生命周期扩展；不以自然语言“问题解决了”触发停止。

|配置/动作|formal_target：现有模式|investigation：显式模式|
|---|---|---|
|正式阶段目标|沿用 requested_rounds|无最低正式产出要求；显式 formal_stage_limit 为上限，允许 0|
|共同资源|既有 provider/wall/研究计算/存储上限|相同类别的显式上限，不因无候选免费重开|
|H finalize|原 H Contract → C → 正式链|有正式额度时走同一路径；无额度时不接受会必需启动正式链的新 H|
|H abstain、C abandon、局部额度耗尽|原 RESEARCH_REJECTED 路由|仍是本 attempt 结束；不自动等同于问题已研究完|
|H conclude_research|无此工具|仅开放 H 可显式结束本 campaign 的调查；最多导出一个 H 的规则保持，因为本次未导出 H|
|达到正式上限|requested_rounds_completed|formal_stage_limit_reached；停止新工作，不声称研究成功|

动作：`conclude_research(reason: string, note_refs: string[] = [])`。
reason 沿现有短理由长度限制；note_refs 仅本 H 新生成文件、受原集合/大小上限，
空列表合法。host 只检查形状与权限并冻结这些普通材料，不评分理由、结论、研究
充分性或读取次数。reason 可以保留不确定性；无须声称问题已解决。索引发布失败
按材料故障停止，不返回一个假的完成结论。

H session 返回单独的 `ResearchConclusion` 数据结果；ProposalPipeline / ExploreStep
传递 typed operational outcome `RESEARCH_CONCLUDED`，不进入 H Contract/C/Protocol。
CampaignLoop 只在显式 investigation 中将它解释为终止原因 `research_concluded`，
formal delta=0；它不是 EVALUATED、RESEARCH_REJECTED、scientific fail 或 promotion。
旧模式拒绝该动作，不根据 note 内容推断同类结果。新 terminal 报告同时给出：
run_intent、实际 formal count、上限、停止原因、结论引用及原科学结果；不伪造一个
requested_rounds_completed 或全局“研究正确”状态。若要呈现已完成，只指调用的
调查生命周期已经结束，E2–E4 另行判断。

仍使用现有 scheduler 选择 H/C/正式阶段；结论动作不抢占正在执行的 Protocol，
不能让 C 在已有 ready/export 后取消后续检查。只有实际获配的开放 H 可调用它。
结束时其他分支待评工作记为未执行，不将其标 fail/abandon/promoted；沿现有 terminal
清理和 P4 保留路径处理，不恢复队列。若已有后台工作，沿既有 terminal drain 语义
收尾、计费，不新派发研究；不能把已发生的 Decision 回滚。

formal_stage_limit=0 适合公开调查，不提供 H finalize/候选选择的动作；仍需有效
公开闭包、资料与研究资源配置。现有 --rounds 继续只表达 formal_target，新增
investigation 参数与它互斥，不能将现有默认整数悄悄解释为零正式目标。达到全局
资源上限、auth/quota、中断、基础设施错误仍优先产生原 typed stop，不因已写一份
结论笔记而改成正常研究结束。没有 terminal resume。

### 5.3 C 实施接口、时序及资源合同

`CampaignManager(..., run_intent="formal_target", formal_stage_limit=None)` 保存普通
不可变运行配置；`run(requested_rounds=...)` 继续表达旧模式。investigation 调用
`run()`，禁止传 rounds；CLI 使用 `--run-intent investigation --formal-stage-limit N`，
与显式 `--rounds` 互斥。省略新配置时仍默认 10 rounds。investigation 必须有
非空 current_question、显式 CodeResearchLimits、至少 O/M 之一、公开研究预算、
provider_call_cap 和 outer_hardwall_sec；配置缺失在首次 provider dispatch 前拒绝。
这些是 operator 的资源条件，不是研究质量或内容门槛。CLI 保留既有 signal hardwall；
直接 Python API 在会话 dispatch/结束与 loop 边界检查 wall，不冒称能抢占宿主调用。

`PublicResearchSession` 提供 host-only `conclude_research(raw)`，H 会话接收独立
`ResearchConclusion` 返回值；pipeline 关闭并发布材料后转为 RESEARCH_CONCLUDED。
reason 是原短理由上限 2000 字符；note_refs 可为空，仅允许当前 H 自写 note，拒绝
旧 H、C、导入、source、fixture、重复或不可用 ref；数量和合计字节使用既有材料
集合/输入限制。正文普通保存为 kind=note，含原 reason/note_refs/source_condition，
dependencies 保留引用。没有哈希身份、签发或另一个结论状态库。

开放 H 的工具和上下文明确给出 phase、run_intent、原始 current_question、正式额度
是否可用以及共享资源用量；材料正文保持原读取权限，不把旧解释改成新 system
指令。零额度隐藏并拒绝 finalize/stage/select；仍可 read/search/observe/write/abstain/
conclude。investigation 的初始化不强制满足“提交 H 所需最少 turns/reads”，因为
合法结论不导出 H；如果实际选择 H 导出，原 source read、research_basis 和既有
frontier 校验仍成立，且不把这些要求扩展到 conclude。C 永不开放 conclude。

动作顺序：有限 schema/权限检查 → 保存结论原件和 index → 返回 ResearchConclusion
→ 关闭/发布会话 → 检查材料/外部 stop/共同资源 → 记录普通 operational step →
loop 停止新派发 → 既有 terminal drain → 再检查故障 → 单一 CampaignRunResult 投影。
已保存结论遇资源/故障时保留引用但不转成正常完成。auth/quota/中断仍沿原 typed
路由；非法动作只给有限反馈；没有 provider 重试、terminal replay 或隐式重新 run。

investigation 的 requested_rounds 为 null；formal_stage_limit 为实际上限，正值达到
即以 formal_stage_limit_reached 停止，0 不触发空循环而只禁正式导出。所有已完成
Protocol stage（含 expansion/validation/frozen）计入上限。结论 formal delta=0，
不是 research rejection，不写算法失败记忆、不清理已验证 head。status=completed
只指合法 research_concluded 或正式上限结束；无正式评价的 scientific run_validity
仍为 invalid_no_evaluated_outcome。正例可完成 invocation 而没有科学收益。
终态保留 run_intent/上限/实际数/conclusion_ref、原科学结果及普通 pending work
清单（not_executed）；branch 原状态和 source 不改写。现有 runtime 是顺序调度，
本切片不增加后台任务或暂停/恢复，原 terminal 路径不删除 live heads。
既有 cleaned-stale / no-accepted-change reconcile housekeeping 仍可继续调度，
不得因它们使用 NOT_EVALUATED 而把 investigation 提前置为终态。

## 6. 失败路由和验收

|事件|预定路由|
|---|---|
|非法脚本/draft、原 test 局部额度不足|既有有限反馈；不启动测试，不伪造 failed observation|
