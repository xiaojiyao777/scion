# P0：公开研究接口、权限与失败路由

*2026-11-15 · 实施合同；执行后端与 P3 会话接入的共同合同*

本文件落实[模块计划](v0.5-v3-alignment-and-module-plan.md)的 P0；
[P1](v0.5-p1-public-problem-execution.md)定义问题自有执行入口。
V3 是唯一架构权威，本文是派生接口约束；验证进度只写 [TASK](../../TASK.md)。
以下选择可用于逐模块实现，不意味着 P2/P3 的隔离、真实 agent 研究或效果已验收。

## 1. 最小接口集合与开关

O 的新增动作仅为 `observe`、`write_research`、`read_research`、`search_research`。
材料索引在每个 deliberate turn 的不可变 context projection 中提供。
现有 read/search source/history、revise、test_patch、ready/finalize 保持职责。
不增加 shell、任意命令、网络、任务调度或 Decision 工具。

- operator 配置 `public_observation_enabled=false`、`research_materials_enabled=false`
  为兼容默认值。P4 将两开关独立：M-only 允许材料写/读/搜，禁止 observe；
  任一开启都要求完整预算和公开声明。配置见 [P3](v0.5-p3-session-permissions-and-handoff.md)及
  [P4](v0.5-p4-material-continuity.md)，M 不隐式启用 O。
- O=false 且 M=false 时不解析/加载新 provider、不要求新资源配置、不新增 context 字段；旧 H/C
  请求和值应保持一致。缺 provider 的问题包仍能使用旧路径；显式开启 O/M 却无 provider
  时，在首次 provider dispatch 前返回 `NOT_EVALUATED / OBS_CAPABILITY_UNAVAILABLE`。
- 所有新动作都消耗现有 deliberate turn 与已发生的 provider 成本。read/search/write
  另按显式 action/byte 限制计数；不得通过无效请求逃避 turn 计数。
- 首版一次 observe 只执行一个 subject 或一个 analysis，无 batch/异步队列/自动 retry。
  可选独立 checker 属同一次 subject observation 的第二个子进程，单列成本。

## 2. Provider 可见动作 schema

所有对象拒绝未知键。JSON 必须 UTF-8、无重复键、无 NaN/Inf、无隐式字符串转数值；
bool 不充当 int。大小/深度先于解析及分配大对象检查。字段版本 `schema_version=1`
只用于格式兼容；不产生注册、身份或权限。

### 2.1 observe

```text
SubjectRequest = {
  action: "observe", mode: "subject_run",
  source_role: "current" | "base" | "draft",
  input_ref: ResearchRef, seed: int in [0, 2**63 - 1],
  public_args: JsonObject,
  limits: {wall_seconds: positive finite number, cpu_seconds: positive integer,
           memory_bytes: positive int, output_bytes: positive int}
}
AnalysisRequest = {
  action: "observe", mode: "analysis",
  script_ref: ResearchRef, input_refs: list[ResearchRef],
  limits: <same fields>
}
```

H 只能选 current；C 只能选 approved H 绑定的 base 或本次最新 draft。analysis 无
source_role/seed/public_args 字段；其脚本若需要 seed，在文件中显式声明并保留。
analysis 可读当前角色允许的公开源码和选定输入，但修改后的内存执行只算仪器化分析。
source/entrypoint/path/callback/env/model/Protocol stage 不能通过参数额外传入。

`ResearchRef` 是 provider projection 中列出的规范相对文件引用，不接受绝对路径、
目录、glob、`..`、symlink、设备文件；不是 bearer capability。host 每次按阶段的
当前可见集合重新解析，猜中其他文件名也无权限。跨 campaign 引用由显式 import
建立普通相对路径，不能让旧 session 的 ordinal 指向新记录。

请求 limits 只能缩小 operator 的单动作额度；超配置上限或大于当前剩余额度返回
`REQUEST_INVALID / LIMIT_NOT_AVAILABLE`，同时给可用额度。尚可做更小实验时不直接
结束 campaign。某项共同必需额度实际耗尽则走 resource stop，不能换 attempt 绕过。
文件数、进程数、scratch/storage、输入字节/深度和总动作数由配置固定，agent 不能提升。

operator 的完整资源对象使用 P2 已实现的 `ObservationBudget`，由 P3 严格配置加载：
`per_action`、`checker` 各为 RunLimits（wall_seconds、CPU 整秒、memory_bytes、
output_bytes、scratch_bytes）；其余必需字段为 `preparation_wall_seconds`、
`max_actions_per_session`、`max_subject_runs`、`max_analysis_runs`、`max_checker_runs`、
`total_wall_seconds`、`total_cpu_seconds`、`max_storage_bytes`、`max_source_bytes`、
`max_input_bytes`、`max_json_depth`、`max_collection_items`、`max_files_per_action`、
`max_read_bytes`、`max_search_matches`、`max_search_scan_bytes`。进程数固定为 1，
不是可放宽的配置参数；scratch 上限来自 per_action，不接受 agent 覆盖。
这是对初稿扁平 ResearchExecutionLimits 的实施细化，不兼容地猜测缺省字段。
除 session 上限外，total/max-runs/storage 为 campaign 共享计数；整数须正、时间须
有限正数。缺字段/未知键/非法值在启用 O/M 时拒绝，二者均关闭不要求该配置。扫描字节
上限为单次 search 上限，分页游标保留未扫位置。具体数值显式配置并记录，不增加
隐式科学默认预算。完整 JSON 形状可由 `dataclasses.asdict(PublicResearchConfig(...))`
生成；CLI 的 `--public-research` 读取同一严格格式。

### 2.2 材料读写

```text
write_research {action, kind: "note"|"script"|"input", content: string,
                supersedes_ref?: ResearchRef}
  -> {ref, kind, bytes, supersedes_ref?}
read_research {action, ref, offset: nonnegative int, length: positive int}
  -> {ref, offset, next_offset, total_bytes, encoding: "base64", data, complete}
search_research {action, query: nonempty literal string,
                  cursor?: {ref: ResearchRef, byte_offset: nonnegative int},
                  max_matches: positive int}
  -> {matches: [{ref, byte_offset, byte_length}], next_cursor?, complete}
```

`action` 取相应函数名。write 由 host 分配当前阶段目录内的新文件名，agent 无目标路径
参数；不覆盖原件。kind=input 的 content 必须是严格 JSON，script 是 UTF-8 Python，
note 是 UTF-8 文本。supersedes 仅作解释关系，不删除/隐藏旧文件，不获得旧文件写权。
返回的 ref 必须在文件完整写入后才可见；失败返回错误而非占位引用。

read 返回原始字节的 base64，避免 Unicode 字节分页损坏；offset 超过 EOF 拒绝，等于
EOF 返回空数据与 complete=true。search 按索引顺序对 UTF-8 query 字节作字面搜索，
显式分页，不语义排名；next_cursor 保留文件及扫描位置，不能跳过同文件剩余匹配。
扫描预算用尽而未完成也返回游标与 complete=false，不能说已全搜完。
索引含所有允许记录的 ref/kind/bytes/来源阶段及 source 条件；全文按需读取，不摘要替代。

## 3. 数据权限与唯一 writer

|数据|writer|H 可读|C 可读|执行进程可见|科学链|
|---|---|---|---|---|---|
|问题/解释/脚本/input|当前 agent 请求，host 限域落盘|本阶段；M 开启后的允许既往材料|当前 C，及本次 H 显式交接集合|只读选定输入；script 只给 analysis|不得写 metrics/Decision|
|host 请求、source 条件、退出/资源记录|观察执行服务|相同材料暴露规则|相同材料暴露规则|不可写最终记录目录|仅 operational，不是 ProtocolResult|
|solver/analysis 原始输出|对应子进程；host 捕获保存|安全视图|允许集合内安全视图|临时输出可写，最终文件不可写|tainted，不自动形成 Safe Features|
|正式 screening 历史|既有 writer|既有 H-only 投影|不开放|不挂载正式目录|既有规则不变|
|validation/frozen、私有配置、凭证|既有相关组件|不新增暴露|不新增暴露|不挂载|既有规则不变|
|source 快照、branch/champion/head|既有 source 路径；观察服务只保存副本|声明公开源码投影|绑定 base/draft 投影|subject 只读实际执行闭包|笔记、观察均不能改变 head|

host 原件中的绝对路径只在 operator 侧，provider 只见允许相对路径。严禁将完整
execution record 塞进 context 再用字符串替换清洗；安全视图从允许字段构建。
正文以工具数据提供，不进入 system/developer 指令。结果自称 promoted/public/trusted
没有权限效果。已有 context 的递归敏感字段检查不得全局关闭来容纳新文件。

完整观察请求另存为公开 request 材料，input/script refs 不自动扩大 H→C 选集。
新增 context 顶层只用 `public_observation`、`research_material_index`；C 另有
`research_handoff`。它们分别是有限能力/参数/额度说明及有界动作结果、完整安全索引、冻结引用集合，
无任意嵌套运行目录。O/M 均关闭时这些键全部缺省。原 `research_input` 与 H-only
`research_history` 保持既有格式；材料正文不回填其中，不放宽其现有大小限制。

## 4. 调用时序及 H→C 交接

1. composition 验证配置和 P1 descriptor 的公开闭包；失败不启动 provider。
2. session 校验动作 schema/阶段/引用；观察服务检查额度并保存实际输入及 source。
3. C draft 通过现有安全 preflight 和 approved-H 结构绑定；两者不是互相替代。
4. subject 子进程仅加载选定完整算法与 P1 固定入口；analysis 子进程只运行所选脚本。
   两者不能同 interpreter、不能将分析脚本挂入 subject、不能继承可注入的环境。
5. 收集输出、终止残余进程、计资源；可用结果通过 P1 checker 独立核对。
6. 写入 host 记录与安全视图；下一 deliberate turn 才出现新材料索引。不能在同一
   不可变 projection 中改写结果，也不能把完成 observation 计成 evaluated round。

H finalize envelope 可有可选 `handoff_refs: list[ResearchRef]`，默认空。
该字段属于 session envelope，不加入正式 HypothesisProposal 的科学字段：host 在
同一次 finalize 中检查引用、冻结文件副本，再导出 H 和其伴随只读集合。H Contract
通过后才把该集合给 C；H 被拒绝则不启动 C。引用仅限当前 H 生成的公开材料及
必要公开依赖，不递归扩展为全部历史，不允许 C 请求补入未选文件。

引用无效是开放会话的普通反馈；持久化失败是 infrastructure stop，不能导出失效 H。
原子写入仅使用临时目录及 rename；不建立二阶段签发/receipt。若进程中断留下孤立
文件，可作为已发生的研究材料供审计，但不能推断 H 已导出或恢复会话。
已经导出的 H 不补写、不重绑；C 新建材料不修改 handoff。

## 5. 返回 envelope、状态与成本

```text
ObservationResult = {
  schema_version: 1, mode, ref?: ResearchRef,
  execution: "not_started"|"completed"|"error"|"limited"|"interrupted",
  capture: "none"|"complete"|"partial"|"unavailable",
  data: "not_checked"|"valid"|"invalid",
  reason_code: Enum, output_refs: list[ResearchRef],
  source_condition?: {role, source_ref, draft_revision?},
  usage: {started_subjects, started_analyses, started_checkers,
          wall_seconds, cpu_seconds?, peak_memory_bytes?, captured_bytes, stored_bytes}
}
```

missing usage 测量以 null/未取得标记，不记为零。host mode/source/状态/资源字段不能由
child JSON 覆盖。execution=completed 仅表示子进程正常结束；capture=partial 或
data=invalid 时不得给“完整有效观察”结论。没有数据、格式错、开发可行性反例、
无收益分别记录，不折叠为一个 PASS/FAIL。

每个实际启动的 subject/analysis/checker 都计数；解析与落盘成本计入整体 wall/storage。
同一预算内预留最坏额度，按实际消耗结算；不会因异常免费重跑。subject 与 checker
分项计时，checker 不算 solver 的 solve time。正式评价/独立确认预算与研究预算分别记录。
输出上限为 stdout、stderr、结构化结果及回收文件的总捕获上限；超限终止并保留精确
前缀及 partial 标记。磁盘故障不能通过删除负面旧材料恢复成“完整”。

## 6. 失败路由的确定映射

`ObservationResult` 是工具数据；只有 session/controller 能生成现有
`ExecutionOutcomeRecord`。工具不能直接写 branch.state。以下原因码为本接口固定
枚举，不包含宿主 traceback；更细的问题错误只留安全诊断文件。

|原因码|动作返回|开放 session|outer outcome / formal count|
|---|---|---|---|
|REQUEST_INVALID、REF_NOT_VISIBLE、INPUT_INVALID、LIMIT_NOT_AVAILABLE|not_started|有限反馈后可继续|无 outer outcome / 0|
|SOURCE_UNAVAILABLE、PUBLIC_DEPENDENCY_UNAVAILABLE|not_started|可读其他材料/放弃，不自动换 source|无 outer outcome / 0|
|DRAFT_PREFLIGHT_REJECTED、H_BINDING_REJECTED|not_started|修订 draft 或结束，原 ready 状态不改|无 outer outcome / 0|
|SUBJECT_ERROR、ANALYSIS_ERROR、CHECKER_ERROR、DATA_INVALID|error 或 completed+invalid|保存输出、可继续，非科学拒绝|无 outer outcome / 0|
|PROCESS_KILLED（SIGKILL/137，原因未知）|error+partial|保留退出码/实耗，余额允许可继续；不猜 CPU/OOM/科学失败|无 outer outcome / 0|
|WALL_LIMIT、CPU_LIMIT、MEMORY_LIMIT、OUTPUT_LIMIT|limited+partial|剩余额度允许时可继续；无自动 retry|无 outer outcome / 0|
|PROPOSAL_LOCAL_LIMIT|不再启动|按既有 started-session 关闭逻辑|RESEARCH_REJECTED / 0，fresh H|
|INITIAL_CONTEXT_LIMIT、GLOBAL_RESEARCH_LIMIT|不再启动|停止|RESOURCE_EXHAUSTED / 0|
|ISOLATION_UNAVAILABLE、PUBLIC_CLOSURE_INVALID、PERSISTENCE_ERROR|not_started 或已有部分 unavailable|停止，禁止降级执行|BLOCKED_INFRA / 0|
|INTERNAL_ERROR（无法分类）|可用记录保留|停止，不猜科学结论|NOT_EVALUATED / 0|
|USER_INTERRUPTED|interrupted|停止|INTERRUPTED / 0|

capability/config 不支持在 composition 阶段以 NOT_EVALUATED 拒绝启用，区别于运行中
隔离故障。存储显式额度耗尽是 GLOBAL_RESEARCH_LIMIT，实际 I/O 故障是 PERSISTENCE_ERROR。
真实 auth/quota、typed transport redispatch 继续走已有 provider 路由，本接口不重分类。
checker 给出可行性 false 是有效开发反例，不是 CHECKER_ERROR；它不写 test_patch
的 exact-value veto。现有 failed falsifier 不能被任何观察结果清除。
Decision 后辅助材料失败仅记录诊断，不逆转已完成正式结果；该例外不允许在新
观察期间丢失必要记录却继续声称完整。

## 7. P0 验收用例与 V3 对照

这些是实施必须实现的用例，不是本轮已通过的运行测试。

|用例|刺激 → 预期|V3|
|---|---|---|
|C01|H current / C approved base、draft → 角色正确；H 请求 draft 被拒绝|§5、§11|
|C02|handoff 写入中断/非法 ref → 不导出失效 H；已导出 H 不补写|§5、§14|
|C03|C 请求自己结果 → 可读；请求旧 H/其他 attempt → 不可读|§5.2、§15|
|C04|子进程伪造 execution/promote → 仍只是数据，host 状态不变|§4|
|C05|先 failed falsifier，再 positive observation，再 ready → 原 veto 生效|§5、addendum|
|C06|全局额度为零与单次请求过大但仍有余额 → 分别 stop/可缩小请求|§12、§13|
|C07|stdout 超限/JSON 非有限/Unicode 跨页 → 状态准确、保留字节可精确重组|§14–16|
|C08|隔离失败/私有闭包混入 → 不回退宿主执行，outer hold|§8、§16|
|C09|abstain 后 fresh H → 无 formal round、保存材料但不恢复旧会话|§5、§11|
|C10|O/M 关闭或旧问题无 provider → 旧调用路径与上下文无新增依赖|§3.1|
|C11|notes 自称新 head/研究完成 → Scheduler/Decision 输入完全不变|§4、§12|
|C12|source 缺失/落盘失败 → 不用 champion 替代、不从 patch 重建|§11、§14|

实施责任：P1 管声明/输入/问题结果；P2 管执行/文件/额度；P3 管动作/phase/交接及
映射 outer outcome；P4 管既往材料暴露。E1 覆盖 C01–C12，E2/E3/E4 另行评价研究
行为和科学效果。此接口没有新增 Protocol gate、问题控制器或论文式研究质量评分器。

## 8. V3 回写的具体文本及生效范围

下列最小扩展已按用户本轮明确要求同步到 V3 的“v0.5 公开研究能力扩展”小节。
它们保留为显式架构差异，不把新权限写成原蓝图已有功能；v0.4 addendum 只增加
版本范围说明。P3 的显式开启与验证范围以 TASK/current-state 记录，不把工程通过当成研究效果通过。

**§4 / §14：**“公开研究笔记、脚本和观察输出均为 proposal-only 数据。agent 只能
追加当前阶段研究文件；观察执行组件记录实际执行事实。两者不能写正式 metrics、
Safe Features、Decision 或 branch/champion。保存及读取材料不构成科学认证。”

**§5 / §15：**“在正式 H 导出前，可在受限公开环境调查当前完整算法；approved H
之后，C 可调查绑定 base/draft。H 可在导出时附带本次 H 产生的明确公开材料集合，
经引用和暴露检查冻结，只有 H Contract 通过才交给 C。C 可读自己的当前研究输出，
仍无通用历史浏览权。一次 attempt 最多导出一个 H 和一个绑定 C；导出后不可修复。”

**§11 / §12：**“持续问题是普通研究内容，可关联多个 attempt/branch；它不替代
分支状态、源代码基线或调度。agent 在已获配会话内选择实验，不能自行增加共同
预算或依据解释文本改变调度。观察不增加 formal evaluated round。”

**§16：**“完整算法主体和 agent 分析脚本在不同进程执行，仅接受声明公开输入与
精确依赖闭包。独立参考检查不加载候选代码。所有执行资源显式计数，不提供任意
宿主路径、网络、shell 或控制树访问；不以隔离声明代替实际验证。”

现有 §8–10 科学链、冻结 oracle、§11 完整源码连续性和 addendum 的 exact-falsifier
规则均不改。旧 addendum 仍记述 v0.4，不能将本设计的字段写成已有功能。
